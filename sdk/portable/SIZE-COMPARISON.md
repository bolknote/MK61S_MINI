# Размеры APP до и после перехода на ABI 3

Дата измерения: 06.09.2026.

FOCAL и BASIC после перехода немного уменьшились на диске. WBMP, CHIP-8
и оба варианта Markdown выросли. BCJ даёт выигрыш каждому новому модулю,
но не во всех случаях компенсирует увеличение несжатого образа.

## Условия сравнения

С нуля собраны шесть комплектов: по три конфигурации до и после переноса.
Исходники до переноса — `68828b4`, после — `a1a3b23`. Это сравнение
реальных версий проекта, а не старого режима, включённого в новых исходниках.

В обеих версиях использованы xPack GNU Arm GCC **14.2.1 20241119**, STM32
Core **2.12.0**, LTO, математическое ядро CORE (`-MathBackend 1`),
FOCAL/BASIC и выключенный USB-экран. В каждой паре одинаковы профиль
и функции прошивки. Штатная оптимизация System APP изменилась вместе
с реализацией: раньше `-Os -flto`, теперь `-Oz -flto`.
Старые APP сжаты ZX0; новые — BCJ + ZX0.

| Конфигурация | Профиль и модули |
| --- | --- |
| `mini` | `mini-v3-a00`: FOCAL, BASIC, текстовый Markdown; CHIP-8 выключен. |
| `classic` | `classic-v3`: FOCAL, BASIC, графический Markdown с WBMP, CHIP-8. |
| `wbmp` | `classic-v3`: FOCAL, BASIC, отдельный WBMP, CHIP-8; Markdown выключен. |

Размер файла включает заголовок **64 байта**, но не метаданные C5.
Размер памяти взят из заголовка APP; проверены длина контейнера, ABI,
CRC заголовка и сжатого потока. Точные размеры, SHA-256 файлов, полные
идентификаторы коммитов и все варианты находятся в
[`SIZE-COMPARISON.json`](SIZE-COMPARISON.json).

## Размер файлов

FOCAL, BASIC, графический Markdown и CHIP-8 в основной таблице взяты из
`classic`; отдельный WBMP — из `wbmp`, текстовый Markdown — из `mini`.

| APP | До, байт | После, байт | Изменение, байт | Изменение |
| --- | ---: | ---: | ---: | ---: |
| FOCAL | 13 987 | 13 620 | −367 | −2,62% |
| BASIC | 11 769 | 11 522 | −247 | −2,10% |
| WBMP | 1 185 | 1 616 | +431 | +36,37% |
| Markdown с графикой | 9 373 | 12 080 | +2 707 | +28,88% |
| Markdown только текст | 3 331 | 3 812 | +481 | +14,44% |
| CHIP-8 | 2 232 | 2 563 | +331 | +14,83% |

Старые APP зависят от профиля и адресов функций resident, поэтому даже
FOCAL/BASIC могут отличаться на несколько байт между комплектами.
Например, в `mini` FOCAL: **13 988 → 13 620**, BASIC:
**11 799 → 11 522**. Новые FOCAL/BASIC/CHIP-8 побайтно одинаковы
в собранных профилях, где соответствующий модуль включён.

Сумма размеров реально поставляемых APP, без одновременного подсчёта
Markdown и встроенного в него WBMP:

| Комплект | До, байт | После, байт | Разница |
| --- | ---: | ---: | ---: |
| mini: FOCAL + BASIC + текстовый Markdown | 29 118 | 28 954 | −164 (−0,56%) |
| Classic: FOCAL + BASIC + графический Markdown + CHIP-8 | 37 361 | 39 785 | +2 424 (+6,49%) |
| Classic: FOCAL + BASIC + отдельный WBMP + CHIP-8 | 29 175 | 29 321 | +146 (+0,50%) |

## Память приложения

Здесь измерены **образ + BSS**, с тем же выбором конфигураций, что
в основной таблице файлов. Стек, буферы resident и workspace интерпретаторов
в эти числа не входят; это не полный расход RAM на запуск модуля.

| APP | До, байт | После, байт | Разница | Остаток окна 20 480 байт |
| --- | ---: | ---: | ---: | ---: |
| FOCAL | 19 208 | 20 140 | +932 | 340 |
| BASIC | 16 280 | 17 252 | +972 | 3 228 |
| WBMP | 1 320 | 1 924 | +604 | 18 556 |
| Markdown с графикой | 11 496 | 15 324 | +3 828 | 5 156 |
| Markdown только текст | 3 960 | 4 652 | +692 | 15 828 |
| CHIP-8 | 2 856 | 3 356 | +500 | 17 124 |

Во всех случаях объём приложения в SRAM вырос. Сжатие влияет на файл
в C5, но не уменьшает распакованный образ. Общее окно в прошивке уже
зарезервировано и осталось прежним, поэтому суммы этой таблицы не нужно
складывать: одновременно загружается один модуль.

У FOCAL самый малый запас: **340 байт**. Его сжатый файл стал меньше,
но для дальнейших изменений существенен именно остаток окна SRAM.

## Сколько даёт сам BCJ

В этой таблице сравнивается **один и тот же новый несжатый образ**:
обычный ZX0 и BCJ перед ZX0. Оба размера включают заголовок 64 байта.
Это отдельный замер фильтра, без влияния изменений исходников и оптимизации.

| APP | Только ZX0, байт | BCJ + ZX0, байт | Экономия BCJ, байт |
| --- | ---: | ---: | ---: |
| FOCAL | 14 511 | 13 620 | 891 |
| BASIC | 12 303 | 11 522 | 781 |
| WBMP | 1 664 | 1 616 | 48 |
| Markdown с графикой | 12 372 | 12 080 | 292 |
| Markdown только текст | 3 890 | 3 812 | 78 |
| CHIP-8 | 2 630 | 2 563 | 67 |

Для языков фильтр окупает увеличение файла: без BCJ новые FOCAL и BASIC
были бы больше старых. Для графического Markdown экономия 292 байта
существенно меньше общего роста; оптимизация только фильтра сжатия
не устраняет увеличение несжатого кода.

## Стоимость в прошивке

Независимость от точного resident требует кода загрузчика и таблиц API.
Чтобы оценка компактности не ограничивалась файлами в C5, ниже приведён
размер прошивки тех же пар сборок.

| Конфигурация | Resident BIN до, байт | После, байт | Разница | Глобальная RAM до → после |
| --- | ---: | ---: | ---: | ---: |
| mini | 235 628 | 240 020 | +4 392 | 47 112 → 47 108 |
| classic | 236 784 | 241 208 | +4 424 | 49 108 → 49 092 |
| wbmp | 236 752 | 241 096 | +4 344 | 49 108 → 49 092 |

Это результат всего переноса, включая API, загрузчик, совместимость
и линковку. Проверка компоновки и бюджетов сборщика прошла для всех
шести комплектов. Она не заменяет функциональный тест приложения.
Результаты аппаратных проверок переноса приведены отдельно в
[HIL-2026-09-06.md](HIL-2026-09-06.md).

Ранее в [System API](SYSTEM-API.md) была измерена другая пара:
ABI 2 и ABI 3 **на исходниках после переноса**. Для неё разница resident
составила 4568 байт. Здесь исходная точка — настоящий коммит до переноса,
поэтому результат `mini` равен 4392 байтам.

## Воспроизведение

Используйте отдельные копии исходников коммитов `68828b4` и `a1a3b23`,
одну установку toolchain и одинаковые зависимости. В каждой копии
из корня репозитория выполните:

```sh
./tools/build-gcc.cmd -Profile mini-v3-a00 \
  -Focal 1 -Basic 1 -Wbmp auto -Markdown 1 -Chip8 0 \
  -UsbScreen 0 -MathBackend 1 \
  -BuildRoot .build/size-mini -OutputDirectory .build/size-mini-output

./tools/build-gcc.cmd -Profile classic-v3 \
  -Focal 1 -Basic 1 -Wbmp auto -Markdown 1 -Chip8 1 \
  -UsbScreen 0 -MathBackend 1 \
  -BuildRoot .build/size-classic -OutputDirectory .build/size-classic-output

./tools/build-gcc.cmd -Profile classic-v3 \
  -Focal 1 -Basic 1 -Wbmp auto -Markdown 0 -Chip8 1 \
  -UsbScreen 0 -MathBackend 1 \
  -BuildRoot .build/size-wbmp -OutputDirectory .build/size-wbmp-output
```

В новой версии ABI 3 включён по умолчанию; при желании явно добавьте
`-PortableApps 1`. В старой версии этого параметра нет.
Сравнивайте `System/*.APP` внутри каталогов результатов. Новая сборка
печатает оба кандидата `ZX0 candidates: plain=… BCJ=…`; эти числа относятся
только к сжатому потоку, поэтому для размера файла к ним нужно добавить 64.

Образ занимает поле little-endian `uint32` по смещению 28 заголовка APP,
образ вместе с BSS — по смещению 32. Формат описан в
[SDK](README.md). JSON этого отчёта позволяет проверить как отдельный
модуль, так и полную сумму каждого комплекта.
