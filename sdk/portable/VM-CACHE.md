# Самодостаточные модули и RAM-кеш VM

Реализация 2026-10-08. Это кеш байткода BASIC/FOCAL, а не кеш нативных APP.
Compiler APP, cold `LANGIN.APP` и hot `LANGVM.APP` по-прежнему загружаются
общим APP runtime. Кеш не пишет файлы и не меняет C6/C8.

## Контракт

Сохранённые BASIC и FOCAL кешируются при явных RUN по ID, имени и выбранному
индексу, включая интерактивный BASIC RUN. Имя разрешается тем же способом,
что и в прежнем frontend; новой семантики путей нет. Запуск из меню/редактора
не кешируется под ID сохранённого файла: там может находиться черновик.

На промахе исходник читается один раз, sizing и EMIT используют один снимок.
EMIT пишет непосредственно в BUILDING-запись. После выгрузки compiler APP
cold verifier проверяет весь образ; только затем resident публикует READY
и передаёт управление hot VM. Ошибка RUN или отмена не удаляет корректную
READY-запись.

На попадании не загружается compiler APP и не повторяется полная проверка.
Код, строки PRINT и подсказки INPUT находятся в RAM. За текстовыми ресурсами
нет обращений к ФС. Явные файловые операции программы и проверка метаданных
этим контрактом не запрещены. INPUT может загрузить cold APP и вычислить
временное выражение; это не повторная компиляция сохранённой программы.

Переменные, массив, RNG и продолжение не входят в образ. Каждый RUN получает
новое состояние исполнения с прежними правилами сохранения значений.
Исходная длина сохраняется для SIZE и квоты массива.

## Wire format v4

Все слова little-endian; opcode остаётся 8-битным. Образ не содержит native
указателей. Магия `LBV1` сохранена, поле версии равно 4. Образы v1/v2/v3 отвергаются.

| Смещение | Размер | Значение |
| --- | --- | --- |
| 0 | 4 | `LBV1` |
| 4 | 1 | Версия 4 |
| 5 | 1 | BASIC=1 / FOCAL=2 |
| 6 | 1 | Требуемое число значений на стеке |
| 7 | 1 | Флаги: expression=1, RF=2, resources=4, owned resources=8 |
| 8 | 2 | Полный размер |
| 10 | 2 | Начало кода |
| 12 | 2 | Число строк |
| 14 | 2 | Длина исходника M8 |
| 16 | 4 | CRC исходника |
| 20 | 4 | CRC образа после заголовка |
| 24 | 6 | Для owned: нули; для SOURCE: ID и media revision |
| 30 | 2 | Конец кода при наличии ресурсов, иначе нули |

После заголовка находятся таблица строк и код. Таблица BASIC содержит
`[u16 line, u16 pc]`, FOCAL — `[u32 address, u16 pc]`; диагностические
SOURCE_POS остаются в коде. Бюджет заголовка, карт и кода — 6144 байта.
Полный owned-образ ограничен 9728 байтами; лимиты исходников и runtime stack
не увеличены. Legacy SOURCE-образ целиком ограничен прежними 6144 байтами.

`GOTO_DIRECT` и `GOSUB_DIRECT` (92/93) содержат `u16 pc`, разрешённый
компилятором для простого положительного номера строки BASIC. `0xFFFF`
обозначает отсутствующую строку: ошибка возникает только при исполнении.
Вычисляемый номер, включая побочные эффекты INPUT(), использует прежние
GOTO/GOSUB и прежнюю проверку номера. Cold verifier проверяет границы pc.

Три составные инструкции v4:

| Opcode | Операнды | Действие |
| --- | --- | --- |
| 94 LOAD_ARRAY_FIXED | u16 index | Загрузка массива без промежуточной константы/стека |
| 95 COMPARE_FALSE | u8 mask, u16 pc | Сравнить два значения, перейти при ложном результате |
| 96 UPDATE_LOCAL | u8 variable, u8 rhs | Обновить локальную переменную ADD/SUB без стека |

COMPARE_FALSE использует биты less/equal/greater/unordered; маски EQ/NE/LT/LE/GT/GE
равны 2/13/1/3/4/6. Cold verifier отвергает старшие биты и неверные границы pc.
UPDATE_LOCAL: rhs bits 0..5 — число/индекс, bit 6 — индекс переменной вместо
числа, bit 7 — SUB вместо ADD. Индексы проверяются и cold, и hot; конечность
операндов/результата проверяется до записи. Компилятор первого этапа эмитирует
только RHS-переменную или CONST_0..15 и только точную последовательность
`A=A+B`/`A=A-B`/`A=A+1`: не пересекает SourcePos, ссылки, массивы, I/O или
дополнительную арифметику. Группировка, overflow promotion и signed zero прежние.

LOAD_ARRAY_FIXED эмитируется только для голого unsigned integer 16..65535;
ошибка превышения квоты остаётся runtime-ошибкой на исходном `@`. Для 0..15
прежняя двухбайтная пара компактнее и сохраняется. Динамические индексы,
INPUT(), дроби и отрицательные числа не меняются. LOAD_ARRAY_FIXED разрешён
также в INPUT expressions; остальные составные инструкции там запрещены.
CHECK (29) в v4 зарезервирован и отвергается: все producing operations уже
проверяют конечность, компиляторы v3 его тоже не эмитировали.

Каталог и пул объединены в компактную последовательность
`[u16 length][length готовых M8-байтов]`. PRINT_RESOURCE и INPUT_RESOURCE
содержат `u16` смещение записи относительно конца кода. Это не ссылка на
исходник. Одинаковые итоговые строки, в том числе составные подсказки,
интернируются внутри модуля. Пустая строка допустима; INPUT по-прежнему
ограничен 95 байтами. PRINT использует существующий ограниченный вывод.

Cold verifier проверяет весь каталог, границы ссылок и длины. Bitmap
инструкций остаётся 768 байт: увеличенный пул не раздувает bitmap на C-стеке.
Проверенный сертификат 16 байт не содержит указателей на cold APP.

Внутренний compiler/runtime request ABI равен 7, ARM Request — 40 байт,
CompilerContext — прежние 240 байт, ExecutionState — прежние 1520 байт.
Compiler/VM/input и language-flow context magics обновлены. Размер union
сам по себе не гарантирует совместимость смещений CompilerStage.
После изменения нужно устанавливать
согласованный resident и каталог System; старый language APP несовместим.
Внешний APP container ABI по-прежнему 6.

## Общий быстрый путь VM

Оптимизации не зависят от игры или файла и работают в BASIC и FOCAL:

- Проверка конечности числа выполняется в каждой производящей операции.
  Повторные CHECK не эмитируются; NaN/Inf по-прежнему дают MATH до STORE
  или следующей операции. В v4 неиспользуемый CHECK удалён из executor.
- SOURCE_POS — диагностический префикс. Он сохраняет столбцы ошибок, но
  пропускается перед основным dispatch и не входит в счётчик steps/limit.
  Service вызывается до первой и каждой 32-й полезной инструкции,
  включая пустые FOR: отдельный повторный опрос на NEXT не нужен.
  Сканирование префиксов ограничено
  размером образа, их границы проверяются.
- Таблица длин заменяет второй switch и повторное чтение opcode. Проверки
  переменных записей, стека, массивов и целей переходов остаются.
- Бинарная арифметика использует два уже существующих элемента стека с
  одной проверкой глубины; точность, overflow promotion и signed zero прежние.
- Фиксированные побитовые копии чисел используют builtin memcpy даже при
  APP `-fno-builtin`. Это перенос представления, не изменение арифметики.
- Восемь direct-mapped записей кешируют точную расшифровку CONST_DEC8/16:
  80 байт временного C-стека, без static RAM, malloc и роста байт-кода.
  Кеш действует только внутри одного run; INPUT/resume строит его заново.

Этот быстрый путь не превращает CORE transcendental math в APP FLOAT и не
заменяет LIBM. Выбранный math backend и числовой ABI остаются прежними.

### Составные операции: первый этап

Выбор сделан по host-профилю неизменённого Turochamp (2/8, без книги), а не
по отдельным именам файлов в runtime. До слияния: 7272816 полезных dispatch;
составные операции дали около 12% сокращения. Это количество инструкций VM,
не device cycles или обещание такого же процента времени всей игры.

115 модулей компилируются; ни один owned-образ не вырос. Сумма 54662 → 53797
байт, High Noon 6992 → 6975, Turochamp 40232 → 39488 (39568 aligned).
Пакет шахмат всё ещё не помещается в payload 23888; увеличение кеша, межмодульный
CALL/RUN, замена cache policy и JIT в эту итерацию не входят.

Статические массивы/ABI states не добавлены. Compiler emission хранит только
два предыдущих коротких opcode в своём временном объекте; sizing и EMIT
пользуются одной схемой, без дополнительной копии всего кода/IR. Поля cold
compiler обнуляются общим initializer; fixed numeric bit copies не вызывают
APP memcpy, большой int32 token упаковывается через один Value, не два.

Цена loaded APP против предыдущего этапа: BASIC 18216 → 18488, FOCAL
18588 → 18604, LANGVM 12876 → 13060, LANGIN 10960 → 11216 байт. APP FLOAT
LANGVM 15356 → 15540. Это разные фазы, их нельзя суммировать как одновременно
занятую RAM. Общий APP arena по-прежнему 20 КиБ; бюджет cache 24576 не меняется.
Hot CORE/LIBM size gate вырос на один 32-байтный allocation quantum:
13056 → 13088, потому что реальный образ на 4 байта превышает прежний ceiling.
FOCAL storage/memory и APP FLOAT ceilings сохранены. Это небольшая цена
native executor/компилятора за меньшие модули и меньшее число dispatch, не
нулевая цена динамической RAM.

Регрессионные проверки покрывают IEEE order/unordered, NaN/Inf, signed zero,
int32 overflow, ошибки/диагностику, точный sizing, invalid operands/targets,
INPUT whitelist, resume и bounded cancellation. Host ASan/UBSan, полный
Turochamp (правила/поиск/UI/книга) и 24624 High Noon cases прошли.
Профилировщик LANGUAGE_VM_TRACE — только host build: в shipping APP нет
счётчиков, callback-полей или дополнительных firmware imports.

Matched baseline исходников `488eaa248` (VM в нём — `b81f5e617`). Согласованные
полные сборки F401 CORE/cache0 и F411 LIBM/cache24576: sealed Flash 256664 →
256664 и 358580 → 358588; ELF static RAM/dynamic pool неизменны — 37904/22760
и 83708/32256 соответственно. Внешние APP-файлы суммарно +764 байта, не
внутренняя Flash. APP FLOAT и CORE/LIBM имеют отдельные loaded-image ceilings.

Matched ARM instruction gate (500 итераций, включает initial validation,
без I/O/загрузки APP): integer/array, mixed, wide, decimals и compound BASIC,
mixed FOCAL — ×1,038..1,053; IF/GOTO BASIC ×1,690; GOSUB BASIC ×1,557;

115 реальных ARM sizing/EMIT/verifier также прошли: максимум вложенного
compiler/service C-стека 6908 байт (ранее 6820), verifier 972. Это не полный
device peak. LIBM и APP FLOAT overlay/INPUT/resume и F401 CORE compiler flow
проверены на трёх адресах с перезаписью выгруженного APP.

Локальные данные: `tmp/vm-fusion-20261008.iL2KAw/`. Последующая разрешённая

### Профиль и политики кеша

`MK61_DWT_RUNTIME_DETAIL=1` — только диагностическая resident-сборка.
По умолчанию 0: прежние 17 точек/структура статистики сохраняются, новые
хуки и таблицы отсутствуют. Диагностика разделяет native APP loading/entry
для BASIC, FOCAL, LANGVM, LANGIN и остальных; файловые source/font reads;
ZX0 для каждого типа APP, source, font и workspace swap. Загрузка включает
поиск/чтение заголовка, а не только decode. `self=` исключает вложенные Scope,
`total=` остаётся включающим: эти колонки нельзя складывать друг с другом.
Accumulator-метрики прежнего core detail не образуют разбиение такого дерева.

Кооперативные вложенные Scope расширяют CYCCNT до 64 бит, поэтому один
долгий VM/INPUT entry не теряет полный оборот счётчика. Требуется чтение
чаще одного оборота (44,7 с на 96 МГц); многократный необслуживаемый пропуск
оборотов DWT сам по себе не восстанавливает. Reset/generation не позволяет
старому Scope или decode context перезаписать новую сессию профиля.
`VMCACHE` содержит до 32 inode/size/hit/miss строк и явный dropped counter.

После аппаратной и общей языковой квалификации resident использует
`CachePolicy::REUSE_DENSITY` по умолчанию:
`MK61_LANGUAGE_VM_CACHE_DENSITY=1`. Значение `0` явно возвращает исходный LRU;
bundle builder проверяет и передаёт этот переключатель. При cache=0 политика
не инстанцируется, малопамятный путь F401 не меняется.
Повторные hit повышают ограниченный счётчик reuse (максимум 255);
жертва имеет минимальное reuse/allocated-byte, при равенстве выбирается LRU.
Сравнение целочисленное, без float/division. После каждого вытеснения reuse
стареет вдвое, чтобы прошлый hot set не закреплялся навсегда. Pinned объекты
по-прежнему не вытесняются. Счётчик занимает прежнее reserved u16 в Entry:
каталог 688, payload 23888 и общий бюджет 24576 байт не меняются.

Host trace/replay на неизменённых шахматах: чистый поиск использует 12 модулей
(21680 выровненных байт) и помещается; полный UI/book-off/Black-search/ESC,
два хода, использует 17 (32256 байт). В повторном полном replay 22611 обращений
штатный C++ LRU даёт 254 misses, C++ density — 120, без fallback. Счётчики
обеих replay-моделей точно совпадают с C++ ImageCache; модель не включает
изменения ФС, конкурентные pins и вытеснения native APP/арен. Это число
промахов, не замер CPU времени и не доказательство происхождения 500 ZX0.

Сопоставимые изолированные F411 LIBM/Os/no-LTO сборки: LRU sealed 358548,
density 358636 (+88 Flash); static RAM одинаковая 83708. Все десять System
файлов побайтно совпадают. Диагностическая LRU-сборка sealed 361332 (+2784),
static RAM 85052 (+1344). F401 CORE/cache0 собран: sealed 256656, static RAM
37904, кеш-политика не активна. Это ELF/image budgets, не полный heap peak.
Артефакты первоначального локального этапа:
`tmp/vm-runtime-profile-20261008.faK65p/`. Тогда аппаратный профиль и A/B
ещё не проводились: плата использовалась параллельным тестом. Последующая
разрешённая квалификация описана ниже. На первоначальном исследовательском
этапе обе опции были off; теперь density включена, а runtime detail остаётся
off по умолчанию.

### Аппаратная проверка density и полный кадр

Последующая проверка 2026-10-08 на том же F411 использует точный установленный
снимок `A3952F33` с PackBits/восстановлением renderer плюс десять shipping
VM-файлов `2c0dd37f5`. Исправления другой задачи сохранены. Сопоставимые обычные
LRU `7206CEB8` и density `0B31EB72`: 96 МГц, LIBM, Os/no-LTO, cache24576,
USB Screen, no grid/loan. В этих сборках sealed358780/358876 (+96), staticRAM
83708 одинаковая; все десять System APP/HELP файлов побайтно одинаковы.

Диагностический LRU `7A5DC978` подтвердил в повторном ходе 11178hits/125misses,
без dropped rows. ZX0=500: по125 source, BASIC, LANGIN и LANGVM; font/swap=0.
При показе board вытесняются status/mobility/threat/unmake/castle. Compiler
entry self13,35 с, cache lookup0,067 с, font activation0,369 с: перенос шрифта

рядов, С/П МЕНЮ и ОК ВЫБОР. До него старый снимок обрывался после шестого
ряда, потому что текст последнего хода уже появлялся и тест мог послать ESC

явно отвергает шестирядный и семирядный кадры. Все следующие цифры получены

### Одна очистка warm RUN и штатная density

Продолжение выполнялось в порядке: однократная инициализация warm RUN,
квалификация/default density, затем подробный профиль. Warm cached RUN теперь
задаёт только language tag для проверки сертификата, после чего
`initialize_validated_state` полностью очищает continuation один раз. Холодная
предварительная очистка сохранена для ранних ошибок. Это не выборочное
обнуление стеков: прежние 1520 байт состояния по-прежнему полностью очищаются,
а persistent variables/array не затрагиваются. Request ABI7, bytecode v4 и
размеры структур не менялись.

Host test-only hook считает reset: 20 повторных RUN требуют ровно 20 полных
инициализаций; START проверяет чистые flags/control/output/input. ASan/UBSan
интеграция автоматически проверяет LRU и density при USB=0/1, а явный

## Бюджет и lifetime

`MK61_LANGUAGE_VM_IMAGE_CACHE_BYTES` теперь означает **общий** бюджет,
а не только байты образов. При 24576 байтах:

- 16 записей каталога;
- 688 байт метаданных и счётчиков;
- 23888 байт payload;
- `sizeof(ImageCache<24576>) == 24576`, без второго массива и malloc.

Для стандартных 16 слотов ненулевой бюджет должен включать хотя бы 688 байт
метаданных и 32 байта образа; меньшая конфигурация отвергается static_assert.

Ключ — язык, file ID и общая media revision. Формат/компилятор/числовой ABI
зафиксированы самой сборкой и её проверками совместимости; кеш только RAM
и не переживает замену firmware. Параметры RUN не создают дубли образа.
Версии отдельных файлов пока не используются: изменение постороннего файла
консервативно инвалидирует READY-записи.

Handle содержит номер слота и поколение. BUILDING невидим для lookup;
reservation закреплена до публикации/отката. READY закрепляется на весь RUN,
INPUT, resume и finish. Обе политики вытесняют только незакреплённые записи, уплотнение
разрешено только без pins. Все операции выполняются в foreground, не IRQ.

Изменение ФС делает закреплённый образ STALE: текущий RUN завершает свой
снимок, но новый lookup его не получает. После последнего release запись
освобождается. Изменение версии до публикации отменяет BUILDING. При возврате
в BASIC-редактор после изменения исходника показывается предупреждение,
старые координаты не применяются.

## Малопамятный путь

На F401 кеш штатно выключен. При выключенном/переполненном кеше сначала
пробуется временный owned-образ в существующих разрешённых аренах. Если
резерв невозможен либо owned sizing переполнился, тот же исходник используется
для SOURCE-образа с прежним чтением строковых ресурсов. Повторно открывать
редактор/выбор программы или перечитывать source для retry не нужно.

Fallback не является cache hit и не обещает автономность ресурсов. Это
best effort: при отсутствии памяти даже для прежнего пути остаётся BUSY.
`cache_diagnostics()` предоставляет бюджет/занятые байты и счётчики
lookup/hit/miss/reservation/failure/publication/eviction/invalidation;
при отключённом кеше возвращает false. Счётчики загрузок compiler и чтений
source/resources пока проверяются тестовыми трассами, а не отдельными
постоянными firmware-счётчиками.

Frozen baseline — `f8133db68`. Одинаковые флаги на обеих сторонах сравнения:

F401 resident math + без USB/grid + cache=0. Screen loan включён в обоих.

Это цена самостоятельных ресурсов и общего lifetime manager, а не новая

ровно одно чтение source на модуль, ноль чтений при EMIT/проверке. Измеренный
вложенный C-стек APP/services: sizing и EMIT максимум 7076 байт, verifier 976.

Временные interning slabs остаются на C-стеке компилятора. Индивидуальный
максимальный frame 3168 байт не является общим compile stack peak: два
наибольших slabs существуют одновременно. ARM отчёты отдельно показывают
вложенные APP/service stack peaks. Resident dispatcher/loader, live heap,
active USB и полный device high-water требуют проверки на устройстве.

## Пакеты — следующий слой, не часть текущего runtime

High Noon уже целиком помещается как четыре независимые записи с прежней
семантикой RUN. Межмодульная дедупликация дала бы **максимум 118 байт** до цены
каталога/заголовка пакета. У Turochamp 40232 байт owned-образов, экономия
общего пула максимум 121 байт, один только код/карты — 38750 байт. Целиком
в 24-КиБ кеше он не помещается даже без строк.

Пакетный runtime, manifest/preload API и общий межмодульный пул пока не
реализованы. Не считать сумму образов исполняемым пакетом и не объединять
семантику отдельных RUN. Для Turochamp сейчас работает ограниченный density-
кеш отдельных модулей с явным LRU override. Нет автоматической загрузки
шрифтов, картинок и всей папки.
