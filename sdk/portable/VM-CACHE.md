# Самодостаточные модули и RAM-кеш VM

Реализация 2026-10-08. Это кеш байткода BASIC/FOCAL, а не кеш нативных APP.
Compiler APP, cold `LANGIN.APP` и hot `LANGVM.APP` по-прежнему загружаются
общим APP runtime. Кеш не пишет файлы и не меняет C6/C8.

## Контракт

Сохранённые BASIC и FOCAL кешируются при явных RUN по ID, имени и выбранному
индексу, включая интерактивный BASIC RUN. Имя разрешается тем же способом,
что и в прежнем frontend; новой семантики путей нет. Запуск из меню/редактора
не кешируется под ID сохранённого файла: там может находиться черновик.

На промахе исходник читается один раз, sizing и EMIT используют один снимок.
EMIT пишет непосредственно в BUILDING-запись. После выгрузки compiler APP
cold verifier проверяет весь образ; только затем resident публикует READY
и передаёт управление hot VM. Ошибка RUN или отмена не удаляет корректную
READY-запись.

На попадании не загружается compiler APP и не повторяется полная проверка.
Код, строки PRINT и подсказки INPUT находятся в RAM. За текстовыми ресурсами
нет обращений к ФС. Явные файловые операции программы и проверка метаданных
этим контрактом не запрещены. INPUT может загрузить cold APP и вычислить
временное выражение; это не повторная компиляция сохранённой программы.

Переменные, массив, RNG и продолжение не входят в образ. Каждый RUN получает
новое состояние исполнения с прежними правилами сохранения значений.
Исходная длина сохраняется для SIZE и квоты массива.

## Wire format v2

Все слова little-endian; opcode остаётся 8-битным. Образ не содержит native
указателей. Магия `LBV1` сохранена, поле версии равно 2. Образы v1 отвергаются.

| Смещение | Размер | Значение |
| --- | --- | --- |
| 0 | 4 | `LBV1` |
| 4 | 1 | Версия 2 |
| 5 | 1 | BASIC=1 / FOCAL=2 |
| 6 | 1 | Требуемое число значений на стеке |
| 7 | 1 | Флаги: expression=1, RF=2, resources=4, owned resources=8 |
| 8 | 2 | Полный размер |
| 10 | 2 | Начало кода |
| 12 | 2 | Число строк |
| 14 | 2 | Длина исходника M8 |
| 16 | 4 | CRC исходника |
| 20 | 4 | CRC образа после заголовка |
| 24 | 6 | Для owned: нули; для SOURCE: ID и media revision |
| 30 | 2 | Конец кода при наличии ресурсов, иначе нули |

После заголовка находятся таблица строк и код. Таблица BASIC содержит
`[u16 line, u16 pc]`, FOCAL — `[u32 address, u16 pc]`; диагностические
SOURCE_POS остаются в коде. Бюджет заголовка, карт и кода — 6144 байта.
Полный owned-образ ограничен 9728 байтами; лимиты исходников и runtime stack
не увеличены. Legacy SOURCE-образ целиком ограничен прежними 6144 байтами.

Каталог и пул объединены в компактную последовательность
`[u16 length][length готовых M8-байтов]`. PRINT_RESOURCE и INPUT_RESOURCE
содержат `u16` смещение записи относительно конца кода. Это не ссылка на
исходник. Одинаковые итоговые строки, в том числе составные подсказки,
интернируются внутри модуля. Пустая строка допустима; INPUT по-прежнему
ограничен 95 байтами. PRINT использует существующий ограниченный вывод.

Cold verifier проверяет весь каталог, границы ссылок и длины. Bitmap
инструкций остаётся 768 байт: увеличенный пул не раздувает bitmap на C-стеке.
Проверенный сертификат 16 байт не содержит указателей на cold APP.

Внутренний compiler/runtime request ABI равен 5, ARM Request — 40 байт,
CompilerContext — прежние 240 байт, ExecutionState — прежние 1520 байт.
Compiler/VM/input и language-flow context magics обновлены. Размер union
сам по себе не гарантирует совместимость смещений CompilerStage.
После изменения нужно устанавливать
согласованный resident и каталог System; старый language APP несовместим.
Внешний APP container ABI по-прежнему 6.

## Бюджет и lifetime

`MK61_LANGUAGE_VM_IMAGE_CACHE_BYTES` теперь означает **общий** бюджет,
а не только байты образов. При 24576 байтах:

- 16 записей каталога;
- 688 байт метаданных и счётчиков;
- 23888 байт payload;
- `sizeof(ImageCache<24576>) == 24576`, без второго массива и malloc.

Для стандартных 16 слотов ненулевой бюджет должен включать хотя бы 688 байт
метаданных и 32 байта образа; меньшая конфигурация отвергается static_assert.

Ключ — язык, file ID и общая media revision. Формат/компилятор/числовой ABI
зафиксированы самой сборкой и её проверками совместимости; кеш только RAM
и не переживает замену firmware. Параметры RUN не создают дубли образа.
Версии отдельных файлов пока не используются: изменение постороннего файла
консервативно инвалидирует READY-записи.

Handle содержит номер слота и поколение. BUILDING невидим для lookup;
reservation закреплена до публикации/отката. READY закрепляется на весь RUN,
INPUT, resume и finish. LRU вытесняет только незакреплённые записи, уплотнение
разрешено только без pins. Все операции выполняются в foreground, не IRQ.

Изменение ФС делает закреплённый образ STALE: текущий RUN завершает свой
снимок, но новый lookup его не получает. После последнего release запись
освобождается. Изменение версии до публикации отменяет BUILDING. При возврате
в BASIC-редактор после изменения исходника показывается предупреждение,
старые координаты не применяются.

## Малопамятный путь

На F401 кеш штатно выключен. При выключенном/переполненном кеше сначала
пробуется временный owned-образ в существующих разрешённых аренах. Если
резерв невозможен либо owned sizing переполнился, тот же исходник используется
для SOURCE-образа с прежним чтением строковых ресурсов. Повторно открывать
редактор/выбор программы или перечитывать source для retry не нужно.

Fallback не является cache hit и не обещает автономность ресурсов. Это
best effort: при отсутствии памяти даже для прежнего пути остаётся BUSY.
`cache_diagnostics()` предоставляет бюджет/занятые байты и счётчики
lookup/hit/miss/reservation/failure/publication/eviction/invalidation;
при отключённом кеше возвращает false. Счётчики загрузок compiler и чтений
source/resources пока проверяются тестовыми трассами, а не отдельными
постоянными firmware-счётчиками.

## Проверки и измерения

Frozen baseline — `f8133db68`. Одинаковые флаги на обеих сторонах сравнения:
Classic V3, CORE; F411 APP FLOAT + USB + screen grid + cache=24576;
F401 resident math + без USB/grid + cache=0. Screen loan включён в обоих.

| Изменение относительно baseline | F401 | F411 |
| --- | ---: | ---: |
| Внутренняя Flash sealed firmware | +88 | +1284 |
| Постоянная RAM по ELF | 0 | −352 |
| Динамический пул по ELF | 0 | +352 |
| Сумма внешних файлов APP | +1065 | +1067 |
| RAM загруженного BASIC.APP | +720 | +720 |
| RAM загруженного FOCAL.APP | +432 | +432 |
| RAM загруженного LANGVM.APP | +56 | +56 |
| RAM загруженного LANGIN.APP | +224 | +224 |

Это цена самостоятельных ресурсов и общего lifetime manager, а не новая
экономия внутренней Flash. Прежние APP size gates сохранены. ELF static RAM,
APP memory и динамический пул нельзя складывать как одновременный peak.

Host+ASan/UBSan проверяют ресурсы, числа, VM и кеш; ARM проверяет настоящие
compiler/VM/input APP на трёх адресах с отравлением выгруженного APP.
Нативная политика handles/pins отдельно проверяется host-тестом и 5000
фрагментированными операциями. High Noon проверяет 24624 сценария, включая
равенство inline и owned образов, текст, паузы, RNG и отмену.

Измеренный корпус — 115 программ, включая 25 модулей Turochamp. High Noon:
4999 байт SOURCE-образов → 7249 owned (7264 с выравниванием), без удержания
5907 байт полного исходника во время RUN. У прежнего streaming пути исходник
тоже не удерживался целиком: рост payload на 2250 байт нельзя выдавать за
экономию RAM относительно него.

Прямые ARM sizing/EMIT и cold validation прошли на всех 115 программах:
ровно одно чтение source на модуль, ноль чтений при EMIT/проверке. Измеренный
вложенный C-стек APP/services: sizing и EMIT максимум 7076 байт, verifier 976.

Временные interning slabs остаются на C-стеке компилятора. Индивидуальный
максимальный frame 3168 байт не является общим compile stack peak: два
наибольших slabs существуют одновременно. ARM отчёты отдельно показывают
вложенные APP/service stack peaks. Resident dispatcher/loader, live heap,
active USB и полный device high-water требуют проверки на устройстве.
Для первого слоя локальных тестов устройство не использовалось; отдельный
hardware-замер Turochamp приведён ниже.

### Turochamp HIL, 2026-10-08

На одной F411/Classic V3, 96 МГц, LIBM, `-Os` **без LTO**, DWT и USB Screen,
без screen grid/loan, установленная `35FE3148` сравнивалась с `029C650B`
(f8133db68 + новый кеш). Не переносить эти числа на конфигурацию таблицы
Flash/RAM выше: там CORE+APP FLOAT и LTO.

Книга выключена, исходная позиция, глубина 2/8. В обеих версиях один поиск
после сброса и два повторных, всегда e2-e3 и 420 узлов. Файлы игры не менялись.

| Поиск | Прежний кеш, с | Новый кеш, с |
| --- | ---: | ---: |
| После сброса | 164,356 | 155,042 |
| Повтор 1 | 161,949 | 153,110 |
| Повтор 2 | 162,295 | 153,435 |
| Медиана повторов | 162,122 | 153,273 |

Сокращение времени повторного поиска **5,46%**, около 8,85 с; первого — 5,67%.
Это маленькая выборка, не статистическая гарантия для любых позиций.
Все 25 модулей не помещаются: повторный поиск всё ещё может делать cache miss.

Медианное число вызовов ZX0 2343,5 → 584, их время 25,030 → 18,034 с.
Число Flash read немного **выросло** (208536 → 212351), время этих чтений
снизилось 16,197 → 15,777 с. Отдельного compiler-load счётчика на устройстве
пока нет; вызовы ZX0 нельзя выдавать именно за загрузки APP. Writes/erases
во время поисков — ноль.

Доска/статус/ход совпадают пиксельно. Whole-frame SHA отличается на 65 пикселей
только в известном disk-activity overlay 16x16: новый снимок застал индикатор
чтения. Эта проверка не утверждает полного равенства необработанных кадров.
После поисков CRC валидна, MPU layout ok, CRASH none. Остаток stack watermark
10228 байт против 9000 у baseline для этого сценария, не универсальный peak.
Перепроверены все 97 файлов вне обновлённого System и 22 каталога: неизменны.
Обновлены только согласованные resident/System с разрешения пользователя.

Для данного no-LTO/LIBM профиля цена firmware: +1760 байт Flash, −352 байта
static RAM. Новая сборка оставлена на устройстве; измерения выполнены до коммита.
Отчёты: `tmp/turochamp-perf-20261008.k5I5IQ/README.md` и `comparison.json`.
Воспроизводимый стенд: `tests/hil_turochamp_performance.py`.

## Пакеты — следующий слой, не часть текущего runtime

High Noon уже целиком помещается как четыре независимые записи с прежней
семантикой RUN. Межмодульная дедупликация дала бы **максимум 118 байт** до цены
каталога/заголовка пакета. У Turochamp 42989 байт owned-образов, экономия
общего пула максимум 121 байт, один только код/карты — 41507 байт. Целиком
в 24-КиБ кеше он не помещается даже без строк.

Пакетный runtime, manifest/preload API и общий межмодульный пул пока не
реализованы. Не считать сумму образов исполняемым пакетом и не объединять
семантику отдельных RUN. Для Turochamp сейчас работает ограниченный LRU
отдельных модулей. Нет автоматической загрузки шрифтов, картинок и всей папки.

## Воспроизведение

```sh
MK61_TEST_SANITIZERS=1 bash tests/run_language_vm_tests.sh
MK61_TEST_SANITIZERS=1 bash tests/run_language_vm_image_cache_tests.sh
bash tests/run_language_compiler_flow_tests.sh
bash tests/run_language_vm_overlay_tests.sh
bash tests/run_language_vm_resident_tests.sh
bash tests/run_app_flow_tests.sh
bash tests/run_high_noon_equivalence_tests.sh
python3 tools/measure_vm_cache.py
python3 tools/measure_app_flow.py --directory tmp/vm-cache \
  --baseline-ref f8133db68 --candidate-label universal_cache
```

`measure_vm_cache.py` строит только host probe и пишет отчёт в tmp. Оценка
shared pool в отчёте — нижняя граница размера без package header/table, не
готовый пакет. Для ARM-прогонов нужны Unicorn, согласованные ELF/System и
разрешённая JIT-память. Nonlocal transcendental suite использует отдельный
LIBM resident: эмулятор не моделирует CORE numeric CPU. CORE отдельно
проверяется `tests/run_mk_math_tests.sh`; продуктовая конфигурация не меняется.

Ни локальные тесты, ни измерители не прошивают устройства.
