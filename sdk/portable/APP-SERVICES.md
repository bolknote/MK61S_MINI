# Общий API приложений

Штатные и пользовательские APP получают одни и те же сервисы прошивки.
Контейнер ABI 6 — сжатый перемещаемый образ без привязки к ELF
прошивки. Вход в API для нового приложения на C: `#include "mk61_app.h"`.

## Получение сервисов

```c
const mk61_app_services* s = mk61_app_get_services(mk61_api,
    MK61_SERVICE_CAP_FILES | MK61_SERVICE_CAP_MEMORY);
if (!s) return MK61_APP_RUNTIME_ERROR;
```

Функция проверяет префикс базового API, наличие `query_service`, magic,
версию и размер таблицы сервисов, затем нужные возможности. Она возвращает
`NULL` при несовместимости или отсутствии хотя бы одной требуемой возможности.
Нулевая маска только получает таблицу; доступность конкретного сервиса тогда
нужно проверить самостоятельно:

```c
uint32_t caps = s->call(MK61_SERVICE_CAPABILITIES, 0, 0, 0, NULL);
```

Базовая таблица имеет 108 байт на ARM. Первые 104 байта и версия 1 сохранены;
в конец добавлен `query_service(id, version)`. Сейчас определён
`MK61_APP_SERVICE_COMMON`, версия `MK61_APP_SERVICES_VERSION=2`.
Неизвестные id и версии возвращают `NULL`. Таблица сервисов имеет 28 байт.
Startup новых APP требует актуальную 108-байтовую таблицу.
Поддержки запуска новых APP на старых прошивках нет.

Версия базового API, версия сервисов и ABI контейнера независимы. ABI 6
требует текущую таблицу сервисов v2; старые APP нужно пересобрать. Отдельной
закрытой таблицы System API больше нет. Имена `MK61_SYS_*` и
`mk61_system_*` оставлены в `loadable_system_api.h` только как алиасы исходного
кода штатных адаптеров к публичным `MK61_SERVICE_*` и `mk61_service_*`.

## Возможности сборки

| Флаг `MK61_SERVICE_CAP_*` | Сервисы | Когда доступны сейчас |
| --- | --- | --- |
| `UI` | Дисплей, клавиатура и её раскладка, язык, громкость, угловой режим, случайные числа, микросекунды | Во всех штатных сборках |
| `FILES` | Каталог C6, поиск, запись, удаление; чтение через базовый API | Во всех штатных сборках |
| `MEMORY` | Исключительная аренда WORKSPACE и SCRATCH | Во всех штатных сборках |
| `FORMAT` | Форматирование целых чисел, строк и символов | Во всех штатных сборках |
| `SETUP` | Оборудование, RTC, калибровка и настройки шрифта | Во всех штатных сборках; подробности через версию и возможности SETUP |
| `DIALOGS` | Выбор файла и места сохранения, меню | Во всех штатных сборках |
| `EDITOR` | Отрисовка редактора, прокрутка и обработка клавиш | Во всех штатных сборках |
| `REGISTERS` | Чтение и запись X/Y/Z/T/R | Во всех штатных сборках |
| `MATH` | Функции настроенного математического ядра прошивки | Во всех штатных сборках |
| `RUNTIME` | Общие ARM EABI и строковые подпрограммы | Во всех штатных сборках |
| `NUMBER_IO` | Общее форматирование/чтение `double` и разбор ссылок `.X`/`.R0` | Когда в сборку включён FOCAL или TinyBASIC |
| `FONT` | Декодирование встроенного растрового шрифта | В сборках с графическим Markdown |
| `TEXT_FONT` | Временная атомарная загрузка `Fonts/*.FMK` | На графическом UC1609 |
| `FLOAT_CONVERT` | Точное ABI-преобразование `double` ↔ битовое представление `float` | В гибридной сборке `CORE + APP FLOAT` |

Доступность определяется составом прошивки, а не именем или типом APP.
Необязательные службы не принуждают компактную сборку включать все языки,
математические библиотеки и графику. Если нужного флага нет, выберите
собственную реализацию, покажите объяснение или верните ошибку запуска.

## Вызовы

Типы и номера определены в [публичном C-заголовке](../../code/loadable_app_services.h).
`s->call(operation, a, b, c, payload)` использует 32-битные параметры и
структуру, соответствующую операции. Неиспользуемые параметры передавайте
нулевыми. Объекты C++ из прошивки через границу API не передаются.

Основные операции (префикс `MK61_SERVICE_` опущен):

| Операция | `a`, `b`, `c` | `payload` и результат |
| --- | --- | --- |
| `CAPABILITIES` | 0, 0, 0 | `NULL`; маска возможностей |
| `FILE_COUNT` | тип, 0, 0 | `NULL`; число файлов этого типа |
| `FILE_ENTRY` | 0, id, 0 | `mk61_service_file*`; 1 при успехе |
| `FILE_ENTRY` | 1, индекс, тип | `mk61_service_file*`; 1 при успехе |
| `FILE_WRITE` | родитель, id или `INVALID_ID`, тип | `mk61_service_write*`; 1 при успехе, возвращённый id в структуре |
| `FILE_REMOVE` | id, 0, 0 | `NULL`; 1 при успехе |
| `MEMORY_ACQUIRE` | арена, владелец, требуемый размер | `mk61_service_lease*`; 1 при успехе |
| `MEMORY_RELEASE` | арена, 0, 0 | та же аренда; 1 при освобождении |
| `EDITOR_DRAW`, `EDITOR_SCROLL` | 0, 0, 0 | `mk61_service_editor*`; 1 при успехе |
| `EDITOR_KEY` | 0, 0, 0 | `mk61_service_edit_key*`; код результата редактора |
| `REF_READ`, `REF_WRITE` | вид регистра, номер R, 0 | `double*`; 1 при успехе |
| `NUMBER_FORMAT` | 0, 0, 0 | `mk61_service_number_format*`; 1 при успехе |
| `NUMBER_PARSE` | 0, 0, 0 | `mk61_service_number_parse*`; 1 при успехе |
| `REF_PARSE` | 0, 0, 0 | `mk61_service_ref_parse*`; 1 при успехе |
| `DISPLAY` | `DISPLAY_FLOW_TEXT`, 0, 0 | `mk61_service_text_flow*`; число выведенных строк |
| `TEXT_FONT` | `BEGIN`/`LOAD`/`RESTORE`/`END`/`ACTIVATE`, 0, 0 | для `LOAD` — имя FMK без расширения; знаковый результат |
| `FLOAT_CONVERT` | `FLOAT_FROM_DOUBLE` или `DOUBLE_FROM_FLOAT`, 0, 0 | `mk61_service_float_convert*`; 1 при успехе |
| `TEXT_ROWS` | число строк, 0, 0 | массив указателей на строки; 1 при успехе |

Для математики предназначен отдельный вызов `s->math(operation, x, y)`.
Унарные операции игнорируют `y`; `MK61_SERVICE_POW` вычисляет степень `x` с
показателем `y`. Единицы и точность определяются выбранным в прошивке
математическим ядром, как у штатных языков.

`DISPLAY_FLOW_TEXT` переносит M8 по словам непосредственно в резидентном
дисплейном слое. На UC1609 он использует реальные advance активного FMK, на
символьном экране — число знакомест. `first_row` и `max_rows` задают окно;
флаг `TEXT_FLOW_TAIL` оставляет последние помещающиеся строки (для вопроса
`INPUT`), `TEXT_FLOW_EMPTY_LINE` превращает пустой текст в одну очищенную
строку (для пустого `PRINT`). Таким образом APP не копирует таблицы шрифта и
не реализует собственную, расходящуюся с прошивкой верстку.

`FLOAT_CONVERT` не вычисляет математическую функцию. Он только переводит
значение через границу ABI: при `FLOAT_FROM_DOUBLE` записывает четыре байта
IEEE-754 в `bits`, при `DOUBLE_FROM_FLOAT` читает их и записывает расширенное
значение в `value`. Это позволяет APP связать локальную single-precision libm,
не втягивая в APP программные ARM EABI-конвертеры `double`/`float`.

`EDITOR_KEY` получает заполненные состояние, карту управляющих клавиш и
обработчики вставки. Для обычного ввода задайте `hook_mask` и callback
`hook`: событие `MK61_EDIT_INSERT` возвращает указатель на вставляемую строку.
Бит `options=8` включает штатное соответствие обычных/K-клавиш тексту без
callback; бит `options=16` использует резидентную карту управляющих клавиш и
позволяет не передавать массив `keys`.
Пример C-callback и полного вызова есть в
[исполняемой пробе](../../tests/portable_app_services_probe.c).

Текущая внутренняя версия службы `SETUP` — 2. Она введена вместе с передачей
подготовленного шрифта из `SETUP.APP` в резидент; старый `SETUP.APP` намеренно
не запускается с новой прошивкой и наоборот. Обновляйте резидент и каталог
`System` из одного комплекта.

`NUMBER_FORMAT` реализует используемое штатными языками компактное
`%g`-подобное представление с заданным числом значащих цифр. `NUMBER_PARSE`
возвращает значение и число разобранных байтов. `REF_PARSE` разбирает имя
регистра без доступа к самому регистру. Для этих трёх операций сначала
проверяйте `MK61_SERVICE_CAP_NUMBER_IO`. Номера операций остаются частью ABI
и в сборке без языков, но capability там снят, а вызовы возвращают 0.

`mk61_app_snprintf(s, buffer, size, format, ...)` вызывает форматировщик
прошивки. Текущие компактные сборки поддерживают целые числа, строки и
символы; `%f`, `%e`, `%g` не включены. Этот сервис не заменяет полный libc.
Пример [SERVICES/main.c](../../examples/portable-apps/SERVICES/main.c)
использует общую математику и форматирует целый результат.

`TEXT_FONT` — сеансовая служба для языков и игр. Резидентный сценарий M61
вызывает `BEGIN`, затем `LOAD`: файл `Fonts/<payload>.FMK` проверяет и один раз
компилирует `SETUP.APP`, а резидент включает только полностью проверенный
готовый образ. `RESTORE` возвращает снимок, не закрывая сеанс; `END` возвращает
снимок и закрывает сеанс. Уже исполняемый APP занимает ту же арену, в которую
загружается `SETUP.APP`, поэтому он не должен вызывать `BEGIN`, `LOAD`,
`RESTORE` или `END`. Для вложенного языка предназначен `ACTIVATE`: он повторно
включает заранее загруженный M61 временный шрифт после выбора обычного
текстового режима. Результаты нужно привести из
`uint32_t` к `int32_t`: `1` — успех, `0` — файл не найден, `-1` — FMK
повреждён/несовместим, `-2` — служба не поддерживается, `-3` — ресурс или I/O
недоступен. После успешного `BEGIN` приложение обязано вызвать `END` на каждом
пути выхода.

`MK61_SERVICE_CAP_USBDISK` и `MK61_SERVICE_USBDISK` — частная граница между
каноническим `USBDISK.APP` и резидентным драйвером C6. Обычные APP не должны
её запрашивать: для файлов им предназначены публичные `FILES` и `file_read`.

## Запись файла из C

Этот фрагмент создаёт текстовый файл в корне C6. Перед ним получите `s`
с возможностью `MK61_SERVICE_CAP_FILES`.

```c
static const uint8_t text[] = "Hello from C\n";
mk61_service_write file = {
    "HELLO", text, sizeof(text) - 1, MK61_SERVICE_INVALID_ID
};
if (!s->call(MK61_SERVICE_FILE_WRITE, MK61_SERVICE_ROOT_ID,
             MK61_SERVICE_INVALID_ID, MK61_SERVICE_FILE_TEXT, &file))
    return MK61_APP_IO_ERROR;
/* file.id теперь содержит id записанного файла. */
```

Для обновления существующего файла передайте его id вторым параметром
вместо `MK61_SERVICE_INVALID_ID`. Размер данных ограничен типом файла и
возможностями C6. Чтение: `mk61_api->file_size(id)` и
`mk61_api->file_read(id, offset, buffer, length)`.

## Временные буферы

```c
mk61_service_lease lease = {0};
if (!s->call(MK61_SERVICE_MEMORY_ACQUIRE, MK61_SERVICE_WORKSPACE,
             MK61_SERVICE_OWNER_APP, 1024, &lease))
    return MK61_APP_BUSY;
/* Пользуйтесь lease.data в пределах lease.size. */
s->call(MK61_SERVICE_MEMORY_RELEASE, MK61_SERVICE_WORKSPACE, 0, 0, &lease);
```

Для SCRATCH замените арену на `MK61_SERVICE_SCRATCH` в обоих вызовах.
WORKSPACE имеет предел 8192 байта, SCRATCH - 1600; реальный доступный размер
возвращается в `lease.size`. Память может быть занята другим потребителем.
В поле владельца передавайте `mk61_app_current_kind`; APPLICATION может также
использовать равный ему алиас `MK61_SERVICE_OWNER_APP`. Это тот же контракт для
обычного и канонического APP. Адрес буфера стабилен на время аренды.

Освобождайте успешную аренду ровно один раз, на каждом пути выхода.
Не копируйте структуру аренды и не сохраняйте её указатели после освобождения.
Прошивка не обещает автоматически освободить забытые приложением аренды.
Перед вызовом C6, диалога или другой службы освободите общие буферы,
которые ей могут понадобиться. Неперсистентные буферы обычного APP
освобождаются и заново инициализируются при следующей аренде.

## Общие подпрограммы компилятора

```sh
python3 tools/build_portable_app.py --name SERVICES \
  --source examples/portable-apps/SERVICES/main.c --shared-runtime \
  --output-dir .build/portable-apps/services
```

Без `--shared-runtime` SDK добавляет необходимые функции `libgcc` в APP.
С этой опцией перечисленные в `loadable_system_runtime.def` 26 функций
вызываются через таблицу прошивки: арифметика и преобразования `double`,
64-битное беззнаковое деление, `strchr`, `strncmp`, `strlen`, `strncat`,
`memcpy`, `memset`, `memmove` и `memcmp`.
Остальные необходимые функции по-прежнему линкуются обычным способом.
Переходники сохраняют соглашение ARM EABI, включая частное и остаток
`__aeabi_uldivmod`. Приложение не получает фиксированных адресов прошивки.

Startup проверяет доступность сервиса и всех 26 подпрограмм до `main()`;
при несовместимости возвращает `MK61_APP_RUNTIME_ERROR`. `sin`, `sqrt`
и остальные математические функции вызываются явно через `s->math`.
Решение о включении опции принимайте по размеру конкретного APP.

## Проверки

`tests/run_portable_app_tests.sh` проверяет усечённые таблицы под ASan,
неизвестные/неподдерживаемые сервисы, версии и неполную таблицу runtime.
`tests/run_app_services_arm_tests.py` исполняет обычный C APP на двух
прошивках по трём адресам и проверяет отсутствие сервисов в сокращённой сборке.
Поиск сервисов, математика, ARM EABI, форматирование и редактор исполняются
из настоящей прошивки; C6 и backing буферов имитируются. Политика владельца
APP отдельно проверяется настоящим диспетчером памяти в host-тестах.

Аппаратный тест использует ту же C-пробу с графической обёрткой:

```sh
python3 tools/build_portable_app.py --name SHARED \
  --source tests/portable_app_services_hil.c --shared-runtime \
  --output-dir .build/services-hil/shared
python3 tools/build_portable_app.py --name LOCAL \
  --source tests/portable_app_services_hil.c \
  --output-dir .build/services-hil/local
```

После резервного копирования состояния прибора установите актуальную прошивку
с APP, языками, графикой и USB Screen и оба файла в `/APISVC`. Для Classic V3:

```sh
python3 tests/hil_app_services.py --port /dev/cu.usbmodem... \
  --public-id YOUR_PUBLIC_ID --directory /APISVC \
  --output-dir .build/services-hil/result --cycles 5 \
  --minimum-stack-remaining 12288
```

Пробы создают, читают и удаляют `/APITEST.txt`; тест отклоняет запуск при
уже занятом имени. Он сверяет все 1536 байт изображения с кодом результата,
возврат WORKSPACE/SCRATCH, каталог C6, MPU, watermark стека и CRC прошивки.
Сравнение изображения обязательно: терминальная команда `open` сейчас
не передаёт код возврата `main()`. После испытания восстановите исходное
состояние прибора. Скрипт теста сам не прошивает прибор и не устанавливает APP.

Измеренные размеры и границы проверки: [результаты](APP-SERVICES-RESULTS.md).
