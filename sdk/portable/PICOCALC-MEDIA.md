# Цвет, двоичные файлы и PCM для PicoCalc APP

Это необязательные расширения ABI 6. C/C++-типы объявлены в
`code/loadable_app_services.h`, Rust — в `sdk/portable/rust/mk61_app.rs`.
Перед использованием проверяйте соответствующие capability. Старые прошивки
и STM32 возвращают отсутствие возможности; ABI и существующие операции сохраняются.
Вся логика эмуляторов, форматов, палитр и звуковых чипов остаётся внутри APP.

## COLOR_DISPLAY

`MK61_SERVICE_CAP_COLOR_DISPLAY`; операция `MK61_SERVICE_COLOR_DISPLAY`.
`AVAILABLE` возвращает 1, `PRESENT` принимает `mk61_service_color_frame`,
`END` ждёт завершения LCD и возвращает обычный монохромный вывод.
Хост автоматически завершает сессию перед освобождением APP.

Необязательный `SPI_HZ`: `b=0`, `c=4`, `payload=uint32_t*` — запрос
12000000 или24000000 Гц;0 возвращает базовую частоту прошивки. Результат —
фактическая частота SPI или0 при отсутствии поддержки/неверном запросе.
Хост сначала завершает отправку предыдущего кадра. `END` и любой возврат
APP восстанавливают базовую частоту, даже если кадры ещё не отправлялись.
Частоты CPU и остальных периферийных устройств не меняются.24 МГц
проверены на данной панели PicoCalc; прежние хосты возвращают0, и APP
может продолжать с исходной частотой.

Палитра содержит 16 слов RGB565. `INDEX4` хранит по два индекса в байте,
старший первым; каждая строка занимает `(width+1)/2` байт. `TILE1` хранит
горизонтальный MSB-first bitmap и байт на плитку 8×8: старший nibble — цвет
нулевого бита, младший — единичного. Для TILE1 размеры кратны восьми.
`TILE8` использует тот же bitmap, но два байта на плитку: индекс paper,
затем ink (0..63). `PALETTE64`, `b=0`, `c=128`, `payload=uint16_t[64]`
копирует RGB565-палитру при свободном LCD. Возвраты: 1 принято, 2 занят,
0 ошибка. Следующий TILE8 кадр перерисовывается после изменения палитры.

Сумма bitmap/индексов и плиток ограничена 12800 байт. Прямоугольник должен
помещаться в 320×320. Фон за его пределами задаётся `background`.
`PRESENT` возвращает 1 после копирования всех данных, 2 при занятом LCD,
0 при неверном запросе. При 2 ничего не копируется; APP может пропустить кадр.
После 1 APP может сразу менять или освобождать исходник. Драйвер использует
существующий снимок монохромного экрана и два буфера строк, не выделяя RGB-кадр.
Неизменившиеся плитки/полосы не передаются. Цветной режим относится к LCD;
desktop USB Screen пока передаёт обычный монохромный кадр.

## FILE_BYTES

`MK61_SERVICE_CAP_FILE_BYTES`; операция `MK61_SERVICE_FILE_BYTES`.
Это чтение физических байтов файла без декодирования UTF-8/M8 и без
определения формата по расширению. Смещения и размеры файлов — 32-битные.

`mk61_service_file_bytes.path` — M8-путь, относительный к каталогу исполняемого
APP или абсолютный от корня SD. `STAT` возвращает `mk61_service_file_info`,
`CHILD` возвращает запись каталога по индексу `offset`, `READ` копирует ровно
`size` байт начиная с `offset`, не более 4096 за вызов. Имена CHILD сохраняют
расширения. Успех — 1, ошибка/конец каталога — 0. APP обслуживает устройство
между блоками чтения через `api->service()`.
`WRITE` перезаписывает существующий диапазон файла тем же запросом,
не более 4096 байт. Размер не увеличивается, новый файл не создаётся.
На PicoCalc запись журналируется и синхронизируется до возврата.

`PATH` преобразует ID выбранного физического файла в абсолютный M8-путь:
`path=NULL`, `data=char[capacity]`, `offset=id`, `size=capacity` вместе с
завершающим NUL. Возвращает1 при успехе; при0 буфер не меняется.
Это позволяет `mk61_app_open_file(id)` открыть файл из другой папки,
сохранив относительные пути ресурсов к каталогу самого APP.
Бинарные файлы с ассоциацией имеют тип `EXTERNAL_BINARY` (254): их байты
не декодируются как текст. Это внешний тип, который не записывается в C6/C9.

## KEY_BITMAP

`KEYBOARD / KEY_BITMAP`, `b=32`, `c=0`, `payload=uint8_t[32]` возвращает
состояние всех 256 исходных кодов клавиатуры PicoCalc. Бит N означает, что
код N удерживается. Учитываются физические события, удалённые клавиши и
временные serial-импульсы; обычная очередь нажатий/отпусканий не потребляется.
Возвращает 1 при поддержке. Это позволяет APP самостоятельно строить матрицы
клавиатур и обрабатывать сочетания с Ctrl/Alt.

## AUDIO_STREAM

`MK61_SERVICE_CAP_AUDIO_STREAM`; операция `MK61_SERVICE_AUDIO_STREAM`.
`OPEN` принимает `mk61_service_audio`: rate=25000, volume=0..100,
samples=NULL, count=0. Поддерживается моно PCM signed 16-bit. Общая настройка
громкости прибора применяется дополнительно при открытии.

`WRITE` принимает до 1024 отсчётов и возвращает фактически принятый `count`.
Вызов не ждёт освобождения очереди; непоместившийся хвост остаётся у APP.
`STATUS` возвращает число ожидающих отсчётов и underrun. `CLOSE` освобождает
таймер и очередь и выключает динамики; APP return делает это автоматически.

`SYNTH_OPEN` принимает `mk61_service_audio_synth`: callback, context,
rate=25000, volume=0..100. Callback возвращает packed signed 16-bit L в
младших и R в старших 16 битах. Он выполняется в timer IRQ второго ядра
и должен быть ограниченным по времени: без выделения памяти, блокировок,
сервисов прошивки и ожидания первого ядра. Передавайте события через
очередь SPSC с acquire/release. Код и context должны жить до возврата
CLOSE. CLOSE выполняется на втором ядре и ждёт завершения callback до
освобождения APP. STATUS сообщает rate, queued=0, underruns=0; собственную
диагностику ведёт APP. Очередь PCM в режиме синтеза не выделяется.

Очередь из 1024 отсчётов выделяется только на время сессии (около 2 КиБ).
Аппаратный таймер второго ядра каждые 40 мкс обновляет PWM GPIO26/27.
Громкость ограничивает амплитуду вокруг середины PWM. Звуковые
сигналы интерфейса не меняют PWM во время сессии. Пустая очередь выдаёт тишину.
