# APP без фиксированного резерва: 6 сентября 2026

Исходная точка: `6c7ceaf`, ABI 4 с физическим пулом 20 КиБ.
Новая штатная сборка не содержит `mk61_module_overlay` и не резервирует
отдельную секцию под APP. Формат ABI 4, C API, ZX0/BCJ и готовые программы
сохраняются. Машиночитаемые результаты: [DYNAMIC-RAM-RESULTS.json](DYNAMIC-RAM-RESULTS.json).

## Размещение памяти

Линкер экспортирует свободный промежуток от `align8(_end)` до защиты стека.
Его верхняя граница: `0x2000E700` на F401 и `0x2001BF00` на F411.
APP получает `align32(memory_bytes)` сверху. 20 КиБ остаются ограничением
размера одной программы, включая образ, данные, BSS и выравнивание.

Системная куча и временная арена OVERLAY используют нижнюю часть. Загрузка
APP не вытесняет занятый нижний буфер и не меняет его адрес или содержимое.
Если блок не помещается, загрузчик возвращает ошибку. Выгрузка возвращает
память APP; неисполняющийся кэш System APP может уступить её временным
буферам. Во время активного вызова APP остаётся закреплённым.

Новый `_sbrk` не пересекает APP или защиту стека и не меняет размер кучи при
занятом нижнем буфере. Сохраняются отдельные статические WORKSPACE,
SCRATCH и BULK. Универсальный malloc для приложений в SDK не добавлялся.

На F411 после CRC-проверки до пяти MPU-областей с подрегионами разрешают
исполнение точно в выделенном блоке. Перед освобождением разрешение
отзывается. Вместе с SRAM XN, защитой нулевого адреса и стековым барьером
используются восемь MPU-областей. Бюджет стека не менялся: F401 6 КиБ,
F411 16 КиБ плюс отдельный барьер 256 байт.

ABI 2/3 отклоняются до записи payload в RAM: их прежний адрес теперь занят
обычными данными resident. Для штатной прошивки их нужно пересобрать в
ABI 4. Явный `PortableApps=0` сохраняет старую manifest-сборку ABI 2 с резервом.

В самой тесной конфигурации постоянная RAM сократилась с 54084 до 33600
байт: освобождено 20484 байта. Свободный участок до барьера составляет
25528 байт до выделения кучи/буферов/APP. После загрузки большой программы
её память занята. Изменение статической RAM по профилям немного различается
из-за выравнивания и раскладки глобальных данных.

Все восемь сборок прошли ограничения Flash, RAM, кадра стека и штатные
проверки ELF. Максимальный статический кадр остался 2032 байта при пороге
2048. Дополнительная проверка `tests/check_app_memory_elf.py` подтверждает
отсутствие резерва, границы RAM, совместное размещение максимальной APP с
индексом C5 и сильное переопределение `_sbrk` во всех девяти проверенных ELF.

Экспериментальный F411 с полным набором APP: BIN 302248 → 302660 байт
(+412), статическая RAM 61360 → 40876. Эта конфигурация включает динамическую
настройку MPU; штатная матрица F411 со встроенными компонентами здесь
целиком не прогонялась. Отдельная сборка комплекта F401 через Arduino CLI
и проверки PowerShell/GCC-упаковщика также прошли.

Перед коммитом повторены полный набор тестов с ASan/UBSan, обе ARM-серии
и чистая сборка самой тесной F401. Результат: PASS; постоянная RAM 33600
байт, BIN 257896 байт, свободно 4248 байт Flash. Разница в 8 байт с таблицей
выше находится только в `.rodata`: `terminal.cpp` и `setup_service.cpp`
скомпилированы в разные секунды и содержат две строки `__TIME__` вместо
одной общей. Машинный код по размеру не изменился. Логи повторного прогона
сохранены в `.build/dynamic-app/precommit/`.

## Программные проверки

- Полный `tests/run_all_tests.sh` с ASan/UBSan: PASS.
- Динамическая память: независимые данные кучи и staging, сохранение адресов
  и байтов при смене размеров APP, полное заполнение свободного участка,
  отказ при пересечении, отрицательный `_sbrk`, переполнение размера,
  закрепление исполняющегося APP и освобождение кэша: PASS.
- Для каждого округлённого размера APP от 32 до 20480 байт проверено
  фактическое покрытие MPU всей F411 SRAM с шагом минимальной области 32
  байта. Статические данные, свободная память, барьер и стек остаются XN: PASS.
- HELLO, WBMP и C-проба релокаций выполнялись как ARM по четырём адресам,
  включая размещение под барьерами F401/F411, с двумя таблицами resident API.
  Для символьной сборки без графики проверен ожидаемый отказ WBMP: PASS.
- Шесть System APP, включая оба варианта Markdown, выполнялись по трём
  адресам свободной RAM с реальными API и ARM-хелперами F411/графика и
  F401/символьный экран. Эти два стенда используют LIBM; C5/периферия и
  снимки workspace имитируются. Арифметика, восстановление состояния,
  редакторы, пиксели, SETUP и границы выделения: PASS.

## Физический F411

Classic V3 / UC1609, public ID `AEB505B6E0067623`, временная прошивка
`EDFFB94F`. Тот же ранее собранный код C-пробы с прежней таблицей релокаций
выполнился по адресам `0x2001B700`, `0x2001B300`, `0x2001A700`.
Дополнительная BSS менялась только в заголовке контейнера; payload одинаков.

Проверены 12 запусков C-пробы, 21 запуск WBMP и 6 переключений дисплея,
12 запусков языков, 6 восстановлений переменных, 3 запуска CHIP-8,
3 запуска Markdown, SETUP hardware/date/calibration/font с отменой правок.
Отклонены ABI 3 и пять повреждённых APP без изменения видимого C5; справка
проверена в полном, отсутствующем, устаревшем и восстановленном состоянии.
`MEM invariant=ok`, MPU `enabled=1 layout=ok regions=8/8`, аварий нет.

Минимальный измеренный остаток стека после всех операций: **11136 байт**.
Это прежнее ограничение относительно общего релизного порога 12 КиБ;
полная release qualification по этому порогу не объявляется пройденной.
Последующее сокращение расхода стека описано в [STACK-RESULTS.md](STACK-RESULTS.md);
числа выше относятся к исходному этапу удаления резерва APP.

Восстановлена исходная прошивка `2504D75A`, все 524288 байт Flash сверены
чтением обратно. Все 18 исходных C5-файлов, каталоги, пустые регистры,
стек и программа восстановлены; удалены 14 временных файлов.
Второй прибор не изменён. Подробные логи и резервные копии находятся в
локальном `.build/dynamic-app/`.
