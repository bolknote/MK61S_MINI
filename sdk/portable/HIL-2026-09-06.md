# System APP ABI 3: обновление и аппаратные проверки 2026-09-06

Итог: Classic V3 обновлён до build **2504D75A** и оставлен на новой
прошивке. В `/System` установлены FOCAL, BASIC, WBMP, Markdown и CHIP‑8
ABI 3. Все пять модулей проверены на физическом STM32F411. Исходные
13 пользовательских файлов сохранены; 11 временных файлов удалены.
После завершающего перезапуска регистры, стек и программа калькулятора
совпали с исходным пустым состоянием.

## Прибор и установленные файлы

Classic V3, UC1609 192×64, STM32F411CE, 128 КиБ SRAM, 512 КиБ внутренней
Flash; C5 на внешней NOR EF3013 объёмом 512 КиБ. Public ID —
`AEB505B6E0067623`, USB serial — `2068336B4731`.
Второй подключённый прибор WS0010 не перепрошивался.

Перед обновлением сохранены все файлы C5 и 524288 байт внутренней Flash.
Исходный build — `4AC27AA8`; его BIN занимал 330176 байт.

| APP | Размер файла, байт | Образ + BSS, байт |
| --- | ---: | ---: |
| FOCAL.APP | 13620 | 20140 |
| BASIC.APP | 11522 | 17252 |
| WBMP.APP | 1616 | 1924 |
| MARKDOWN.APP, графический вариант | 12080 | 15324 |
| CHIP8.APP | 2563 | 3356 |

Все APP заново собраны независимым сборщиком без resident ELF/BIN.
У всех ABI 3, BCJ + ZX0, адрес `0x20000000`, нулевые поля привязки
к resident. Каждый файл прочитан с прибора и сопоставлен с исходным APP.
C5 показывает расширение `.app` строчными буквами; содержимое не меняется.

## Прошивки

Arduino CLI, STM32 Core 2.12.0, xPack ARM GCC 14.2.1,
FQBN `STMicroelectronics:stm32:GenF4:pnum=BLACKPILL_F411CE,upload_method=dfuMethod,xserial=none,usb=CDCgen,opt=osstd`.
Включены FOCAL, BASIC, CHIP‑8, USB Screen, LoadableModules, PortableApps
и проверка resident CRC; математический backend — LIBM (`0`).
Linker script преобразован `tools/.mk61-gcc/portable-layout.py`.

Сначала испытан отдельный WBMP.APP. Затем заменена только прошивка:
те же APP остались в C5 без пересборки и переустановки. В итоговой сборке
просмотр WBMP выполняет MARKDOWN.APP; отдельный WBMP.APP тоже оставлен
в `/System`, но его включение определяется конфигурацией прошивки.

Обе сборки прошли проверки глобальных конструкторов, раннего DFU и
подключения USB suspend callbacks. Это функциональный прогон System APP
на одном F411; физический F401 в нём не участвовал.

## Проверки на приборе

Финальный автоматический прогон `tests/hil_portable_system_apps.py`:

- Три цикла с 12 запусками языковых программ. Перед вычислением тест
  обнуляет выходные регистры и проверяет обнуление чтением обратно.
  FOCAL вычисляет `2+3*4=14`; BASIC — `6*7=42` и
  `SIN(0)+COS(0)+SQRT(16)+LN(EXP(1))=6`.
- Шесть восстановлений переменных при обмене FOCAL ↔ BASIC: отдельные
  программы читают сохранённые значения `A=14` и `A=42` после смены APP.
- Три запуска CHIP‑8. Сравниваются все пиксели кадра до и после нажатия
  клавиши: ROM ждёт ввод и переносит контрольный спрайт.
- Три запуска Markdown: кадры совпадают между запусками, прокрутка
  меняет изображение, обратная прокрутка возвращает исходный кадр.

На каждой из двух прошивок также выполнен `tests/hil_portable_apps.py`:
четыре запуска обычного C CHECK.APP с проверкой свежих `.data`/BSS,
семь просмотров WBMP, точные кадры при горизонтальной/вертикальной
прокрутке и переключение USB → UC1609 → USB. Вместе эти два прогона
дают 56 полных сравнений контрольных кадров; CHIP‑8 добавляет ещё шесть
в финальном прогоне. USB Screen проверяет CRC16 каждого принятого кадра.

Через обычное меню прибора проверены оба редактора. Временный FOCAL-файл
изменён с номера строки `1.10` на `1.11`, BASIC — с `10` на `11`.
Штатные диалоги сохранили файлы в `/SAPPTEST`; прочитанные байты точно
совпали с ожидаемыми. Обе сохранённые программы затем запущены и записали
`7` в соответствующий регистр.

APP с повреждённым сжатым потоком и APP с неизвестным битом flags
отклонены при установке (`PUT_APP`). Полный снимок видимых файлов C5
до и после этих отказов совпал. Ошибок загрузки и crash dump не появилось.

Проверена существующая `/Pogonya/MANUAL.md`: текст и встроенные картинки
по относительным ссылкам `view.wbmp` отображаются через новый Markdown.
Кадры сохранены и просмотрены. Оптическая проверка физического LCD
не выполнялась; контроль пикселей использует USB Screen с реального MCU.

## Память и уточнения сценария

`MEM invariant=ok`, `CRASH none`, MPU включён с корректной раскладкой
и четырьмя областями из восьми. Исполняется только 20-КиБ APP-окно;
остальная SRAM сохраняет XN. Минимальный остаток 16-КиБ стека по watermark
после языков, редакторов и просмотров — **6800 байт**. После завершающего
перезапуска — 13848 байт. Это измерения данного прогона, а не прохождение
общего release-порога 12 КиБ после всех этих сценариев.

В ходе расширения теста исправлены два его предположения. Команда
обнуления требует пробела: `R0= 0`; финальный тест дополнительно проверяет
результат обнуления. Состояние языков сохраняется прежним RAM-кэшем:
WORKSPACE плюс один сжатый снимок в BULK. Третий потребитель может
вытеснить снимок, поэтому проверка обмена двух языков выполняется до
запуска CHIP‑8. Постоянного хранения всех переменных эта схема не обещает;
исходные файлы программ при вытеснении не удаляются.

## Итоговая сверка

Установленные 306772 байта прошивки прочитаны обратно через DFU и
побайтно совпали с проверенным BIN. SHA-256:
`ef179aa46368484d27e58d8edf05bd0c98557e66fc8a6a4dafeeba5fa0cb0058`.
После перезапуска прибор подтвердил `2504D75A` и валидный аппаратный CRC.
В C5 остались 13 исходных файлов и пять System APP; все они повторно
прочитаны и сверены. Временный каталог `/SAPPTEST` удалён.

Локальные доказательства находятся в `.build/portable-system-hil/`:
`completion.json`, `final-resident-readback.bin`, `final-c5.json`,
`test-final-checked/`, `test-wbmp-pixels/`, `test-final-pixels/`,
`extras-result.json`, `edited-*`, `editor-probe/`, `manual-*.png`.
Команды сборки, исходная резервная копия и журналы DFU находятся там же;
бинарные снимки не входят в Git.

Для повторения автоматических проверок сначала сгенерируйте и установите
временные файлы из `--write-fixtures`, затем запустите тест:

```sh
python3 tests/hil_portable_system_apps.py --write-fixtures .build/system-fixtures
# После установки файлов в /SAPPTEST и System APP в /System:
python3 tests/hil_portable_system_apps.py --port /dev/cu.usbmodem... \
  --public-id PUBLIC_ID --cycles 3 --markdown --output-dir .build/system-hil-result
```

Сам тест не прошивает MCU и не пишет C5; он меняет R0–R4 и передаёт клавиши.
Сохранение пользовательского состояния, установка и уборка выполняются
отдельно.
