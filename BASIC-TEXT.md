# Текстовые расширения BASIC v1

Реализация предназначена для общей Flash VM STM32F401/F411. Исходники
разбиваются на `.tbi`, диспетчеризация остаётся в M61. Службы компилятора и
текстовых инструкций резидентны, чтобы BASIC.APP и LANGVM.APP сохраняли лимит
20 КиБ. Числовая ячейка остаётся восьмибайтовой. Формат байткода — v14,
отпечаток компилятора изменён; нужно обновлять прошивку и System вместе.

## Сеанс и строки

Корневой M61 владеет строками, дескрипторами и незавершённым вводом до своего
завершения, ошибки или ESC. `END` вложенного BASIC возвращает управление M61
и сохраняет эти ресурсы. Отдельный запуск TBI получает свой сеанс.
Числовые переменные сохраняют прежние правила языка.

```basic
10 DIM A$(80),B$(160),P$(96)
20 A$="Hello":B$=A$+" world"+LF$
30 N=LEN(B$)
40 P$=MID$(B$,2,4)+STR$(N)
50 IF A$<>"bye" PRINT B$
```

* Есть `A$`…`Z$`, отдельные от числовых `A`…`Z`. DIM резервирует 1…255
  байт M8; суммарно 1024. Повторный DIM с той же ёмкостью сохраняет значение;
  другая ёмкость, необъявленная строка, переполнение — ошибка программы.
* Выражение содержит не более 16 фрагментов через `+`: литерал, переменную,
  `LF$`, `STR$(числовое выражение)`, `MID$(переменная или литерал,P,N)`.
  Вложенные строковые функции и конкатенация первым аргументом MID запрещены.
  Числовые аргументы чистые: без `CALL`, `INPUT()`, `RND` и строковых сравнений.
  `LEN(A$)` допустим в числовом выражении, включая аргументы строковых функций.
* MID использует позиции с 1; P — положительное целое, N — неотрицательное.
  Выход за конец даёт пустую строку или обрезанный остаток. STR использует
  штатное форматирование до 10 значащих цифр, без дополняющих пробелов.
* `=` и `<>` сравнивают M8 побайтно, с учётом регистра. Результат — число
  0/1. Присваивание атомарно: при переполнении прежняя строка сохраняется.
  Буфер сборки выражения ограничен 1536 байтами. LF — один байт 10.
* Старый PRINT литералов и чисел сохраняет поведение. PRINT строковой
  переменной или конкатенации выводит собранный текст на обычный дисплей.

## Статусы

Каждая новая операция ввода-вывода требует `STATUS S`, где S — обычная
числовая переменная A…Z. Результат дескриптора/позиции и STATUS должны быть
разными переменными. Неудача не меняет дескриптор, позицию или строку;
`END` при чтении/перечислении очищает строку. Закрытие освобождает дескриптор
даже при ошибке подтверждения USB; числовую переменную вызывающий обнуляет сам.

| Код | Имя | Значение |
|---:|---|---|
| 0 | OK | Операция завершена |
| 1 | END | Больше данных нет |
| 2 | TIMEOUT | Истёк указанный срок |
| 3 | CLOSED | Посетитель отключён или канал требует закрытия |
| 4 | NOT_FOUND | Нет файла/каталога |
| 5 | TOO_LONG | Ввод/путь/вывод не помещается |
| 6 | NO_SPACE | Не хватило памяти хранилища |
| 7 | BUSY | Уже открыт канал/файл или ввод привязан к другой строке |
| 8 | IO | Ошибка обмена/хранилища |
| 9 | BAD_TEXT | Текст не представим в M8 |

Неверные аргументы, неизвестный или устаревший дескриптор, тип файла,
нецелые/отрицательные значения — ошибки программы, а не статусы.
TIMEOUT измеряется в миллисекундах, от 1 до 2147483647. Операции последовательны.
Он ограничивает ожидание USB, включая отправку фрагментов. Файловый CLOSE
синхронен: его общий аргумент TIMEOUT не прерывает атомарную транзакцию C9.
Нельзя использовать один дескриптор одновременно из двух исполнителей.

## USB:TEXT

```basic
10 OPEN "USB:TEXT" AS C TIMEOUT 60000 STATUS S
20 PRINT TO C,"Name? "; TIMEOUT 5000 STATUS S
30 LINE INPUT FROM C,A$ TIMEOUT 60000 STATUS S
40 CANCEL INPUT C TIMEOUT 10000 STATUS S
50 CLOSE C TIMEOUT 5000 STATUS S
```

Один логический канал и один посетитель. PRINT TO принимает одно строковое
выражение до 255 байт, добавляет LF; `;` подавляет LF. OK означает, что мост
принял целый вывод в свою очередь, а не что человек прочитал его. TIMEOUT/IO
вывода и ошибка отмены делают канал непригодным до CLOSE.

LINE INPUT возвращает целую строку без CR/LF. После TIMEOUT запрос остаётся
привязанным к той же строковой переменной. Повтор продолжает этот запрос;
другая строковая переменная даёт BUSY. Мост хранит ответ до INPUT_ACK, поэтому
ответ, пришедший после тайм-аута устройства, не теряется. Слишком длинная или
непредставимая строка отбрасывается целиком и даёт TOO_LONG/BAD_TEXT.

CANCEL очищает очередь и незавершённый ввод. При наличии части строки мост
отбрасывает остаток до границы строки и только затем подтверждает отмену.
Истечение срока отмены требует CLOSE. CLOSE всегда завершает локальное
владение каналом. Физический USB CDC остаётся доступен. Поздние фреймы
поглощаются до обычного декодера команд терминала.

Мост имеет очередь до четырёх строк, каждая до 255 символов M8, и очередь
вывода TCP до 4096 байт. Переполнение очереди отключает посетителя. Telnet
IAC-команды отфильтровываются; опции отклоняются. Ввод UTF-8, поддерживаются
Backspace/Delete. Смена посетителя требует нового OPEN.

## Файлы

```basic
10 P$="Messages/example.txt"
20 WRITE FILE P$,A$+LF$+B$ STATUS S
30 OPEN P$ FOR INPUT AS F STATUS S
40 READ FROM F,B$ STATUS S
50 CLOSE F TIMEOUT 1000 STATUS S
60 K=0
70 DIR "Messages",K INTO P$ STATUS S
```

Один открытый читатель TXT; READ возвращает блок до ёмкости целевой строки.
Последний непустой блок даёт OK, следующий READ — END и пустую строку.
OPEN сохраняет версию файла, READ продолжает её после замены оригинала.
Для этого служба создаёт атомарную копию во Flash `/System/BasicIO/Snapshot.txt`
под проверенной меткой владельца `Owner.txt = BTX1`. Открытие читателя тоже
может вернуть NO_SPACE/IO. Копия освобождается при CLOSE/конце корня.

WRITE FILE атомарно заменяет весь TXT, до 1536 байт; не добавляет LF и не
имеет отложенного commit. Допустима конкатенация длиннее 255 байт без
промежуточного присваивания строковой переменной. При потере подтверждения
записи после commit IO допускает старую или новую целую версию; повторять
запись автоматически нельзя. Каталог назначения должен существовать.

DIR выдаёт видимое имя файла без пути. K=0 начинает обход, OK увеличивает K
до следующего внутреннего ключа inode, END очищает имя. Порядок не является
алфавитным и обход не является снимком: новые файлы впереди могут появиться,
позади — пропускаются. Посторонняя запись не сбрасывает K. При ошибке K и
строка сохраняются. Все типы файлов перечисляются; открывать как TXT можно
только обычный TEXT. Пути и регистр имён разрешаются штатным storage_path.

Относительные пути привязаны к папке корневого M61 либо отдельно запущенного
TBI. Вложенный модуль не меняет эту папку. Абсолютные пути начинаются с `/`.

## Проводной протокол TEXT/1

Каждый фрейм имеет собственные начальный и конечный нулевые байты;
между ними COBS. Максимум 32 байта payload. После декодирования:

| Смещение | Поле |
|---:|---|
| 0…1 | ASCII `BT` |
| 2 | Версия 1 |
| 3 | Тип; бит 7 — MORE |
| 4…7 | Идентификатор логического сеанса, uint32 LE |
| 8…9 | Номер запроса, uint16 LE |
| 10…11 | Смещение фрагмента, uint16 LE |
| 12… | Payload |
| последние 2 | CRC16-CCITT, poly 0x1021, init 0xffff, LE |

Типы: OPEN=1, ACK=2, PRINT=3, INPUT=4, DATA=5, CANCEL=6, CLOSE=7,
ABORT=8, INPUT_ACK=9, PING=10, PONG=11. ACK содержит один байт статуса;
INPUT — один байт ёмкости. В PRINT бит 15 смещения задаёт добавление LF.
PRINT и DATA передаются подряд с нулевого смещения; последний фрагмент
сбрасывает MORE. OPEN повторяется через 500 мс до ответа, INPUT повторяется
с тем же номером до завершения. PRINT не повторяется при неоднозначном исходе.
Мост проверяет живость PING каждые 2 секунды и закрывает осиротевшего
посетителя после 15 секунд без ответа. USB Screen имеет отдельную сигнатуру;
OPEN USB:TEXT возвращает BUSY при активном Screen.

## Память и границы проверки

Строковое состояние занимает 1160 байт в хостовой сборке, включая 1024 байта
данных. Полное добавленное состояние службы с дескрипторами, декодером и
учётом выделения — менее 1536 байт; предел проверяется static_assert, включая
выравнивание выделения. Оно выделяется лениво из LifetimeBuffer и
освобождается целиком, не входит в сохраняемую числовую рабочую область VM.
Буфер выражения на 1536 байт берётся из существующего общего SCRATCH,
удерживается только на время команды и освобождается после неё; отдельного
массива этого размера расширение не добавляет. Пул предварительно готовится
перед загрузкой APP. После дисплейного PRINT он освобождается после копирования
вывода, до перехода к другой программе.
Стек компилятора, VM и C9 проверяется штатным анализатором сборки отдельно;
полный пик добавочного стека на устройстве не измерен.

Тесты покрывают обе формы байткода, настоящий C9 на эмуляторе NOR, изменение
хранилища во время исполнения BBS, открытый файл после замены, тайм-ауты,
ядовитый канал, отмену ввода, ESC, PTY/TCP и UTF-8/Telnet. Это не заменяет
аппаратную проверку USB CDC на конкретной плате.
