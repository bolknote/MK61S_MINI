# Spectrum / Pentagon 512K / 1024K для PicoCalc

`SPECTRUM.APP` — обычное загружаемое приложение MK61S для Pico H / RP2040,
ABI 6. Скопируйте весь каталог `SPECTRUM` в `apps/` на microSD и откройте
APP в проводнике. Используйте UF2 из того же комплекта: нужны сервисы
COLOR_DISPLAY, FILE_BYTES, KEY_BITMAP и AUDIO_STREAM. Z80, AY и дисковые
контроллеры находятся внутри APP.

Файлы `.z80`, `.sna`, `.szx`, `.tap`, `.tzx`, `.trd` и `.scl` можно открывать прямо в проводнике.
Нужны обновлённая прошивка и APP с обработчиком `Z1`. Проводник ищет APP
рядом с игрой, в родительских каталогах и в папках приложений, включая
подкаталоги. Поэтому игры можно хранить отдельно от эмулятора и его ПЗУ.
Снимок загружается и сразу продолжается. Лента появляется в меню Tape.
Диск подключается к Beta Disk только для чтения, после чего запускается машина.
Программу внутри диска выбирают штатными средствами TR-DOS. Esc открывает меню эмулятора,
F10 завершает APP. Обычное открытие SPECTRUM.APP по-прежнему показывает меню.

Рядом с APP обязательны `48.rom`, `128-0.rom`, `128-1.rom`.
Для дисков нужны `trdos.rom` и `esxmmc.rom`. Исходные лицензии и copyright
находятся в `licenses/`. Spectrum ROM, TR-DOS и esxDOS не относятся к
MIT-лицензиям ядер Z80 и AY.

ПЗУ являются обычными файлами на SD рядом с `SPECTRUM.APP`. При выборе
модели её ПЗУ загружаются в PSRAM; TR-DOS/esxDOS загружаются при подключении
соответствующего устройства. CPU читает их через общий кэш страниц в SRAM.
Фиксированные банки RAM занимают 32 КиБ, ещё 16 КиБ SRAM совместно используют
страницы ПЗУ, переключаемой RAM и DivRAM. Страницы ПЗУ доступны только
для чтения; вытеснение изменённой RAM сохраняет её в PSRAM.
Загрузчик Pico H допускает до 58 КиБ кода и данных APP. Динамическая
память эмулятора и звука выделяется отдельно из той же SRAM. Расширенный
APP рассчитан на PicoCalc с PSRAM.

Flash Pico целиком предназначена для прошивки и настроек. Устанавливать
`ROMCACHE.uf2` больше не требуется: APP не читает старую область кэша,
а сборщик не создаёт пакеты ПЗУ для Flash. Для замены ПЗУ достаточно
обновить файл на SD и перезапустить приложение или выбрать модель заново.

## Запуск и управление

По умолчанию выбирается Pentagon 512K. Меню рисуется поверх экрана Spectrum:
стрелки выбирают пункт, Enter открывает его, Esc возвращает на уровень выше.
В главном меню Esc завершает APP. `R` запускает/продолжает машину,
`O` открывает снимок, `B` сбрасывает, `M` открывает выбор модели:
Spectrum 48K, Pentagon 512K или Pentagon 1024K. `P` открывает настройки,
`D` — Beta Disk, `I` — DivMMC, `L` — лента, `S` — сохранить снимок,
`H` — клавиши, `Q` — выход.
Во время эмуляции Esc ставит на паузу, F10 завершает APP.
После выхода восстанавливается оболочка MK61S.

Игра и её меню запрашивают LCD SPI24 МГц через необязательный сервис
прошивки. После выхода восстанавливается базовая частота LCD.
Сервис LCD24 необязателен для APP, который умещается в лимит своей прошивки.
Частота эмулируемого Z80 остаётся 3,5 МГц.

В выборе файлов стрелки меняют запись, Enter открывает файл/каталог,
Backspace поднимается к родителю, Esc отменяет. Пути относятся к каталогу
APP; его можно переносить и переименовывать. Игры можно класть в подкаталоги.
`DEMO.sna` и `DEMO128.sna` — оригинальные тесты с анимацией; второй
включает три тона AY, шум и повторяющуюся огибающую.

- Ctrl — Caps Shift, Alt — Symbol Shift, Tab/F2 — Extended Mode.
- F1 — Edit, F3/F4 — курсор влево/вправо, F6 — Graphics.
- F7 — Caps Lock, F8/F9 — True/Inverse Video.
- Backspace/Delete — удаление, PgUp/PgDn — курсор вверх/вниз.
- Стрелки и F5 — направления и огонь выбранного джойстика.
- В 48K BASIC действует ввод ключевых слов: например, `P` — PRINT.

В Options (`P`) клавиши 1–4 переключают TurboSound, Covox, SpecDrum и ULAplus;
по умолчанию доступны все четыре. `J` меняет джойстик: Kempston,
Sinclair right (6–0), Sinclair left (1–5).

## Лента, снимки и экран Pentagon

В меню Tape выберите TAP или TZX, затем запустите машину и введите
`LOAD ""` в BASIC. Ленту можно остановить, запустить, перемотать или извлечь.
TZX поддерживает стандартные и турбоблоки, чистые тоны и импульсы, direct
recording, CSW RLE, паузы, переходы, вызовы и циклы. Предел индекса —
4096 блоков. Generalized Data, выбор ветки и CSW Z-RLE пока не поддерживаются.

`S` сохраняет `ZX0001.SZX` или следующий свободный номер рядом с APP.
Снимок содержит все 3, 32 или 64 банка, регистры Z80, переключатели памяти,
бордюр, регистры основного AY и палитру ULAplus. При загрузке SZX модель
выбирается из файла. Читаются сырые и zlib-сжатые RAMP-страницы.
Диски, ленты и ПЗУ остаются отдельными файлами.

Pentagon 1024K включает расширенные режимы через `EFF7`: бит 0 — 16 цветов
на пиксель, бит 6 — 384×304. В широком режиме PicoCalc показывает все
304 строки и центральные 320 из 384 столбцов.

## Диски

Beta Disk (`D` в главном меню) подключает `.trd`/`.scl` к дисководу A Beta Disk и сбрасывает
машину. Beta Disk начинает с 48K ROM без блокировки банков: загрузчики
128K продолжают пользоваться `7FFD`. После загрузки BASIC нажмите Esc,
затем `T` для TR-DOS.
Доступен и обычный вход `RANDOMIZE USR 15616` из 48K BASIC.
WD1793 поддерживает seek/step, read/write sector, multiple sector,
read address, read/write track, DRQ/INTRQ, таймаут потери данных и защиту записи.
Геометрия TRD: 80 цилиндров × 2 стороны × 16 × 256 байт.
`BLANK.trd` — пустой форматированный диск. Усечённые TRD читают отсутствующие
секторы как нулевые; запись ограничена имеющимся размером файла.

SCL проверяется по сигнатуре, размерам и контрольной сумме SUM32, затем
разворачивается в 640 КиБ PSRAM. Он доступен только для чтения; исходный
архив не меняется. Для записываемого диска используйте TRD.

DivMMC (`I` в главном меню) подключает SD-образ `.img` к DivMMC и сбрасывает машину.
Размер — от 1 МиБ, кратный 512 байтам. Эмулируются SPI, SDHC, чтение/запись
одного и нескольких блоков, CRC16, 128 КиБ DivRAM, CONMEM, sticky MAPRAM
и автоматическая подмена ROM при M1. `ESXDOS.img` содержит FAT16 и
штатные SYS/BIN esxDOS 0.8.9. Доступны `.ls`, `.mkdir`, `.tapein` и другие
команды. Esc → `N` нажимает эмулируемую NMI-кнопку и открывает браузер.
Перед снимком при включённом DivMMC сначала запустите esxDOS: снимки не
содержат его RAM, поэтому APP сохраняет уже загруженное ядро.

`W` в устройствах включает запись в выбранный файл образа. Новые
подключения всегда защищены от записи. Записи секторов синхронные,
через журналируемый сервис прошивки. Физическая карта PicoCalc
не предоставляется гостю как SD-устройство. `U` отключает дисковое
устройство и сбрасывает машину. Beta Disk и DivMMC выбираются по очереди:
их перехваты ROM пересекаются.

## Память, видео и два ядра

Pentagon: 32 банка по 16 КиБ. Биты 0–2 и 6–7 порта `7FFD` выбирают банк
`C000–FFFF`; бит 3 выбирает экран 5/7, бит 4 — ROM, бит 5 блокирует
переключение до сброса. Банки 5 и 2 постоянно находятся в SRAM;
при установленном кэше ПЗУ ещё 16 КиБ SRAM обслуживают кэш из 16 страниц
по 1 КиБ. Страницы разных банков сохраняются при переключении `7FFD`;
из PSRAM загружается только отсутствующая страница. Обратно записываются
только изменённые страницы при вытеснении. Алиасы банков 2/5 используют
одну память. Z80 читает страницы напрямую через таблицу указателей.

Pentagon 1024K: 64 банка по 16 КиБ. При сброшенном бите 2 порта `EFF7`
бит 5 `7FFD` выбирает старшую половину RAM и не блокирует переключение.
Если бит 2 `EFF7` установлен, доступны восемь банков и бит 5 `7FFD`
вновь блокирует переключение; после блокировки `EFF7` тоже не меняется.
Бит 3 `EFF7` подставляет RAM банка 0 вместо нижних 16 КиБ ROM.
Поэтому 512K и 1024K оставлены разными профилями: программа может
рассчитывать на разное значение одних и тех же битов.

Файлы ПЗУ у Pentagon 512K/1024K одинаковые. 512K начинает со штатного
128K меню, 1024K — с 48 BASIC и разблокированными 64 банками.
Дополнительное ПЗУ для мегабайта памяти не требуется.

Резерв PSRAM — 1925120 байт: 1 МиБ Spectrum RAM, ROM, 128 КиБ DivRAM,
развёрнутый SCL и два индекса TZX. SRAM содержит код/данные APP, 32 КиБ постоянно доступных банков RAM,
общий кэш из 16 страниц по 1 КиБ и очередь из 256 звуковых событий.
Кэш обслуживает ROM, верхние банки RAM, нижнюю RAM0 у Pentagon 1024K
и DivRAM. ROM-страницы доступны только для чтения; грязные страницы RAM
при вытеснении сохраняются в PSRAM. Открытие OSD не уничтожает кэш.
Для расширенного APP на Pico H требуется PSRAM.

Первое ядро выполняет Z80, переключение банков и дисковые протоколы.
Второе синтезирует звук по очереди событий с временными отметками,
рядом со штатным worker LCD/клавиатуры/UART. Перед освобождением APP
прошивка останавливает звуковой таймер на втором ядре и ждёт LCD.
Полноэкранный RGB-буфер не выделяется. Beta Disk/DivMMC ROM загружаются
с SD в PSRAM и используют тот же общий кэш SRAM.
Переключение M1 не копирует заново целые 16 КиБ ROM.
Перед паузой грязные страницы DivRAM записываются в PSRAM.
Клавиатура опрашивается раз в 20 мс; клавиша запуска меню не
передаётся гостю до отпускания.

Все обращения Z80 используют одну таблицу из 64 страниц по 1 КиБ для
чтения и такую же для записи. Код в частично кэшированном верхнем банке
не требует дополнительного вызова функции при каждом чтении. Холодные
страницы и первая запись в чистую страницу по-прежнему вызывают MMU.
Состояние машины находится в зарезервированном стеке APP до остановки
звука и вывода; оно не дробит heap рядом с гостевой RAM.
В режиме с PSRAM два фиксированных банка SRAM выделяются частями:
15 КиБ через BUFFER_DIRECT и последняя страница 1 КиБ в стеке.
У общего 16-КиБ страничного кэша 10 КиБ лежат в heap, 4 КиБ в стеке
и 2 КиБ в конце монохромного буфера экрана. Эта область буфера находится
за пределами данных кадра и меню.

Кадры ожидают микросекундный срок с учётом уже исполненной части
следующего кадра. Период не округляется до миллисекунд: 19 968 мкс для
48K и 20 480 мкс для Pentagon. Ожидание не меняет число виртуальных тактов.
Готовый кадр передаётся LCD перед ожиданием срока: следующий участок Z80
и звуковых событий начинается без задержки преобразования изображения.

Повторы `LDIR` по доступной SRAM объединяются до ближайшей границы
прерывания или участка исполнения. Неперекрывающиеся блоки копирует
штатный быстрый `memcpy`. Перекрытие с изменением следующего читаемого
байта сохраняет последовательность Z80; собственный код, подмена ROM
по M1 и обращения к отсутствующим страницам выполняются обычным способом.
Сохраняются такты, флаги, R и WZ; синхронный звуковой режим использует
отдельные инструкции.

Экран 256×192 выводится 1:1 с бордюром, BRIGHT и FLASH. ULAplus даёт
64-цветную CLUT из 256 значений GRB; FLASH/BRIGHT выбирают группу палитры.
Занятый LCD пропускает промежуточные кадры. Кадр: 69888 T-states для 48K,
71680 для Pentagon при Z80 3,5 МГц.

## Звук

AY-3-8912: три 12-битных тона, 17-битный шум, микшер, 16 уровней громкости
и все 16 огибающих. `FFFD`/`BFFD`: выбор, запись и чтение регистров;
AY работает на 1,75 МГц. TurboSound добавляет второй AY: `FF`/`FE`
выбирают первый/второй чип. Covox: OUT FB, SpecDrum: OUT DF — unsigned
8-bit, 128 означает тишину. Beeper FE смешивается с чипами, DC удаляется.

В Options доступны `Sound chip` (`C`: AY-3-8912 / YM2149) и `Stereo`
(`S`: Mono / ABC / ACB). По умолчанию — AY и ABC. В ABC канал A слева,
B по центру, C справа; в ACB по центру C, справа B. Для каждого чипа
TurboSound применяется та же раскладка. Beeper, Covox и SpecDrum звучат
по центру. Выбор сохраняется при паузе, сбросе машины и загрузке снимка
до выхода из APP. Смена чипа не сбрасывает игру или её регистры.

Локальный синтезатор выдаёт signed16 L/R, 25 кГц; M3 сразу считает
готовые unsigned8 L/R для PWM GPIO26/27. Оба пути используют один проход
генераторов на отсчёт и независимые фильтры левого и правого выходов.
Громкость регулируется колёсиком PicoCalc. При паузе динамики выключаются,
состояния чипов сохраняются. Часы звука запускаются после открытия
нативного потока, с начальным запасом 2 мс. При задержке CPU AY продолжает
синтез с последними опубликованными регистрами; просроченные события
обрабатываются по мере поступления. Очередь не блокируется в ожидании
эмулированного времени, которое должен опубликовать сам ожидающий CPU.
Счётчик `starved` считает отсчёты без достаточной истории CPU, а не
пропущенные выходные отсчёты.

### Синтезатор STM32 M3

Сборщик добавляет рядом с APP модуль `AY.S3M`. Сервис `AUDIO_PSG_CONFIG_OPEN`
загружает его в SRAM совместимого Southbridge, передаёт выбор AY/YM,
раскладку и состояния двух чипов
и очередь событий. Модуль считает AY/TurboSound, beeper, Covox, SpecDrum
и DC-фильтры; выдаёт готовые 8-битные стерео PWM-отсчёты. PWM GPIO26/27 остаётся
на Pico: один непрерывный DMA-канал обслуживает кольцо из 64 отсчётов.
UART RX и TX используют отдельные DMA-каналы. Передача запросов не
останавливается при заполнении FIFO; RX догоняет байты, пришедшие во время декодирования.
Модуль не обращается к периферии STM32 и не меняет его Flash.

Стереоблок содержит 118 кадров L/R (236 байт звука, 4,72 мс при 25 кГц).
Он вместе с заголовком помещается в единственный ответ `START_RESULT`;
дополнительного `READ` в звуковом потоке нет. Протокол SAY2 сохраняет
оба фильтра и стереосостояния при остановке и возобновлении. Прежние
моно-запросы SAY1 и `AUDIO_PSG_OPEN` поддерживаются. Если старая прошивка
не понимает новый сервис, APP использует локальный синтез с выбранными
AY/YM и раскладкой, не заменяя стерео на моно незаметно.

Pico готовит следующий пакет событий в том же буфере, пока M3 считает
предыдущий блок. Для обоих результатов заранее резервируется место в
кольце; при закрытии подготовленный пакет досчитывается до экспорта
состояния чипа. UART RX принимает непрерывные COBS-участки через штатные
быстрые процедуры памяти, сохраняя проверку длины, номера и CRC.

Штатный комплект для SD включает `AY.S3M` со сжатием одинаковых
соседних стереопар PCM для UART. Модуль отправляет исходные пары,
если сжатие не сокращает блок.

Стерео прошло строгую квалификацию на Pico 125 / STM32 72 МГц:
четыре сочетания AY/YM и ABC/ACB, затем 30 000 кадров Cosmic Payback
(614,359 с). Из 130 166 блоков ни один не превысил 4,72 мс;
максимум — 4,588 мс. Пропущенных PWM-отсчётов и задержек кадров больше
1 мс нет; темп Z80 — 3,500000 МГц. Порог не ослаблялся: при проверке
частоты учитывается только разрешение таймера 1 мкс.

Для этого результата нужны обновлённая прошивка Pico и M3 BIOS KEY25:
поиск состояний клавиш больше не обходит десять слотов при каждом из
152 чтений GPIO. Все чтения, порядок событий и повторы сохранены.
Готовый воспроизводимый BIOS находится в `firmware/picocalc-m3-boot`.
Короткие и длинный прогоны, хеши и границы проверки:
[измерения 10 ноября](../../../doc/measurements/picocalc-spectrum-stock-stereo-20261110.json).

С ускоренным микшером и сжатым UART при тех же 125/72 МГц снова прошли
четыре коротких теста и 30 000 кадров Cosmic Payback. Максимум из
130 167 блоков составил 4614 мкс. [Измерения 14 ноября](../../../doc/measurements/picocalc-spectrum-uart-20261114.md).

Предыдущая серия с редкими поздними блоками сохранена как исторический
HOLD в [измерениях 8 ноября](../../../doc/measurements/picocalc-spectrum-stereo-20261108.json).
Раздельные GPIO26/27 подтверждены чтением реального PWM: в боковом тоне
неактивная сторона остаётся на 128, центральный тон даёт одинаковые L/R.
Разделение динамиков на слух пока не подтверждено.

Моно-версия Cosmic Payback прошла строгую непрерывную проверку на Pico 125 / STM32 72 МГц
длительностью 30 000 кадров (результаты ниже). При отсутствии совместимого
M3 или ошибке обмена включается локальный синтезатор Pico 200 МГц.
Иностранный модуль на STM32 не выгружается. Старые прошивки без нового
сервиса используют прежний локальный путь. Проверка этой игры не гарантирует
реальное время для любой программы с двумя одновременно активными AY.

Фактический контроль Cosmic Payback с локальным Pico 200 прошёл 598 кадров
при ≈3,500 МГц, `starved=0`, без underrun звукового DMA. Ранний строгий
аппаратный M3-прогон на старом обмене завершил 3 блока по 96 отсчётов, затем
16 недостающих отсчётов дали `M3_ERROR=-29`. Максимальное полное время блока
было 4518 мкс, первые три заняли 12001 мкс при бюджете 3840 мкс; сам M3
выполнял задание не дольше 1902 мкс. `M3_READY_POLLS=0`, ошибок UART, PMU и
выгрузки не было. Значит, узким местом был stop-and-wait обмен и глубина
очереди, а не синтезатор или опрос готовности.

Кандидат использует `START_RESULT`: STM32 сам возвращает готовый блок
в единственном отложенном ответе, без STATUS/READ-опросов готовности.
В ответ включены номер задания и максимальное время вызова синтезатора.
Повтор запроса не повторяет синтез; ошибки INIT/STEP/срока задания
возвращаются как ошибки, без принятия недостоверных отсчётов.
Отдельная команда модуля `PROFILE` возвращает число отсчётов/заданий/вызовов,
суммарное время внутри рендеринга и максимумы на задание/вызов. Профиль
запрашивается после остановки звука, поэтому не добавляет запросов в
рабочий поток. Диагностика `M3_BLOCK_US` включает весь обмен;
`M3_RENDER_US` исключает обмен и ожидание готовности. Счётчики и новый
режим обмена проверены на хосте; на устройстве этот кандидат ещё
не проверен. Исходные аппаратные результаты сохранены в
`.build/spectrum-m3-audio-20261107/integration/`.

Следующий вариант добавляет опциональную команду `START_RESULT_INPUT`:
входной PSG-пакет до 240 байт передаётся вместе с запуском, поэтому отдельные
`WRITE` и его подтверждение исчезают. Блок увеличен до 120 отсчётов
(4800 мкс), кольцо — до 512 отсчётов, воспроизведение начинается после трёх
блоков (14,4 мс запаса). Пакеты больше 240 байт автоматически используют
старый путь. Новый capability-бит проверяется при HELLO; старый BIOS остаётся
совместимым, но строгая квалификация требует fused-путь и ноль потоковых
`WRITE`. Для этого выведены `M3_INLINE_INPUT`, `M3_INLINE_REQUESTS` и
`M3_STREAM_WRITE_REQUESTS`.

Новый BIOS-кандидат объединяет fused-команду с неблокирующим PMU. Он собран
для штатных 72 МГц STM32: 29244 байта Flash, 5920 байт свободной RAM сверх
зарезервированного 4-КиБ стека, SHA-256 `ccbfc200c416a8eb…`. Pico при M3-звуке
остаётся на штатных 125 МГц; аппаратная проверка этого сочетания ещё нужна.

В M3-ядре убраны повторное сканирование обработанных событий и циклическое
продвижение шума на коротких интервалах: обе обратные связи 17-битного LFSR
вычисляются за один набор сдвигов/XOR. Проверены все 131072 состояния LFSR
для 0..8 шагов и 948864 отсчёта с полным состоянием PSG против независимого
эталона. В одинаковом ARM-наборе число выполненных инструкций модуля
снизилось 703978→646082 (≈8,2%). Это счётчик инструкций, не измерение времени
на устройстве и не обещание такого же прироста FPS.

Для сравнения вариантов на Classic/M4 служит
`tools/apps/spectrum/build_spectrum_m3_classic_bench.py`. Он встраивает
неизменённый бинарник M3 в обычный APP, переносит его в SRAM и измеряет DWT
для трёх сценариев: три тона, TurboSound/шум/огибающая, плотные DAC-события.
Каждый сценарий сверяет CRC отсчётов с эталоном. Ядро синтеза остаётся
M3/soft ABI, без DSP/FPU M4; тактирование платы не меняется. Циклы M4
помогают сравнить варианты, но не заменяют итоговый тест STM32 M3 при 72 МГц.

На Classic/F411 при штатных 96 МГц выполнено два отдельных сравнения по семь
чередующихся запусков A/B/A/B/A/B/A. Первый вариант с вызовом noise-helper
замедлял тяжёлый TurboSound на 0,31%, несмотря на меньшее число инструкций.
Принудительное встраивание helper устранило накладные расходы. Итоговый
M3-бинарник `6e6a5cf1…` занимает 5860/6144 байта и даёт такие медианы DWT:

| Сценарий | Исходный, тактов/отсчёт | Итоговый, тактов/отсчёт | Снижение времени |
|---|---:|---:|---:|
| Три тона |927,55|900,14|2,95%|
| TurboSound, шум, огибающая |2705,82|2673,79|1,18%|
| Плотные DAC-события |1274,45|1216,01|4,59%|

Все три CRC совпали во всех запусках. RCC подтверждает 96 МГц без изменений
между запусками. Временные APP/результаты удалены; регистры, стек, программа,
текущий каталог и исходный список файлов калькулятора сохранены, CDC закрыт.
Сырые данные и receipts: `.build/spectrum-m3-audio-20261107/classic-hil/AB-001/`
и `AB-002/`. Это измерения синтеза на M4, без UART-обмена и звукового вывода;
не результат непрерывного M3-аудио при 72 МГц.

Для следующего аппаратного испытания есть отдельный строгий режим
`AUDIO_PSG_ONLY_OPEN` (операция 6 с той же структурой запроса). Отсутствие
M3 или ошибка потока завершают звук без локального синтеза и разгона Pico.
Конечный тест Cosmic Payback использует этот режим; контрольная сборка
явно выбирает локальный синтез. В обычном APP остаётся автоматический выбор
через `AUDIO_PSG_OPEN` с восстановлением локального звука при отказе M3.

Диагностика сохраняет минимум/сумму/максимум времени получения блоков,
число блоков дольше их бюджета, время начального заполнения очереди и
минимальный остаток отсчётов. `M3_READY_POLLS` должен оставаться нулевым.
После закрытия потока `SYNTH_DMA=0`; сохранённый `SYNTH_BLOCKS` показывает
выполненные DMA-заполнения. Профиль M3 отдельно измеряет время синтеза.

Подготовка полного комплекта без доступа к устройству:

```sh
python3 tools/apps/spectrum/prepare_spectrum_m3_hil.py --output .build/spectrum-m3-hil-ready
```

Сборщик запускает хостовые проверки, собирает прошивку/APP/модуль и конечные
тесты, проверяет SRAM/Flash и фиксирует исходники и SHA-256. `PLAN.md`
задаёт порядок аппаратных испытаний. Начинать их можно после освобождения
устройства и подтверждения установки объединённой прошивки Southbridge.
Каталоги `remote/app` и `local/app` уже самодостаточны: рядом с `S3GAME.APP`
лежат `AY.S3M`, `48.rom`, `128-0.rom` и `128-1.rom`; вручную собирать набор
на SD из отдельных файлов не требуется.
`qualify_spectrum_m3_run.py` разбирает сохранённые логи: проверяет нижнюю
границу 3,5 МГц с погрешностью таймера 1 мкс, кадры, непрерывность звука,
отсутствие fallback, ошибки I2C/UART и освобождение ресурсов. Сам разбор
логов не обращается к аппаратуре.

При испытании учитывается также планировщик Southbridge. Новый блок из 120
отсчётов при 25 кГц занимает 4800 мкс. Хостовая модель с настоящими протоколом
и очередью переносит единичную паузу обслуживания 5 мс без underrun; пауза
12 мс штатно завершается собственным 10-мс дедлайном задания. Если M3
продолжает обслуживаться, та же 12-мс пауза foreground-кода не мешает звуку.
Это моделирование пауз, не замер платы.

Проверенный объединённый BIOS включает неблокирующий PMU, fused-команду и
немедленный запуск UART DMA после готового ответа. CRC STM32 использует
аппаратный блок F103: разворот битов `RBIT`, целые 32-битные слова и
программный хвост 0..3 байта без дополнения. CRC защищает команды и данные;
повторов аудиоблоков в реальном времени нет. На Pico небольшая CRC-таблица
занимает 1 КиБ только внутри активного звукового контекста. Общий DMA sniffer
продолжает обслуживать CRC экрана и SD. [Описание блока F103, RM0008 §4](https://www.st.com/resource/de/reference_manual/cd00171190.pdf#page=64).

Итоговая аппаратная квалификация 8 ноября: короткий тест 600 кадров и
непрерывный тест 30 000 кадров прошли strict PASS при штатных 125/72 МГц.
В длинном окне измерены 29 999 кадров, 2 150 328 194 такта за 614 379 484 мкс:
ровно 3,5 МГц. Все 128 000 блоков / 15 360 000 отсчётов уложились в бюджет
4,8 мс; максимум блока 4503 мкс, старт очереди 16631 мкс. Задержек кадров
более 1 мс, пропусков DMA, ошибок UART/I2C, fallback и опросов готовности —
ноль. Максимальное опоздание реального pacing — 6 мкс, сбросов его эпохи нет.
Исходный длинный тест обнаружил два поздних блока; этот отказ сохранён
вместе с успешным повтором, критерии квалификации не ослаблены.

Рабочий поток использует собственный аппаратный таймер core1; его ожидания
больше не создают IRQ таймера на ядре Z80. CRC и преобразование LCD
обслуживают M3 между короткими участками работы. Bitmap сравнивается словами,
цвета разворачиваются по 8 пикселей, сервис вызывается каждые 64 пикселя.
Постоянные DAC и изменяющиеся DAC кодируются проходом по событиям и их
интервалам. Опрос клавиатуры сохраняет 2-мс запас перед pacing и оставляет
первый участок CPU после него свободным. Молчащий AY2 продвигается пакетами
с сохранением всех фаз; активный AY2 использует обычный точный путь.

Обычный APP занимает 47968 байт, модуль M3 — 6132 из 6144 байт. Полный
комплект включает три ROM рядом с APP и `AY.S3M`. Каталог проводника и его
необязательный графический буфер освобождаются непосредственно перед входом
в APP; это устраняет повторный `Not enough SRAM` после обслуживания UI
загрузчиком. [Итоговые журналы и измерения](../../../doc/measurements/picocalc-spectrum-strict-20261108.json).
Ранние профили ускорения Z80 сохранены [отдельно](../../../doc/measurements/picocalc-spectrum-producer-20261108.json).
Для повторной диагностики сборщик конечного теста принимает
`--producer-profile`, а `--producer-trace` дополнительно сохраняет первые
65 мс продвижения CPU и потребителя; `--frame-trace` сохраняет реальные
дедлайны первых 64 кадров. Вывод начинается после остановки замера.
`--frames 30000` задаёт десятиминутный тест; квалификатор получает тот же
размер через `--run-frames 30000` и требует минимум 29 998 измеренных кадров.
Исходный короткий отказ сохранён [отдельно](../../../doc/measurements/picocalc-spectrum-m3-fused-20261108.json).

## Проверки и пределы

48K/128K SNA и Z80 v1/v2/v3: сырые/RLE-банки, AY-регистры Z80,
TR-DOS-флаг SNA при включённом Beta Disk. 128K-снимки заполняют восемь
банков; остальные 24 или 56 доступны программе и изначально нулевые.
Точная contention и эффекты ULA внутри строки пока не реализованы.
Формат TRD хранит секторные данные. Для нестандартной разметки
дорожек и слабых битов потребуется другой формат образа.

Хостовые ASan/UBSan-проверки: настоящие ROM BASIC/TR-DOS/esxDOS, PRINT,
банки, снимки, чтение/запись секторов, FAT `.ls`/`.mkdir`, NMI, генераторы,
очередь между потоками, палитры и полный цикл меню APP. ARM APP и UF2
собираются. На Pico H при 125 МГц проверены все 64 банка Pentagon 1024K,
новое OSD, загрузка Snow Trap Dizzy через Beta Disk и выход из игры.
После исправления страничного доступа, ожидания кадров и звуковой очереди
Manic Miner выполняется с 3,500000090 МГц, Cosmic Payback — с
3,500003605 МГц, со включённым AY/TurboSound 25 кГц. Для каждой игры
проверены все десять последовательных окон по 300 кадров; нижняя граница
с учётом разрешения таймера не ниже 3,5 МГц. Сбросов срока кадра нет.
У Cosmic Payback остаются задержки отдельных кадров до 3515 мкс и
отсчёты с запоздавшей историей CPU. Это замеры двух игровых сценариев,
а не гарантия для всех программ или безупречного звука.
Обычный APP установлен и проверен до и после игр. Код/данные APP занимают
46672 байта heap, измеренный high-water стека — 25500 из 32768 байт.
[Численные результаты и методика](../../../doc/measurements/spectrum-picocalc-20261106.md).
Электрические характеристики звука и весь набор расширений аппаратно
ещё не проверены.

В `games/` включены The Sword of Ianna 1.1, Cosmic Payback и файлы коллекции ULAplus
с исходными разрешениями и авторством. Если при сборке передан каталог
устройств с `esxdos089.zip`, там также находится `GAMES.img`: DivMMC SD-образ
с играми и штатным esxDOS. В `games/` для SD находится только `GAMES.img`.
Список и ограничения: `third_party/spectrum-games/README.md` в репозитории.
Эта дополнительная коллекция распространяется бесплатно для некоммерческого
использования; её условия отличаются от лицензии APP.

Для распространяемого набора используются игры с найденным разрешением.
По отдельному указанию пользователя Snow Trap Dizzy временно возвращена
для внутренней проверки и подлежит удалению после неё. В игровой комплект
она не входит. Источники, контрольные суммы и порядок проверки описаны в
[TEST-GAMES.md](TEST-GAMES.md).

```sh
python3 tools/apps/spectrum/build_spectrum_app.py --fetch-devices
MK61_TEST_SANITIZERS=1 bash tests/run_spectrum_tests.sh
SPECTRUM_DEVICE_ASSETS=.build/spectrum-app/devices MK61_TEST_SANITIZERS=1 bash tests/run_spectrum_tests.sh
```

`--device-assets DIR` использует подготовленные ROM/образы без сети.
`tools/apps/spectrum/fetch_spectrum_devices.py --output DIR` проверяет закреплённые SHA-256.

### Stereo transport candidate (2026-11-08)

The lossless PWM3 repeat-pair codec is a HOST-qualified candidate, not yet
hardware-qualified. It keeps 118 stereo frames per block, 8-bit channels and
25 kHz, with a raw PWM2 fallback whenever compression would grow a block.
The resident and both Pico clients use wire version 2. Commands 11/12 now
return `min(actual_output_bytes, result_ceiling)` bytes; there are no alternate
legacy commands. HELLO bit32 identifies that contract; bit16 still denotes
entry to the unchanged recovery loader. Module ABI1 is unchanged.

Upgrade the BIOS with the existing updater/recovery loader before installing
the new Pico client and BIOSUPD.APP. The candidate install target is the
boot-preserving BIOS.M3U, not the unrelocated async BIOS binary. Mixed wire
versions fail before a module job can execute. HOST/ARM checks pass, including
exact PCM and PSG state, replay, actual package readback and recovery models.
Four Cosmic traces predict 62–70% less reply traffic; physical strict tests at
125/72 MHz remain pending. All four short cases must pass before the long run.

On 2026-11-09 all four short strict Cosmic tests passed at 125/72 MHz. The
30000-frame run still failed the unchanged zero-late-block condition: one of
130166 blocks took 4765 us,45 us above4720. No underruns, protocol errors,
fallbacks or frames delayed over1 ms occurred. See
[`picocalc-spectrum-stereo-20261109.json`](../../../doc/measurements/picocalc-spectrum-stereo-20261109.json).
The next HOST-qualified candidate moves the bounded PWM decoder to244 bytes
of SRAM code; its hardware timing improvement has not been measured.
