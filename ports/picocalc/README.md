# MK61S на PicoCalc / Pico H

Первый самостоятельный аппаратный профиль: ClockworkPi PicoCalc v2.0 с
Raspberry Pi Pico H, RP2040 / Cortex-M0+. Версия — 0.4.1.

Он собирает **то же `code/mk61emu_core.cpp`**, что и STM32, с отдельными
драйверами и оболочкой на Pico SDK. В обычной сборке STM32 флаг
`MK61_CORE_STANDALONE` отсутствует, поэтому прежние конфигурация, драйверы,
оптимизации и путь сборки сохраняются.

## Что работает в прототипе

- Общее ядро МК-61, 105/112+F/AUTO, стек, регистры, ввод/выполнение программ.
- Основной индикатор из `calculator_face`, общие шрифты МК-61/Classic и Ark Pixel.
- Экран 320×320: X, стек, регистры, программа и подсказки клавиш.
- Главное меню с тем же порядком пунктов, русским и английским интерфейсом.
- Настройки звука, скорости, памяти, К СЧ, шрифтов и подсветки.
- Настройки сохраняются в журнале из двух секторов flash, после остановки ядра.
- Проводник microSD: каталоги, создание, открытие, переименование, удаление
  с подтверждением и сохранение программы МК-61 в текстовом HIN `.m61`.
- Редактор исходников до 65 534 байт, UTF-8 на карте и M8 внутри редактора.
- Общие компиляторы и VM TinyBASIC/FOCAL, PRINT, INPUT, регистры МК-61,
  математика и графика 192×64 с увеличением на экран PicoCalc.
- Полный общий исполнитель `.m61`: метки, вложенные `open`/`load`/`run`,
  условия, `reinit`, `wait`, `ret`, `trap`, `bind` и `bind OK`.
- `print` с ANSI-управлением курсором и подстановками регистров; `loadfont`
  с восстановлением шрифта при завершении/ошибке/Esc; LED и звуковые последовательности.
- Вызовы `.tbi`/`.bas` и `.foc` с сохранением переменных/массивов между
  файлами; FMK определяет `COLS`/`ROWS`. Turochamp использует штатные 27×9.
- Загрузка программ МК-61 `.bin` (CRC32+ZX0), инструкции Markdown/текст
  и просмотр WBMP из сценариев. Пути разрешаются относительно текущего `.m61`.
- USB CDC и USB Mass Storage: компьютер получает карту целиком. В это время
  файловая система Pico размонтирована; возврат требует извлечения диска на ПК.
- QWERTY-клавиатура PicoCalc через штатный контроллер STM32 и I²C.
- Все 30 клавиш калькулятора и переключение градусной меры.
- Подсветка экрана/клавиатуры, восстановление соединения с клавиатурой.
- Диагностика через родной Micro-USB Pico и UART0 / USB-C PicoCalc.
- Программная арифметика RP2040 и проверка наших binary64-функций.

Сборка использует FAT/FAT32/exFAT на microSD и встроенную RAM RP2040.
PSRAM не требуется. Нативные STM32 `.APP` требуют отдельной сборки под
RP2040; загрузчик проверяет CPU до исполнения. CHIP-8, USB Screen, RTC,
будильники, сон и обычные нативные APP включены в профиль 0.4. `.bin` здесь означает переносимую программу МК-61,
а не машинный код STM32. Markdown показывается как читаемый текст без
интерактивных ссылок. RTC Pico H теряет ход после полного снятия питания; это ограничение платы.
Системные службы в этом профиле встроены в UF2, пользовательские APP загружаются с microSD.

Исполнитель `code/m61_text.cpp`, синтаксис `terminal_script_runtime.cpp`,
каталог команд, клавиши, BASIC/FOCAL и декодер бинарных программ общие со
STM32. Платформенные файлы `script_files.cpp`/`script_runtime.cpp` соединяют
их с FatFs, дисплеем и циклом Pico SDK. CI проверяет разрешённые команды
сценариев, настоящий Turochamp, ловушки, привязки и вложенные файлы.

Чтобы запустить сценарий, открыть `.m61` в проводнике и нажать F3. Ввод `/`
в проводнике открывает поле для полного или относительного пути. F3 запускает
неизменяемую копию текущего текста, включая несохранённые правки. Enter
вызывает `bind OK`, а Esc завершает сценарий и восстанавливает шрифт.
Несохранённый исходник после завершения возвращается в редактор с прежним
курсором и признаком изменений, даже если сценарий открывал другие исходники.
Esc в открытой инструкции возвращает к сценарию; Esc в BASIC/FOCAL останавливает
весь вызвавший его сценарий. Ошибка показывает имя `.m61` и номер строки.

Экран показывает белые символы на чёрном фоне. LCD-подсветка по умолчанию 240 —
максимум штатного BIOS; подсветка клавиатуры — 40. Ответ контроллера виден
в serial-отчёте как `LCD_BKL` / `KBD_BKL` (−1 означает ошибку подтверждения).

## Сборка

Нужны Python 3, CMake 3.20+, Ninja и GNU Arm GCC с C++17. Проверено с
GNU Arm GCC 14.2.1 и Pico SDK 2.2.0. Компилятор можно переиспользовать из
существующей установки Arduino; Arduino Core в сборку не входит.

Из корня репозитория:

```sh
python3 tools/build_picocalc.py --profile picocalc-pico-h --fetch-sdk
```

SDK и TinyUSB скачиваются в игнорируемый `.build/picocalc-deps`, только если
их ещё нет. SDK закреплён на теге 2.2.0, commit
`a1438dff1d38bd9c65dbd693f0e5db4b9ae91779`. Для уже установленного SDK и GCC:

```sh
python3 tools/build_picocalc.py --sdk /path/to/pico-sdk --toolchain /path/to/gcc/bin
```

Пути также можно задать через `PICO_SDK_PATH` и `MK61_GCC_TOOLCHAIN`.
`--build-path` и `--output-dir` позволяют выбрать отдельные каталоги.

Результат по умолчанию: `binary/picocalc-pico-h/` с `.uf2`, `.bin`, `.elf`,
картой компоновки и `manifest.json` с размерами и SHA-256. Сборщик проверяет
ARMv6-M / soft-float и реконструкцию BIN из UF2. Признак `hardware_verified`
в манифесте сборки всегда false: одна компиляция не подтверждает работу железа.

## Первая загрузка

1. Подключить **Micro-USB на самой плате Pico**, удерживая её BOOTSEL.
   Должен появиться диск `RPI-RP2`. USB-C корпуса — последовательный интерфейс,
   он не является родным USB-загрузчиком RP2040.
2. Скопировать `mk61s-picocalc-pico-h.uf2` на этот диск. После полной записи
   Pico перезапустится. Новая прошивка заменяет существующую прошивку Pico;
   файлы на SD-карте остаются на месте.
3. Включить PicoCalc кнопкой питания. Для работы экрана и клавиатуры должна
   быть включена основная плата; питание одного Pico через Micro-USB этого
   не подтверждает. Прошивка ждёт I²C-клавиатуру и инициализирует экран после
   её обнаружения. При необходимости подключить также USB-C корпуса.

Если копирование через файловую систему зависает, официальный `picotool`
может записать тот же UF2 напрямую в загрузчик:

```sh
picotool load -v -x binary/picocalc-pico-h/mk61s-picocalc-pico-h.uf2
```

При нескольких устройствах Pico следует задать `--ser` с серийным номером
нужного загрузчика. Подключённые STM32 этим инструментом не прошиваются.
В дальнейшем родной USB позволяет вернуться в BOOTSEL через serial-команду
`!` или открытие CDC-порта на скорости 1200; кнопка BOOTSEL сохраняет работу.
Также доступно Tab → «UF2 прошивка» → Enter → Enter.

## Меню, файлы и редакторы

Tab открывает главное меню. Стрелки выбирают пункт, Enter открывает,
Esc возвращает назад. В калькуляторе ↑/↓ переключают стек, регистры,
программу и подсказки; PgUp/PgDn прокручивают регистры и программу.
В настройках ←/→ меняют значение. Выбор шрифта интерфейса не меняет
шрифт индикатора калькулятора.

В проводнике Enter открывает файл/каталог, F1 — действия с выбранным
файлом, F2 — новый файл, F4 — каталог, F5 — сохранение программы МК-61.
`/` позволяет открыть файл текущего каталога по имени. Имена и пути на
карте — UTF-8; полный путь ограничен 383 байтами.

В редакторе обычная QWERTY-клавиатура вводит текст, Enter добавляет строку,
стрелки перемещают курсор, Home/End/PgUp/PgDn работают с текстом,
Backspace/Delete удаляют символы. F1 — сохранить под новым именем,
F2 — сохранить, F3 — запустить. Esc предлагает отменить несохранённые
изменения. Во время выполнения Esc останавливает программу; после
выполнения Enter/Esc возвращает в редактор. Для исходников используются
расширения `.bas` и `.foc` (также `.fcl`), для обычного текста — `.txt`.

Карта не форматируется при включении или ошибке открытия. Системный пункт
«Формат диска» стирает карту только после отдельного подтверждения на экране.
Запись файла сначала создаёт собственный временный файл, закрывает и
синхронизирует его, затем заменяет целевой файл через резервное имя.
После внезапного отключения питания могут остаться `.MK61-*.TMP/.BAK`;
это не транзакционный журнал FAT. Обычная работа с картой сохраняет
другие файлы и разделы.

Для USB-диска нужен Micro-USB самой Pico. Выбрать «USB-диск», работать с
обычным FAT/exFAT-накопителем на компьютере, безопасно извлечь его и затем
нажать Enter/Esc на PicoCalc. До извлечения редакторы и проводник не могут
получить карту. USB-C корпуса остаётся последовательным UART-интерфейсом.

## CHIP-8, USB Screen, RTC, сон и APP (0.4)

| Возможность | Управление |
| --- | --- |
| CHIP-8 | Открыть `.ch8`/`.c8` в проводнике или через `open` в `.m61` |
| USB Screen v2 | Tab → Система → USB Screen, затем подключиться приложением `apps/mk61_usb_screen` |
| Часы / два будильника | Tab → Система → Часы; ←/→ меняют поле, «Сохранить время» применяет |
| Сон | Tab → Система → Сон; первая физическая клавиша будит и поглощается |
| Автосон | Настройки → Сон через: 0 (отключён), 1, 5, 15, 30 минут |
| Нативные приложения | Открыть Pico H `.APP` в проводнике или через `open` в `.m61` |

CHIP-8 использует общее ядро `code/chip8.cpp`: 700 инструкций/с и таймеры
60 Гц, изображение 64×32 увеличивается с сохранением пропорций. Раскладка:
`1234 / QWER / ASDF / ZXCV` соответствует `123C / 456D / 789E / A0BF`.
Стрелки дают 4/6/2/8, Enter — 5, F3 — пауза, Esc — выход. Удержание и
отпускание учитываются отдельно; виртуальная клавиатура USB Screen работает
в том же цикле. Звуковой таймер выводится на динамик.

USB Screen использует общий протокол v2: COBS, CRC16, PackBits и атомарные
кадры 192×64. Калькулятор, меню, сценарии, CHIP-8 и графика APP доступны
на компьютере. При отсутствии heartbeat в течение 3 секунд виртуальные
клавиши отпускаются. USB-диск получает исключительное владение картой;
запуск приложений во время экспорта исключён.

Desktop USB Screen распознаёт `MK61S PicoCalc` (VID/PID `CAFE:4003`) и
активирует экран пакетом `ACTIVATE`, сохраняя ввод калькулятора. Ввод с ПК
использует двоичные `KEY_EVENT`. Профиль Pico не объявляет поддержку команды
терминала STM32 `kbd`. Для STM32 сохраняются прежние идентификаторы и активация.

RTC работает от кварцевой тактовой системы RP2040. Установка времени и
калибровка доступны в меню; время используется для дат FAT. Положительная
поправка ppm ускоряет часы; дискретность аппаратного делителя около 21 ppm.
Дата и признак установки сохраняются при программном reset в scratch
регистрах watchdog. После полного снятия питания время надо установить
снова. Будильники A/B могут быть однократными или ежедневными, хранятся
в журнале настроек, подают звук и будят экран. В `.m61` работают общие формы:

```text
date 2026-10-17 18:30:00
alarm a in 60
alarm b daily 08:00:00
alarm a off
```

Начиная с 0.4.1 USB Screen при подключении устанавливает **только сброшенные**
часы по местному времени компьютера. Уже установленное время сохраняется.
Без захвата экрана то же делает утилита для macOS/Linux:

```sh
python3 tools/sync_picocalc_clock.py --port /dev/cu.usbmodem1401
python3 tools/sync_picocalc_clock.py --port /dev/cu.usbmodem1401 --read
python3 tools/sync_picocalc_clock.py --port /dev/cu.usbmodem1401 --force --timezone Europe/Moscow
```

Перед запуском утилиты закрыть USB Screen, чтобы освободить CDC-порт.
Передача идёт CRC-защищённым пакетом, без ввода команд в калькулятор или
редактор. Полная потеря питания без компьютера по-прежнему требует установки
времени: в штатной плате нет независимых часов с резервным питанием.

Во сне выключены дисплей, обе подсветки и звук, ядро калькулятора стоит;
Основной PLL отключён. При USB процессор работает от PLL_USB на 48 МГц;
от батарей — от XOSC на 12 МГц с обоими PLL, ADC и USB-clock выключенными.
В SLEEP аппаратные маски оставляют тактирование RTC, таймера, watchdog и,
при USB, контроллера USB. Пустая клавиатура опрашивается примерно раз в
80 мс, между опросами CPU спит. RTC постоянно работает от XOSC / 256,
поэтому переключение PLL не останавливает ход времени. После пробуждения
возвращаются 125 МГц и прежние настройки I²C/UART/экрана. Подключение или
отключение USB во сне автоматически меняет источник тактирования.

RAM, RTC и будильники сохраняются. Сон разрешён после остановки RUN,
сценария и APP. Автосон запрещён при открытом редакторе, USB-диске или
подключённом USB Screen. Полный DORMANT останавливает XOSC и требует
внешнего события для пробуждения. Штатный BIOS отдаёт клавиши по запросу
I²C, отдельной линии IRQ клавиатуры к Pico нет. Для DORMANT с клавиатурой
и сохранением времени нужен дополнительный механизм пробуждения и хода
часов; одной заменой UF2 Pico H это не обеспечивается. Измерение тока всей
платы этим изменением не подменяется; диагностический статус показывает реальные
`SYS_HZ`, `PERI_HZ`, `PLL_MASK` и число `BATTERY_SLEEPS`.

Для APP сохраняется публичный C ABI 6: текст/M8, графика 192×64, клавиши
и их состояние, файлы, LED, звук, математика, числовой ввод/вывод, регистры,
временная память, редактор и файловые диалоги. `.sheet` находит обработчик
по magic `S1` рядом с файлом либо в `/app`, `/Apps`, `/Applications`,
`/System`, `/`. Возврат APP освобождает память; следующий запуск получает
свежие `.data`/`.bss`. APP для M4 и для M0+ различаются флагом контейнера:
сборки STM32 отвергают M0+ APP, Pico H отвергает M4 APP.

Собрать HELLO, SERVICES, ELIZA, SHEET и WBMP из обычных исходников:

```sh
python3 tools/build_picocalc_apps.py
```

Результат — `binary/picocalc-pico-h/apps/`. Копировать на microSD через
USB-диск. Сборка отдельного приложения:

```sh
python3 tools/build_portable_app.py --target picocalc-pico-h --name HELLO \
  --source examples/portable-apps/HELLO/main.c \
  --arm-toolchain-bin /path/to/arm-gcc/bin --output-dir .build/hello-pico
```

У Pico лимит памяти одного APP — 48 КиБ: soft-float код SHEET требует
больше памяти, чем M4. Выделение ограничено реально свободной RAM и не
заходит в 32-КиБ стек. Обычная сборка APP по умолчанию остаётся STM32
с прежним лимитом 20 КиБ. Для Rust выбирается `thumbv6m-none-eabi`.
`--system`/`--shared-runtime` относятся к STM32; службы Pico встроены в UF2.

## Клавиатура

| Клавиши PicoCalc | МК-61 |
| --- | --- |
| `0`–`9`, `.`, `+`, `-`, `*`, `/` | Те же клавиши |
| Enter | В↑ |
| Escape, Backspace, Delete | Cx |
| F1 или F | F |
| F2 или K | К |
| F3 или R | С/П |
| F4 или G | БП |
| F5 или C | ПП |
| B, Shift+F1 (F6) | В/О |
| L, Shift+F2 (F7) | П→X |
| S, Shift+F3 (F8) | X→П |
| Стрелки ←/→, `[`/`]` | Шаг назад/вперёд |
| E | ВП |
| N | /−/ |
| X | X↔Y |
| D / A / T | Градусы / радианы / грады |

Последовательность `F`, `E` включает ПРГ; `F`, `N` возвращает АВТ.
Функции с префиксами F и К исполняет оригинальное ядро. Например,
`9`, `F`, `-` даёт квадратный корень, а в режиме DEG `9`, `0`, `F`, `7` —
синус 90°. Клавиши выполняются как отдельные нажатия, с фазой отпускания.
FIFO BIOS: первый байт — состояние (1 нажато, 2 удержание, 3 отпущено),
второй — код. Удержание/отпускание повторно цифры не вводит.

## Математика M4 и RP2040

У калькулятора вычисления выполняет эмуляция микрокода К145ИК; это не
native binary64-библиотека интерпретаторов. Наши целочисленные ядро и таблицы
пересобираются для ARMv6-M, без STM32 bit-band и DWT.

`native_eabi_arm.S` и `native_eabi_fixed.S` содержат `.cpu cortex-m4`, Thumb-2,
`UBFX`, `CLZ`, `UMULL` и другие инструкции, непригодные для Cortex-M0+.
Они в Pico-сборку **не входят**. `compact_math.cpp` переносим: C++-умножения
компилируются под M0+, а защищённый `__ARM_FP` путь `VSQRT.F32` заменяется
имеющейся программной веткой. Основные float/double EABI-функции предоставляет
Pico SDK, в том числе оптимизированные функции ROM RP2040.

Для ранней проверки в прототип включены те же `compact_math.cpp` и
12 проверок sin/cos/tan, asin/acos/atan, ln/log10/exp/pow, точного sqrt(2)
и знака sqrt(-0). Это проверка переноса; она не заменяет полную квалификацию
точности и скорости будущих FOCAL/BASIC/APP на RP2040. Оптимизации STM32
остаются включены в соответствующих STM32-сборках.

## Диагностика и проверка

Открыть serial-порт **нужного Pico** (UART / USB-C — 115200 бод; родной
USB CDC не зависит от выбранной скорости, кроме 1200 для BOOTSEL).

- `?` в калькуляторе/меню печатает состояние. ENQ (Ctrl+E, `0x05`) делает
  это также внутри редактора, INPUT и USB-диска, где `?`/`!` — обычные символы.
- `m` повторяет математическую проверку и печатает `MATH_TEST=OK failures=0`.
- `LCD=ST7365P RGB565 SPI_HZ=… FRAMES=…` показывает драйвер, фактическую
  частоту SPI и число отправленных кадров с момента инициализации дисплея.
- `!` переводит Pico в ROM BOOTSEL. Не посылать его для обычной диагностики.
- Калькулятор принимает те же ASCII-клавиши, что перечислены выше.
- `SERVICE`, `SOURCE`, `DIRTY`, `PATH` показывают файловый интерфейс;
  `SD`/`USB_DISK` — владельца карты; `STACK_USED` — измеренный максимум
  использования отдельно зарезервированного стека 32 КиБ.
- `MSC_READ/WRITE`, `READ_ERROR/WRITE_ERROR`, `USB_MAX_GAP_US` помогают
  диагностировать передачу блоков. В режиме USB-диска выполнение ядра и
  повторная отрисовка статичного экрана приостановлены: большие команды
  чтения должны укладываться в SCSI-таймаут компьютера.
- `MSC_SD_READ_US`, `MAX_READ_US/BYTES/LBA` отделяют время чтения карты от
  передачи USB. Последовательные секторы читаются CMD18/CMD12 с проверкой
  CRC16 каждого сектора; таблица CRC вычисляется при компиляции.

У USB-профиля отдельная комбинация CDC+MSC с VID/PID `CAFE:4003` из
примеров TinyUSB. Идентификатор SDK для одного CDC здесь не используется.
На проверенном Mac медленное поштучное чтение секторов приводило к отказу
монтирования FAT32 примерно через 22 секунды без ошибок CRC. После
перехода на последовательное чтение аппаратная проверка прошла полный
цикл: автоматическое монтирование, чтение файлов, запись нового исходника,
безопасное извлечение и запуск записанного файла в BASIC на PicoCalc.
Сама карта также проверена через отдельный кардридер. Существующие файлы
и разделы не форматировались.

Host-проверки используют реальные ядро, математические функции и растр:

```sh
MK61_TEST_SANITIZERS=1 bash tests/run_picocalc_tests.sh
```

Тест проверяет ввод очередью, 12+34, корень, тригонометрию, регистры,
запись/запуск программы 1+2, BIOS-коды/состояния, переполнение очереди,
математику и границы изображения, а также UF2-заголовки, адреса, семейство,
ограничение Flash и повреждение транспортных блоков. Дополнительно настоящая
FatFs проверяется на диске в памяти: FAT/exFAT, UTF-8/M8, ошибки записи,
владение картой, редактирование, компиляция/запуск, INPUT и графика.
Полный M61-прогон использует настоящее ядро и FatFs: вложенные каталоги,
сохранение BASIC/FOCAL-состояния, RUN, TRAP с восстановлением контекста,
BIND/OK, FMK, CRC32+ZX0 через границу банков, INS с коррекцией адресов и
права команд. Большие текстовые ресурсы проверяются с SOURCE-рецептами.
Неизменённый `Turochamp/autoexec.m61` доходит до доски и корректно выходит по Esc.
Чтобы сохранить точный экран в PBM, передать тесту путь выходного файла.

Автоматическая проверка на устройстве через его родной USB CDC:

```sh
python3 tests/hil_picocalc.py --port /dev/cu.usbmodem1401 --output binary/picocalc-pico-h/hardware-smoke.json
```

Имя порта следует заменить на порт нужного Pico. Проверка сверяет профиль,
выполняет математический self-test, 12+34, √9 и sin(90°); она изменяет X.
Ключ `--ui` дополнительно проверяет меню, язык, шрифты и сохранение настроек.

Проверка служб создаёт только новые тестовые исходники с уникальными именами:

```sh
python3 tests/hil_picocalc_services.py --port /dev/cu.usbmodem1401 --write-test-files --output binary/picocalc-pico-h/hardware-services-smoke.json
python3 tests/hil_picocalc_usb_disk.py --port /dev/cu.usbmodem1401 --sources-report binary/picocalc-pico-h/hardware-services-smoke.json --write-test-file --output binary/picocalc-pico-h/hardware-usb-disk-smoke.json
python3 tests/hil_picocalc_m61.py --port /dev/cu.usbmodem1401 --write-test-files --output binary/picocalc-pico-h/hardware-m61-smoke.json
python3 tests/hil_picocalc_runtime.py --port /dev/cu.usbmodem1401 --write-test-files --output binary/picocalc-pico-h/runtime-hil
python3 tests/hil_picocalc_clock.py --port /dev/cu.usbmodem1401 --output binary/picocalc-pico-h/clock-hil
```

Второй скрипт предназначен для macOS: он сверяет модель USB-носителя,
читает тестовые файлы, записывает новый BASIC-исходник, извлекает карту и
открывает/запускает файл через проводник PicoCalc. Он не форматирует карту.

Для аппаратной приёмки нужны видимый экран, ввод с физической клавиатуры
и serial-отчёт. Успешный USB upload не подтверждает работу этих узлов.

Результаты приёмки 0.2.0 на первом устройстве, SHA-256 прошивки и
проверки STM32 записаны в
[отчёте UI/services](../../doc/measurements/picocalc-pico-h-ui-services-20261017.json).

прежняя ошибка проверки стека `program_store` — 2304 байта при лимите 2048;
та же ошибка присутствует в контрольном исходнике без Pico-порта.

Приёмка 0.3.0 полного M61 сохранена в
[отчёте M61](../../doc/measurements/picocalc-pico-h-m61-20261017.json).
На точной UF2 проверены вложенные файлы, ловушки, привязки, инструкции,
сохранность несохранённого редактора и неизменённые Turochamp/Bumblebee.
Пользователь подтвердил русские надписи и физические стрелки Turochamp;

## Аппаратный контракт и источники

| Узел | Подключение |
| --- | --- |
| LCD SPI1 | SCK 10, MOSI 11, MISO 12, CS 13, DC 14, RESET 15 |
| Клавиатура I²C1 | SDA 6, SCL 7, адрес 0x1F, 10 кГц |
| FIFO клавиш | Регистр 0x09, 2 байта, пауза 16 мс между выбором и чтением |
| Подсветка | LCD 0x05, клавиатура 0x0A; запись с битом 0x80 |
| USB-C serial | UART0, GPIO 0/1 |
| Micro-USB Pico | Собственный USB RP2040, CDC / MSC / BOOTSEL |
| microSD SPI0 | SCK 18, MOSI 19, MISO 16, CS 17; 400 кГц init / 12,5 МГц data |

Параметры дисплея и протокол BIOS сверены с официальным
[clockworkpi/PicoCalc](https://github.com/clockworkpi/PicoCalc/tree/fdcfe2c87a56b6dbcd540e91de1161d483872af9/Code):
`picocalc_helloworld/lcdspi`, `picocalc_keyboard` и `picocalc_kbd_tester`.
Драйвер использует **ST7365P и RGB565**. Базовая последовательность
COLMOD/MADCTL/INVON/entry mode сверена с рабочим
[драйвером PicOS](https://github.com/jeffory/PicOS/blob/b96031fc0c1dd6e868478bf7c4d426931f3d8753/src/drivers/display.c).
Питание, VCOM, гамма и развёртка сохраняют значения панели после reset/NVM;
параметры ILI9488 для этих регистров сюда не переносятся. Адаптивная яркость
по содержимому (CABC) явно выключена. SPI запрашивает 10 МГц (при системных
125 МГц реально 8,93 МГц), в пределах периода записи ≥66 нс из
[спецификации ST7365P](https://github.com/clockworkpi/PicoCalc/blob/fdcfe2c87a56b6dbcd540e91de1161d483872af9/ST7365P_SPEC_V1.0.pdf).

Дисплей хранится в монохромном буфере 12 800 байт; изменившийся кадр целиком
отправляется за одну транзакцию CS вместе с RAMWR, преобразуясь по одной
строке в RGB565 без полного цветного framebuffer. На первом устройстве
совместимая инициализация ILI9488 давала полосы при частичных обновлениях;
полный кадр выровнял изображение, но при вводе цифр яркость продолжала
меняться. Это потребовало отдельной настройки ST7365P, а не только
увеличения внешней подсветки. После перехода на ST7365P пользователь
подтвердил стабильную яркость при повторном вводе `1` на физической
клавиатуре. Для других ревизий экрана нужна такая же аппаратная проверка.

Формат UF2: [официальная спецификация](https://github.com/microsoft/uf2).
Протокол SPI-карты и остановка CMD18 командой CMD12 сверены с
[описанием автора FatFs](https://elm-chan.org/docs/mmc/mmc_e.html#dataxfer).
