# Постоянный загрузчик корпуса PicoCalc

Загрузчик STM32F103R8 принимает BIOS по USART3 от Pico H. Обычное обновление
BIOS не стирает загрузчик, не меняет option bytes и не пишет настройки.
Это отдельная программа в Flash M3; заводской ROM STM32 сохраняется.

| Область | Адреса |
|---|---|
| Загрузчик, 8 КиБ | `08000000..08002000` |
| BIOS, до 53 КиБ | `08002000..0800F400` |
| Метаданные, 1 КиБ | `0800F400..0800F800` |
| Существующие настройки, 2 КиБ | `0800F800..08010000` |

Сборка из чистого репозитория с закреплёнными HAL/CMSIS из Southbridge:

```sh
python3 tools/firmware/picocalc/build_boot_bios.py \
  --drivers /path/to/pinned-southbridge/Drivers \
  --toolchain /path/to/arm-none-eabi/bin \
  --output-dir .build/m3-boot
```

Сборщик проверяет закреплённый исходный архив базы, применяет актуальные
асинхронный PMU и расширение сопроцессора, переносит BIOS и его векторы.
Он создаёт `bootstrap.bin`, `boot.bin`, `bios.bin`, `BIOS.M3U`, манифест с SHA256,
полное дерево M3 в `source.zip` и `sd/Apps/BIOS/BIOSUPD.APP` с образом BIOS.
Архив содержит `rebuild.py`: после распаковки задайте ему `--drivers` и
`--toolchain`. Он проверит исходники/зависимости и совпадение четырёх BIN/M3U
побайтно с исходной сборкой. USB при сборке не открывается.

## Первая установка

Один раз установите **весь `bootstrap.bin`** через заводской ROM-загрузчик M3
при DIP1 ON. Адрес `08000000`, стирание только страниц 0–61, с проверкой чтением.
Настройки на страницах 62–63 сохраняются. Затем верните DIP1 OFF и полностью
перезапустите питание. Старый BIOS с векторами по адресу `08000000` для
обновления через новый загрузчик не подходит: нужен файл `BIOS.M3U`.

## Последующие обновления

Скопируйте каталог `sd/Apps/BIOS` на microSD. Откройте `BIOSUPD.APP` в
проводнике PicoCalc и нажмите **Enter**; **Esc** до начала отменяет обновление.
Рядом должен лежать `BIOS.M3U`. APP также обрабатывает открытый файл с magic
`M3`, если его выбрал механизм обработчиков проводника.

APP сначала проверяет заголовок, длину, CRC32 и векторы и полностью помещает
образ в общий буфер (PSRAM при доступности, SRAM как запасной вариант).
Только после этого M3 переводится из BIOS в загрузчик. BIOS должен
поддерживать бит `0x10` в transport flags HELLO и команду `0x30`: два слова
`BOOT` (`0x544F4F42`) и target `0x410`. Переход разрешён только в состоянии
EMPTY, после окончания передачи ACK. Питание Pico сохраняется; аппаратный
reset M3 для этого перехода не используется.

Восстановительный UART: USART3 PC10/PC11 ↔ Pico UART1 GP9/GP8, 115200 8N1.
Основной BIOS продолжает использовать 2,25 Мбод. APP меняет скорость только
после эксклюзивного захвата UART1 и возвращает его регистры/пины при выходе.

При записи M3 временно не обслуживает физическую клавиатуру, RTC по I²C и
индикацию питания. Pico продолжает работать. APP проверяет весь результат
через READ и сохранность CRC области загрузчика, получает ACK команды RUN и
возвращает управление Pico. Маркер `M3UPDATE HANDOFF code=0` означает проверенную
запись и подтверждённую передачу запуска; проверка HELLO работающего BIOS
выполняется новым сеансом после выхода APP. Успешная установка не требует
второго нажатия Enter.

Если обмен или питание прерваны до завершения записи, неполный BIOS не
запускается. Загрузчик включает питание Pico и ждёт повторной установки по
UART. Запустите тот же APP через USB-терминал Pico (`run
"/Apps/BIOS/BIOSUPD.APP"`) и подтвердите Enter через удалённую клавиатуру.
При отсутствии работающего BIOS физическая клавиатура корпуса недоступна;
автоматическое восстановление без участия компьютера пока не реализовано.
Потеря связи допускает повтор блока; после потери питания установка
начинается заново. Заводской ROM/DIP остаётся способом ремонта загрузчика
или BIOS, который имеет верную CRC, но зависает при выполнении.

## Целостность и протокол

`BIOS.M3U`: восемь little-endian u32, затем тело с выравниванием до четырёх
байт (`FF`): magic `M3U1`, версия 1, target `0x410`, база `08002000`, длина,
CRC32 тела, идентификатор сборки (первые 4 байта SHA256 тела), CRC32 первых
28 байт заголовка. CRC обеспечивает контроль ошибок; образ считается
доверенным программным кодом, криптографическая подпись не применяется.

Кадры COBS с нулевым разделителем, заголовок 8 байт: версия `0x42`, команда,
sequence u16, длина u16, flags u16=0; до 256 байт данных и CRC32 заголовка с
данными. Ответ использует `command|0x80`, первым словом идёт status.
Команды: INFO=1, BEGIN=2 (32-байтовый заголовок), WRITE=3 (offset u32 и до
240 чётных байт), COMMIT=4, RUN=5, READ=6 (address/count, до 240 байт).
Дубликат последней sequence с тем же запросом повторяет кешированный ответ.
Тот же sequence с другими данными игнорируется. Повтор WRITE с новой
sequence принимается только при полном совпадении уже записанных байтов.

BEGIN сначала стирает метаданные и только затем страницы BIOS. COMMIT
сверяет CRC и векторы, записывает заголовок и последним — маркер `C001CAFE`.
При включении проверяется маркер, заголовок, SP, Thumb entry и CRC всего тела.
Переход в BIOS переключает VTOR, MSP и включает прерывания после очистки NVIC.
Восстановительный режим работает с выключенными прерываниями; GPIO питания
Pico удерживается, IRQ/таймеры/UART/DMA прежнего BIOS остановлены. RTC и его
backup domain не сбрасываются. Обновление самого загрузчика через UART не
предусмотрено: запись и стирание ниже `08002000` аппаратным адаптером запрещены.

Проверки: `python3 tests/picocalc_m3_boot_self_test.py` (HOST ASan/UBSan,
2226 прерываний, реальный APP и PSRAM-модель) и
`python3 tests/picocalc_m3_boot_arm_self_test.py --firmware .build/m3-boot
--output .build/m3-boot/arm-result.json` (Unicorn). ARM-модели проверяют код,
но не электрические сигналы и не время операций Flash на плате.
