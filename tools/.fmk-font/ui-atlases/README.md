# Reviewed UC1609 UI rasters

These six native, monochrome FreeType atlases are the exact samples selected
in the September 2026 computer comparison. They cover ASCII, Russian including
Ё/ё, degree, arrows, ellipsis and ≤/≥. Roboto lacks ←/→ in this source; firmware
uses the same-size DejaVu glyphs for those two characters. Both families have
the same baseline and total glyph envelope at each selected size:

| Full envelope | Native ppem | Ascent | Descent | Interline gap |
|---|---|---|---|---|
| 12 px | 10 | 10 | 2 | 1 |
| 14 px | 11 | 11 | 3 | 2 |
| 16 px | 14 | 13 | 3 | 2 |

The compact 12 px line box fits five rows exactly into 64 pixels
(`5×12 + 4×1`). Four 14 px rows occupy 62 pixels and are vertically centred;
16 px deliberately uses three rows with a two-pixel gap rather than allowing
adjacent full-envelope glyphs to touch.

No antialiasing, rescaling, synthetic bold, kerning or runtime font engine is
used. A safe horizontal advance preserves at least one blank column between
glyph bounding boxes. This is deliberately different from blindly using
FreeType's native advance at tiny resolutions.

## Reproduction

Normal firmware builds consume `code/ui_font_data.inc`; Python and FreeType
are not firmware dependencies. Regenerate from the reviewed JSON using:

```sh
python3 tools/generate_ui_fonts.py
python3 tools/generate_ui_fonts.py --check
bash tests/run_ui_font_tests.sh
```

The generator verifies SHA-256 of each input atlas, checks baseline/advance
invariants and emits deterministic Flash-only arrays. Identical glyph bytes
are shared within each face. Tests compare every firmware glyph pixel and
metric with its reviewed source, including Roboto fallback. Source atlas
checksums are explicit in the generator; intentional changes require a new
raster review, not merely refreshing generated bytes.

To reproduce the *rasterization* first build `tools/.fmk-font/font_preview.cpp`
against FreeType (see its adjacent `README-preview.md`), then run it on each
font with `--height 12`, `--height 14` and `--height 16`. Different FreeType releases can
change grid fitting; do not silently replace these reviewed atlases with a
new rasterizer's output. The JSON remains the authoritative visual input.
