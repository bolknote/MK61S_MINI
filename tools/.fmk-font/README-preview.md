# Исследование пропорциональных шрифтов

Это инструменты **для компьютера**, не новый движок прошивки. `font_preview.cpp`
выводит JSON с настоящими однобитными растрами FreeType. `font_preview_study.py`
собирает изображения UC1609 192×64 и интерактивное сравнение. Исходники прошивки
используются только для экспорта эталонного встроенного 5×8.

## Воспроизведение

Нужны C++17, FreeType с pkg-config и Python 3 с Pillow. Из корня репозитория:

```sh
mkdir -p tmp/ui-font-study
clang++ -std=c++17 -Wall -Wextra -Werror \
  -DARDUINO=100 -DMK61_DISPLAY_UC1609 -DFONT_PREVIEW_BUILTIN \
  -Icode -Itests/mk_math_shim $(pkg-config --cflags freetype2) \
  tools/.fmk-font/font_preview.cpp code/builtin_font.cpp \
  code/ERM19264_graphics_font.cpp $(pkg-config --libs freetype2) \
  -o tmp/ui-font-study/font-preview
python3 tools/font_preview_study.py \
  --exporter "$PWD/tmp/ui-font-study/font-preview" \
  --roboto /absolute/path/Roboto-Regular.ttf \
  --dejavu /absolute/path/DejaVuSans.ttf \
  --out tmp/ui-font-study \
  --html "$PWD/tmp/ui-font-study/comparison.html"
python3 tests/font_preview_study_test.py
```

`comparison.html` — самостоятельный по данным HTML-фрагмент для inline-просмотра,
не полноценный сайт. PNG и JSON можно читать без него. `*-1x.png` имеют исходное
разрешение; `comparison-*.png` увеличены ровно втрое без интерполяции.

Источники шрифтов для текущего опыта:

- [Roboto Regular](https://github.com/googlefonts/roboto-2/blob/38062f4b4a0be4346d07a928408da21602545e9e/src/hinted/Roboto-Regular.ttf), Apache 2.0;
- [DejaVu Sans 2.37](https://github.com/dejavu-fonts/dejavu-fonts/releases/tag/version_2_37), лицензия из архива шрифтов.

Лицензии надо сохранять вместе с распространяемыми шрифтами. TTF не включены
в исходники инструмента. В `measurements.json` записываются SHA-256 входных файлов.

## Что именно сравнивается

- Нативный целочисленный ppem, monochrome hinting; **без сжатия букв по осям**,
  сглаживания, искусственного жирного/курсива и кернинга.
- Размер 12 означает предел **полного растра** набора, включая верхние и нижние
  элементы, а не кегль 12 пунктов и не высоту только прописной буквы.
- Между непустыми прямоугольниками соседних глифов минимум один пустой столбец;
  исходные advance/bearing сохранены отдельно. Межстрочный просвет 1/2/3 px.
- 169 символов: ASCII, русские буквы с Ё/ё, градус, четыре стрелки, многоточие,
  ≤ и ≥. Отсутствующие символы отражаются явно, без подмены похожими.
- Эталон меню: встроенный 5×8 в клетке 12 px, строки через 10 px; эталон прозы:
  тот же 5×8 с шагом 6 px. Это реконструкция шрифта/сетки, **не USB-снимок**.
- Строки меню/настроек — из `code/menu.cpp`; файлы — из `games/`; проза — из
  `games/Pogonya/manual.md`. Стресс-текст и расположение элементов — тестовые.
- Подсчёт tight_bitmap_bytes не включает метрики, индекс, выравнивание и заголовок;
  это **не** размер FMK-файла, не расход RAM и не изменение размера прошивки.

## WS0010

Модель WEH001602A: логические 80×16 точек; физически точка 0,55×0,65 мм,
шаг 0,60×0,70 мм и дополнительные промежутки 0,60 мм после каждых пяти столбцов,
0,70 мм после восьмой строки. Получается активная область 56,95×11,85 мм.
Видимые пробелы посреди букв — следствие расположения точек, а не неисправность
рендера. Это геометрическая модель; яркость, свечение, оптика и расстояние до глаза
не моделируются. Для конкретного модуля требуется проверка на устройстве.

## Граница следующего этапа

После выбора растра: отдельный опциональный профиль интерфейса UC1609, пиксельная
ширина строк/переносов, единые метрики измерения и рисования, таблицы во Flash,
страничный рендер без дополнительного framebuffer. Калькулятор, код и дампы
остаются моноширинными. A00/A02 не меняются. Для символьного WS0010 пропорциональный
режим не следует автоматически включать: межзнаковые физические зазоры мешают ему.
