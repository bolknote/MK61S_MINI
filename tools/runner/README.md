# Runner на МК61S

Три уровня по три этажа и 12 клеток. Нужно собрать по три клада,
избегая преследователей. На первом уровне один враг, дальше два;
карты лестниц и расположение кладов различаются. Последний клад завершает
уровень; после третьего появляется `ALL CLEAr`. Столкновение показывает
`CAUGHt 0`, повторная попытка запускается кнопкой 0.

На экране виден этаж героя. Кольцо `6B` обозначает героя, `77` — врага,
`C9` — клад, `7E` — лестницу с полом, `08` — пол, `00` — прожиг.
При активном прожиге герой падает на этаж ниже. Враг остаётся в ловушке
до восстановления пола, затем возвращается к месту старта.
Нижний этаж и лестницы защищены; одновременно открыт один прожиг.

| Кнопка | Действие |
| --- | --- |
| 4 / 6 | Влево / вправо, с удержанием |
| 8 / 2 | Вверх / вниз по лестнице, с удержанием |
| 7 / 9 | Прожиг слева / справа |
| 5 | Номер уровня и оставшиеся клады, пауза 900 мс |
| 0 | Повтор текущего уровня; после всей кампании — новая игра |
| OK | Памятка с паузой |
| ESC / долгое Cx | Выход / системный выход с отменой всех bind |

Противоположные удержания блокируют друг друга, вертикальное направление
имеет приоритет. Короткое down/up сохраняет одно действие. Последний новый
запрос за кадр заменяет предыдущий. Враги движутся и без нажатий.
Рекомендуемая скорость калькулятора — MAXIMUM.

## Сборка и установка

```sh
python3 tools/runner/build.py
python3 tools/runner/build.py --check
bash tests/run_runner_tests.sh
MK61_TEST_SANITIZERS=1 bash tests/run_runner_tests.sh
```

Предпросмотр через настоящее ПЗУ и сегментные плоскости UC1609 (нужен Pillow):

```sh
MK61_RUNNER_BUILD_DIR=.build/runner-host bash tests/run_runner_tests.sh
python3 tools/runner/preview.py --runner .build/runner-host/runner-native \
  --output .build/runner-preview.png
```

В `/games/Runner` нужны все восемь файлов из `programs/games/Runner`:
`autoexec.m61`, три `levelN.m61`, три `runnerN.bin`, `manual.md`.
Старый `runner.bin` больше не используется. BIN содержит CRC32 и ZX0;
текст перед записью в C9 кодируется M8. Файлы укладываются в ограничения:
1536 байт для M61/MD, 4096 для BIN. Принудительный режим 105 шагов не подходит.
Требуются `bind key`, `bind timer`, `2F 8n` и новые общие операции
`1F 4n/Bn/Dn`, `2F 54/55/56`, M61 `lookup/@` и компактные `Rn=значение`; описание —
[в спецификации](../../doc/src/MK61s-mini-Extended-Opcodes.md).

## Исполнение

Python только собирает калькуляторные команды и неизменяемые таблицы.
На устройстве движение, лестницы, падение, клады, преследование и отрисовка
исполняются M61, ПЗУ и расширенными командами. Прошивка не содержит правил Runner.
M61 принимает клавиши, планирует кадры и часы, выбирает экран
поражения/победы, загружает уровни.

Для каждого положения героя сборщик вычисляет кратчайшие пути врагов по
графу клеток и лестниц. M61 читает таблицы движения, падения, преследования
и кладов общей командой `lookup` (короткая форма `@`). Правила и карты
находятся в файлах игры. ПЗУ выполняет прожиг, перезапуск, счёт и финальные
экраны; `2F 56` собирает слои, `2F 53` публикует готовый кадр.
На уровень нужен образ из 32 банков; следующая карта загружается поверх него.

Игра использует монотонный таймер 4000 мс. `bind timer` ставит RE=-1,
а корневой цикл между кадрами восстанавливает пол и начинает новый период.
Порог RE задаёт шаги врагов: 2000 мс на первом уровне, 1000 мс на остальных.
Успешный прожиг начинает новый четырёхсекундный период. Памятка и счёт
сохраняют остаток через `timer pause/resume`. Время расчёта входит в срок;
видимый результат ждёт готового кадра. Просроченные шаги врагов объединяются.
Если враг достиг героя, поражение имеет приоритет перед движением.

Обработчики клавиш записывают удержание в R9…RC и последний запрос в RD.
Противоположные направления по одной оси отменяются, по другой оси движение
остаётся доступным. Короткий down/up во время отрисовки ждёт следующего кадра.
После публикации программа останавливается в банке 0; в покое M61 обслуживает
`wait 30`, не пересчитывая кадр. Scheduler не исполняет лишний idle-шаг ПЗУ
между порциями строк M61, когда сама калькуляторная программа остановлена.

| Регистры | Значение |
| --- | --- |
| R0…R3 | Буфер / рабочие значения; R3=1 после публикации |
| R4 | Клетка героя 0…35; -1 — поражение, -2 — победа |
| R5 / R8 | Клетки врагов; 36 — отсутствует |
| R6 | Маска собранных кладов, умноженная на 36 |
| R7 | Прожиг; 36 — отсутствует, 0 — системный выход |
| R9…RC | Удерживаемые направления |
| RD | Запрос направления/прожига либо -1 перезапуск, -2 счёт |
| RE | Следующий порог часов; -1 — событие окончания периода |
| RF | База композиции; -1 новый прожиг, -2 перезапуск, -3 счёт |

`runner.map.json` содержит карты, метки и адреса таблиц каждого уровня.
Хостовые проверки используют production-парсер M61 и настоящее ПЗУ,
с вариантами native/packed UC1609 и scalar/LCD1602 A00. Проверяются все
клетки и направления, маски кладов, обе фигуры врагов, кратчайшие пути,
прожиг/ловушки/падение/восстановление, проигрыш, пауза, переполнение часов,
удержания и прохождение всех трёх уровней обычными клавишами.
Фикстуры отдельно покрывают отрисовку и граничные состояния.
Дополнительно проходят две кампании подряд с ходом каждого врага перед
каждым действием героя; проверяются перезапуск после финала и отсутствие
голодания ввода при расчёте дольше периода врагов.

Текущий кандидат прошёл полную HOST-кампанию с асинхронной доставкой кадров,
финальную победу и перезапуск при 28 мс / 40 мс и 31 мс / 80 мс
(шаг ядра / задержка наблюдения). Проблемное состояние второго уровня
проверяется отдельно в восьми фазах. Эти параметры моделируют задержку,
а не USB и не точную внутреннюю фазу реального калькулятора.

Новый кандидат ещё не прошёл всю кампанию на Classic. Физический Window7
прошёл первый уровень, затем безопасно остановил тест на втором; максимальная
задержка там была 1,474 с. Эти результаты сохранены отдельно от HOST PASS.
Подробности и границы проверок — [в отчёте](../../doc/measurements/runner-campaign-20261031.md).

`tests/hil_runner_campaign.py` использует общий frame-only контроллер на
уровнях 2/3. Модуль контроллера сам не открывает устройства. Аппаратный запуск
требует отдельного согласованного окна, совпадающей прошивки и файлов.
Старые отчёты и старые `hil_runner_classic.py`, `hil_runner_picocalc.py`,
`compare.py` сохранены для воспроизведения прежних измерений.
