# Runner для MK61s: прототип движения

Три этажа по 12 клеток, кольцо вместо героя, лестницы `H`, один прожиг
с восстановлением пола и автоматическим падением. Программа работает
непрерывно; для каждого шага нажимать С/П не нужно. Клады, противники
и смена уровней пока не реализованы.

Первый проход оптимизации 28.10.2026 сократил работу в покое с 77 до 13 шагов
ядра, шаг вправо — с 80 до 40, прожиг — со 142 до 66. На 1200 кадрах со
смешанными нажатиями исходная и новая версии дали одинаковую механику и
картинки; число шагов уменьшилось со 111845 до 48005. Новых опкодов нет.
Сравнение на том же Classic и методика — в
[отчёте](../../doc/measurements/runner-speed-20261028.md).

Второй проход 29.10.2026 добавил загрузку готового кадра `2F 8n`,
числовое копирование регистров M61 и короткие пути для движения и таймера.
Обычный шаг теперь занимает 18 команд ядра. Аппаратные замеры и проверки —
в [новом отчёте](../../doc/measurements/runner-speed-20261029.md).

Исходный прототип также проверялся на PicoCalc:
[первый аппаратный отчёт](../../doc/measurements/runner-picocalc-20261028.md).
Замеры ускоренной версии на Classic не являются замерами PicoCalc.

Пакет для калькулятора находится в [`programs/games/Runner`](../../programs/games/Runner).
Скопируйте всю папку в `/games` на диске устройства. Выберите скорость
`MAXIMUM`, затем войдите в папку. Требуется прошивка с `bind key` и
расширениями `1F`/`2F`, включая `2F 8n`, числовое копирование `R0= RA` и
обработку `bind key` во время обычного `wait` (29.10.2026). Принудительный
режим памяти 105 шагов не подходит.

## Управление и поле

| Кнопки | Действие |
| --- | --- |
| 4 / 6 | Влево / вправо, с удержанием |
| 8 / 2 | Вверх / вниз по лестнице, с удержанием |
| 7 / 9 | Прожечь соседний пол слева / справа |
| 0 | Начальная позиция и восстановленный пол |
| OK | Памятка; после закрытия игра продолжается |
| ESC / долгое Cx | Выход с очисткой калькулятора / системный выход |

Старт — колонка 1 среднего этажа. Лестницы 3/9 соединяют этажи 1 и 2,
лестницы 7/11 — этажи 2 и 3. На экране показан только этаж героя.
Противоположные удерживаемые направления взаимно блокируются; при обычном
удержании вертикальное направление имеет приоритет над горизонтальным.
Нижний пол и лестницы защищены от прожига. Активный прожиг закрывается
через 18 кадров; новое нажатие 7/9 до закрытия игнорируется. Шаг на открытый
участок автоматически переносит героя этажом ниже.

## Где выполняется игра

`game.py` собирает **калькуляторные команды**, используя ассемблер ELITE.
Python не выполняет игровую логику на устройстве. Движение, границы,
лестницы, прожиг, таймер и гравитация исполняются ПЗУ МК‑61 и расширенными
командами. M61 принимает события кнопок, выбирает действие и запускает
один расчёт кадра. После атомарной публикации программа исполняет С/П
в банке 0; сценарий выдерживает `wait 30` и запускает следующий расчёт.
Ловушки не используются. Реальный период включает паузу, обработку M61
и время калькуляторных команд; он зависит от устройства.

Есть три входа: движение без открытого прожига, уменьшение таймера без
движения и полный расчёт движения при активном прожиге. Первый не проверяет
гравитацию и таймер, второй перерисовывает экран только при восстановлении
пола. В покое без прожига M61 продолжает ждать и обслуживать клавиши,
не запуская пустые кадры калькулятора.

Для всех 36 сочетаний «этаж, колонка» есть заготовки по 12 байтов-масок.
`2F 84` загружает нужную запись атласа по `RF + 12*R4` прямо в R0…R3.
Затем программа стирает активный прожиг и публикует весь кадр одним `2F 53`.
Используются четыре маски: пробел `00`, пол `08`, лестница с полом `7E`,
кольцо с полом `6B`. На LCD1602 нужны два CGRAM-глифа.

На клетку отведена запись из 28 байтов с переходами для прожига слева/справа
и процедурой очистки с проверкой этажа. Четыре записи помещаются в банк.
Допустимость прожига вычисляется сборщиком из карты лестниц. Во время игры
не нужны деление для определения этажа дырки, поиск её колонки и повторные
проверки лестниц. RE хранит базу записей этажа, RB — адрес очистки открытой
клетки. Падение сравнивает адрес текущей клетки с RB. Смена этажа загружает
готовые константы R5, RE и RF вместо повторных вычислений.

| Регистры | Назначение |
| --- | --- |
| R0…R3 | Сборка кадра; между кадрами R0 — адрес действия + 1, R3 — фаза |
| R4 / R5 | Колонка 1…12 / этаж 1…3 |
| R6…R9 | Удерживаемые 4, 6, 8, 2; записывает M61 |
| RA / RC | Последний одноразовый запрос / резерв |
| RB / RD | Адрес очистки открытой клетки / оставшиеся кадры |
| RE / RF | База записей текущего этажа / база его атласа масок |

`down` записывает удержание и запрос; `up` снимает только удержание.
Корневой блок M61 выбирает удерживаемое направление, затем заменяет его
одноразовым запросом RA, если тот есть, и очищает RA. Обработчики кнопок
не прерывают этот блок. Поэтому и повторное нажатие той же кнопки, и короткое
down/up во время ожидания сохраняют один шаг. Несколько новых нажатий
за кадр объединяются в последнее. Косвенный вызов через R0 использует
предекремент, поэтому запрос хранит адрес обработчика + 1.

R3=3 отмечает расчёт, R3=1 — уже опубликованный кадр. Экран хранится
отдельно от рабочих регистров: выбор следующего действия не меняет картинку.
Образ занимает 2053 значащих байта калькуляторной памяти; упакованный файл —
703 байта, сценарий — 936 байт. Атлас занимает 432 байта и пересекает банки.

## Воспроизводимая сборка и проверка

```sh
python3 tools/runner/build.py
python3 tools/runner/build.py --check
bash tests/run_runner_tests.sh
MK61_TEST_SANITIZERS=1 bash tests/run_runner_tests.sh
```

Сборщик записывает `runner.bin`, `autoexec.m61` и `runner.map.json`.
Тест запускает их через production-парсер M61 и настоящее ПЗУ: проверяет
все 36 кадров, удержание/отпускание и короткие нажатия, границы, обе пары
лестниц, прожиг в каждом допустимом столбце, падение, восстановление,
памятку, перезапуск и очистку при выходе. Варианты: native/packed и scalar/LCD1602 A00.
Подменены только файловая система, часы и аппаратные функции платы.
Проверены все 72 варианта прожига и бюджет шагов для покоя, движения и таймера.

Для сравнения со старой папкой игры можно сохранить исполняемый стенд:

```sh
MK61_RUNNER_BUILD_DIR=/tmp/runner-build bash tests/run_runner_tests.sh
python3 tools/runner/compare.py --runner /tmp/runner-build/runner-native \
  --baseline /tmp/runner-baseline --output /tmp/runner-comparison.json
```

Сравнение включает короткие нажатия, удержание, противоположные направления,
памятку и перезапуск; проверяет кадры, координаты, удержание и таймер.

Проверка и одинаковый скоростной маршрут на Classic:

```sh
python3 tests/hil_runner_classic.py --port /dev/cu.usbmodemPORT \
  --public-id PUBLIC_ID --build-id BUILD_ID --output /tmp/runner-classic \
  --confirm-game-reset
```

Стенд запускается из калькулятора и по умолчанию возвращает игру к началу.
`--benchmark-only --leave-calculator` оставляет только скоростной маршрут
и возвращает калькулятор для замены файлов. Он не пишет прошивку или файлы.

Проверка на PicoCalc с уже установленными файлами и всеми перечисленными
расширениями прошивки:

```sh
python3 tests/hil_runner_picocalc.py --port /dev/cu.usbmodemPORT \
  --uid DEVICE_UID --build-id BUILD_ID --directory /games/Runner \
  --output /tmp/runner-hil --confirm-game-reset
```

Этот тест отправляет обычные виртуальные нажатия, не подставляет состояние
игры и сохраняет реальные USB-кадры. Перед его запуском нужно сохранить
состояние калькулятора и освободить serial-порт в настольном клиенте.
