# RACE для MK61s

Калькуляторная гонка от первого лица на существующих расширенных командах.
Готовая папка: `programs/games/RACE`; скопируйте её целиком в `/games`
на USB-диске MK61s и откройте в Проводнике. Установите скорость MAXIMUM,
выберите ГРД и нажмите С/П.

Р ведёт влево, Г — вправо, ГРД — прямо. Руль читается на каждом игровом
кадре; выбранный поворот продолжается до переключения в ГРД.
Нижняя метка указывает свободную полосу: когда она под носом машины,
верните ГРД. Ближний проход отмечен уголками по краям. Столбики растут
и расходятся через левые и правые вертикальные сегменты индикатора.
Соперник приближается от точки до машины в два знакоместа.

Три жизни, двадцать участков по шесть кадров: пять фаз приближения
и один кадр счёта. Есть пять положений машины, от −2 до +2.
Руль смещает машину на одно положение за кадр; на повороте дорога
смещается каждые два кадра. Стенка начинается при модуле координаты 3;
после несмертельного удара машина возвращается к координате ±1.
Контакт с соперником в той же полосе проверяется на шестом кадре.
Повторный урон отключается на три кадра. Одновременный контакт со
стенкой и соперником отнимает одну жизнь. Смертельный удар на последнем
участке приводит к `CrASH`, а не к финишу.

Удар и граница участка показывают счёт `L3 n00 20`: жизни и число
уже пройденных участков. После `FInISH` или `CrASH` исполнение
останавливается; ГРД, С/П начинают новую игру.
Обычный С/П приостанавливает исполнение, следующий С/П продолжает его.
Памятка доступна через OK, возврат — ESC.

## Ускорение

При езде по экранной метке новый вариант требует в среднем 59,5 шага
ядра на кадр вместо 209,5: расчёт ускорен примерно в 3,5 раза. Диапазон
на полном заезде — 52…79 шагов; отдельные столкновения могут стоить больше.
Движение стало крупнее: участок занимает шесть кадров вместо 36,
полный заезд — 120 вместо 720. Это отдельное сокращение длины заезда,
а не дополнительное ускорение исполнения одного кадра.

На mini V3 / LCD1602 A00, 96 МГц, MAXIMUM, прошивка `0579C96C` полный
заезд по метке прошёл за 136,2 с с тремя оставшимися жизнями.
Аппаратная проверка использовала временный M61-запускатель с чтением
регистров и окнами управления по 50 мс; время включает эти операции.
Медианный интервал между различными наблюдаемыми игровыми состояниями —
1,069 с. Это темп инструментированного теста, не измерение частоты
физического LCD. Исходный вариант давал около 4,51 с между видимыми
изменениями при езде вдоль стенки; для его полного заезда оценка
составляла примерно 45 минут.

## Сборка

Основная экономия — готовые кадры со стенками, соперником и меткой.
Python собирает 75 рисунков для трёх полос соперника, пяти положений
машины и пяти фаз приближения. Во время игры байт-код выбирает рисунок
из таблицы вместо вычисления и наложения отдельных знакомест.
Страницы рисунков читаются через штатный обмен Ms; данные страницы
и R0…R8 восстанавливаются после чтения. Руль различается через
`arccos(0)` — 1,5707963 / 100 / 90 — и обычный косвенный переход.

Кадр собирается в R0…R3 и публикуется через `2F 53`.
`2F 7n` использует палитру страницы из 16 масок, `2F 6n` — счёт.
Все правила выполняются байт-кодом на настоящем ядре МК-61;
Python нужен для сборки и проверок. Новых опкодов и изменений прошивки
для ускорения не требуется. Используются ассемблер из
`tools/elite/assembler.py` и штатный упаковщик CRC32/ZX0.

R0…R3 — кадр; R4 — положение; R5 — фаза; R6 — пройденные участки;
R7 — жизни; R8 — защита; R9 — изгиб; RA — полоса соперника;
RB — база группы рисунков; RC…RF — выбор рисунка, палитра и временные
значения. Адреса и размещение находятся в `race.map.json`.
Текущая сборка: 3037 занятых байт, 547 свободных; `race.bin` — 1510 байт.

```sh
python3 tools/race/build.py
bash tests/run_race_tests.sh
```

Проверка на ПК использует настоящее ПЗУ, бинарный загрузчик и M61
в двух профилях: native/packed и scalar/LCD1602 A00. Она проверяет
все 75 рисунков, повторное чтение палитр, Р/ГРД/Г, столкновения,
защиту, смертельный удар перед финишем и полный заезд по видимой метке.
Среднее число шагов на полном заезде ограничено 60.

## Проверка на Mini

Восемь аппаратных граничных проверок совпали с ПЗУ по R0…RE:
нейтраль, влево, вправо, стенка, соперник, защита, финиш и смертельный
удар перед финишем. Для них тест временно ставит остановки на границах
кадров в RAM. Отдельный тест проходит все 20 участков: наблюдатель
читает кадр, выбирает Р/ГРД/Г по метке и передаёт настоящие USB-нажатия.
Он не подставляет координаты и не рассчитывает физику на компьютере.
M61-ловушки задаются локальными адресами, поэтому возможны повторные
наблюдения в других банках; они исключаются из интервалов состояний.
USB-нажатия проверяют обработчик ввода, но обходят физические GPIO.

Результаты ускоренной версии: `doc/measurements/race-mini-speed-20261014.json`.
Исторические замеры исходной версии: `doc/measurements/race-mini-20261014.json`.
После аппаратных тестов штатная заставка восстанавливается, временный
запускатель удаляется.

Повторить проверки после `tests/run_race_tests.sh`:

```sh
python3 tests/hil_race_game.py --port /dev/cu.usbmodemPORT \
  --public-id PUBLIC_ID --build-id BUILD_ID \
  --runner "${TMPDIR:-/tmp}/mk61_race_core_runner-mini" \
  --output-dir /tmp/race-hil --confirm-game-reset
python3 tests/hil_race_play.py --port /dev/cu.usbmodemPORT \
  --public-id PUBLIC_ID --build-id BUILD_ID \
  --output-dir /tmp/race-play-hil --confirm-game-reset
```

На LCD1602 правая стенка с маской `06` отображается как CGROM-цифра `1`,
а виртуальный экран mini этой сборки сохраняет мелкий символьный вид.
Возможен `SEG!`, если кадр требует более восьми пользовательских глифов;
на UC1609/графическом WS0010 этого ограничения нет.
