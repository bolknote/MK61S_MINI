# ELITE для MK61s

Рабочая первая версия космической торговой игры, целиком на командах
калькулятора. Загрузчик M61 только размещает код и данные в памяти.

Готовая игра: [`programs/games/ELITE`](../../programs/games/ELITE).
Скопируйте эту папку целиком в `/games` на USB-диске MK61s и откройте её
в Проводнике. Нужна прошивка с дальними командами `1F`, сегментным выводом
`2F` во все 12 позиций, пакетным кадром `2F 53` и форматированием `2F 6n/7n`,
обменами `55/56` и сохранением банков при вложенном
`open`. Игра занимает все 32 слота банков; загрузка упакована в шесть частей
по лимиту 1536 байт на M61-файл.
Вход в папку сначала открывает короткую памятку. Закройте её;
на заставке `三 ELItE 三 СП` нажмите С/П.

Правила: [основные команды](../../programs/games/ELITE/manual.md),
[бой](../../programs/games/ELITE/fight.md),
[миры](../../programs/games/ELITE/worlds.md).

## Первая партия

Каждый код подтверждается С/П. `1` — кредиты; `10` — цена еды;
`30` — купить еду; `20` — количество еды в трюме. `71` выбирает соседний
мир, `9` показывает расстояние, `60` начинает перелёт. Во время встречи
`21` означает «держать курс и стрелять лазером», `22` — ракету,
`34` — отходить и заряжать гиперпрыжок. Четыре заряда подряд дают побег.

Экран удерживается во время вычислений и набора команды. Готовый кадр
публикуется целиком одной командой; одинаковый кадр не перерисовывается.
Просмотр приборов и выбор цели не расходуют ход.
`ErrOr` означает невозможную команду; игровое состояние при отказе сохраняется.
Повторный вход в папку начинает новую партию.
Автоматического сохранения партии в этой версии нет.

## Сборка и проверка

```sh
python3 tools/elite/build.py
bash tests/run_elite_tests.sh
```

Python 3 и C++17-компилятор нужны только на компьютере разработчика.
На калькулятор копируются M61-файлы и короткие памятки, исходники Python
ему не нужны. Генерация детерминирована; `build.py --check` проверяет,
что загрузочные файлы соответствуют исходникам.

Тестовый драйвер исполняет `autoexec.m61` через настоящий `m61_text.cpp`,
включая вложенные файлы и очистку памяти, затем нажимает
клавиши и исполняет команды через настоящее ПЗУ. Он проверяет все 256 имён,
торговлю и ограничения, станцию, маршруты, пирата и носитель с пятью дронами,
одновременный урон, исходы, отсутствие повторной награды и неизменность
индикатора при вводе, отсутствие промежуточных кадров и предел числа шагов
для основных экранов. Отдельные крайние случаи используют начальные данные
в банках; сами игровые команды не подменяются обработчиками на компьютере.

На Classic V3 / UC1609, 96 МГц, MAXIMUM, прошивка `6A808B5B`
аппаратный замер через USB Screen 22.09.2026 дал:

| Действие | До готового кадра | Шаги ядра |
| --- | ---: | ---: |
| Начать партию | 5,85 с | 182 |
| Деньги | 3,62 с | 111 |
| Купить еду | 12,24 с | 385 |
| Груз | 4,54 с | 140 |
| Выбрать мир | 4,29 с | 132 |
| Расстояние | 4,33 с | 133 |
| Перелёт | 9,67 с | 303 |

Во всех семи действиях записана ровно одна смена индикатора. Предыдущая
версия тратила на деньги 38 с и показывала промежуточный кадр. Отрисовка
исправлена, но торговля и перелёты ещё ограничены скоростью логики на ПЗУ;
мгновенной реакции эта версия не даёт.
Повторяемая проверка: `tests/hil_elite_performance.py --help`. Она сверяет
файлы на устройстве, записывает PNG и время кадров, сбрасывает партию,
проверяет торговлю и перелёт, затем возвращает заставку.

## Исходники

| Файл | Назначение |
| --- | --- |
| `assembler.py` | Упаковка чисел, метки, размещение, ближние/дальние переходы |
| `game.py` | Запуск, диспетчер, режимы, выбор страниц приборов |
| `ui.py` | Алфавит, сообщения, формирование и публикация кадра |
| `economy.py` | Миры, цены, торговля, станция, навигация и встречи |
| `combat.py` | Манёвры, оружие, враги, дроны и исходы |
| `build.py` | Генерация банков, загрузчика и карты адресов |
| `elite.map.json` | Фактические адреса меток, занятые байты и части модулей |

[Схема банков и соглашения о регистрах](../../doc/design/Segment-Elite.md).

После арифметики перед дальним условием сборщик при необходимости вставляет
`54` (NOP): текущее ядро может читать знак X на этапе предварительной выборки
раньше, чем ПЗУ завершит его запись. NOP сохраняет стек и даёт результату
зафиксироваться. Регрессия — отказ от покупки при нулевом балансе.

Для подробного следа: `ELITE_TRACE=1` у исполняемого тестового драйвера
печатает адрес, код и X на границах команд в stderr. Этот наблюдатель
не меняет инструкции или регистры.
