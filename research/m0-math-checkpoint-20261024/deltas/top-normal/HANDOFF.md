# dadd/dsub: быстрый путь для максимального конечного порядка

Прямая работа по исходной цели — быстрее Qfplib или с той же скоростью,
с правильным округлением и сохранением M4. Отдельный private WIP поверх
принятого mixed-sign кандидата; прежние review targets не менялись.

Раньше exponent2046 отправлял нормальные конечные аргументы в C++ fallback.
Теперь отдельный guard принимает этот порядок. Разные знаки используют
прежнюю точную ветвь; одинаковые — отдельную ветвь с ранним выходом в Inf
при переполнении и проверкой переноса после RNE. Обычное сложение сохраняет
старый код и число инструкций. В fallback сокращён push/pop при той же
24-байтной глубине кадра; запись R3 использует прежнее alignment word.

|---|---:|---:|---:|---:|
| Разные знаки, среднее инструкций | 1001 | 307.05 | 62.66 | 85.51 |
| Одинаковые знаки, среднее инструкций | 1070 | 248.92 | 55.14 | 76.55 |

На всех этих2071 входах результат Qfplib тоже правилен и новый кандидат
не медленнее его. Это утверждение о проверенном наборе, не обо всех binary64.
На8692 обычных same-sign входах число инструкций совпало с предыдущим
кандидатом. Все17 ранее исправленных mixed-sign входов сохраняют свои
результаты и стоимость.

Итого11 018 целевых случаев /33 054 ARM-вызова с exact integer RNE,
направленным MPFR4.2.2 и прямым Qfplib:0 ошибок у нового и предыдущего
кандидатов. По инструкциям против родителя2221 быстрее /8797 равны /
0 медленнее. На этом наборе2051 прежнее отставание от правильного Qfplib
устранено; новых проигрышей правильному Qfplib нет. Неверные114 raw
результатов Qfplib сохранены. IEEE/cold/subnormal проигрыши вне нового
нормального пути также сохранены, не исключены из отчёта.

Целевые проверки включают нормальные ветви обоих знаков, границы overflow
midpoint и соседние значения, guards, quiet/signaling NaN и старые17.
На каждом вызове проверяются R4–R11, восстановление SP, ограниченные записи
стека и сохранение READY/DIRTY SIO. Исполнялись настоящие ELF и captured ROM,
без абстрактных моделей служебных ROM-функций. Это инструкции, не такты.

Контрольные assembly objects: блок648→880 байт (**+232 байта кода**),
таблиц/global RAM не добавлено. Все остальные allocated sections и весь
последующий multiply/divide код побайтно прежние; undefined dependencies
совпадают. M4 soft/hard и generic M0 controls совпали. Это object isolation,
а не новый полный M4 build или оценка итогового Flash production-прошивки.

`body-equivalence.json` связывает все880 байт публичного объекта с реально
исполненным diagnostic ELF, кроме одной BL relocation на неизменный
`mk61_m0_dadd_slow`0x100e6e44. API entry offsets также совпали. После
квалификации исправлено только выравнивание конца source-блока; diagnostic
ELF остался бит-в-бит тем же. Это явно связывает прежний source hash из
qualification с финальным исходником, без повторного численного прогона.
Первый failed object audit и причина сохранены в align-error заметке.

Результат для review: `top-normal-only.patch` и полная private копия
`native_eabi_m0_rp2040.S`. Сведения о границах доказательства — `PROOF.md`.
Данные: `qualification.json`, `object-isolation.json`, `body-equivalence.json`,
`undefined-symbols.json`; хэши перечисляет `result.json`.
