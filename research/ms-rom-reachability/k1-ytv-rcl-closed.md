# Замкнутый выход из Y/T/V через П→X 0 и резерв нижнего числа

29 сентября 2026 года. Из нового клавиатурного входа Y/T/V построен
**выход с возвращением всех 23 исходных чисел в хранимую память**.
Лишние метки удалены; ручной счёт `2 В↑ 3 +` и заранее записанная
программа дают 5. Два разных набора прошли нативные проверки и полностью
совпали с независимыми повторами без наблюдателя. Ядро и ПЗУ не изменены.

Это **альтернатива перед LastX**, а не исправление его уже выполненного
результата: в [предыдущем пути](k1-z-backed-lastx.md) заменяем LastX на
П→X 0 при той же подготовке Y/T/V. Получена законченная нижняя
перестановка, **не новая ёмкость и не полная К1**. Верхние четыре Ms
не меняются, последние P9/P10 по-прежнему не участвуют. Стыковка с
[верхней трёхэтапной композицией](k1-adapted-third-entry.md) не проверена.
Новых опытов на физическом калькуляторе нет.

## Почему теперь получается выйти

Проблемой было не само снятие метки, а потеря последней копии v при
следующем служебном запросе. Сначала делаем две одинаковые копии u
в X/Y, затем вычитаем их. Результат — точный ноль, а штатный сдвиг
стека копирует прежнее T сразу в Z и T. В T как раз находилось v.
Следующее вращение может изменить одну копию своим запросом:
вторая остаётся целой. Округление и арифметическое «поглощение» здесь
не используются.

Обозначения: p — исходное обычное П0; u/v/w/q — исходные Ms U/V/W/Q;
a/b/c/d — исходные Ms P7/P8/P9/P10; m=`9990FFFFFFF0`.
Во всей таблице П0=w, верхние a/b/c/d остаются на месте.

| Граница | X / Y / Z / T | Ms U / V / W / Q | Лишние метки |
|---|---|---|---|
| Готовый вход Y/T/V | u / m / v / m | u / m / q / p | Y, T, V |
| П→X 0 вместо LastX | w / u / m / v | u / w / q / p | Z |
| F , | u / m / v / w | w / w / q / p | Y |
| К0 | u / m / v / w | u / w / q / p | Y |
| В↑ | u / u / m / v | u / u / q / p | Z |
| − | 0 / m / v / v | u / u / q / p | Y |
| F , | 0 / h(v) / v / u | u / u / q / p | нет |

h(v)=`250` + последние девять тетрад v. Это испорченная служебным
запросом копия, а не сохранённое число. После последнего F , полное v
находится только в Z; поэтому одним удалением меток опыт не заканчивается.

Два обычных вращения переводят v в X. Прежний читатель W достаёт q,
сохраняя входной X; q записывается в П0. Два нижних переноса с нужными
видимыми вращениями возвращают v и остальные числа в банк:

```text
конец: П0=q; U=v, V=w, W=u, Q=p; P7/P8/P9/P10=a/b/c/d
карта исходников: П0 ↔ Q; U → W → V → U
```

Остальные 14 обычных регистров и четыре верхних слова фиксированы.
Ни один исходник не остаётся только в видимом стеке. Это та же итоговая
нижняя карта, что у прежнего Z-выхода; новизна — совместимый выход
из дополнительно подготовленной конфигурации Y/T/V.

## Какие участки ПЗУ это обеспечивают

[Нативный аудит](k1-ytv-rcl-closed-check.cjs) проверяет следующие события
в обеих фикстурах. Номера относятся к полному запуску драйвера.

| Операция | Существенные события |
|---|---|
| П→X 0 | 972740 EE(W=q); 972753 D6 читает обычное П0=w; 972764…972767 подъём X/Y/Z/T; 972779 поздний EE(X=w); 972829 E7(V=w) |
| Первое F , | 979473 E9(U=w); 979482 запрос 25h в control; 979515…979518 вращение X/Y/Z/T; 979548 поздняя E7(U=w) |
| К0 | два чтения X=u, затем единственная изменяющая запись 986268 E7(U=u) |
| В↑ | 992358 EE(U=u); 992369…992372 подъём; 992399 EE(X=u); 992449 E7(V=u) |
| Вычитание | 998517 запрос 11h в control; 998565…998568 вывод 0/m/v/v; 998583 поздняя E7(U=u) |
| Последнее F , | 1005253 E9(X1=0); 1005256 запрос 25h в Z; 1005284 позднее чтение старого X=0; 1005285…1005288 вторичный вывод; 1005344 E7(X=0) |

Поздний читатель последнего F , срабатывает **за одну команду до**
вторичного вывода. Поэтому поздняя E7 возвращает в X именно ноль,
а не появившееся там u. Сохранность нельзя вывести только из обычной
семантики клавиш: важны первичные записи, вторичный вывод и их порядок.

Для шести новых операций проверены полные выходы всех 630 тетрад кольца,
точные копии, запросы, подтверждения, пути форматировщика и отсутствие
посторонних изменяющих записей. Оба заключительных нижних подъёма
проверены как точные 48-тетрадные записи с безопасно вытесняемыми копиями.
Прежний префикс проверяется заново на срезе этой же пассивной трассы,
без импорта состояния в калькулятор.

Два [символьных](k1-ytv-rcl-path-check.py)
[разбора](k1-ytv-rcl-drop-check.py) доказывают локальные пути по ПЗУ:

- П→X 0 при приёме на настоящем control и метках Y/T/V; дополнительные
  точки приёма П→X 0 этим доказательством не покрыты;
- В↑ при одной Y с приёмом на control или Z;
- К0 при одной Y с указанными флагами приёма;
- точное вычитание равных канонических отрицательных чисел с
  отрицательным порядком и классом 0: X=0, Y=старое Z, Z=T=старое T;
- связанные запросы, два вторичных вращения и нужные классы позднего
  форматирования, включая ноль.

Каждая предпосылка проверена на выполнимость, отрицание соответствующего
вывода — на невыполнимость. Это локальные условные доказательства,
не теорема о любой клавиатурной последовательности или любом числе.

## Полные запуски и отрицательные контроли

| Исходник | Базовый набор | Другой набор |
|---|---|---|
| p | 201 | 301 |
| u | −1.2345678E−31 | −2.3456789E−30 |
| v | −9.8765432E−17 | −9.1234567E−17 |
| w | −7.654321E−23 | −6.543219E−23 |
| q | −1.2345678E−42 | −8.7654321E−42 |
| a | −1E−99 | −3.1415926E42 |
| b/c/d | 9022 / 9033 / 9044 | −7.654321E23 / 1.2345678E42 / 8.7654321E−17 |

Во втором наборе a намеренно длинное, с положительным порядком:
новый суффикс, в отличие от прежнего LastX, **вообще не читает P7**
и не использует короткое a для направления поздней копии.
Это не снимает числовые условия с остальной цепочки.

Оба набора прошли:

- 228 кадровых и 213 нативных границ: все 23 различных исходника живы
  в банке и видимых словах на каждой проверяемой границе;
- точную конечную перестановку всех 23 хранимых слов, удаление лишних
  меток, сохранение программы и защищённых полей;
- ручной счёт с результатом 5, Сx с результатом 0, запуск сохранённой
  программы с результатом 5; исходные хранимые числа после этого целы;
- полный независимый повтор без наблюдателя, совпавший по каждому
  сериализованному полю эмулятора.

Сохранность на границах действий не означает существования 23
канонических копий на каждом отдельном микротакте. Во время контрольного
исполнения программы допускаются её обычные временные служебные записи;
конечная программа и банк сверяются отдельно.

SHA256 конечных состояний после независимых повторов:

```text
base:  492b24a9e3e81f010116cb5c054ff6f2e75eed650923b2564777d8fe29738edd
other: 47020efde41f166460dd06e3eeedf86565c09cce6fe9401042fcbad1fd87d360
```

[Отрицательные контроли](k1-ytv-rcl-negative-check.cjs) на базовом наборе:
если заменить вычитание ожиданием той же длительности, теряется v;
если так же убрать восстанавливающий К0, теряется u. Отдельно прежний
LastX с продолжением Сx, 1 теряет v при вводе цифры — ввод константы
не является готовой заменой найденного резерва. Эти контроли кадровые,
без отдельного полного аудита всех отрицательных трасс; они не доказывают
невозможность иных продолжений.

## Воспроизведение и границы результата

[Драйвер](k1-ytv-rcl-closed.cjs) управляет только клавишами, ожиданиями
и индикатором. Публичный контракт проверен без доступа к значениям
фикстуры. При первой успешной попытке каждого из пяти чтений индикатора
протокол с контрольным выходом занимает 264 клавиши / 2120 кадров,
не считая исходного заполнения калькулятора.

Это не человеческая инструкция с произвольными паузами. До действий
хвоста `К0; П→X 0; F ,; К0; В↑; −; F ,` добавляются соответственно
`1, 1, 0, 0, 1, 1, 0` кадров; перед возвратным читателем — ещё один.
Остальные штатные ожидания заданы драйвером. Указанные фазы точные,
не минимальные задержки.

```bash
python3 tmp/ms-rom-reachability/k1-ytv-rcl-path-check.py
python3 tmp/ms-rom-reachability/k1-ytv-rcl-drop-check.py
K1_YTV_CLOSED_UNOBSERVED=1 node tmp/ms-rom-reachability/k1-ytv-rcl-closed-check.cjs
K1_YTV_CLOSED_UNOBSERVED=1 K1_YTV_CLOSED_OPTIONS='{"incoming":"301","values":["-8.7654321E-42","-6.543219E-23","-9.1234567E-17","-2.3456789E-30"],"fullUpper":["-3.1415926E42","-7.654321E23","1.2345678E42","8.7654321E-17"]}' node tmp/ms-rom-reachability/k1-ytv-rcl-closed-check.cjs
node tmp/ms-rom-reachability/k1-ytv-rcl-negative-check.cjs
```

До полной К1 нужны полезный перенос через более глубокое верхнее окно
с совместимым выходом, доступ к последним двум Ms, сборка восьми пар
и общий числовой/временной договор. Этот выход — проверенный строительный
блок для такой композиции, но сам по себе не меняет верхний банк.
Прямой выход из результата прежнего LastX, неограниченное повторение
и произвольный числовой диапазон здесь не доказаны.

Продолжение: [сохраняющий вход Z/W и чтение верхнего P8](k1-zw-entry.md)
действительно перемещают скрытую метку глубже и исходное П0 в P7.
Но это другая раскладка: настоящий закрытый выход из данного отчёта
ещё не состыкован с ней, а v остаётся только в T.

Контрольные SHA256 неизменённых источников:

```text
rom.cjs  6c3f85b3e942cdd4d4191e46e98a50829eb850011b8b7a3cc01b12e5e2a31a33
```
