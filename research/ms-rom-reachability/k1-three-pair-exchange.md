# Замкнутый обмен трёх пар без расходования рабочих регистров

12 сентября 2026 года. Неизменённый эталон МК-61, 15 страниц.
Нативные клавиши в схемотехнической модели; новых опытов на приборе нет.

**Продолжение 19 сентября:** новый читатель устранил конкретную потерю
длинных чисел; тройной обмен прошёл на широком наборе с крайними порядками.
Остаётся отдельный фазовый отказ сканера, полного К1 ещё нет.
[Новый результат и точные границы](k1-zero-nop-wide-exchange.md).

## Результат

Получен условный обмен:

| Обычный регистр | Слово Ms |
|---|---|
| П0 | U |
| П1 | V |
| П2 | W |

П3 используется временно и **возвращается к исходному значению**.
Остальные 11 обычных регистров, Q и четыре верхних слова Ms не меняются
даже временно. Программная память и служебные поля сохранены в течение
самого обмена. Все 23 исходных хранимых слова различны в тестовой фикстуре;
проверяется конкретное соответствие исходников назначениям, а не только
совпадение сумм или одного числа на индикаторе.

Базовый набор: П0/П1/П2 = 201/102/103, П3 = 777,
U/V/W/Q = 844/833/822/811, верхняя Ms = 9011/9022/9033/9044.
Все прочие обычные регистры также заполнены независимыми числами.

**Два непрерывных обмена** восстановили все 23 слова. Между ними нет
чтений памяти, выравнивания, подстановок состояния или сброса. После этого
проверены ручное `2 ↑ 3 + → 5`, отдельный `Сx → 0` и запуск сохранённой
программы `2 ↑ 3 + С/П → 5`. Все 105 программных байтов остались исходными.
Полная сериализация всех полей калькулятора совпала с отдельным запуском
без наблюдателя:

```
9fcf08f3dc7f8b1c3c2f38271d0b8dd1ef231d9a711117b0a545e00b4c244a1a
```

175 клавиш / 1825 кадров на один обмен, без отдельной фикстуры.
Непрерывный повтор использует явно заданные 2 кадра между вызовами.
Эти кадры — время модели, **не рекомендация для человеческих пауз**.

Отдельный наблюдаемый обмен в начальной фазе 1 прошёл для
П0/П1/П2 = −301/602/−703 и U/V/W = −844/733/−622.
Проверены все промежуточные перестановки, сохранность защищённых
тетрад и нормальный выход; SHA-256 полного конечного состояния:
`0ad03f7413d9a8b27ec627a6a831054db54ea15d7d3a2debad00e36dbd1886b4`.

Это три пары, а не три дополнительные сверх физической памяти ячейки,
не шесть скрытых чисел и **ещё не полный К1**. Остальные пять слов Ms
данным протоколом не обмениваются.

## Новый элемент: четырёхместный цикл

В предыдущем читателе Q логическая пустышка `9990FFFFFFF0` заменяла
также T. При сдвиге T/U/V/W её копия попадала в U и требовала удаления.
Другой, уже известный способ получения пустышки `0000F0000000`
**сохраняет Y/Z/T**. Поэтому теперь в U попадает полезное прежнее П0.

Пусть p — П0, u/v/w — исходные U/V/W, r — исходное П9.

| Этап | X / Y / Z / T | U / V / W | П0 |
|---|---|---|---|
| Подготовлены копии | w / w / p / p | u / v / w | p |
| Пустышка с сохранением хвоста | m / w / p / p | u / v / w | p |
| Нативный сдвиг | m / w / p / r | p / u / v | p |
| Сx, +, запись П0 | w / p / r / r | p / u / v | w |

Здесь m=`0000F0000000`; Q и верхние слова не участвуют.
Итог: **П0 → U → V → W → П0**. П9 только читается, не расходуется.
В конце остаётся единственная штатная метка.

Фактический перенос базового случая начинается на команде 207272:

```
D6(M1 control = обычное П9)
  → A7(X1) → E5(X=m) → E6(Y) → E8(Z)
  → E7(T) → A8(U) → A8(V) → A8(W) → A9(Q) → AC(P7)
```

Точная проверка сравнивает все 630 тетрад вокруг четырёх записей,
48 адресов записи, переносимые и вытесненные слова. Отдельное связанное
символьное доказательство охватывает произвольные 12 тетрад источника
П9 и прежних T/U/V/W, произвольные остальные данные и сигналы клавиатуры
внутри этого десятикомандного суффикса. Оно не доказывает весь вход.

Цикл — 37 клавиш / 412 кадров. На базовом наборе точные тесты прошли
начальные фазы 0, 1 и 2. Для фазы 0 полное состояние совпало без
наблюдателя:

```
5340f29e8d0354a070d9a2f3e9cac3ca5a11ad6b286cd28872341f46b4f84496
```

Четыре непрерывных цикла с двухкадровыми промежутками восстановили
все исходники. Проверен каждый промежуточный четырёхместный цикл,
удаление меток после каждого, сохранность защищённых тетрад по потоку
записей, нормальный счёт и независимый запуск программы.
Отдельно четыре цикла прошли на П0=−201, U/V/W=−844/733/−622
с проверкой конечных данных без наблюдателя.

## Как из цикла получены три обмена

В качестве центрального регистра используется П3 вместо П0.
Обозначим C — цикл П3→U→V→W→П3, S(a,b) — обычный обмен двух регистров.
Последовательность выполняется слева направо:

```
C, S(П3,П2), C, S(П3,П1), C, S(П3,П0), C
```

Она даёт П0↔U, П1↔V, П2↔W и возвращает П3.
Алгебра проверена на 23 различных символах отдельно от эмулятора.
Нативный тест проверяет также каждую границу C и каждого обычного S;
это не только рассуждение о композиции уже известных операций.

Между очередным S и C вставлен один кадр: цикл занимает 412 кадров,
обычный обмен 58, вместе с паузой получается 471 — кратно трём.
Никакая внутренняя фаза во время работы не читается.

## Существенные числовые ограничения

Нельзя переносить ширину локального 12-тетрадного сдвига на весь рецепт.
Начальное чтение W всё ещё использует историческую цепочку пустышки.

- Один цикл с исходным П0=12345678 прошёл точную проверку конечных
  данных без наблюдателя; все 12 тетрад попали в U.
- Но при **исходном W=12345678** первая же стрелка читателя записывает
  это число вместо U, вторая — вместо V. Исходные u/v потеряны из
  банков и видимого стека **до начала нового сдвига**.
- Точные отрицательные записи: E7(U), команда 78528, и E7(V), 86374.
  Вокруг каждой сравниваются все 630 тетрад и 12 адресов записи.
- Композиция также не универсальна для широких входных регистров:
  набор П0/П1/П2 = −1.2345678E−42 / 12345678 / 9.8765432E73
  не выполняет обмен; в итоговом банке отсутствуют исходные П1, П3 и U.
  Первый проверяемый расходящийся рубеж — после третьего C, перед
  обменом П3/П0: прежние П3 и W уже заменены входным П2.
  Отрицательный тест проходит как ожидаемый отказ, а не отключается.

Таким образом, общий диапазон чисел для всего протокола не доказан.
Рабочие короткие наборы и отдельная успешная широкая запись не дают
права обещать обратимый обмен любых полных чисел. Произвольные паузы,
нули, все сочетания мантисс и исполнение самого рецепта из пользовательской
программы также пока не покрыты.

## Что означает проверка программы

Во время самого обмена программные тетрады не меняются даже временно.
При последующем штатном запуске контрольной программы наблюдаются
временные записи M3 через C9, затем исходная страница восстанавливается.
Для исполнения программы проверяется конечная сохранность 105 байтов,
а для числовой и служебной памяти — также временная сохранность.
Первоначальный запрет вообще любых M3-записей даже при запуске программы
был чрезмерным; он не должен маскироваться как дефект нового обмена.

## Отношение к приёму Пухова и дальнейшая работа

Число коротких скрытых значений само по себе не заявляется новым.
Отличие проверенного результата — **замкнутый двусторонний обмен**,
сохранность исходных рабочих регистров, Q и верхней Ms, повторяемость
в модели и проверяемый нормальный выход. Старый трёхместный FIFO расходует
независимое Q и прежнее П9; этот рецепт их удерживает.

Сообщение о шести коротких числах остаётся без конкретного источника
и последовательности. Оно не объявляется ни доказанным, ни опровергнутым;
превосходство нового рецепта по ёмкости или ширине всех чисел не заявляется.

Следующий содержательный шаг — заменить ограниченный начальный читатель
W, затем связать сохраняющую композицию с Q и четырьмя верхними словами.
Ветвь `k1-q-return-probe.cjs` остаётся исследовательским опытом, а не
готовой парой с Q: там метка U удалялась, но дальнейшая ротация портила
порядок единственной копии W. Возврат известного порядка −42 делением
на степени десяти не восстанавливает произвольный неизвестный порядок.
