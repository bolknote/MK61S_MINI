# Резерв p до upperwrite: точный условный путь LastX

26 сентября 2026. Локальный структурный результат исходного ПЗУ.
Это **не достигнутый клавиатурный резерв**: обычный сканер 9B вообще
не позволяет выбрать нужную позицию при текущих метках. Полезность
условного суффикса не означает достижимость его предпосылки.

## Исходная геометрия

После deep → сохраняющий НОП с коротким верхним a:

```
П0=w; X1=INV0; X/Y/Z/T=1/u/q/m;
U/V/W/Q=v/m/a/p; верхние P7/P8/P9/P10=a/b/c/d.
```

Метки находятся в real, T и V. Имеются два экземпляра a, в W и P7,
но p находится только в Q. Это последняя стадия перед RCL0, на которой
LastX может вытолкнуть из видимого T только ненужный m, а не q.

## Достаточный путь

Если пользовательский LastX принят **9C на физической Z**, он читает p
из Q, поднимает видимый стек и не меняет Ms:

```
9C(Z) → 9E(T) → 8C(U) → 91(V) → 92(W)
→ 93(Q) → 94(P7) → 95(P8) → 98(P9) → 9A(P10)
→ 93(real) → 94(control) → 95(X1) → 98(X) → 9A(Y)
→ 8D(Z) → 4F(T) → FF(U) → E5(V) → E6(W) → EE(Q)
→ F0(P7) → E0(P8) → A7(P9) → E5(P10/real)
→ E6(control) → E8(X1) → E7(X) → A8(Y/Z/T) → A9(U)
→ E1(V) → ... → E2(T) → E5(U/V) → E6(W) → ED(Q)
→ EE(P7), возврат E3.
```

Связанный символический тест проверяет весь путь до второго EE, все
его записи, их источники и адреса. Только 48 числовых тетрад X/Y/Z/T
записываются, итог p/1/u/q. Ни E9, ни A3, ни других кольцевых записей нет.
В частности, Ms W=a и Q=p остаются резервами, X1 не меняется.

После подъёма остаются real/V. Из уже проверенного локального договора
форматирования EE(P7) следует: при классе a 7/8 поздняя запись возвращает
a в P7, оставляя новый видимый p в X. Для a=−1E−99 это требуемый класс.
При классах 0…6 поздняя запись пришла бы в X и стёрла новый резерв p.

Условный итог:

```
П0=w; X1=INV0; X/Y/Z/T=p/1/u/q;
U/V/W/Q=v/m/a/p; верхние a/b/c/d; метки real/V.
```

Это снимает прежний барьер единственного p в Q: последующая E9(Q) уже
может быть безопасной, если сохранён p в стеке. Но сразу ставить RCL0
нельзя: его видимый подъём вытолкнул бы единственное q из T. Нужна
сохраняющая перестановка, а её ранний источник и поздняя запись пока
отдельный вопрос. Условный путь не объявляется готовой композицией.

## Полная карта раннего чтения LastX

Предпосылки: принятие 9C, R30=F, R33=0, S1=F и метки real/T/V.
Управление принимается при M34 ≥ (M31=F ? 1 : 7).

| Где принято 9C | Первый EE | Результат раннего читателя |
|---|---|---|
| real, control, X1, X, P9, P10 | V | Читает метку |
| Y, Z | Q | Читает нужное p |
| T, U, V, W, Q, P7, P8 | X1 | Читает INV0 |

Для текущих чисел Y=u=−12345678 не удовлетворяет условию приёма,
а Z=q=−1.2345678E−42 удовлетворяет. Условно подходящая цель — 9C(Z),
но одного числового условия недостаточно для её достижения.
Тест проверяет все 15 принятых позиций, а не только выбранную удачную.
Дополнительно проверены такие же карты ENTER и STORE: ни одна ранняя
EE у этих двух команд при такой геометрии не читает q из Z или p из Q.
Один STORE поэтому не даёт требуемый резерв до upperwrite.

## Почему подбор паузы не может получить нужный вход

Следующий более сильный факт проверен для любых остальных полей и
сигналов клавиш: 9B переходит в 9C **только при M22=F**, иначе остаётся
в 9B. Кольцо при этом не меняется. Следующая команда относится уже к
следующей физической странице. Поэтому при фиксированных real/T/V:

| Маркер, найденный 9B | Следующая 9C | Первый EE у LastX |
|---|---|---|
| real | control | V=m |
| T | U | X1=INV0 |
| V | W | X1=INV0 |

Ни Y, ни Z в список не попадают. Для 9C(Z) сканеру потребовался бы
**маркер в Y**, которого здесь нет. Новая задержка способна изменить
выбранную существующую метку, но не создать такой предшественник.
Это локальное исключение пути LastX(Q) из обычного 9B-сканера при
данной неизменной геометрии, не запрет другой подготовки меток или
иной точки входа в 9C.

Отказ 9C — не простой переход на следующую числовую страницу.
Проверены точные адреса:

```
9C: принято → 9E, отказ → 9D
9D: R32 + [R29=F] >= 10 → 96, иначе → 97
96 → A2
97: R2 < 8 → 99, иначе → 63
99: R26=0 → 9B, иначе → 74
```

Весь этот однокомандный набор удерживает кольцо. При ветви возврата к
поиску получается 9C→9D→97→99→9B: четыре команды до нового 9B, после
чего число шагов определяется положением следующей метки. Постоянного
сдвига между отказавшей и следующей принятой 9C отсюда не следует.

Вариант EE(V=m) также не даёт резерв p: он поднимает видимый стек до
m/1/u/q, оставляя **новую X-метку**. Тогда геометрия уже real/X/V;
поздний EE(P7) для текущего короткого a класса 7 попадает в T и стирает
единственное q. Все 25 канонических случаев локального форматирования
проверены отдельно: классы 0…6 пишут X, классы 7/8, включая ноль, — T.
Нельзя применять к этому варианту договор real/V: метка X перехватывает
сканер раньше V.

Связанный путь от принятой 9C(control) через EE(V), весь видимый подъём
и второй EE(P7)→E3 также проверен символически: это не предположение
о том, что следующая EE непременно читает P7.

Получается несовместимость двух числовых требований именно этой
композиции:

| Класс a | Предыдущий NOP | LastX(V=m), если W уже обычное число |
|---|---|---|
| 0 | Портит P8; W не очищена | Поздняя запись в X |
| 1…6 | Читает a в X; W остаётся меткой | Поздняя запись в X |
| 7/8 | Копирует a в W и снимает W-метку | Поздняя запись в T уничтожает q |

Таким образом, среди проверенных канонических классов нет такого a,
которое одновременно обеспечивает именно этот НОП-выход и безопасный
LastX(V). Это локальный составной запрет данной пары блоков, а не общая
невозможность K1, иной подготовки или операций с неклассическими словами.

## Один нативный отрицательный контроль этого исследования

Выполнен ровно один вариант: NOP → LastX без дополнительного кадра,
с обычным ожиданием восьми кадров после команды. Это свежий полный
клавиатурный префикс и пассивная полная трасса, без импорта состояния.

```
784578 9C(U), сразу принято; других 9C в этом действии нет
784603 EE(X1=INV0) → F0
784606 A7(Z)
784610 E7(W), 784611 A8(Q), 784612 A8(P7), 784613 A8(P8)
784634 позднее EE(X=1) → E3
784694 E7(X=1)
```

Это не видимый подъём: из-за T-метки он пишет W/Q/P7/P8. Итог там
INV0/a/p/a, исходное b больше не находится среди 23 хранимых слов и
X1/X/Y/Z/T. Старый b вытеснен из P8 во внутренний A, после чего A9
не сохраняет его как полный 12-тетрадный резерв. Точная общая
невозможность восстановления b из всех полей микросхем не утверждается.

В этом независимом исследовании других задержек не проверялось.
Root отдельно проверил lead=1 и также получил accepted9C(U),
EE(X1) и потерю b; его отчёт не заменяется этой заметкой.
Нельзя переносить
фазовую привязку ENTER или RCL0 на LastX: перед EE у LastX дополнительный
дисплейный путь 8C…8D и собственный выбор источника.
