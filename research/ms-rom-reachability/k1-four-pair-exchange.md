# К1: замкнут обмен четырёх нижних пар без расходования регистров

19 сентября 2026 года. Продолжение
[безопасного читателя и тройного обмена](k1-x1-retry-reader.md).
Цель — полный восьмисловный К1 либо доказательство его невозможности.
**Ни один из этих двух исходов ещё не достигнут.**

Следующее продолжение: [сохраняющий мостик к первому верхнему слову](k1-first-upper-bridge.md).
Перестановка через границу нижней/верхней Ms уже проверена, но её
возвратная укладка и нормальный выход ещё не замкнуты.

## Новый проверенный результат

Клавиатурная композиция на неизменённом эталонном МК-61 выполняет:

```
П0 ↔ U, П1 ↔ V, П2 ↔ W, П3 ↔ Q
```

Остальные 11 обычных регистров, верхние четыре числовых слова Ms,
служебные тетрады и программа удержаны. Проверено не только тождество
после двух вызовов: сравнивается точная перестановка после каждого
из шести блоков, включая первый полный обмен до обратного вызова.

Основной набор содержит 23 различных исходных слова:

- П0…П3: −1.2345678E−42 / 12345678 / 9.8765432E73 / −6.5432109E65;
- U/V/W/Q: −1.2E−42 / −12345678 / −9.8765432E99 / 1E−99;
- верхняя Ms: 9011 / 9022 / 9033 / 9044;
- остальные обычные регистры: 105…115.

Два непрерывных вызова в начальной фазе 0 прошли весь наблюдаемый
договор, затем ручной счёт 2+3=5, отдельное обнуление X и запуск
исходной программы с результатом 5. Все 105 программных байтов сохранены.
75406 наблюдавшихся записей; 110 изменившихся программных тетрад относятся
только к последующему штатному исполнению программы, не к обмену.
Отдельный запуск без наблюдателя совпал по **всем** сериализованным полям
через `deepEqual`; SHA-256:

```
c68d2ac170f59908ac12387c702065460a09c197ce9b23e19435375b916d8974
```

Тот же двойной тест прошёл фазы 1 и 2: соответственно 74898 и 76570
записей, те же 14 контрольных границ и конечный хэш. Независимые запуски
без наблюдателя обеих фаз также совпали по всем сериализованным полям.

## Как подключено четвёртое слово

Новый элемент G обменивает **только V и Q**, восстанавливая U/W и все
обычные регистры. В отличие от прежних верхних/нижних протоколов он
не требует пожертвовать исходным П9, A или другими рабочими регистрами.

Пусть C — новый цикл с числом t в видимом X:

```
X=t; U=u,V=v,W=w  →  X=w; U=t,V=u,W=v
```

Q, верхняя Ms, обычные регистры, программа и служебные поля сохраняются.
Начальные прочие видимые значения не входят в договор C.
Сначала C(0) освобождает U, а исходное W оставляет видимым. Поэтому
служебный ответ запроса может испортить U, не уничтожив ни одного
исходного числа. Обозначим этот заведомо расходуемый ответ h.

| Этап | X либо его сохранённая видимая копия | U/V/W/Q |
|---|---|---|
| Исходно | 0 | u/v/w/q |
| C(0) | w | 0/u/v/q |
| Метка T, обмен W/Q | w в Y/Z | h/u/q/v |
| Удаление метки, C(w) | q | w/h/u/v |
| C(q) | u | q/w/h/v |
| Нижний сдвиг с u, без чтения h | расходуемый видимый стек | u/q/w/v |

Здесь h имеет вид `1F?000000000`: нижние девять тетрад прежнего нуля
не меняются. h не форматируется как число и не читается новым читателем:
последний сдвиг намеренно выбрасывает его из W. Прежние исходники
U/V/W/Q всё время имеют живую копию.

## Читатель W, сохраняющий входящий X

Новый читатель временно использует только П0, возвращая его после
**каждой** попытки. Пусть t — входящий X, p — исходное П0.
Подготовка оставляет `X/Y/Z/T = 0/t/p/m`, где m — логическая метка
`9990FFFFFFF0`. Прямая запись в П0 получает W либо безопасный X=0.
Затем RCL0 вытесняет метку из T, не затрагивая Ms:

```
candidate/0/t/p
```

Три обычных вращения, запись П0 и ещё одно вращение возвращают p в П0,
а видимую четвёрку — к `candidate/0/t/p`. Только после восстановления
банков контроллер смотрит на индикатор. При нуле две ротации возвращают
t в X для следующей попытки. Всего не более трёх попыток; настоящий
нулевой W проходит все три. Внутренние данные для выбора действий
не читаются, значения из фикстуры не используются.

`k1-visible-reader-cleanup-check.py` доказывает локальный связанный путь
из 16 микрокоманд D6(U)…AC(V): произвольное 12-тетрадное П0 попадает
в X, старые Y/Z — в Z/T, Y становится нулём, старое T вытесняется.
Ровно 48 числовых записей, все прочие тетрады, X1 и оба банка удержаны.
Y/Z и вытесняемое T не ограничены выбранными тестовыми числами.
Это **не** сквозная теорема о клавиатурном входе, форматировщике или
сходимости повторов при любых паузах.

Десятикомандный нижний перенос D6(control)…AC(P7) повторно проверен
`k1-lower-stack-cycle-path-check.py`: старое T→U, U→V, V→W;
обычный П9 только читается в T. Здесь все 12 тетрад источника и
перемещаемых слов произвольны. Подготовка и последующая очистка
проверяются отдельно нативной трассой.

## Сборка четырёх пар

Пусть T — предыдущий чистый тройной обмен, G — новый V↔Q,
A — обычный П1↔П3. В порядке выполнения:

```
T, G, T, A, T, G
```

Независимый расчёт на 23 символических именах даёт ровно четыре
нужные пары, а не просто перестановку с тем же квадратом. Нативный
проверяющий код сравнивает каждый макроэтап с этим расчётом.

Минимум — **1212 клавиш / 9421 кадров модели**, если все 18 внутренних
чтений успешны с первой попытки. Повторы увеличивают длину. Это
фиксированное расписание эмулятора, не обещание работоспособности
при любых человеческих паузах; аппаратный опыт на этом этапе не делался.

## Что осталось

Подключены четыре нижние Ms; **четыре верхние ещё не подключены к
сохраняющему все исходники обмену**. Старые протоколы верхнего доступа
расходуют нижние значения и обычные регистры; их нельзя просто склеить
с новым блоком. Дополнительный барьер — сохранение нескольких вытесненных
чисел во время постановки скрытой метки W. Новый удерживающий читатель
снял часть этого дефицита, но полного верхнего входа пока нет.

Общий числовой и временной договор целой четырёхпарной последовательности
тоже не доказан. Конечный набор нативных тестов и локальные произвольные
12-тетрадные переносы — разные уровни утверждений. Ни полной K1, ни
невозможности полной K1 этот результат не устанавливает.

## Воспроизведение

```sh
python3 tmp/ms-rom-reachability/k1-visible-reader-cleanup-check.py
python3 tmp/ms-rom-reachability/k1-lower-stack-cycle-path-check.py
K1_VQ_UNOBSERVED=1 node tmp/ms-rom-reachability/k1-visible-q-swap-check.cjs
K1_FOUR_OPTIONS='{"twice":true,"verifyExit":true}' K1_FOUR_UNOBSERVED=1 node tmp/ms-rom-reachability/k1-four-pair-check.cjs
K1_FOUR_OPTIONS='{"phaseOffset":2,"twice":true,"verifyExit":true}' K1_FOUR_UNOBSERVED=1 node tmp/ms-rom-reachability/k1-four-pair-check.cjs
```

Тела протоколов — `k1-visible-stack-cycle.cjs`, `k1-visible-q-swap.cjs`,
`k1-four-pair-exchange.cjs`. Их публичную поверхность проверяет прокси,
разрешающий только клавиши, ожидания и объявленные чтения дисплея.
В теле нет C7/C8/C9, импорта состояния или внешнего копирования данных.
Нативные тесты выполняют настоящие команды неизменённого ПЗУ.
