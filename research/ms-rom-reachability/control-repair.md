# Control после возврата верхней Ms

12 сентября 2026 года. Проверки только на неизменённых эталоне и ПЗУ.
**Общая профилактика или полноценный клавиатурный ремонт ещё не получены.**
Здесь зафиксированы два отрицательных нативных опыта и ограниченный
положительный контракт квитирования после удаления дополнительных меток.

## Исходный дефект

В [верхнем цикле](ms-quiet-upper-cycle.md) значение
`d=1.2345678E42` даёт `EE(P8) → E7(control)`: вместо
`1F0000000000` в control появляется `042012345678`.
Все четыре верхних числа и их обычные копии при этом сохранены.

Две прямые попытки ремонта не подходят:

- Дополнительный `↔` после полного цикла действительно даёт
  `A3(control=14) → IK1303:27(control=1F)`, но перед этим выполняет
  `E9(P7=b)`: исходное a в пятом слове Ms заменяется b. Копия a в П4
  остаётся. Итоговое control — `1F3012345678`, а не двенадцать прежних тетр.
- `Сx` между загрузками d и c выполняет `E7(P8=0)`, не запись в control.
  Последующие c/b переносят этот ноль в P10: d в Ms потеряно, хотя копия
  в П5 сохранилась. Control остаётся `042012345678`.

Оба опыта исполнены целиком через клавиши, без чтений/выравниваний между
этапами. Второй воспроизводится экспериментальным
`probe_ms_control_repair.cjs` с `insertAfterD: [['Сx']]`; первый — исходным
`probe_ms_quiet_upper_restore.cjs` с `afterRestore: [['↔']]`.
Это наблюдённые отрицательные результаты, не положительные тесты ремонта.

## Что именно означает ACK 1F

`check_ms_control_repair_semantics.py` доказал:

1. У IK1302 команда 9C при байте 1F принимает control. После неё **всё
   внутреннее состояние чипа**, а не только адрес перехода, не зависит
   от десяти младших числовых тетр control. Входящие сигналы клавиатуры
   и остальные поля произвольны.
2. У IK1303 тихая обработка 1F имеет путь `6E → 5E → 39 → 6E`, не
   изменяет ни одной тетры кольца и возвращает R29=0. После неё десять
   тетр control могут влиять только на **R23**. Эта остаточная зависимость
   сохраняется после двенадцати последующих сканирований 6E без метки.
3. IK1303:27 пишет **только M31=F**. M34 не заменяется единицей: поэтому
   1F получается из уже существующего запроса 1x. Все остальные 41 тетра
   текущего слова сохраняются.

Следовательно, ACK не является очисткой всего control. Для рабочего
выхода побитовое восстановление этого служебного числового слова само по
себе не требуется, но его остаточные цифры нельзя без проверки объявить
неиспользуемыми.

## Ограниченный положительный следующий запрос

`check_ms_control_repair_dispatch.py` проверяет связанное кольцо из
пятнадцати страниц с **единственной штатной меткой**, запросом 14 и
произвольными десятичными цифрами в остальных десяти числовых тетрах
control. Сравнение производится с тем же состоянием, где эти десять
тетр равны нулю. Получен однозначный путь:

```
6E(marker) → 5E(control) → 50(X1) → 52(X) → 53(Y) → 4F(Z)
→ 41(T) → 43(U) → 4D(V) → 60(W)
→ 37(Q) → 37(P7) → 37(P8) → 37(P9) → 37(P10) → 37(marker)
→ 27(control) → 61(X1) → 4E(X) → 2A(Y) → 39(Z) → 6E(T)
```

На всём пути данные кольца вне исходного payload control совпадают
побитово; совпадает и всё внутреннее состояние, кроме объявленного R23.
Control получает ACK 1F. Все записи в связанное кольцо учитываются,
следующие страницы не подменяются независимыми значениями при повторном
проходе. Это контракт **вторичной части обычного `↔` после удаления W
и других дополнительных меток**, не готовый нативный выход.

## Почему оставлена оговорка о R23

Выполнена локальная проверка всех 256 слов ПЗУ IK1303. При различии только
в R23 потенциально могут изменить другие поля следующие команды:

`22 3B 65 71 72 7D 80 88 89 8D 8E E2`.

Например, 22 переносит разницу в R20, а 3B — в R22 даже для R23 в
диапазоне 0…9. Это **не доказательство достижимости** такого чтения после
ACK: исходные внутренние состояния локальной проверки произвольны.
Но это исключает необоснованный вывод «R23 никогда не используется».
Проверка находится в `check_ms_control_repair_r23.py`.

## Что остаётся проверить

- Нативное удаление W и всех дополнительных меток с сохранением верхних
  чисел и обычных копий, в том числе для отрицательного d.
- Клавиатурный вход в обычный запрос после этого удаления: предыдущий
  нативный `↔` **до** удаления W портит P7.
- IK1306 и нормальные арифметические команды после ACK; ограниченный
  вторичный контракт `↔` не доказывает произвольное последующее вычисление.
- Сохранение требуемых служебных тетр M1/M2 и всех программных шагов в
  полном составном протоколе.

```
python3 tmp/ms-rom-reachability/check_ms_control_repair_semantics.py
python3 tmp/ms-rom-reachability/check_ms_control_repair_dispatch.py
python3 tmp/ms-rom-reachability/check_ms_control_repair_r23.py
```

Все три проверки выполнены до конца. Их вывод явно отделяет положительные
условные контракты от локальных потенциальных наблюдателей и не утверждает
полную К1 или нормальный выход калькулятора.
