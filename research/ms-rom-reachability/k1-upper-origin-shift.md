# Верхний перенос с временным занятием физического маркера

26 сентября 2026 года. Продолжение [резервирования верхнего слова](k1-upper-reserves.md).
Эталонный эмулятор и ПЗУ не изменялись. Аппаратных опытов не проводилось.

**Получен условный клавиатурный перенос верхнего a в обычный П0,
с сохранением всех 23 исходных чисел.** Прежнее П0 перед записью
сохраняется в верхней Ms. Последнее верхнее число d при этом занимает
числовую часть физической страницы штатной метки. Это новое промежуточное
размещение, **не замкнутый обмен и не дополнительная готовая пара**:
штатную метку ещё предстоит восстановить, V/W убрать, u/q вернуть из стека.

## Точная перестановка

Как и ранее, p — исходное обычное П0; u/v/w/q — исходные нижние Ms;
a/b/c/d — исходные верхние Ms. P7…P10 ниже — физические позиции Ms,
не обычные регистры с похожими именами. m=`9990FFFFFFF0`.

После сохраняющего входа V/W и чтения верхнего слова:

```
обычное П0=w; X1=00008FFFFFFF; X/Y/Z/T=a/1/u/q;
U/V/W/Q=v/m/m/p; верхние P7/P8/P9/P10=a/b/c/d;
физическая метка=000FFFFFFFFF.
```

Без дополнительного фазового ожидания, `П→X 0`, затем `X→П 7`.
После каждой пары клавиш — 8 кадров; подготовка и её временной договор
содержатся в `k1-upper-origin-shift.cjs`. Это условия эмуляторного опыта,
не обещание работоспособности при произвольных человеческих паузах.

| Место | После читателя | После `П→X 0` | После `X→П 7` |
|---|---|---|---|
| Обычное П0 | w | w | a |
| Ms P7 | a | a | a |
| Ms P8 | b | w | w |
| Ms P9 | c | b | b |
| Ms P10 | d | c | c |
| Числовое поле физической метки | метка | d | d |

Остальные 14 обычных регистров, весь программный слой и служебные тетрады
не меняются. Видимый стек и U/V/W/Q также остаются прежними во всём
новом хвосте. Обычная команда записи в П7 фактически пишет в П0 из-за
ложной адресации; это подтверждено физическим местом записи, не только
показанием индикатора.

Нормальный 23-словный оракул закономерно сообщает отсутствие d: оно
теперь вне его области, в числовом поле страницы маркера. Тест **не
подменяет** этот оракул положительным результатом: отдельно проверяет
точное новое место d и помечает нормальный договор как невыполненный.
Речь о сохранности на границах клавиатурных действий; внутри подъёма
вытесняемое слово кратковременно находится в аккумуляторе микропрограммы.

## Путь ПЗУ

Для базовой фикстуры:

```
784017  9C(control), истинный запрос
784027  EE(P7=a) → AB
784038  D6(U), читает обычное П0=w; стек возвратов начинается A7/AC
784039  A7(V)
784040  E5(W), проверяет W[22]=F
784041  E6(Q)
784042  E8(P7)
784043  E7(P8=w)
784044  A8(P9=b)
784045  A8(P10=c)
784046  A8(marker=d)
784047  A9(control) → AC
784057  поздняя EE(P7=a)
784117  поздняя E7(P7=a), повторная запись того же значения

790745  9C(W), запрос записи
790762  EE(P7=a) → AB
790788  D4(U), записывает a в M1 обычного П0
790822  поздняя EE(P7=a)
790882  поздняя E7(P7=a), также без изменения значения
```

`k1-upper-origin-shift-path-check.py` символически проверяет десять
связанных команд D6…A9. Источник обычного П0 и четыре старых целевых
слова P8/P9/P10/marker произвольны, сигналы клавиатуры произвольны;
предпосылки — адрес D6, стек A7/AC и W[22]=F. Доказаны точные четыре
12-тетрадных переноса и неизменность остальных выходных тетрад ИК1302
на этих десяти страницах. Нативный тест отдельно проверяет количество
записей, все 630 тетрад, другие микросхемы, вход и поздние записи.
Локальное доказательство **не означает** универсального клавиатурного
входа или готового восстановления маркера.

## Проверки

`k1-upper-origin-shift-check.cjs` проверяет весь прежний префикс,
точный подъём 48 тетрад, точную запись 12 тетрад в обычный регистр,
127 границ действий и ограниченный список разрешённых изменений
в новом хвосте. Программа и служебные поля проверяются даже на временную
порчу. Управляющая процедура использует только клавиши, ожидания и
ранее предусмотренные публичные показания; подстановка фикстуры
в параметры не меняет последовательность действий.

Три свежих клавиатурных прогона совпали с собственным полным повтором
без наблюдателя по всем сериализованным полям:

| Верхние a/b/c/d | SHA-256 конечного состояния |
|---|---|
| 9011 / 9022 / 9033 / 9044 | `ed9ea648266fdf23bda777a51bf0715d8b98ddf64a11cc4f216fd0d352290f00` |
| −7.654321E23 / −1E−99 / 1.2345678E42 / 8.7654321E−17 | `36065974e71856fd97d8683f4d71efedd30ae5c74cea32754c40653c3d179b85` |
| 9011 / −7.654321E23 / 1.2345678E42 / −1E−99 | `ebbfb2c40c7cc99de00eb295f76c409dd7b4cc5b625d7afa6f6f3e46ae1e80d9` |

Последний набор проверен независимо. Короткое **d** не мешает его
хранению в странице маркера; это **не** снимает числового ограничения
читателя первого верхнего **a**. Текущий положительный договор читателя
по-прежнему ограничен классами нормализации 1…6 и проверенным префиксом.
При первой успешной попытке публичных чтений драйвер содержит 178
клавиш / 1420 кадров, без подготовки фикстуры и начального сдвига.

```sh

K1_ORIGIN_OPTIONS='{"fullUpper":["-7.654321E23","-1E-99","1.2345678E42","8.7654321E-17"]}' K1_ORIGIN_UNOBSERVED=1 node tmp/ms-rom-reachability/k1-upper-origin-shift-check.cjs
K1_ORIGIN_OPTIONS='{"fullUpper":["9011","-7.654321E23","1.2345678E42","-1E-99"]}' K1_ORIGIN_UNOBSERVED=1 node tmp/ms-rom-reachability/k1-upper-origin-shift-check.cjs
K1_ORIGIN_NEGATIVE=1 node tmp/ms-rom-reachability/k1-upper-origin-shift-check.cjs
K1_ORIGIN_LASTX_NEGATIVE=1 K1_ORIGIN_UNOBSERVED=1 node tmp/ms-rom-reachability/k1-upper-origin-shift-check.cjs
python3 tmp/ms-rom-reachability/k1-upper-origin-shift-path-check.py
```

Отрицательный фазовый контроль: два дополнительных кадра перед
`П→X 0` выбирают другой подъём, P7/P8/P9/P10, с источником обычного П8.
Последнее верхнее d вытесняется без сохранения. Поэтому пауза здесь не
просто минимальная задержка; установлен только конкретный договор.

Дополнительный отрицательный контроль — `F В↑` после нового переноса.
Он действительно читает p из Q (797496), но подъём P7…P10 (797512)
даёт p/a/w/b и вытесняет единственную копию c. d остаётся на месте
физического маркера. Проверены точные 48 записей, конечное отсутствие c
среди 23 хранимых слов, видимого стека, X1 и временного места маркера;
полный повтор без наблюдателя совпал:
`26310d570848570563cc60b1629cabd0db1f20806710b9f34f3184a4236e0535`.

## Чего ещё нет

В этой раскладке нельзя просто восстановить штатный маркер: там единственная
копия d. Следующий подъём P7…P10 теряет c, а подъём P8…marker — d,
если заранее не создать дополнительную копию вытесняемого слова.
Обычный запрос, пишущий в Q, тоже опасен: там единственная копия p.
Это местные препятствия конкретного продолжения, не доказательство
невозможности полного К1.

Следующий содержательный шаг — получить полезный резерв **до** этого
переноса либо иной сохраняющий выход. Готовой полной К1 и общего
доказательства её невозможности по-прежнему нет.
