# Нейтральный запрос 28h: удаление Y/Z при сохранении W

12 сентября 2026 года. Это проверенная подготовка верхнего обмена,
**не полная К1**. [Критерии полной цели и препятствие К2](full-commands-contract.md).

## Зачем нужен новый запрос

Прежний читатель шестого слова оставлял в Q запрос 25h. Видимая метка Y
скрывала его от ИК1303; удаление следующей метки открывало старый запрос,
и запоздалое вращение уничтожало W. Поэтому сначала требуется заменить
25h на запрос, который при открытии не меняет данные.

Разбор штатного ПЗУ дал целое семейство 26h…2Eh. При входе ИК1303 с
R29=0, меткой W и таким запросом в Q выполняется ровно девять команд:

```
6E(W) → 5E(Q) → 50(P7) → 52(P8) → 53(P9)
→ 4F(P10) → 24(marker) → 26(control) → 39(X1) → 6E(X)
```

Ни одна из 42 тетрад каждой страницы не меняется; R29 снова равен нулю.
Это связанное символьное доказательство с произвольными остальными данными
и клавишами, а не только наблюдение одного числового примера. Оно само
по себе не доказывает достижимость входа и поведение третьей микросхемы.

## Клавиатурное продолжение

Используется код 28h, пользовательские клавиши `K ×`. После уже проверенной
загрузки h=−1.234E−42 три попытки `K ×` с дополнительным одним кадром перед
второй и третьей обходят три кадровые фазы. В каждой испытанной фазе ровно
одна A3 пишет запрос 28h в Q; остальные попытки используют видимое Z.

Пусть g=−1.2345678E−42, m=`0000F0000000`, а a,b,c,d — исходные верхние
числа Ms. Для испытанного класса b состояния после этапов таковы:

| После этапа | X,Y,Z,T | U,V,W,Q | Верхние слова |
|---|---|---|---|
| Загрузка h | h,m,m,0 | g,h,m,g | a,b,c,d |
| Три `K ×` | b,m,`2880F0000000`,0 | h,g,m,`288912345678` | a,b,c,d |
| `F ,` | b,`2580F0000000`,0,h | h,g,m,`288912345678` | a,b,c,d |
| `↔` | b,b,`14?000000000`,h | h,g,m,`288912345678` | a,b,c,d |
| Ещё `↔` | b,b,`14?000000000`,h | h,g,m,`1F?912345678` | a,c,b,d |

Здесь `?` — третья тетрада полного 12-тетрадного числа b. Запрос 28h
действительно читается ИК1303 после удаления Z; это не оставшаяся навсегда
замаскированной запись. Первая `↔` удаляет Y парой 4E(X)/2A(Y), вторая
даёт 27(Q), затем 4E(P8)/2A(P9): точную перестановку b/c и ответ 1F.
W остаётся единственной дополнительной скрытой меткой, все четыре
верхних исходных числа сохраняются, хотя средняя пара переставлена.

## Доказательства и границы

- `analyze_ms_pending_opcodes.py` — разбор префиксов запросов ИК1303.
- `check_ms_quiet_request_path.py` — связанная первичная запись 28h в Q,
  затем девятикомандный нейтральный префикс ИК1303; выполнен успешно.
- `probe_ms_clone_quiet_request.cjs` — только клавиши и кадры на живом ядре;
  прежняя остановка по общедоступному индикатору остаётся единственным
  условным чтением в протоколе.
- `check_ms_clone_quiet_request.cjs` — точные блоки 48 и 24 записей,
  сравнение всех 630 тетрад вокруг них, контроль программы, обычных
  регистров, верхних слов и отсутствие недекларированных верхних записей.
  Сценарии с ответом 1F прошли во всех трёх фазах, включая b=−1.23E−42
  и соседнее c=−1E−99.
- Полное состояние после исполнения с наблюдателем и без него совпало:
  SHA‑256 `f35a6a1d9aa59ee60ca88849c01ff6ff1981d0f7217d862a75c9409e651e6c32`.
- `check_ms_quiet_keyboard.cjs` — отдельный прокси, не предоставляющий
  скрытых геттеров, импорта состояния и доступа к фикстуре.

Контракт пока допускает только каноническое ненулевое b с s+d≤5,
где s — число подавляемых хвостовых нулей, d — дополнительная команда
десятичного форматирования. Общий вход, ноль, нечисла и произвольные
паузы не доказаны. Рабочие нижние U/V/W/Q и обычные П6/A/E не восстановлены;
для подготовки h используется П2. Исходное содержимое рабочих регистров
нельзя объявить сохранённым. Следующий обязательный шаг — действительное
сохранение исходящих верхних слов и запись входящих, затем распределение
всех исходных данных для полного двустороннего обмена.
