# П9 → U и обратная запись четырёх числовых слов Ms

10 сентября 2026 года. Продолжение `ms-header-repair-boundary.md`.

## Полученный результат

На неизменённом эталоне получена самостоятельная операция клавишами:

```text
до:     U,  V,  W,  Q
после:  П9, U,  V,  W
```

Переносятся **все 12 числовых тетрад**, включая знак и порядок. П9 не
изменяется. Сохраняются программа, все обычные регистры, обе дополнительные
тетрады каждой страницы и оставшиеся четыре слова Ms. Старое Q вытесняется
и операцией не сохраняется. Стек X/Y/Z/T очищается; X1 и счётчик программы
не обещаны как неизменяемые.

Четыре таких вызова позволяют записать всю четвёрку U/V/W/Q. Проверена
составная операция **П4/П5/П6/П7 → U/V/W/Q**: данные подаются в обратном
порядке через П9. П3 должен быть нулевым, П9 используется как временный
регистр и в конце равен П4. Все остальные обычные регистры и программа
сохраняются. Это вспомогательная раскладка, **не штатное соответствие К1**.

Это не новая найденная целая К1 и не точечная починка U после W/Q.
Получен рабочий путь обратной записи четырёх слов без установки
вспомогательной пользовательской программы. Тело — уже известный конечный
числовой блок E7/A8; новый результат здесь — самостоятельный вход от П9,
возврат и проверенная композиция с сохранением чужой программы.

## Как адресация дала этот путь

П3 лежит в дорожке M1 физической страницы Q. После его чтения поиск E5
начинается в P8, проходит настоящую метку и направляет E7 в обычный X.
Поэтому нулевой П3 пригоден для безопасного удаления ложной метки.

У П9 другая физическая позиция: M1 страницы настоящего управления.
После чтения П9 поиск E5 начинается в X и успевает встретить ложную метку Y:

```text
D6(управление: П9, дорожка M1) → A7(X1)
→ E5(X) → E5(Y: ложная метка) → E6(Z) → E8(T)
→ E7(U) → A8(V) → A8(W) → A8(Q) → A9(P7) → AC(P8)
```

Так источник П9 и место записи U совпали в одном реальном исполнении.
D6 полностью заменяет внутреннее A, поэтому предварительное чтение
не того слова M2 не подмешивает разряды к записываемому числу.
В E7 входит счётчик S1=8; после трёх A8 он становится 0, следует конечный
выход A9→AC. A9 не записывает вытесненное Q обратно в Ms.

## Самостоятельная последовательность

Предусловия: обычный АВТО, П3=0, нужное число уже находится в П9.
В проверенных исходных Ms находятся обычные числовые слова без дополнительных
ложных меток F. Последовательность **сдвигает U/V/W и теряет старое Q**.

```text
Сx В↑ В↑ В↑ +
Сx K − ВП K 0
П→X 3
П→X 9
П→X 3
П→X 3
П→X 3
П→X 3
Сx В↑ В↑ В↑ +
```

28 нажатий. Для клавиш изготовления пустышки тесты добавляют по 12 кадров,
для остальных групп по 8; проверен и вариант 8/12. Это интервалы эталонного
эмулятора, не инструкция для нового аппаратного опыта и не гарантия
произвольных пауз. Проверены все три начальные кадровые фазы.

## Четыре разных слова подряд

Для записи П4/П5/П6/П7 в U/V/W/Q выполняются четыре стадии:

1. Обычными клавишами скопировать П7 в П9; выполнить приведённый писатель.
2. Скопировать П6 в П9; выполнить писатель.
3. Скопировать П5 в П9; выполнить писатель.
4. Скопировать П4 в П9; выполнить писатель.

Между стадиями нет сброса, синхронизирующего чтения состояния, подстановки
цифр через хост или правки программы. Источники читаются именно штатными
«П→X n», а не расшифровываются проверяющим кодом и вводятся заново.

Для составного опыта использованы разные значения: `−1.2345678E−42`,
`−9.8765432E99`, ноль и `12345678`. Во всех трёх начальных фазах итоговые
12-тетрадные слова совпали с исходными П4…П7. Остальные Ms сохранены;
из обычных регистров изменяется только явно выделенный П9. Сохранённая
пользовательская программа после операции запускается и получает 5.

## Доказательства и проверки

- `check_ms_p9_push.py`: связанный путь от D6 до AC, произвольные 12 тетрад
  источника и вытесняемых чисел, сохранность всех остальных выходов.
  Отдельно проверена расшифровка 69 до помощника чтения M1.
- `check_ms_p9_push.cjs`: девять основных сценариев, все три фазы для
  положительного числа и отрицательного порядка, ноль, крайние порядки,
  ненулевые обычные регистры, другие интервалы; три повтора без сброса.
  Для каждого блока сверяются все 630 тетрад кольца и ровно 48 записей
  всех микросхем. Все меняющие Ms записи за всю операцию находятся в этом
  четырёхкомандном блоке.
- Дополнительный нативный опыт проверяет ненулевые Ms P7/P8.
- `check_ms_fill4.cjs`: составная запись четырёх разных чисел без наблюдателя
  и выравнивания между стадиями, в трёх начальных фазах.

Наблюдаемое и ненаблюдаемое полное состояние после одиночного писателя
совпадает: `fc4c35d33637e3478665ff2287c403ddf570964cef08e2470ca12aeda6c86c53`.
Успешный перенос не использует адрес C7 или C8 и не входит в C9.

```sh
python3 tmp/ms-rom-reachability/check_ms_p9_push.py
node tmp/ms-rom-reachability/check_ms_p9_push.cjs
node tmp/ms-rom-reachability/check_ms_fill4.cjs
```

## Что ещё не выполнено

Продолжение: [составное чтение четвёрки с восстановлением Ms и исправленный
W/Q](ms-fourword-restore.md) уже получены для проверенной области с
неотрицательным порядком U. Ms меняются временно; общий случай остаётся
открытым из-за отрицательных порядков исходного U.

Полная К1 требует обмена восьми пользовательских регистров с восемью
словами Ms. Здесь пока только однонаправленная запись четвёрки и временный
П9. Для безопасного восстановления четвёрки после W/Q сначала нужны
сохранённые исходные значения всех четырёх слов; общий неразрушающий
читатель Q и снятие ограничения входа W/WQ ещё не получены.
Новые кнопки на физическом приборе не проверялись; эталон и ПЗУ неизменны.
