# Запись обычного П0 в верхнюю Ms после НОП

26 сентября 2026 года. Новая ветвь глубокого V/W-входа на неизменённых
ПЗУ и ядре. Это **промежуточный сохраняющий перенос**, не новый замкнутый
обмен, не увеличение числа уже замкнутых пар и не полный К1.

## Что получилось

После [сохраняющего НОП](k1-vw-nop-cleanup.md) обычная команда `П→X 0`
поднимает видимый стек, затем её поздний форматировщик записывает
прочитанное число не обратно в X, а в физическую верхнюю Ms P7.
Прежнее верхнее число a заранее сохранено в W, поэтому потери нет.

Обозначения — **исходные** числа: p из обычного П0, u/v/w/q из нижней
Ms, a/b/c/d из верхней. К моменту нового чтения обычный П0 уже содержит
w, а не первоначальное p.

| Места | Перед чтением П0 | После чтения П0 |
|---|---|---|
| Обычный П0 | w | w |
| X1 | INV0 | INV0 |
| X / Y / Z / T | 1 / u / q / m | w / 1 / u / q |
| Ms U / V / W / Q | v / m / a / p | v / m / a / p |
| Верхние P7 / P8 / P9 / P10 | a / b / c / d | w / b / c / d |

`m=9990FFFFFFF0`, `INV0=00008FFFFFFF`. Основной физический маркер
остался целым; лишняя метка теперь только в V. Число w продублировано
в верхней Ms, поэтому обычный П0 можно использовать как рабочее место.
Но a теперь единственно в W, p — в Q, u/q — в Z/T. Старый нижний push
не разрешён: он уничтожил бы единственную a.

В отличие от [переноса со сдвигом начала](k1-upper-origin-shift.md),
последнее верхнее d не занимает страницу основного маркера. Цена другой
геометрии — новый барьер снятия V, разобранный ниже.

## Проверенный путь

После полного глубокого входа и НОП, без дополнительного кадра перед
новым `П→X 0`, после команды восемь кадров:

```
784580 EE(W=a) → AB
784593 D6(U, M1=w) → A7
784594 A7(V) пропускает собственную страницу
784595…784601 E5(W…real)
784602 E6(control), 784603 E8(X1)
784604…784607 E7(X), A8(Y), A8(Z), A8(T)
784608 A9(U)
784619 EE(X=w) → E3
784672 E7(P7) ← w
```

Четырёхсловный push вытесняет только m. Поздняя запись заменяет a,
чья копия уже в W. E9 и A3 в новом действии отсутствуют. Проверщик
сравнивает все 630 тетрад при переносах и разрешает во всём действии
только эти 48+12 числовых записей; остальные изменённые тетрады запрещены.

127 границ действий удерживают все 23 исходника среди хранимых слов и
X1/X/Y/Z/T. Программа, служебные тетрады, 14 других обычных регистров
и три остальных верхних слова защищены полным журналом записей, а не
только конечным сравнением.

Протокол — 176 клавиш / 1409 кадров при одном успешном чтении каждого
префиксного читателя; подготовка фикстуры и начальная фаза не включены.
Контроллер не читает внутренние поля и не подставляет исходные числа;
разрешено только публичное показание для уже существующих читателей.

## Числовая граница и два полных теста

Символически проверены 24 канонических ненулевых случая и ноль для
**локального** позднего EE(X) при метках real/V. Классы форматирования
0…7 пишут P7, класс 8 пишет X. Поэтому ноль и соответствующие короткие
числа не выполняют этот верхний перенос. Это не доказательство всего
клавиатурного префикса для произвольных чисел.

Нативно проверены два набора верхних слов:

- a/b/c/d = −1E−99 / 9022 / 9033 / 9044;
- a/b/c/d = −2E−50 / −7.654321E23 / 1.2345678E42 / 8.7654321E−17.

В обоих p=201, u=−12345678, v=−9.8765432E−17,
w=−7.654321E−23, q=−1.2345678E−42. Каждый полный запуск совпал со
свежим запуском без наблюдателя по всем сериализованным полям:

```
base a962c29417771acbd37b9bb3edfdcbef8100e6edf5ec45b2dc265b86ec8b9880
wide ee20808ff19dc8525e9d20e1c4e5b924f02148de3c84fb861113d60a2d2fb495
```

```sh
K1_UPPER_WRITE_UNOBSERVED=1 node tmp/ms-rom-reachability/k1-vw-upper-write-check.cjs
K1_UPPER_WRITE_OPTIONS='{"fullUpper":["-2E-50","-7.654321E23","1.2345678E42","8.7654321E-17"]}' K1_UPPER_WRITE_UNOBSERVED=1 node tmp/ms-rom-reachability/k1-vw-upper-write-check.cjs
python3 tmp/ms-rom-reachability/k1-vw-upper-write-formatter-check.py
```

## Почему старую очистку нельзя приписать к новому переносу

В прежнем закрытом выходе метка T ещё существовала: E9 попадала в V,
после чего отдельный подъём убирал T. Здесь новый RCL0 уже убрал T.
При только real/V запись E9 может попасть в X1 либо Q, но **не V**:
это смещение на две страницы от найденной метки, а не вопрос задержки.
[Обе семьи K× проверены для всех 15 принятых позиций 9C](k1-single-v-neutral-map.md).

Прямое продолжение `K ×` без добавленного кадра проверено нативно:

```
791300 9C(W=a) принимает управление
791309 EE(X=w) → A1
791316 E9(Q) ← w              уничтожает единственное p
791322 A3(control) ← 287h
791339 EE(X=w) → E3
791392 E7(P7) ← w             идемпотентная поздняя запись
```

Это не смена источника на P7: ранний источник — именно X. Единственные
изменения нового действия — Q и три тетрады заголовка control; V
остаётся меткой. Отрицательный тест проверяет этот конкретный отказ,
а не невозможность всех продолжений.

```sh
K1_UPPER_WRITE_NEGATIVE_CLEAR=1 K1_UPPER_WRITE_UNOBSERVED=1 node tmp/ms-rom-reachability/k1-vw-upper-write-check.cjs
```

Отрицательный тест прошёл, включая свежий повтор без наблюдателя;
полные состояния совпали, SHA256:
`873dbae2d887a78a7e3575c78ab707627657246fcb115bc103ab002fc0e54e6c`.

## Другие результаты этого шага и следующий барьер

- [Верхняя свободная P8 после K8/LastX](k1-upper-vacancy.md) — отдельный
  сохраняющий блок: верхние b/0/c/d, но a/u/q только в стеке. Полная
  трасса и повтор без наблюдателя прошли; выхода и резерва p нет.
- [Карта STORE при real/V](k1-single-v-store-map.md) условно даёт
  X→настоящий П0 через код 47h. Это не готовое сохранение q или p:
  они ещё не поданы в X, нативная фаза и поздний хвост не доказаны.
- [ENTER(W) нельзя сделать бесподъёмным флагами](k1-enter-no-push-notes.md):
  E0 безусловно ведёт в A7, старое q вытесняется из T.
- [Перестановка перед НОП](k1-vw-pre-nop-upper-notes.md) на шести
  проверенных вариантах теряет нижние данные и не меняет верхнюю
  четвёрку; это кадровые диагностики, не всеобщий запрет.
- [Другие отвергнутые стыковки](k1-vw-rejected-exits.md): ↔ после НОП,
  нижний push до удаления V и короткое b в блоке свободной верхней ячейки.
- [Непрерывный повтор прежнего закрытого выхода](k1-vw-nop-restored-repeat.md)
  не проходит на втором входе. Одноразовую перестановку нельзя выдавать
  за готовую повторяемую операцию.

Ближайшая задача — сохранить q или p в освобождённом П0, **до** нового
подъёма или записи в Q, либо получить иной сохраняющий писатель V.
[Условный план восстановления после безопасного снятия V](k1-upper-normal-exit-conditional-plan.md)
существует, но само снятие в новой раскладке ещё не найдено. Обычная работоспособность
на этом выходе, повторяемость и полная К1 не достигнуты.
