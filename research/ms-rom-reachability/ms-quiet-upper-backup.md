# После ответа 1F: точные копии шестого/седьмого слов и путь к пятому

12 сентября 2026 года. Продолжение [нейтрального запроса 28h](ms-quiet-request-ack.md).
Это исследовательская подготовка, **не полная К1**: обычные П2/П3 и другие
регистры префикса используются как рабочие, а не сохраняют свой исходный банк.

**Следующее продолжение завершило условное сохранение пятого:** нулевая
защита и раздельные клавиши записи дали a → П4 во всех трёх фазах.
[Три верхних копии, точные пути и тесты](ms-quiet-fifth-zero.md).
Ниже сохранён разбор предшествующих неудачных переходов.

## Две подтверждённые копии

После 28h, удаления Y/Z и ответа 1F верхняя Ms имеет вид `(a,c,b,d)`:
пара b/c переставлена, но все четыре исходных числа ещё на месте.

```
X→П 8        → исходное b в обычный П2
X→П 9        → исходное c в обычный П3
```

После каждой пары клавиш в испытанном протоколе — восемь кадров.
Запрашиваемые 8/9 не равны физическим П2/П3: скрытая W сдвигает начало
поиска обычного регистра на девять страниц по кольцу.

Первая запись использует `EE(X=b) → … → D4(W/M1)`. Только после неё
служебный возврат читает `EE(P8=c)` и пишет c в X. Поэтому показание c
после первой команды **не означает**, что в П2 записано c. Вторая команда
сохраняет уже настоящее X=c через D4(Q/M1).

`check_ms_quiet_upper.cjs` подтвердил обе копии во всех трёх исходных
фазах. Для каждой D4 проверены ровно двенадцать исходных тетрад, единственные
двенадцать записей M1 и все 630 тетрад кольца до/после. На протяжении
обеих записей не меняется даже временно ни одна тетрада Ms; вся программа
сохранена. Дополнительно проверяется полный ранний префикс по его пассивной
трассе, без повторного запуска или подстановки состояния.

Проверенные дополнительные числа включают `b=−1.23E−42`,
`b=1.2345678E42`, `c=8.7654321E−17` и соседнее `d=−1E−99`.
Ограничение прямого сохранения: оба b/c канонические, ненулевые и имеют
s+d≤5 в формуле форматировщика. Иначе поздний возврат может не писать X;
это не универсальный читатель любого представления числа.

## Почему простого «возврата X» недостаточно

На базовом продолжении `F В↑` действительно достигает пятого слова:

```
EE(P7) → F0(P8) → E0(P9) → A7(P10)
→ E5(marker) → E6(control) → E8(X1)
→ E7(X) → A8(Y) → A8(Z) → A8(T) → A9(U)
```

Связанный контракт `check_ms_quiet_lastx_path.py` выполнен: источник
содержит двенадцать произвольных тетрад, перенос меняет только 48 тетрад
видимого стека и не касается Ms или программы. Однако поздний
`EE(P8=c) → … → E7(X)` снова заменяет X=a на c. Следующее сохранение
пишет c вместо a. Обнаружить первое EE недостаточно для объявления чтения
законченным; этот путь выделен в `check_ms_quiet_lastx_negative.cjs`.

## Защита нулём

Клавиша `Сx` после двух сохранений очищает только физическое P8. Его
старое c уже лежит в П3; a, b, d остаются целыми. Дальнейшая обработка
нуля имеет особую ветку:

- нормализация от EE до 40 занимает ровно 47 команд;
- возврат начинается `40 → 41 → 43 → 46`, а не обычным 42;
- с метками только W и штатной marker итоговая E7 пишет ноль в P8,
  **не в X**.

`check_ms_zero_formatter.py` доказывает этот локальный путь по ПЗУ.
В нативном опыте с раздельными `F`, паузой и `В↑` получено EE(P7=a),
затем a удержано в X, тогда как индикатор показывает ноль. Обычное
следующее сохранение пока может выбрать P8=0 вместо X=a; требуется
отдельно подтвердить выбор нужного источника, а не считать чтение пятым
законченным только из-за удачной промежуточной копии.

Другой испытанный вариант — ввод `1E−99` — вызывает дополнительный
четырёхсловный сдвиг, переносит d в штатную marker, а следующий сдвиг
теряет d. Он не подходит для сохранного чтения всей четвёрки.

## Воспроизведение

```
node tmp/ms-rom-reachability/check_ms_quiet_upper.cjs
python3 tmp/ms-rom-reachability/check_ms_quiet_lastx_path.py
python3 tmp/ms-rom-reachability/check_ms_zero_formatter.py
node tmp/ms-rom-reachability/check_ms_quiet_lastx_negative.cjs
```

Общий контракт полной К1/К2 остаётся в
[full-commands-contract.md](full-commands-contract.md). Полученные две
копии и локальный путь чтения пятого не решают сохранение обоих исходных
банков, всех рабочих регистров, общего числового класса и штатного выхода.
