# От нашего листинга к C8: подписи к иллюстрации

9 сентября 2026. Исходный опыт с конечным индикатором `00 00 00 30`.
Основа — непрерывная трасса неизменённого эталона, не реализация К1/К2
в расширенном режиме MK61S. Это объясняющая схема; полный порядок
нажатий и паузы приведены в [протоколе](c8-human-test.md).

## 1. Необычное слово в П7 и счётчик

Программа A, начиная с шага 00:

| Шаг | Код | Команда |
| --- | --- | --- |
| 00 | 22 | x² |
| 01 | 22 | x² |
| 02 | 22 | x² |
| 03 | 60 | П→X 0 |
| 04 | 12 | × |
| 05 | 47 | X→П 7 |
| 06 | 50 | С/П |

Перед пуском: П0 = 1,0000003; X = 1E75. Пуск: В/О, С/П.
Порядок проходит 75 → 150 → 300 → 600. Умножение задаёт последнюю
цифру мантиссы 3. В П7 сохраняется сырое слово `600010000003`.
Это последовательность 12 тетрад, не десятичное число 600010000003.
Затем вводим 1 и X→П 2: в пользовательском П2 находится единица.

## 2. Вторая версия программы

Программа B вводится поверх A с шага 00, а не дописывается после неё:

| Шаг | Код | Команда |
| --- | --- | --- |
| 00 | 22 | x² |
| 01 | 22 | x² |
| 02 | 22 | x² |
| 03 | 60 | П→X 0 |
| 04 | 12 | × |
| 05 | 50 | С/П |

Перед пуском: П0 = 1,0000005E4; X = 1E87. Пуск: В/О, С/П.
Квадраты дают порядки 174, 348, 696; умножение добавляет 4.
Промежуточное слово — `700010000005`. Это не утверждение о его
неизменном сохранении в X после всей последующей обработки.
П7 и П2 сохраняются.

## 3. Переключения и последний вызов

Следуют F АВТ, F ПРГ, В↑, F АВТ, БП 5 8, БП 5 8, П→X 7.
F АВТ обозначает F /-/; F ПРГ — F ВП. Паузы и установочные нажатия
здесь сокращены, не исключены из полного проверенного протокола.

На входе AC последнего чтения одновременно:

| Поле | Значение |
| --- | --- |
| PC | 58 |
| R[1] | 5 |
| ST[32] | F |
| ST[35] | 9 |

ПЗУ проходит AC → … → EE. EE читает реальное слово `600010000003`
из X. Внутреннее состояние не присваивается проверяющей программой.

## 4. Автоматическое продолжение

После последнего П→X 7 новые нажатия не нужны для этого результата.
Промежуточные перемещения объединены в таблице:

| Источник | Где используется |
| --- | --- |
| Прежнее R[1] = 5 | Восстановление переносит 5 в R[2] |
| Прежний PC = 58 | Становится кодом цикла L2 |
| Последняя цифра 3 прочитанного слова | Приходит в R[0] перед DD |
| R[0] = 3 | DD записывает R[38] = 3 + 1 = 4 |
| Прочитанная единица П2 | Рабочая копия уменьшается до нуля; ветвь без повторной записи сохраняет селектор 4 |

Важно: пользовательский П2 при этом **остаётся равным 1**. Ноль —
результат обработки его рабочей копии, а не новая запись в П2.
После полного опыта проверено сырое П2 = `000010000000`.

У последней развилки 07 → 6D → 60 → C8:

```text
R[2] = 5
R[26] = 9
R[38] = 4
R[25] = R[31] = 0
```

В участке 60 при сработавшем сравнении адрес собирается так:

```text
Старшая тетрада: R[39] ← (R[38] + 8) mod 16 = C
Младшая тетрада: R[36] ← 8
Адрес следующей команды ПЗУ: C8
```

C — шестнадцатеричная цифра 12. Пользователь не вводит команду
перехода на C8; адрес вычисляет существующая логика ПЗУ.

## 5. Чтение и видимый результат

| Исполнение C8 | Команд ПЗУ после AC | Позиция кольца | Прочитанные 14 тетрад, младшие сначала |
| --- | ---: | --- | --- |
| 1 | 121 | W | 00000000000000 |
| 2 | 141 | P10 | 00000000000000 |
| 3 | 161 | Y | 00000005039000 |

Это счёт выполненных внутренних команд, не паузы для человека.
W, P10, Y — обозначения физических позиций кольца, не номера Пi.
Каждая C8 копирует 14 тетрад M2 в R[1], R[4], …, R[40].
Это чтение, не взаимный обмен. Выход каждой C8 — 6E → 61.
После дальнейшей обработки индикатор показывает:

```text
00 00 00 30
```

Без запятой. Это результат исходного опыта, не полная К2.
Адреса ПЗУ подтверждены трассировкой эталона; пользователь сообщил
о повторении внешнего показания на аппаратном калькуляторе.

П0/П2/П7 — пользовательские регистры. R[…] и ST[…] — внутренние ячейки.
Коды пользовательского листинга и адреса ПЗУ — разные уровни, даже
если их шестнадцатеричные обозначения совпадают.
