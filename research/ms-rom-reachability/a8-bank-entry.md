# Клавиатурный вход в восьмикратный цикл A8

10 сентября 2026 года. Эталонный МК-61 с исходными ИК1302/03/06; не
обработчики К1/К2 режима 112ШГ MK61S. Физический прибор не использовался.

Последующее уточнение: [условия однократного выхода и полное покрытие
входов A8](a8-exit-and-entry-bound.md). Для восьмикратного блока возврат
всегда 6E; она перезаписывает мантиссу последнего вытесненного слова.
Существуют условные пути до 63 без повторного блока, но их клавиатурная
подготовка пока не найдена.

## Полученный результат

**Найден настоящий клавиатурный вход `60 → A8×8 → A9 → 6E`.**
Каждая A8 меняет местами все 12 числовых тетрад рабочего A и очередной
страницы M2. Восемь таких обменов выполняются подряд. Подготовка и запуск
используют только обычные клавиши; подстановки внутреннего состояния,
редактирования ПЗУ и загрузки программы через host API нет.

В частности, старое полное число из Q переходит в P7. Это область за
пределами четырёх слов, доступных прежнему писателю «пустышкой». Проверен
перенос `−1,2345678·10⁻⁴²` с сохранением всех тетрад, а не только мантиссы.

**Это не К1 и пока не пригодная подпрограмма.** Первый проход задевает
служебные страницы; следующие продолжают переставлять память. Найденный
контекст повторения оказался точным замкнутым циклом, а не следствием
слишком длинной задержки проверяющего кода.

## Почему выбран именно этот вход

Из уже проверенного устройства диспетчера:

- DD присваивает `R38 = прежнее R0 + 1` по модулю 16;
- при равных `R25` и `R31` команда 60 выбирает `((R38+8) mod 16):8`;
- для прежнего C8 нужен `R38=4`; для A8 нужен `R38=2`.

Поэтому в подготовке первого числа достаточно заменить множитель
`1.0000003` на `1.0000001`. В П7 получается настоящее сырое слово
`600010000001` вместо `600010000003`. Вторая подготовка с
`1.0000005E4` и счётчик П2=1 остаются прежними. Это изменение выведено из
логики DD/60, а не найдено перебором клавиш.

Параметр `lowDigit=1` добавлен в существующую подготовку; его значение
по умолчанию осталось 3. Все прежние проверки C8 прошли повторно.

На входе A8 получается S1=0. После каждого обмена S1 увеличивается на 2:
`0, 2, 4, 6, 8, A, C, E`; восьмая команда выходит в A9. Адреса здесь
внутренние, шестнадцатеричные, не пользовательские коды и не клавиши.

## Что именно переставляется

Если перед циклом рабочее слово равно A, а восемь последовательных слов
равны W0…W7, перед выполнением A9 результат таков:

```text
страницы: A, W0, W1, W2, W3, W4, W5, W6
рабочее A: прежнее W7
```

У каждой страницы сохраняются две дополнительные тетрады M2. Дорожки M1
с обычными регистрами и M3 с программой этот цикл не меняет. То есть он
сдвигает скрытые слова через рабочий буфер, а не обменивает восемь пар
«Пi ↔ Ms_i». Для К1 ещё нужны чтения и записи соответствующих Пi.

Первый проход в проверенном протоколе идёт по страницам:

```text
W, Q, P7, P8, P9, P10, метка, управление
```

Исходный A здесь равен `FFFFFFFFFFFF`. Поэтому первый проход не только
сдвигает полезные данные, но и изменяет числовые поля метки и управления.
Второй проход начинается с U и охватывает ровно восемь страниц Ms:

```text
U, V, W, Q, P7, P8, P9, P10
```

Однако он уже следует после порчи служебных страниц и не является
самостоятельно управляемой операцией. A9 дополнительно заменяет две верхние
числовые тетрады вытесненного W7 значениями R32/R35. Затем управление идёт
в 6E, а не в запись D4. Безопасное сохранение последнего слова не получено.

## Повторение разобрано точно

Между вторым и третьим входами в 60 на эталоне наблюдаются 28 команд:

```text
60, A8×8, A9, 6E, 61,
3A, 06, 07, 6D, 60, 61,
3A, 06, 07, 6D, 60, 61,
3A, 06, 07, 6D, 60
```

В символическую проверку перенесены только управляющие поля этого
наблюдённого состояния. Все 12 тетрад A, всё содержимое поступающих страниц
кольца, S, флаги и сигналы клавиатуры на каждом такте оставлены произвольными.
Доказаны все 28 переходов и возвращение всех зафиксированных полей R/ST/S1
к исходным значениям. Получен индуктивный цикл.

**В данном контексте другое содержимое Ms, ожидание или нажатия внутри
цикла не выводят из него.** В кольце 15 страниц, а 28≡−2 (mod 15), поэтому
начало прохода каждый раз сдвигается на две страницы назад и со временем
посещает все 15 позиций, не только Ms. Это доказательство относится именно
к полученному контексту, не ко всем возможным входам в A8.

## Проверки

`check_a8_bank_keyboard.cjs` проверяет шесть вариантов: пустую Ms,
четыре различных целых, четыре различных числа со знаками и порядками,
две другие фазы кадра и увеличенную паузу подготовки. В каждом варианте
в записанном окне наблюдаются 193 завершённых восьмикратных прохода.

Для **каждого** такого прохода сравниваются все 630 тетрад кольца с
ожидаемыми восемью обменами. У первого прохода также проверены ровно
96 физических записей: только ИК1302/A8, только числовые тетрады M2.
Независимый запуск без наблюдателей даёт то же полное состояние машины.

`check_a8_bank_semantics.py` доказывает вход 60→A8, все восемь точных
обменов и выход A9→6E для произвольных данных. `check_a8_reentry.py`
проверяет описанный выше замкнутый цикл от наблюдённого состояния.

```sh
node tmp/ms-rom-reachability/check_a8_bank_keyboard.cjs
python3 tmp/ms-rom-reachability/check_a8_bank_semantics.py
python3 tmp/ms-rom-reachability/check_a8_reentry.py
node tmp/ms-rom-reachability/check_c8_keyboard.cjs
```

Вход в существующий цикл теперь получен. Следующая задача — иной
управляющий контекст: первый проход должен начинаться с U, последнее
вытесненное слово нужно сохранить, а продолжение не должно повторять цикл.
Дополнительные паузы для уже доказанного замкнутого контекста не помогут.

## Проверенные альтернативы для прямого К1

Параллельно исследована цепочка D6→E7→DD→D4. При требовании сохранять
всё слово именно в A поиск полностью закончился без кандидата: 52 061
состояние с учётом фазы и 3 817 без неё. Это ограниченный класс путей,
не доказательство невозможности К1.

Команда 91 действительно обменивает два полных внутренних числовых
буфера. Более широкий поиск копирований через R/ST/S ограничен 500 000
состояний в каждом направлении и **не завершён**. Он не моделирует
арифметические преобразования или временное хранение слова во внешнем
кольце. Найденный соединением направлений длинный кандидат отвергнут
точной проверкой передачи состояния уже на `35→45→8B→48→B1`:
35 устанавливает R32=F, 45 увеличивает его до 0, а 48 для B1 требует
R32≥4. Подмена этого короткого распознавания клавиши длинным путём через
C5 устранила первое противоречие, но не дала исполнимого продолжения B3→BE.

Исследовательские инструменты: `analyze_k1_carrier.py`,
`analyze_k1_buffers.py`, `check_k1_buffers.py`. Положительный путь в их
упрощённом графе никогда не считается клавиатурным протоколом без
проверки на полном эталоне.
