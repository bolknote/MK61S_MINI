# Селектор 9: высокий R[2] нужен уже до DD

9 сентября 2026 года. Продолжение
[исследования селектора 9](selector9-bootstrap-closure.md).

**Два оставшихся кандидата D4/D6 с низким R[2] исключены.**
Для исследуемого чтения высокий R[2] должен быть готов **до** DD,
создающей девятку. Поднять его только после этой DD и сохранить девятку
до нужного входа не получается ни в одном из допустимых контекстов.

Это не доказательство общей недостижимости C8. Рабочей клавиатурной
последовательности пока нет. R[i] — внутренние тетрады ИК1302,
не пользовательские регистры Пi; адреса ПЗУ записаны шестнадцатерично.

## Что именно исключено

Цель — вход в ROM 60 с одновременными условиями:

```text
R[38]=9, R[26]=1, R[2]≥5, R[25]=R[31].
```

Это начало ранее разобранного чтения 60→18→1B→1D→2E,
а **не сама C8**. Ранее установлено, что последняя команда изменения
R[26] здесь — 62, а последний источник девятки — DD, не 1F.

Теперь исследованы продолжения DD, которая записывает R[38]=9
при исходном R[2]<5. Обход останавливается **перед каждым следующим
присваиванием R[38]**, даже если оно вновь записало бы девятку.
Поэтому отрицательный результат применяется именно к последней DD
перед выбранным входом, не запрещая последующие подготовки вообще.

**Последующее уточнение:** вопрос о готовой единице и повторных чтениях
теперь разобран. Перед первым C8 у последней DD необходим именно
нулевой маркер; положительный прямой путь не требует девятки.
[Новый разбор](dd-zero-marker-and-circular-read.md).

## Настоящие контексты возврата вместо произвольного стека

Исходный анализ от сброса повторён: **52 349 состояний, очередь пуста**.
Из него отдельно выделены DD, присваивающие девятку и выходящие в D4/D6.
Получено **113 пар «выход + точный трёхбайтовый стек»**:

| Семейство | Контекстов |
| --- | ---: |
| D4→26, продолжение записи | 14 |
| D6→2F, продолжение чтения | 10 |
| Возврат сразу в DD | 14 |
| Восстановление через 93, затем DD/E5 | 4 |
| AF/C3/CF, затем DC | 24 |
| 76/E5, затем E6 | 30 |
| A5, затем 1F | 8 |
| A7, затем E6 | 9 |

Набор адресных стеков совпал с прежним набором для четвёрки. Однако
числовые условия и цель отличаются, поэтому результат для четвёрки
не переносился автоматически: для девятки выполнен отдельный обход.

В ключе каждого нового состояния сохранены адрес ПЗУ и **все три
адресных байта стека**. При начальной DD сохранён также допустимый
класс вектора A3 из исходной проекции. Начальные R[26]/R[35] намеренно
не сужены по её таблице; все остальные данные, сигналы клавиатуры
на каждом такте и последовательные входы кольца произвольны.

## Завершённое покрытие

Для всех 113 начальных контекстов вместе:

- **3 128 пересчётов** переходов;
- **1 629 контекстов** с точным стеком;
- **165 адресов ПЗУ**;
- очередь пуста, указанной цели нет;
- конечные команды: 1F, 59, 7C, 85, B3, CD, DD, DE, E6.

Все конечные команды заново присваивают селектор. Ожидания и циклы
внутри покрытия не ограничены заданным количеством повторений.

Независимая от кода построения покрытия проверка также завершилась:
**113 непустых начальных классов, 1 512 замкнутых переходов покрытия**.
Для всех 113 начальных D4/D6 подтверждён настоящий возврат через
исходный верхний байт с точным вращением всего адресного стека.

Использованы прежние независимые инварианты от сброса, включая
исключение 7E с типом 7 и ненулевым маркером. **Новая лемма о запрете
77 с девяткой в этот запуск не подмешивалась** (`selector9_gate=False`).
Таким образом, закрытие D4/D6 не зависит от её дополнительного отсечения.

Остальные 14 выходов DD с низким R[2] уже закрыты отдельными завершёнными
обходами в предыдущем отчёте. Вместе результаты покрывают все 16 выходов
DD, создающей девятку, при низком исходном режиме.

## Положительный контроль: высокий режим сам по себе не спасает путь

Чтобы не принять пустую модель за доказательство, проверен точный путь
с искусственным исходным состоянием:

```text
DD: R[0]=8, S1=6, R[26]=0, R[35]=5,
    вектор FF, стек 2F/AC/9A

DD → D6 → 2F → 21 → 22 → 36 → 37 → 38 → 06 → 07
   → 6D → 6F → 62 → 6E → 61
   → три увеличения счётчика → 60 с девяткой и маркером 1.
```

Он совместим для **каждого начального R[2]=5…F** и несовместим при
R[2]<5. Это математический контроль границы, не найденный штатный вход:
одновременная достижимость исходных служебных полей клавишами не доказана.

Продолжение чтения до следующей DD тоже совместимо, но **обязательно
даёт ей R[0]=F**. Она записывает селектор 0, а не нужный 4.
Полная проверенная цепочка из 110 переходов до C8 несовместима.
Следовательно, одного получения высокого R[2] перед этой конкретной
подготовкой недостаточно — конфликт числовых данных остаётся.

## Куда переместился открытый вопрос

Вариант «получить девятку при низком режиме, а потом поднять режим,
не потеряв девятку» исключён для выбранного входа. Искать подготовку
нужно раньше DD: совместно с её R[0]=8 уже требуется R[2]≥5.

Следующий предмет разбора — происхождение этого высокого R[2] и порядок
DD/62. В частности, в проекции семейства D6/2F маркер 1 допускается
только у стеков **2F/6E/08 и 2F/6E/78**. Нужно отдельно установить,
не требуют ли такие подготовки уже более раннего нужного входа 60,
а не принимать их за независимую точку начала. Это пока гипотеза для
следующей проверки, не результат настоящего покрытия.

Иные маркеры, другие высокорежимные ветви и более поздние присваивания
селектора данным отрицательным результатом не исключены.

## Воспроизведение

```sh
python3 tmp/ms-rom-reachability/analyze_dd_contexts.py --selector 9 --verbose
python3 tmp/ms-rom-reachability/analyze_dd9_stack_lifetime.py --check-certificate --expect-excluded
python3 tmp/ms-rom-reachability/check_selector9_shift.py
node tmp/ms-rom-reachability/check_selector9_keyboard.cjs
```

Новый запуск сам получает начальные контексты из завершённого анализа
от сброса; таблица стеков для девятки не задана вручную. Проверка
сертификата отдельно проверяет включение каждого начального класса и
каждого точного перехода в итоговое покрытие, не используя код
проекции, объединения доменов или рабочей очереди.

Регрессия прежнего селектора 4 после параметризации инструмента:
**2 665 пересчётов, 1 082 контекста, очередь пуста**; дополнительно
успешно проверены **10 начальных классов и 1 021 переход покрытия**.
Повторены семь универсальных фактов о чтении, положительные и
отрицательные пути для четвёрки, 12 фактов о возвратах и две цепочки
восстановления, а также два клавиатурных опыта для девятки.

ПЗУ, эталонный эмулятор и прошивка MK61S не менялись. Все изменения —
исследовательские проверки и отчёты в `tmp/ms-rom-reachability`.
