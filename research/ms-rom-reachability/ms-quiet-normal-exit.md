# Верхний цикл с удалением всех дополнительных меток

12 сентября 2026 года. Продолжение `ms-quiet-upper-cycle.md`.
**Это условное чтение/возврат верхних четырёх слов, не полная К1.**
Нижняя Ms и ряд обычных регистров остаются рабочими; прежние значения
этих мест не спасены. Новое достижение — нормальная геометрия кольца
после возвращения верхних чисел, без оставшейся метки W.

## Проверенный результат

**Итоговый защищённый вариант** прошёл базовый набор во всех трёх фазах
и смешанный набор с отрицательными порядками в фазе 1. В фазах 0/1 после
выхода проверены ручное 2+3=5, отдельное обнуление X и запуск сохранённой
программы с результатом 5. Для базовой фазы 0 со всеми этими проверками
полные JSON-состояния и результат начального видимого контроля сравнивались
через `deepEqual` с отдельным запуском без наблюдателя — совпали:

```text
a129f31b1706bc860ceba086a4af57594e517a0a8588bdd5b2ef7100c6c764ca
```

Пусть a/b/c/d — исходные P7/P8/P9/P10 в физической Ms. В конце:

- все четыре полных слова верхней Ms равны исходным, включая служебные поля;
- точные 12-тетрадные копии a/b/c/d находятся в обычных П0/П4/П6/П5;
- единственная M2-метка находится в штатном слове marker;
- control = `1F0000000000`, видимые X/Y/Z/T = 0;
- исходные 105 шагов программы сохранены;
- нижняя Ms = `h,g,d,1F…`, а не её исходные четыре значения;
- обычные П2=m, П3=0, П7=b, A/E=m; это расходуемая рабочая область.

Первоначальный хвост без дополнительной нулевой защиты для
a/b/c/d=1111/2222/3333/4444 во всех трёх фазах прошёл строгие проверки
восстановления и удаления меток. Отдельный запуск без наблюдателя в фазе 2 дал тот же SHA-256
полной JSON-сериализации калькулятора:

```text
b162a70026c7e114c9f5427870f59b0e47531a88b7117a61078c44b3200978dd
```

На предварительном варианте после выхода в фазах 0/1 проверены обычное `2 ↑ 3 +` и запуск сохранённой
программы; X=5, все обычные регистры, Ms и 105 шагов удержаны относительно
состояния после цикла. Независимый review заметил, что одинаковое число
до/после запуска само по себе недостаточно: тест усилен отдельным Cx и
обязательным X=0 перед запуском, затем требуется X=5. Усиленная проверка
в фазе 0 прошла. Её же прошёл новый защищённый отрицательный набор в фазе 1,
описанный ниже. Это два отдельных опыта, а не одно неизменившееся показание.

## Как удалена W

Внутри предыдущего возврата уже существуют дубликаты b/c в П7/П6.
Поэтому П2 можно использовать для m, а П3 для 0. Перед перезаписью
П4=b его прежнее a сохраняется в П0. Исходное П0 здесь **расходуется**,
поэтому эту перестановку нельзя объявить сохраняющей оба банка полной К1.

После возвращения a/b/c/d выполняется следующий точно наблюдённый путь:

| Этап | Видимый стек/запись | Смысл |
|---|---|---|
| Cx | P8 := 0 | b уже продублировано в П4/П7 |
| RCL 9 | D6(M1 Q=0), видимый подъём X=0; поздняя запись P8=0 | **Новая защита:** перед постановкой видимой метки числовой X заменён нулём |
| RCL 8 | D6(M1 W=m), видимый подъём; поздняя запись P8=m | Получена видимая X=m и её лишняя копия P8=m |
| RCL B | D6(M1 P8=d), подъём X/Y/Z/T | Метка X переходит в Y |
| Cx | P8 := 0 | Удалена лишняя верхняя копия метки |
| RCL 0 | D6(M1 P7=b), видимый подъём; EE(X=b)→E7(P8) | Метка Y переходит в Z, а P8 восстанавливается значением b |
| RCL 5 | D6(M1 P8=d), видимый подъём; EE(X=d)→E7(W)→47 | Метка Z переходит в T, W заменяется числом d **одиночной** записью |
| RCL 0 | D6(M1 U=a), видимый подъём | T-метка вытесняется; остаётся только штатная |
| Обычная очистка | X/Y/Z/T := 0 | Возврат к обычному видимому стеку |

Здесь B обозначает селектор `/-/`, а не обычный регистр B при сдвинутой
адресации. Таблица описывает реальные физические источники, а не догадку
по надписям клавиш. В частности RCL 0 сначала берёт обычное П4, а после
удаления W — уже обычное П0. Это установлено трассировкой D6.

Последние два существенных переноса в защищённом смешанном журнале:

```text
EE(X=b) 438539 → E7(P8=b) 438593 → 47
EE(X=d) 445259 → E7(W=d) 445310 → 47
```

Проверка сравнивает все 630 тетрад до/после каждого E7/A8-подъёма
и одиночной записи; последняя затрагивает ровно 12 числовых M2-тетрад
нужного слова. Служебные тетрады, M1 и программная дорожка при очистке
не меняются даже временно. a/c/d остаются в верхней Ms на всём хвосте.

## Числовые границы не исчезли

Для канонического ненулевого числа q=s+δ, где s — число подавленных
нулей, δ=1 для обычного десятичного представления и 0 для научного.
Нормализатор EE→40 занимает ровно 39+q команд. Доказаны оба знака и
все мантиссы каждого из 24 классов для каждой геометрии:

| M2-метки | q | Последняя одиночная запись |
|---|---|---|
| marker/Z/W | 0…4 | V — не нужное P8 |
| marker/Z/W | 5…8 | P8 |
| marker/T/W | 0…5 | W |
| marker/T/W | 6…8 | P8 — W остаётся |

Вместе с условиями предыдущего читателя/возврата текущему целому циклу
нужны **q(b)=5, q(c)≤5, 4≤q(d)≤5**. Это **необходимые, не достаточные**
условия. Они являются условными контрактами для двух
конкретных EE-входов; они сами не доказывают достижимость всех предыдущих
клавиатурных этапов для произвольных данных. Нули/неканонические слова
не покрыты новыми формулами. Произвольные человеческие паузы не доказаны.

Неудачные промежуточные решения не подменяют успешный хвост:

- без Cx после переноса X→Y остаётся P8=m; последующий путь сдвигает W
  в Q и портит c, хотя копия c в П6 ещё спасена;
- без предварительного П4=b поздняя запись восстанавливает в P8 число a,
  а не b; W удалена, но верхний банк ещё не возвращён.

Отдельный полный отрицательный опыт **без нулевой защиты** использует фазу 1 и верхние числа
`−1E−99 / −1.23E−42 / 3333 / −1.234E−42`. Они удовлетворяют приведённым
q-ограничениям, но клавиатурный вход не проходит. После появления X=m
в Y остаётся b=`958912300000`. 9C принимает **Y за control** (команда
419460), поэтому RCL B читает D6(M1 T=m), а не D6(M1 P8=d).
Следует подъём P8/P9/P10/marker (419498), а следующий Cx стирает
саму штатную marker (425111). Это не успех с иной индикацией, а порча
дальнейшей адресации. Точный ложный control, источник, четыре записи и
стирание marker закреплены `check_ms_quiet_normal_exit_negative.cjs`.

Этот конкретный дефект уже исправлен дополнительным RCL 9 из П3=0
перед RCL 8. D6(Q) читает ноль, видимый подъём кладёт его в X; следующий
подъём метки даёт X=m, **Y=0**. Поэтому 9C больше не принимает Y за control,
и RCL B читает именно M1 P8=d. Тот же смешанный набор в фазе 1 прошёл
полный проверяющий код: верхние числа/копии сохранены, метки удалены,
счёт и запуск программы после нулевого контрольного X дают 5.
Защита включена в `probe_ms_quiet_normal_exit.cjs` по умолчанию;
`zeroBeforeMarker:false` оставляет воспроизводимый отрицательный вариант.
Это устраняет данный контрпример, но не превращает условия отдельных
EE-входов в доказательство всего клавиатурного протокола для всех чисел.

## Воспроизведение

```sh
node tmp/ms-rom-reachability/check_ms_quiet_normal_exit.cjs
node tmp/ms-rom-reachability/check_ms_quiet_normal_exit_keyboard.cjs
node tmp/ms-rom-reachability/check_ms_quiet_normal_exit_negative.cjs
MS_NORMAL_EXIT_UNOBSERVED=1 node tmp/ms-rom-reachability/check_ms_quiet_normal_exit_keyboard.cjs
MS_FORMAT_MARKERS=W_Z python3 tmp/ms-rom-reachability/check_ms_numeric_formatter_phase.py
MS_FORMAT_MARKERS=W_T python3 tmp/ms-rom-reachability/check_ms_numeric_formatter_phase.py
```

`probe_ms_upper_w_cleanup.cjs` сохраняет исследовательские варианты;
`probe_ms_quiet_normal_exit.cjs` задаёт конкретный положительный хвост.
Прокси проверяет отсутствие скрытых чтений и изменений: только клавиши,
ожидания и один ранее объявленный видимый контроль клонирования W.
Итого без защиты 133–135 клавиш / 812–832 кадра; защита добавляет
две клавиши и 12 кадров. Отдельная фикстура в эти числа не входит.

Эталон и ПЗУ не изменены; их контрольные суммы заново совпали.

Выполнены: четыре защищённых нативных случая, отдельный старый
незащищённый отрицательный контроль, два полных прохода символьного
форматировщика по 24 класса, регрессия прежней геометрии cloned,
поверхностный прокси и полное сравнение без наблюдателя. Наблюдатель
может прореживать **только журнал** до этапа 32; ни клавиши, ни паузы
от содержимого журнала не зависят. Произвольная программа и весь
диапазон чисел после выхода этим конечным набором тестов не доказаны.

## Что осталось до цели

Полный обмен не получается склейкой нижнего и верхнего циклов:
они расходуют исходные значения друг друга ещё до появления буферов.
[Аудит размещения](k1-bank-allocation-audit.md) предлагает более экономный
однопарный захват без чужих регистров. Там уже удержаны обе стороны пары,
но обратная запись пока не замкнута.

[Ремонт control](control-repair.md) доказал ограниченные свойства ACK,
но не снял числовые ограничения. Общая точная К2 на неизменённом цифровом
MK61 по-прежнему исключается инвариантом; [независимая проверка](k2-independent-review.md)
усилила его контрпримером, где весь программный банк равен 22.
