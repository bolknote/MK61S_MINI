# ENTER после сохраняющего Y/T-входа: первая потеря u

26 сентября 2026. Нативный отрицательный контроль неизменённого
эталонного МК-61. Проверяется **один конкретный хвост**, не общая
невозможность ENTER, иного продолжения или полной K1.

## Точный запуск

`k1-y-t-entry.cjs` фиксирует clonePrefix=[], cloneKeys=[↔], clonePhase=0.
Параметр `afterClone:[['В↑']]` передаётся в `deep.finish` без изменения;
это одна клавиша ENTER, без дополнительного ведущего кадра, затем
восемь кадров ожидания. Префикс каждый раз исполняется на свежем
калькуляторе с клавиатурно подготовленной фикстурой. Импорта состояния
или исправления памяти между действиями нет.

Перед хвостом:

```
П0=w; X1=q; X/Y/Z/T=v/m/q/m;
Ms U/V/W/Q=v/u/q/p; верхние a/b/c/d; метки real/Y/T.
```

Здесь u=−12345678 (`007912345678`), v=−9.8765432E−17
(`983998765432`), m=`9990FFFFFFF0`, a=−1E−99; остальные
числа — стандартная различимая фикстура Y/T-входа.

## Где именно исчезает u

| Номер команды в пассивной трассе | Действие |
|---|---|
| 774492 | 9C(control), принят заголовок `3F0000000000` |
| 774513 | EE(U) читает v, возврат E0 |
| 774515 | A7(W), поиск до настоящей метки |
| 774524…774527 | E7(X), A8(Y/Z/T): видимые становятся v/v/m/q |
| 774554 | Поздняя EE(X) снова читает v, возврат E3 |
| **774604** | **E7(V) записывает v поверх единственного u** |

Сам видимый подъём безопасен: вытесняется только старая метка из T.
u всё это время остаётся в Ms V без изменений. Разрушение происходит
позже, при возвращении форматировщика, а не при чтении ENTER или
перемещении видимого стека.

Первая изменённая тетрада единственного u: **ИК1302, E7, V[1], 8→2**.
Всего поздняя E7 пишет точную 12-тетрадную копию v; это не арифметическое
искажение числа. Новая метка Z направляет позднюю запись в V=Z+3.
Непосредственно перед этой командой u присутствует ровно один раз
среди 23 хранимых и X1/X/Y/Z/T; после команды его в этих местах нет.

После хвоста:

```
П0=w; X1=q; X/Y/Z/T=v/v/m/q;
Ms U/V/W/Q=v/v/q/p; верхние a/b/c/d; метки real/Z.
```

## Что проверяет регрессия

`k1-y-t-enter-negative-check.cjs` проверяет точные источники двух EE,
видимый push (48 записей), позднюю копию V (12 записей) и все 630 тетрад
кольца вокруг обоих переносов. Во всём хвосте запрещены любые другие
изменённые тетрады. E9 и A3 отсутствуют. Программа, служебные поля,
14 прочих обычных регистров и верхняя четвёрка Ms удержаны, включая
временные записи. Исчезает только исходное u, на конечной границе.

```
node tmp/ms-rom-reachability/k1-y-t-enter-negative-check.cjs
K1_Y_T_ENTER_UNOBSERVED=1 node tmp/ms-rom-reachability/k1-y-t-enter-negative-check.cjs
```

Второй режим дополнительно сравнивает полное сериализованное состояние
со свежим повтором без наблюдателя. Полный диагностический журнал
доступен через `K1_Y_T_ENTER_AUDIT=1`.

Обе проверки прошли. Полные состояния с наблюдателем и без него
совпали, SHA256:

```
3fd34bf22f9607c2583a1bee4dafc20e9d1f850caed54ae1fecb29a887be77d2
```

Отсутствие u утверждается для хранимых чисел и пяти видимых/временных
числовых регистров, а не для всех возможных кодировок во внутренних
полях трёх микросхем. Другие фазы, иной числовой договор и другие
продолжения этим отрицательным тестом не исключены.
