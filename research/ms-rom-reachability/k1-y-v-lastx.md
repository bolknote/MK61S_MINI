# Условный читатель p с предварительными Y/T/V-метками

26 сентября 2026. Доказан связанный первичный путь исходного ПЗУ,
но **клавиатурная подготовка именно этой раскладки не получена**.
Нативных запусков этого кандидата здесь нет.

**Дополнение 29 сентября:** [Z-backed-подготовка](k1-z-backed-lastx.md)
достигает этой геометрии клавишами и проходит тот же LastX-суффикс
на двух наборах с точным нативным аудитом. Распределение исходников
другое: U=u, X=u, Z=v, W=q. Поэтому конкретную карту ниже нельзя
переносить по именам чисел; доказанный подъём имеет общий вид
`старое Q / старое X / старое Y / старое Z`, затем `V←старое P7`.
Прежнее отсутствие клавиатурной подготовки больше не является текущим итогом.
Чистого выхода и полного К1 это дополнение ещё не даёт.

## Договор входа и результат

```
До:    X/Y/Z/T=u/m/q/m; Ms U/V/W/Q=v/m/q/p; верхние a/b/c/d.
После: X/Y/Z/T=p/u/m/q; Ms U/V/W/Q=v/a/q/p; верхние a/b/c/d.
```

Предпосылки: сохранена настоящая метка, ложные метки только Y/T/V;
LastX принят 9C на физической Z, R30=F, R33=0, S1=F; q удовлетворяет
обычному условию приёма 9C; a — каноническое число класса форматирования
7 или 8. W исходно содержит обычное q, **не метку и не верхнее a**.
Обычный П0=w и остальные поля кольца не записываются этим первичным
суффиксом. Заявления о других чипах относятся к ещё не выполненному
нативному тесту, а не следуют из локального доказательства.

Реальная Y-метка делает 9C(Z) допустимым выходом штатного 9B-сканера.
Это отличие от геометрии real/T/V, где обычный сканер такой вход
исключает. Сам выбор Y вместо других меток клавишами пока не проверен.

## Связанный путь

```
9C(Z) → 9E(T) → 8C(U) → ... → 8D(Z)
→ 4F(T) → FF(U) → E5(V) → E6(W) → EE(Q)
→ F0(P7) → E0(P8) → A7(P9) → E5(P10/real)
→ E6(control) → E8(X1) → E7(X) → A8(Y/Z/T) → A9(U)
→ E1(V) → ... → E2(T) → E5(U/V) → E6(W) → ED(Q)
→ EE(P7), возврат E3.
```

Проверка связывает каждую команду с предыдущей, не подставляет
промежуточные регистры. До второго EE происходят только 48 точных
числовых записей видимого подъёма. Новый X=p, Y=u, Z=m, T=q;
старый T=m вытеснен. Остальная память цела. После подъёма метки только
real/Z/V; это также установлено символически, а не предполагается.

Второй EE точно читает a из P7 и возвращается в E3. Пять канонических
случаев позднего форматирования покрывают все классы 7/8: научные ветви
обоих знаков порядка, десятичные ветви классов 7/8 и точный ноль.
Во всех поздняя E7 пишет точные 12 тетрад a в V. Ненужная V-метка
удаляется, исходное a остаётся также в P7, единственные оставшиеся
метки — real/Z.

Это одновременно резерв p в X и снятие V, но ещё не закрытый выход.
u остаётся в Y, а q продублировано в W/T; верхняя четвёрка не изменена.
Ни полноценный межбанковый обмен, ни повторяемость отсюда не следуют.

## Отличие от нового нативного clone-↔

Найденная root сохраняющая подготовка clone-↔ заканчивается иначе:
X/Y/Z/T=v/m/q/m, Ms U/V/W/Q=v/u/q/p, метки real/Y/T, **без V-метки**.
Этот положительный нативный результат не является входом настоящего
доказательства: нельзя считать обычное V=u меткой или заменить X=v
на требуемое u. Соединение двух результатов пока отсутствует.
