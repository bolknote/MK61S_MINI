# Число из V получено, выход из Y/T замкнут

27 сентября 2026. Продолжение исследования неизменённого ПЗУ МК-61.
**Ближайший барьер пройден:** после сохраняющей подготовки Y/T повторная
↔ читает физическую V в X. Найден также сохраняющий выход: все 23
исходника возвращаются в хранимый банк, ложные метки удалены, ручной счёт
и сохранённая программа работают. Это **не полный К1 и не новая верхняя
пара**: четыре верхних слова в этом проходе вообще не изменяются.

## Результат простыми словами

Раньше обычные читатели обходили нужную V, а ближайшее продолжение
затирало её содержимое. Теперь другая микросхема читает V и передаёт
полное число в X. Побочный эффект первичной микросхемы тоже учтён:
число дополнительно записывается в W, а прежнее W пережидает в X1.

Нельзя оставлять его там и бездумно продолжать: X1 перезаписывается
при создании следующей метки. Поэтому новый выход сначала убирает T,
затем возвращает резерв из X1 в стек и из стека — в нижнюю Ms.

Обозначения — исходные числа: p из обычного П0, u/v/w/q из Ms U/V/W/Q,
a/b/c/d из верхних Ms P7/P8/P9/P10. Физическая V на новой точке входа
содержит **u**, а не исходное v.

| Стадия | Обычный П0 | Ms U / V / W / Q | Где ещё нужен резерв | Ложные метки |
|---|---|---|---|---|
| Исходная фикстура | p | u / v / w / q | — | — |
| Сохраняющая подготовка Y/T | w | v / u / q / p | Все числа в хранимом банке | Y, T |
| Новая ↔ | w | v / u / u / p | q только в X1; u также в X | T |
| Новый выход | w | q / v / u / p | Все числа снова в хранимом банке | Нет |

Итоговая перестановка исходников — цикл
`П0 → Ms Q → Ms U → Ms W → П0`; остальные 19 слов, включая Ms V, неизменны.
Данные не возвращены на исходные места, но каждое исходное число
сохранилось ровно один раз в 23 хранимых словах. Это проверенный частный
цикл, не обмен П0…П7 со всем Ms и не доказательство повторяемости.

## Почему работает повторная ↔

[Исходный вход](k1-y-t-entry.md) даёт:

```
П0=w; X1=q; X/Y/Z/T=v/m/q/m;
U/V/W/Q=v/u/q/p; upper=a/b/c/d; markers=real/Y/T.
```

`m=9990FFFFFFF0`. После обычной ↔ без дополнительного ведущего кадра
и с восемью кадрами ожидания происходит следующее:

1. ИК1302 читает W=q и делает точную E9(X1)←q. Резерв уже был там;
   запись идемпотентна, но её источник и порядок важны.
2. A3 пишет запрос 14h в три тетрады Z. Полное q в Z теперь испорчено,
   но его копия в X1 цела.
3. ИК1303 начинает от Y-метки: `6E(Y) → 5E(Z) → 50(T) → 52(U) → 53(V)`.
   Таким образом, источником является именно V=u.
4. Повторный поиск 37 находит настоящую метку; выход `4E(X), 2A(Y)`
   даёт X=u, Y=прежнее X=v. Y больше не метка. **Это не обычный X/Y-обмен.**
5. Поздний форматировщик ИК1302 читает X=u и при проверенном числовом
   классе копирует u в W. q остаётся в X1, поэтому потери нет.

Базовая полная трасса:

```
774500 EE(W=q) → A1
774508 E9(X1) ← q
774511 A3(Z) ← request 14h
774515 ИК1303:53(V) читает u
774525 ИК1303:4E(X) ← u
774526 ИК1303:2A(Y) ← прежнее v из X
774539 EE(X=u) → E3
774590 E7(W) ← u
```

Связанные символические проверки доказывают весь первичный путь от
принятой 9C(control) до A3 и весь вторичный путь от 6E(Y) до возврата
в сканер. Они не подставляют промежуточные процессорные регистры.
Нативный тест отдельно подтверждает действительную стыковку микросхем,
включая полный путь от вторичного чтения V до двух выходных записей.

Поздний форматировщик доказан для канонического десятичного класса 1,
к которому относятся оба проверенных u. Это не доказательство полного
протокола для произвольного u или всех исходных банков.

## Как закрыт выход

После новой ↔ видимые слова равны `X1=q, X=u, Y=v, Z=14q…, T=m`.

- `П→X 0` читает w. Его D6 всегда здесь попадает на физическую U
  обычной памяти, а следующий A7 — на V. Поиск начинается **после T**,
  поэтому подъём приходится на X/Y/Z/T, а не скрытые слова.
  Получается `w/u/v/14q…`; вытеснена только T-метка. X1=q не меняется.
- Обычный LastX (`F В↑`) теперь читает q из настоящего X1. Видимые
  становятся `q/w/u/v`. Ложных меток уже нет, поздняя запись идёт в X.
- Три ENTER дают `q/q/q/q`. Вытесненные v/u/w имеют хранимые копии.
- Ранее проверенный нижний push переносит прежнее T=q в U, прежнее
  U=v в V, прежнее V=u в W. Старое W=u можно вытеснить: оно дублируется.
  Стандартное завершение этого push удаляет созданную им метку.

Для двух допустимых исходных позиций принятия RCL0 (control/U) по ПЗУ
связно доказаны D6(U)→A7(V), точные 48 записей видимого подъёма,
сохранность X1 и всех хранимых слов до позднего EE. Два отдельных
канонических форматировщика доказывают последующую запись обратно в X
для текущих классов w/q при единственной настоящей метке.

В базовой нативной трассе:

```
781233 D6(U, M1=w), 781234 A7(V)
781244…781247 видимый push, вытесняет только m
787978 LastX: EE(X1=q)
787994…787997 видимый push, вытесняет только испорченный запрос Z
793589, 794699, 795824 начала трёх видимых дублирований q
850712…850715 push T/U/V/W, вытесняет дубликат u
```

## Проверки

Проверены два полных клавиатурных набора, без исправления состояния,
импорта памяти или изменения ПЗУ:

| Число | Базовый набор | Другой набор |
|---|---|---|
| p | 201 | 301 |
| u | −12345678 | −23456789 |
| v | −9.8765432E−17 | −9.1234567E−17 |
| w | −7.654321E−23 | −6.543219E−23 |
| q | −1.2345678E−42 | −8.7654321E−42 |
| a/b/c/d | −1E−99 / 9022 / 9033 / 9044 | −2E−50 / −7.654321E23 / 1.2345678E42 / 8.7654321E−17 |

На обоих пройдены:

- 124 границы до нового резерва и 140 границ полного прохода с выходными
  проверками: все 23 исходника присутствуют в хранимых и видимых словах;
- точные E9, три тетрады A3, 24 выхода вторичной операции, поздняя
  копия W и все шесть четырёхсловных подъёмов нового выхода;
- сравнение всех 630 тетрад вокруг переносов и защита программы,
  служебных полей, 14 остальных обычных регистров, четырёх верхних Ms
  и числового слова настоящего маркера;
- итоговая биекция всех 23 хранимых слов по заранее заданной перестановке;
- отсутствие ложных меток; ручное `2 ENTER 3 + = 5`, очистка X и запуск
  сохранённой программы с результатом 5, без изменения числового банка.

Во время самого исследования журнал контролирует временные записи,
не только конечные снимки. При контрольном исполнении пользовательской
программы отдельно проверяются сохранность числового банка и служебных
полей, а все 105 шагов сравниваются до и после; временные M3-поля
этого исполнения не объявляются неизменными.

Полный контроллер с выходными проверками учитывает 197 клавиш и
1593 кадра, без подготовки фикстуры. До нового резерва — 172 клавиши
и 1393 кадра. Доступ контроллера ограничен клавишами, ожиданиями и
публичным индикатором прежних читателей; исходные числа он не считывает.

## Почему нельзя заменить чтение П0 на ENTER

Один конкретный такой хвост закреплён отрицательным тестом. После резерва
ENTER принимается в 9C(U), читает X=u, затем A7(Z) находит T. Поэтому
он пишет **W/Q/P7/P8**, а не видимый стек:

```
780125…780128: W/Q/P7/P8 ← u/u/p/a
780200: поздняя E7(W) ← u, идемпотентно
```

Исходное b из P8 вытеснено из хранимых/видимых слов. Все остальные
поля полного кольцевого снимка проверены. Это точный отказ выбранного
продолжения; другие фазы ENTER и все возможные обходы не исключены.
Именно разбор положения A7 подсказал RCL0, а не перебор длинных цепочек.

без пассивного наблюдателя, с полным сравнением всех сериализованных
полей калькулятора. Это выполнено и для одного резерва, и для полного
выхода с ручным счётом и программой. Также совпал отрицательный ENTER.

## Чего ещё нет

Этот результат закрывает **новую ветвь Y/T**, а не выход после любого
верхнего обмена. Верхняя четвёрка остаётся a/b/c/d; число завершённых
межбанковых пар не увеличено. Для основной цели ещё нужна стыковка
с сохраняющим верхним переносом и полный восьмипарный протокол.

Два набора чисел не доказывают всю числовую область; допустимые паузы
и непрерывное повторение новой композиции не доказаны. Проверки на
физическом калькуляторе для этого блока не проводились.
