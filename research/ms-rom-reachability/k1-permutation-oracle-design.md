# Машинный оракул пригодной перестановки К1

12 сентября 2026 года. Проект теста; тяжёлых трасс не запускалось.
Прочитаны `k1-lastx-v-exchange.cjs`, `k1-bank-v-capture.cjs`, его проверка
и `k1-composition-contract.md`.

## 1. Ровно 23 места, а не все найденные копии

Защищённая проекция B имеет фиксированный порядок:

```text
П0 П1 П2 П3 П4 П5 П6 П7 П8 П9 A B C D E | U V W Q P7 P8 P9 P10
```

Слева обычные M1, справа Ms M2. Имена верхних Ms P7/P8/P9/P10 надо
пространственно разделять, например `ms.P7` и `reg.7`, чтобы не спутать
их с одноимёнными обычными регистрами.

Каждый элемент — **все 12 исходных тетрад**, а не число JavaScript,
отформатированный индикатор или только мантисса. X/Y/Z/T/X1 не входят в B.
Нахождение старого значения только в них не удовлетворяет контракту
повторяемой перестановки 23 защищённых слов.

Снимок до операции должен быть после установки всей явно отдельной
фикстуры, но **до первой живой клавиши операции**. Нельзя передвигать эту
границу за потерю U или исходного П0 и затем считать потерянные данные
новым входом. Для реального универсального протокола сама операция не
имеет права заново вызывать `prepare` с известными значениями.

## 2. Строгий критерий одного различимого нативного опыта

Для открытия новой перестановки требовать 23 попарно различных слова
`before`. Иначе результат — `INCONCLUSIVE_NON_DISTINCT_FIXTURE`, не PASS
и не опровержение правильного протокола. Особенно нельзя принимать
четыре одинаковых верхних нуля за четыре независимо сохранённых слова.

```javascript
function discoverPermutation(before, after) {
  assert.equal(before.length, 23);
  assert.equal(after.length, 23);
  for (const word of [...before, ...after])
    assert.match(word, /^[0-9A-F]{12}$/);
  assert.equal(new Set(before).size, 23,
    'INCONCLUSIVE_NON_DISTINCT_FIXTURE');
  const origin = new Map(before.map((word, i) => [word, i]));
  const dstToSrc = after.map(word => origin.get(word));
  assert.ok(dstToSrc.every(Number.isInteger), 'unknown/generated output');
  assert.deepEqual([...dstToSrc].sort((a,b) => a-b),
    Array.from({length:23}, (_,i) => i), 'missing or duplicated origin');
  return dstToSrc;
}
```

Не достаточно проверки `каждое исходное число где-нибудь присутствует`
по всем слотам или множества индикаторных значений. Здесь точная биекция
требует, чтобы каждый из 23 различных оригиналов занял **ровно одно из
23 защищённых мест**. Дополнительные копии в свободном видимом стеке
разрешены, но не спасают отсутствующий элемент B.

Диагностика должна назвать неизвестные выходы, дублированные оригиналы
со всеми адресами и отсутствующие оригиналы. Это информативнее одного
`assert.deepEqual` и сразу отличает перенос от изготовления константы.

Для полезности отдельно проверить межбанковое ребро: хотя бы один
`dst >= 15` имеет `dstToSrc[dst] < 15`. Тождественная перестановка данных
безопасна, но не новый элемент К1. При заявлении именно V/П0 требуется
конкретный ожидаемый массив, а не любая найденная биекция.

## 3. Не переоткрывать перестановку под каждый удачный ответ

Полученный `dstToSrc` — гипотеза одного опыта. После проверки её надо
зафиксировать как контракт `expectedPi`. Каждый следующий набор данных,
фаза и повтор должны выполнять:

```javascript
assert.deepEqual(after, expectedPi.map(src => before[src]));
```

Перестановку нельзя заново подбирать для каждого результата. Иначе
зависимые от знака, нулей или фазы разные маршруты будут ошибочно
представлены одним генератором группы.

На повторных специальных тестах с совпадающими/нулевыми числами этот
заранее фиксированный массив применим, но такой тест сам по себе не
доказывает происхождение совпавших слов. Нужно хотя бы два независимо
переназначенных различимых набора, не содержащих известных рабочих
констант/меток, плюс числовые граничные классы. В идеале изменение каждого
отдельного исходного слова должно менять только его ожидаемый выход.
Это можно проверять ненаблюдаемыми повторами, не собирая 23 тяжёлые трассы.

**Ни один конечный набор чисел не доказывает универсальность.** Для общего
контракта требуется связанный символьный договор данных, где 23 слова
независимы, и доказательство допустимости управляющего пути на заявленной
области. Нативный оракул честно подтверждает точную перестановку лишь в
исполненных опытах; он не превращает совпадение с константой в доказанную
зависимость от входа.

## 4. Программа и служебные поля проверяются отдельно

В дополнение к B нужны точные снимки:

- всех 105 программных байтов M3;
- M1[36] и M1[39] каждой из 15 физических страниц;
- M2[37] и M2[40] каждой из 15 физических страниц.

На границе операции каждый из них равен исходному. Сравнения только
служебных префиксов восьми Ms недостаточно: они пропускают служебные
поля обычных регистров и семи остальных страниц M2.

Если заявлено отсутствие временной порчи, полный журнал изменённых
записей обязан дополнительно не содержать запись в эти поля или M3.
Для минимального обратимого контракта временный перенос программы
можно разрешить лишь явно, при точном восстановлении и сохранении всех
исходных данных; отсутствие временных записей — более сильная гарантия,
не логически необходимое следствие конечной перестановки.

Журнал должен учитывать все три чипа и все изменённые записи, а не лишь
выбранные события IK1302. Локальный записывающий блок желательно проверять
сравнением **всех 630 тетрад**, чтобы правильные два выходных числа не
скрывали дополнительного повреждения.

## 5. Выход и повторяемость — отдельный обязательный шлюз

Успех биекции нельзя объявлять «пригодным генератором», пока выход не
принадлежит входному классу следующего вызова. Минимальная практическая
регрессия должна содержать в одном непрерывном запуске без геттеров между
операциями:

```text
G → объявленная пауза → G → … → Gⁿ → обычное 2 ENTER 3 +
```

Здесь n — порядок заранее фиксированной перестановки. Проверять B и
защищённые поля пассивно на каждой границе, а не только после Gⁿ:

- после вызова k проекция равна `pi^k(before)`;
- после n вызовов все 23 слова вернулись;
- пауза не меняет защищённую проекцию;
- обычный счёт даёт 5 и не меняет конечные 23 слова, программу и
  дополнительные поля;
- для заранее установленной безопасной тестовой программы её выполнение
  также даёт ожидаемый результат без порчи банков.

Нужны отсутствие ложных F-меток в числовых страницах/видимом стеке и
доказанный предикат штатного сканирования без отложенного опасного запроса.
Одного условия `M22 != F` или одного адреса IK1302 недостаточно: второй
чип может иметь ещё не выданный буфер. Не следует угадывать константы
такого предиката по одному удачному снимку. Пока управляющий предикат
не обоснован, результат следует называть «биекция и повторный вход
проверены на данных опытах», а не универсальным нормальным выходом.

Конечная пауза и арифметика — полезные отрицательные фильтры, но не
доказательство бесконечной устойчивости. Формальный нормальный выход
требует индуктивного управляющего договора, а не только трёх кадров.

`aligned`, `registers`, `program`, `fullMsPages` не вызывать между живыми
этапами: некоторые из них продвигают эмулятор. Границы фиксировать пассивными
снимками кольца. Диагностическое выравнивание после всей транзакции не
должно «доделывать» обмен: его защищённая проекция обязана совпасть с
непосредственным снимком выхода. Полное конечное состояние с наблюдателем
и без него должно совпасть; клавиатурный прокси запрещает скрытые чтения,
присваивания, сброс и импорт.

## 6. Ожидаемый диагноз текущих ветвей

`k1-bank-v-capture` на положительном классе даёт `П0=v, Ms V=v`, а p
остаётся лишь в X/Y. На различимой фикстуре строгий оракул обязан сообщить:

```text
duplicate: old ms.V at reg.0 and ms.V
missing: old reg.0 from the 23 protected slots
exit: false marker remains in Z
```

Это правильный промежуточный захват, но не пригодная перестановка. Новый
LastX-хвост нельзя принимать по тому, что p или u видны в стеке: после
него снова применяется тот же оракул от **первоначальной** границы, до
захвата V. Новые совпадающие копии и известная метка не создают нового
места для независимого исходного значения.

Рекомендуемые классы результата теста:

```text
NON_DISTINCT_FIXTURE
DATA_LOSS_OR_DUPLICATION
PROTECTED_FIELD_DAMAGE
PERMUTATION_INSTANCE_ONLY
PERMUTATION_WITH_CHECKED_REENTRY
FULL_DOMAIN_CONTRACT_PROVED
```

Ни последняя, ни предпоследняя категория сами по себе не означают полную
К1: дополнительно требуется композиция именно восьми целевых пар.
