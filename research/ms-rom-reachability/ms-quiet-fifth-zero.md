# Три верхних копии: пятое слово сохранено через нулевую защиту

12 сентября 2026 года. Новый проверенный этап после
[прямых копий шестого/седьмого слов](ms-quiet-upper-backup.md).
**Не полная К1:** нижняя Ms и обычные рабочие регистры не восстановлены,
исходные входящие банки полного обмена ещё не размещены.

## Результат

Пусть исходная верхняя Ms равна `(a,b,c,d)`. После полного нового протокола:

| Место | Содержимое |
|---|---|
| Обычный П4 | точное исходное a, пятое слово Ms |
| Обычный П2 | точное исходное b, шестое слово Ms |
| Обычный П3 | точное исходное c, седьмое слово Ms |
| Ms P7/P8/P9/P10 | a, 0, b, d |
| Видимое физическое X | a |
| Индикатор | `0,` |

Таким образом, все четыре исходных верхних числа удержаны, но одно из
них уже находится только в обычном регистре: исходное c нельзя терять
или объявлять неиспользованным рабочим местом. Восьмое d не затронуто.
Число в X и число на индикаторе здесь действительно различаются.

## Клавиши продолжения

После ответа 1F нового префикса выполняются группы:

```
X→П 8       # b → обычный П2; возврат доставляет c в X
X→П 9       # c → обычный П3
Сx          # только Ms P8 := 0; старое c уже сохранено
F
В↑          # чтение a из Ms P7, перенос в X
X→П
,           # a → обычный П4
```

После **каждой строки** — восемь кадров эмулятора. Последние четыре
строки намеренно разделены: это не те же кадровые фазы, что две пары
клавиш без промежуточного ожидания. Полный путь вместе с подготовкой —
75–77 нажатий и 456–476 кадров, в зависимости от начальной остановки
по общедоступному защитному показанию. Отдельная фикстура сюда не включена.
Секунды и произвольные аппаратные паузы из этого не следуют.

## Почему теперь получается

1. `Сx` записывает ровно двенадцать нулевых тетрад в P8. Сдвига нет;
   a,b,d, служебные тетрады и программа остаются целыми.
2. Раздельные F/В↑ дают `EE(P7=a) → … → E7(X)/A8(Y/Z/T)`.
   Одиннадцатикомандный связанный контракт сохраняет все двенадцать
   произвольных тетрад a, не только выводимые цифры.
3. Поздний `EE(P8=0)` имеет 47-командную нормализацию и особую ветку
   `40 → 41 → 43 → 46`. Возвратная E7 пишет ноль обратно в P8, не в X.
4. Раздельные X→П/`,` приводят к принятому Q, затем `EE(X=a)` и
   `D4(P7/M1)`, то есть обычному П4. Весь 32-командный участок отдельно
   доказан для произвольного двенадцатитетрадного источника; M2/M3 не пишутся.
5. Следующий форматировщик снова возвращает ноль в P8. Сохранённое a
   остаётся и в П4, и в X; исходное a в Ms P7 также не изменено.

## Проверки

- `check_ms_quiet_fifth_zero.cjs`: три полных нативных сценария прошли,
  по одному на каждую исходную фазу. Проверены базовые a/b/c/d,
  a=−7.654321E23 и **a=−1E−99**, научная запись b/c и соседнее d=−1E−99.
  Точные блоки сверяются по всем 630 тетрадам и по журналу каждой записи;
  все 105 шагов программы сохранены.
- `check_ms_quiet_lastx_path.py`, `check_ms_zero_formatter.py` и
  `check_ms_quiet_store_path.py`: связанный разбор оригинального ПЗУ,
  выполнимость предпосылок и отсутствие символьных контрпримеров; все прошли.
- `check_ms_fifth_zero_keyboard.cjs`: прокси предоставляет только клавиши,
  кадры и исходное публичное защитное показание. Доступ к фикстуре,
  скрытым регистрам, импорту состояния и внутренним тактам запрещён.
- Полное конечное состояние с наблюдателем и без него совпало:
  SHA‑256 `9077b4438bb3c700430d776c085fbb5c17451fe1711bedc9a9ed9feb05655f93`.
- Отрицательный `MS_FIFTH_ZERO_NEGATIVE=1`: объединённая последняя пара
  X→П/`,` принимает другое управление, читает P8=0 и сохраняет ноль
  вместо a. При этом a продолжает существовать в X, Ms и программа
  сохранены. Следовательно, защита от форматировщика сама по себе ещё
  не доказывает правильный источник следующей записи.
- `check_ms_quiet_lastx_negative.cjs`: прежний вариант без нулевой
  защиты читает a, но затем заменяет его c; также выполнен успешно
  именно как отрицательный контроль.

## Границы и следующая работа

Начальный префикс и прямые копии по-прежнему требуют канонических
ненулевых b/c с s+d≤5. Доказательство локальной произвольности a не
делает весь клавиатурный путь универсальным для нечисловых слов или
произвольного расположения меток. П2/П3/П4, П6/A/E и нижняя Ms рабочие;
их исходные значения не считаются сохранёнными.

Следующий шаг — сохранить d, затем восстановить нормальную геометрию
меток и собрать двустороннюю верхнюю запись. После этого всё ещё
необходимо разместить оба исходных восьмисловных банка и сохранить
обычные П8…E, чтобы выполнить [полный контракт К1](full-commands-contract.md).
