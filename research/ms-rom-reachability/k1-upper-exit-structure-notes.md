# Альтернативы выхода из верхнего вращения: NOT и порядок u/q

26 сентября 2026 года. Это ограниченные структурные пробы на неизменённом
эталонном эмуляторе. Замкнутый выход, полная К1 и общая невозможность не
установлены. Файлы эмулятора и ПЗУ не менялись.

## Полезный резерв через NOT

После `k1-preserving-upper-rotation`, один дополнительный кадр, `K Сx`
(логическое NOT) дали:

```
П0=w; U=v,V=m,W=3A3…,Q=p; P7/P8/P9/P10=b/c/d/a;
X1=b; X=INV(b); Y=a; Z=u; T=q.
```

Для b=9022 `INV(b)=00008FDDFFFF`; это НЕ метка, поскольку первая тетрада
мантиссы равна 8, не F. Все 23 исходника присутствуют на границах действий.

Полная пассивная трасса выделила:

```
804747 9C(control) -> 804757 EE(P7=b) -> 804763 E9(X1=b)
-> 804770 A3(W=3A…)
804787 позднее EE(P7=b) -> 804839 E7(X=b)
```

В конечном X уже INV(b): логическая обработка не эквивалентна обычной
арифметике над P7 при той же V-метке. Нельзя переносить адресацию одной
вторичной команды на все остальные.

Следующее `K 8` при той же фазе сохраняет исходники, но делает P7=0,
X=X1=b. Оно читает b из P7, а не ранее полученный видимый INV(b).

Отрицательный тест: `K Сx; В↑; K 8`, с ожиданиями 8/10/8 после действий,
теряет q. После NOT этот ENTER поднимает обычный видимый стек и выталкивает
q из T. Контракт верхнего ENTER после канонического X сюда не переносится.
Без дополнительного кадра перед NOT другая ветка также плоха: Q заменяется
на a, P7 на INV(a), исчезают p и b.

## Другая фаза глубокого клонирования

В `k1-repack-deep-clone-probe` замена `clonePhase:1` на 2 при SIGN даёт:

```
П0=w; U=v,V=u,W=q,Q=p; верхние a/b/c/d;
X1=q; X=m; Y=328912345678; Z=q; T=m.
```

Это полезный полный резерв q в X1 с сохранением 23 исходников, но метки
V/W ещё не созданы. Y уже не является исходным u. Прямой LastX читает u
из V, однако поздняя запись U=u затирает v; отложенный SIGN оставляет X=-1.

Вариант с `clonePrefix:['F'], cloneKeys:[','], clonePhase:2` без иных
изменений также отрицательный: X=v,Y=q,Z=m,T=m,X1=q,V=m, и исходный u
утрачен. Сначала служебный запрос портит Y=u, затем метка заменяет V=u.

## Безопасная перестановка подготовки

Перед `marker-0` можно вставить:

```
F ,; ↔; F ,; F ,; F ,; ещё два кадра ожидания
```

Эта сопряжённая перестановка меняет местами Y и Z в обычной, ещё не
помеченной видимой раскладке. Затем `F ,` с `clonePhase:2` нативно даёт:

```
П0=w; U=v,V=m,W=q,Q=p; верхние a/b/c/d;
X1=INV0; X=q; Y=u; Z=m; T=m.
```

Все 23 исходника живы. Это другой single-V вход: u/q переставлены
относительно прежнего. Ожидаемый резерв u в X1 НЕ появился — изменилось
управление из-за другого числового источника. Поэтому полезный результат
здесь именно переставленная раскладка, а не дополнительный регистр.

Диагностические опыты используют `k1-frame-boundary-probe`: снимки
пассивные, без синхронизирующих чтений и без импорта состояния. Кроме
описанной полной трассы NOT, это проверки границ действий, не доказательства
отсутствия временной порчи между ними. Отдельное полное сравнение с запуском
без наблюдателя для новых вариантов пока не выполнено.

Воспроизведение:

```
node tmp/ms-rom-reachability/k1-upper-exit-structure-probe.cjs not-reserve
node tmp/ms-rom-reachability/k1-upper-exit-structure-probe.cjs not-fraction
node tmp/ms-rom-reachability/k1-upper-exit-structure-probe.cjs not-enter-negative
node tmp/ms-rom-reachability/k1-upper-exit-structure-probe.cjs q-reserve
node tmp/ms-rom-reachability/k1-upper-exit-structure-probe.cjs q-lastx-negative
node tmp/ms-rom-reachability/k1-upper-exit-structure-probe.cjs q-rotate-negative
node tmp/ms-rom-reachability/k1-upper-exit-structure-probe.cjs swapped-v
```

Модуль экспортирует `swapped.finish`; суффикс можно передавать штатными
`afterClone`, `afterClonePhase`, `afterCloneWaits`, не изменяя core.

## Переставленный вход действительно достигает верхнего вращения

`k1-swapped-upper-rotation.cjs` после него исполняет `0; K0; 0; F,`,
с ожиданиями 8/10/9/8, без прежних двух дополнительных кадров после клона
(их уже обеспечивает clonePhase=2). Проверенный нативный результат:

```
П0=w; U=v,V=m,W=2F3912345678,Q=p;
P7/P8/P9/P10=b/c/d/a; X1=X=Y=a; Z=q; T=u.
```

Все 23 исходника живы на границах. Это не замкнутый выход: два исходника
по-прежнему вынесены из хранимой памяти.

Структурная проба `+1 кадр; F,` после него проверена полной трассой:

```
838340 9C(W) -> 838349 EE(X=a) -> 838356 E9(Q=a)
838379 позднее EE(X=a) -> 838432 E7(P7=a)
```

Она теряет p и b. Новое T=u не помогает этой фазе: T вообще не выбирается
как слово управления. Видимые q/u переходят в Y/Z, но ценой необратимых
для этого продолжения перезаписей Q и P7. Обобщение на все фазы не делалось.

## Неудачные попытки оставить метку X во время клонирования

Замена SIGN на fraction (`K8`, clonePhase=1) действительно сохраняет X=m
и T=m, но портит Y=u до `0F7912345678`, уже заменив V на m: u теряется.
Замена на ABS (`K4`, та же фаза) также портит Y, дополнительно заменяет
P7 на m и теряет a. Нельзя считать эти команды нейтральными над m,
опираясь только на обычный математический смысл ABS или fraction.

```
node tmp/ms-rom-reachability/k1-upper-exit-structure-probe.cjs fraction-clone-negative
node tmp/ms-rom-reachability/k1-upper-exit-structure-probe.cjs abs-clone-negative
node tmp/ms-rom-reachability/k1-swapped-upper-rotation.cjs
```

Следующая достаточная, но ещё не достигнутая цель выхода: убрать T-метку
без дополнительного видимого подъёма, оставив u/q в Y/Z и дубликат в T.
Тогда чтение Q сможет вынести p, не выталкивая единственный исходник.
