# Сохраняющий выход из глубокого входа V/W

26 сентября 2026 года. Продолжение сохраняющего [входа V/W](k1-preserving-vw-entry.md).
ПЗУ и эталон не изменялись; новых аппаратных опытов не было.

**После глубокого входа удалось убрать все лишние метки и вернуть
все 23 исходных числа в хранимые слова.** Дополнительный обычный регистр
и временное занятие физического маркера не понадобились. Пройдены
нативные проверки и проверки ручного счёта / сохранённой программы.
Это замкнутый по местам хранения **одноразовый условный проход**, не
полная К1: верхние четыре слова пока неизменны, нижние переставлены.
Непрерывное повторение и общий числовой/временной договор не доказаны.

Важная граница: это продолжение исходного глубокого входа **до** вращения
верхних слов. Его нельзя автоматически приставить к прежнему верхнему
вращению или [origin-shift](k1-upper-origin-shift.md): там другие метки,
видимая раскладка и числовые источники.

## Почему прежний LastX мешал

После глубокого SIGN:

```
П0=w; X1=INV0; X/Y/Z/T=1/u/q/m;
U/V/W/Q=v/m/m/p; верхние=a/b/c/d;
m=9990FFFFFFF0, INV0=00008FFFFFFF.
```

LastX поднимал видимый стек, перемещая u/q в Z/T. Тогда поздняя запись
в T уже уничтожала q. НОП позволяет запустить позднее форматирование
**без этого подъёма** и без E9 или нового вторичного запроса.

После одного дополнительного кадра, `K 0`, ожидание 8 кадров:

- для базового a=9011 меняется только X: 1→a;
- для a=−1E−99 меняется только W: m→a. Верхнее a остаётся в P7,
  u/q — в Y/Z, T остаётся меткой.

Все указанные клавиши — только хвост большой подготовки из драйвера,
не самостоятельная инструкция ввода на чистом калькуляторе.

## Точная числовая граница по ПЗУ

`k1-vw-nop-formatter-check.py` проверил 25 связанных канонических
ветвей позднего форматировщика. Предпосылки: физический источник P7,
верх стека возвратов E3, метки real/T/V/W.

| Класс нормализации | Поздняя запись | Значение для этой раскладки |
|---|---|---|
| 0 | P8 | Затирает b; не годится |
| 1…6 | X | Читает a без подъёма |
| 7…8, включая ноль | W | Убирает W-метку точной копией a |

Локально доказана сохранность всех 12 тетрад источника и отсутствие
других выходных изменений ИК1302 до возврата в 47. Это не доказательство
клавиатурного входа для любых чисел; сам вход и другие микросхемы
проверяются нативными тестами. Последующее снятие V требует дополнительно
принимаемого 9C числового заголовка W. Поэтому локальный класс 7/8 сам
по себе не обещает работоспособности **всей** последовательности.

## Снятие V и T

Для проверенного a=−1E−99 после НОП выполняются:

```
K ×    (8 кадров после пары клавиш)
0      (8 кадров)
```

Без дополнительного фазового ожидания между НОП и `K ×`.
Нативный путь:

```
777869 EE(X=1) → AB             раннее чтение НОП
777892 EE(P7=a) → E3           позднее чтение
777950 E7(W=a) → 47            W-метка убрана

784580 9C(W=a) → 9E            принимается числовое a
784589 EE(X=1) → A1
784594 E9(V=1) → A2            V-метка убрана
784602 A3(control=280000000000) нейтральный запрос
784619 поздняя EE(X=1)
784679 E7(X=1)                 повторная запись того же значения

790199 E7(X), A8(Y), A8(Z), A8(T)
       подъём 48 тетрад; вытеснена только T=m
790244 E7(X=0)                 завершение ввода нуля
```

На этом остаётся только настоящий маркер. Промежуточная раскладка
после этих трёх действий, **до возврата u/q в банк**:

```
П0=w; X1=INV0; X/Y/Z/T=0/1/u/q;
U/V/W/Q=v/1/a/p; верхние=a/b/c/d.
```

Все исходники присутствуют. Но u/q ещё не хранимые Ms-слова,
V занят служебной единицей, а W — дубликатом верхнего a. Поэтому
`normalStoredBankContract=false`, `workingExit=false`, `fullK1=false`.
Даже отсутствие лишних меток не разрешает объявить обычный счёт
безопасным для данных, которые пока находятся только в стеке.

## Строгие нативные проверки

Файлы: `k1-vw-nop-read.cjs`, `k1-vw-nop-read-check.cjs`.

Тест проверяет весь сохраняющий префикс; точные E7(W), E9(V), три
тетрады запроса A3, видимый подъём и поздние записи среди всех 630
тетрад; ограниченный список допустимых изменений по всему новому
хвосту, включая вторичные микросхемы. Программа, 14 остальных обычных
регистров и служебные тетрады не меняются даже временно.

126 границ у варианта с одним НОП, 128 у снятия всех лишних меток.
177 клавиш / 1419 кадров у полного хвоста с подготовкой, при первых
успешных публичных чтениях, без самой фикстуры и начального сдвига.
Драйвер не читает скрытые данные; проверка с подменёнными параметрами
фикстуры подтверждает ту же клавиатурную последовательность.

Повтор одного НОП без наблюдателя совпал по всем сериализованным полям:
`327711a8795bf133ea3b6b74709dc3682933c7d70c404252b732cdfe96c5b703`.

Полное снятие V/W/T также совпало со свежим запуском без наблюдателя:

- a/b/c/d = −1E−99 / 9022 / 9033 / 9044:
  `ce5225eb62ab41f8bc89b479fd61354ae2cec5b5f40951d8500067ccc6473497`;
- a/b/c/d = −2E−50 / −7.654321E23 / 1.2345678E42 / 8.7654321E−17:
  `9c3a2bb43f5307ee981b563717ad58cd336c10e489457f29840e7288ab5f7cda`.

В обоих случаях строгий тест прошёл все 128 границ и весь список
разрешённых записей. Эти два набора не доказывают любой числовой домен.

```sh
K1_NOP_UNOBSERVED=1 node tmp/ms-rom-reachability/k1-vw-nop-read-check.cjs
K1_NOP_CASE=clean K1_NOP_UNOBSERVED=1 node tmp/ms-rom-reachability/k1-vw-nop-read-check.cjs
K1_NOP_CASE=clean K1_NOP_OPTIONS='{"fullUpper":["-2E-50","-7.654321E23","1.2345678E42","8.7654321E-17"]}' K1_NOP_UNOBSERVED=1 node tmp/ms-rom-reachability/k1-vw-nop-read-check.cjs
K1_NOP_CASE=phase K1_NOP_UNOBSERVED=1 node tmp/ms-rom-reachability/k1-vw-nop-read-check.cjs
python3 tmp/ms-rom-reachability/k1-vw-nop-formatter-check.py
```

Фазы не произвольны: НОП без дополнительного кадра рано читает метку W,
затем поздно читает видимую единицу и пишет её в P8, теряя b. Строгий
отрицательный контроль и его полный повтор без наблюдателя совпали:
`b58bd4994c74f118caecbd3335398be53501e36bd8291b0011a041c80f70477f`.
Независимая кадровая
диагностика также отвергла один дополнительный кадр перед `K ×`:
запрос портит числовой заголовок U и теряет v. Положительная диагностика
другой фазы не заменяет полного нативного теста этой фазы.
[Матрица свежих кадровых опытов](k1-vw-nop-keyboard-frame-notes.md).

## Возврат двух исходников из видимого стека

Нужен именно низкоуровневый `push()` из `k1-visible-stack-cycle.cjs`,
без `read`, `finish` и `blindPush`: их подготовка расходует прежний
видимый стек. У `push` есть сохраняющий договор T→U→V→W, с вытеснением
старого W. Сам перенос ранее проверен по связанному десятикомандному
пути; здесь заново проверено его нативное сопряжение с новым выходом.

Пусть r — исходное обычное П9. Два вызова и два промежуточных вращения:

| Этап | X/Y/Z/T | U/V/W | Что вытеснено |
|---|---|---|---|
| После снятия V/W/T | 0/1/u/q | v/1/a | — |
| Первый push | 1/u/r/r | q/v/1 | Дубликат a, оригинал остаётся в P7 |
| Два `F ,` | r/r/1/u | q/v/1 | Ничего |
| Второй push | r/1/r/r | u/q/v | Служебная единица |

На базовой фикстуре точные подъёмы начинаются в 845102 и 924632.
Каждый проверен как 48 числовых записей с полным сравнением 630 тетрад.
В итоге:

```
П0=w; U=u,V=q,W=v,Q=p; верхние=a/b/c/d.
```

Все 23 исходника теперь в обычных 15 регистрах и восьми Ms-словах,
никаких данных только в видимом стеке не осталось. Проверена точная
биекция: П0←w, V←q, W←v, Q←p; U и верхние четыре слова неизменны.
Это **перестановка**, не возвращение всех чисел на исходные места.

`k1-vw-nop-restored.cjs` и `k1-vw-nop-restored-check.cjs` проверяют весь
непрерывный путь, 153 границы действий с выходными тестами, точный
список допустимых изменений Ms при восстановлении и сохранность 14
других обычных регистров / программного слоя / служебных полей.
Ручное `2 В↑ 3 +` даёт 5; после обнуления запуск исходной программы
также даёт 5 и не меняет хранимые числа. Законные перемещения потока M3
во время исполнения программы отделены от запрета менять её сохранённый
листинг и числовые поля. Отдельный тест приёма новой клавиши **после**
этой программы не добавлялся.

201 клавиша / 1679 кадров без выходных тестов, 209 / 1723 с ними;
фикстура и начальная фаза в счёт не входят. Базовый полный повтор без
наблюдателя совпал по всем полям:
`76396cbb5ed83722ee693ff013ff464f679796ac3fbe3b83a6961c1c9b258379`.

Независимый полный тест верхнего набора −2E−50 / −7.654321E23 /
1.2345678E42 / 8.7654321E−17 также прошёл 153 границы и оба выходных
опыта. Его полный повтор без наблюдателя совпал:
`3f15cf9e85dbe65a50374011620f3ddc45ada85409df197ea6ae08cc23bc49ca`.

## Чего ещё не хватает до полной К1

1. Совместить этот выход с полезным **изменением верхних слов**. Нынешняя
   проверенная композиция возвращается из глубокого входа, но оставляет
   верхнюю четвёрку нетронутой. У прежнего вращения другие метки и
   числовые условия; склеить готовые драйверы недостаточно.
2. Доказать общий числовой и временной договор. Даже два разных набора
   не охватывают все числа и паузы.
3. Построить допустимое непрерывное повторение. Первый фиксированный
   [повтор без сброса и дополнительных кадров](k1-vw-nop-restored-repeat.md)
   проверен и теряет данные уже на втором раннем входе. После первого
   прохода изменены и числовое содержимое, и фаза; вклад этих причин
   данным опытом не разделён. Это не общий запрет согласованного повтора.

Общая невозможность К1 этим не установлена. Дополнительные разобранные
пути и точные местные препятствия: [выбор вторичной области и прямой
AD→A3](k1-origin-secondary-selection.md), [альтернативные резервы и
отрицательные продолжения](k1-upper-exit-structure-notes.md).
