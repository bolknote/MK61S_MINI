# Промежуточный результат математики M0+: R48 и exp Q73

Сохранены исходники, доказательства, полные записи измерений и отрицательные результаты. Выбранный частный авторский кандидат — R48. Производственная реализация, M4 и обычный M0 не изменены.

| Работа | Результат | Статус |
| --- | --- | --- |
| R48, ранний выбор пути деления | 2 371 465 публичных ARM-вызовов авторской проверки. На 79 846 проверенных парах нет отставания деления от корректного Qfplib. Обычный путь −1 инструкция, нормальный результат со степенью двойки −10 относительно R47; все увеличения пограничных путей сохранены. | Частный авторский кандидат; независимая приёмка и внедрение открыты. |
| Q73, модели и Thumb-ядро | Полная модель корпуса, целочисленное ядро полинома за 226 инструкций; 180 528 вызовов проверки ядра. Используются существующие таблицы. | Это ещё не стоимость полного exp. |
| Q73, полный exp V1 / V2 | На старых 512 отстающих входах осталось 126 / 24; на полном корпусе — 2382 / 856. Ошибок результатов не найдено. Все новые отставания и увеличения стоимости сохранены. | Оба варианта не выбраны. |
| Q73, полный exp V3 | На старых 512 входах осталось 12. На полном корпусе 568 856 входов / 1 224 907 состояний осталось 399 отставаний, включая 387 новых входов. Ошибок результатов не найдено. Сохранены 796110 увеличений стоимости относительно R48. | Не выбран; требуется ускорить уточняющий пересчёт. |

У R48 в проверенном конечном объединении остаются `pow` — 2045 пар, `exp` — 512 входов. Это не исчерпывающий перечень функций или пространства binary64. Все корректные результаты Qfplib сравниваются; ошибочные результаты и их стоимость также сохранены. Метрика — исполненные инструкции Thumb, не аппаратные такты. Кэшированные эталоны и новые исполнения разделены в исходных отчётах; диагностические вызовы Q73 не добавлены в квалификацию R48.

Универсальное корректное округление, завершимость общего `pow`, приёмка FMA, универсальные границы стека, физические замеры, независимая проверка и внедрение остаются открытыми. `scope.json` задаёт актуальную область утверждений. Исторические журналы сохранены с исходными формулировками; они не отменяют эту область.

Проверка из этого каталога:

```sh
python3 verify_checkpoint.py --records
```

Проверка автономно сверяет SHA-256, исходные манифесты FROZEN и пересчитывает сохранённые записи. Она не запускает исторические производители, ARM, MPFR или устройства. Нужна только стандартная библиотека Python. Большие исторические JSON проверяются потоком без загрузки в память.

`provenance.json` сопоставляет исходные пути с содержимым `payloads/`. Байты исходников, FROZEN и результатов сохранены. Имена payload адресованы хэшем, исключая зарезервированные имена Windows и совпадения регистра; `.gitattributes` сохраняет байты. ELF и объектные файлы не включены; сохранены их размеры, хэши, исходники и рецепты сборки. Этот архив не зависит от предыдущего checkpoint или живых файлов `.build`; исторический коммит `54cf2afda1d5392346efd74ade184d12372a456c` указан только для происхождения.
