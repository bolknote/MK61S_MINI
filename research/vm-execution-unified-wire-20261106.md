# Ускорение исполнения общей BASIC/FOCAL VM

Статус на 6 ноября 2026: реализация, локальная квалификация и аппаратный
A/B/A шахмат на Classic завершены. Время тёплого поиска сократилось на
7,95% с USB Screen и 8,25% без него. Приведённые отдельно проценты
по ARM относятся к числу инструкций.
Код закоммичен в `feature/vm-execution-20261105`:
`965876680be55f34761d4035a4e553ba3a174f9f`. Слияния в main не было.

База: `602f1995863f566c20a978e94e27978cdbc2880e`.
Лаборатория: `.build/vm-execution-20261105-001` в основном checkout.
Исходники сборок и тестов зафиксированы в её `final-source`;
SHA256 `MANIFEST.json`:
`51dd5ee446be6a0261d881b5a422b0f1f161bce381f47bd162e62956be443bf6`.
Снимок содержит исходники и программные тестовые данные, без материалов
посторонних исследований. Планы и лабораторные артефакты не предназначены
для коммита.

## Что изменилось

1. Один формат LBV2 версии 15 для целых программ, страниц и INPUT.
   Один исполнитель; LBV1 больше не принимается. Адреса и таблица строк
   везде 32-битные. Лимиты исходника, рабочего места компилятора, стека и
   встроенных ресурсов сохранены.
2. Общий ограниченный анализ последних команд компилятора BASIC/FOCAL.
   Новые команды берут операнды непосредственно из локальных переменных
   или малых целых констант; результат можно сразу сохранить в локальную
   переменную. Для сложного левого операнда используется существующая
   вершина стека. Компилятор сворачивает точные целые ADD/SUB/MUL.
   Порядок вычислений, внешних вызовов и ошибок сохраняется.
3. Цепочки команд используют существующий целочисленный исполнитель
   без промежуточной упаковки каждого результата в Value. У проверенного
   непрерывного образа верхнее целое значение может оставаться в регистре.
   Перед внешним вызовом, выходом и переходом к обычной операции состояние
   материализуется. Переполнение, дробные значения и особые случаи идут
   через обычную арифметику, включая знаковый ноль.
4. Сертификат неизменяемого образа позволяет убрать повторные проверки
   структуры команд и идентификаторов операндов. Динамические проверки
   типов, арифметики, массива и управляющих стеков остаются. Публичный
   запуск с изменяемой или перекрывающейся памятью сохраняет необходимые
   проверки в том же исполнителе.
5. Координаты исходника перенесены из исполняемого потока в хвост образа.
   Повторяющиеся колонки объединяются без изменения результата поиска
   позиции ошибки. Маленькая таблица строится во втором проходе в хвосте
   уже заимствованного буфера исходника; для большой таблицы остаётся
   файловый проход. Дополнительного постоянного пула RAM нет.

Для размещения в прежних бюджетах общий постраничный Writer также читает
через свою существующую страницу; холодные операции с индексом и завершением
образа используют общий resident-код через существующий синхронный callback.
Редактор FOCAL проверяет фрагменты тем же парсером без ненужной генерации кода.

Сохранены обе конфигурации арифметики. Ни правила оптимизации, ни исполнитель
не используют имена шахматных файлов, номера их строк или признаки программы.

## Квалификация

- Полный host VM-набор с ASan/UBSan, BASIC/FOCAL и обе арифметики.
- Независимые скалярные сравнения целочисленного исполнения: по 247127
  точных сравнений на арифметику, включая сертифицированные образы без TRACE.
- Flash, канарейки и точный размер выходного буфера, страницы, большие
  адреса, ресурсы, ошибочные позиции, INPUT/ESC/resume и сервисные точки.
- Файловый кеш и смешанный кеш: обе арифметики, с USB и без него,
  повреждения/устаревание/отмена, прежние ограничения памяти.
- Настоящие ARM APP и resident: более 5000 строк и более 64 КиБ
  исполняемого образа, три адреса загрузки, непрерывный и постраничный
  образ, INPUT после отравления памяти выгруженного APP.
- Настоящий ARM редактор: передача из компилятора, 34-КиБ исходники,
  Save/Cancel/ошибка записи и три адреса загрузки. Старый тестовый драйвер
  имел устаревшие до этой работы смещения ABI; для этой проверки сохранён
  отдельный адаптированный драйвер. Большие программы проверяет актуальный
  Flash ARM-набор, старый полный драйвер не объявляется прошедшим.
- Turochamp: правила/perft/превращения/рокировки/взятие на проходе,
  undo/повторы/исход партии, оценка/поиск/клавиши/весь экран, 17 линий книги,
  настройки сторон и книги. Проверены варианты интерпретатора и VM.
- Связанные программы, холодный загрузчик и общий механизм повторных вызовов.
- Пары ELF/BIN запечатаны штатными инструментами с побайтной сверкой
  результата objcopy; шесть APP имеют отдельные SHA256.

Добавлена регрессия для BASIC `A=1,@(INT(4/2))` и `A=1,@(2/1)+3`:
откат пробного разбора левой части теперь откатывает и координаты исходника.
Проверяются результат исполнения и отсутствие случайной записи в массив.

## Classic: аппаратный A/B/A

Одна база `4110ccfaa0ad91de54d8c136020ad07aacb31440`, тот же компилятор,
те же файлы Turochamp и настройки: компьютер играет белыми, книга выключена.
BASE — исходная VM; NEXT — эта же база с патчем `965876680`. На каждой
стадии установлены согласованное ядро и все шесть соответствующих APP.
Измерительные CRC: BASE/контроль `FC3FBF3E`, NEXT `6A5015D3`.

| Сценарий | BASE A1, с | NEXT, с | BASE A2, с | Снижение времени |
|---|---:|---:|---:|---:|
| Тёплый поиск, USB Screen включён | 25,186555 | 23,181950 | 25,184323 | 7,955% |
| Тёплый поиск, USB Screen выключен | 24,137233 | 22,145466 | 24,137572 | 8,252% |
| Первый поиск с пустым файловым кешем, Screen включён | 41,761935 | 38,511447 | 41,963444 | 8,005% |
| Первый поиск после перезагрузки с готовым файловым кешем, Screen включён | 25,452015 | 23,433507 | 25,452833 | 7,932% |

Тёплые значения — медиана двух повторов на каждой стадии. Для процентов
использовано среднее двух BASE: `1 − NEXT / ((A1 + A2) / 2)`. Дрейф контроля
тёплого поиска: −0,008862% с экраном и +0,001404% без него, при прежнем
пороге 3%. Контроль первого поиска: +0,483%; после перезагрузки: +0,0032%.

Время измеряет MCU KEYWAIT: от принятия OK до следующего блокирующего
ожидания клавиши APP. Профилировщик во время поиска выключен. В режиме
без USB Screen устройство отключает передачу экрана до старта таймера;
значение фиксируется MCU в конце поиска. Хост ждёт заранее выбранное
90-секундное окно и подключает экран для проверки готовой доски. Эти
90 секунд не входят в результат измерения. Физический USB остаётся подключён.

Всего 21 измеренный поиск и один дополнительный проверочный запуск обычной
прошивки. Во всех случаях подтверждены 420 узлов, e2–e3 и все восемь рядов
доски; SHA256 пикселей доски:
`ef261082a0230600d21d7c4ae116e7cfc226f0fb9ce43a22fbbc26bcbe580460`.
Стандартная маска исключает только документированный прямоугольник значка
дисковой активности; полный исходный кадр тоже сохранён.

После сравнения установлена и проверена обычная NEXT `6186AE4B`, 407108 байт,
без измерительного KEYWAIT. Холодный проверочный поиск на ней прошёл за
38,137 с по часам хоста; это отдельный smoke, не сравнительный замер MCU.
Все шесть APP побайтно сверены. Тестовые `/VMEXEC` и созданный тестом кеш
убраны; штатный VMSTORE оставлен. Процесс завершился с кодом 0, все 40
созданных объектов порта закрыли дескрипторы и блокировки без ошибок;
независимая проверка ОС не обнаружила владельцев CDC. Classic передан
координатору свободным. Mini и PicoCalc не использовались.

Flash, RAM, APP и стек проверялись с прежними пределами. Для обычной F411
вклад изменения — +8 байт внутренней Flash, глобальные данные не выросли.
Общий предел APP F401/F411 остаётся 20480 байт, максимум NEXT — 20444.
Аппаратных измерений задержек опроса на общем большом BASIC/FOCAL-корпусе
этот шахматный A/B/A не заменяет.

### Подготовка стенда

Первую попытку остановила ошибка лабораторного контроллера: слишком ранняя
проверка появления CDC после успешной DFU-записи. Добавлено ограниченное
ожидание отсутствующего пути; другой UID и неоднозначная цепочка регистрации
по-прежнему останавливают тест. BASE затем продолжил без повторной прошивки.

Создание VMSTORE на заполненном стенде вернуло PUT_IO. Причина воспроизведена
с настоящим C9 и каноническими локальными файлами установки URQ: данных
250454 байта, у C9 на NOR 512 КиБ только 71 сектор данных, то есть 290816 байт.
С учётом округления крупных файлов и staging третий блок VMSTORE не находил
целого свободного сектора: `WriteFailure::RECORD`, detail 0. На пустой модели
C9 все шесть APP записываются успешно. В заполненной модели освобождение
трёх поставочных частей Jim, всего 143396 байт, устраняет отказ.

По отдельному прямому согласию пользователя на Classic удалены только
`/URQ/Джим из Космоса/p0000.uqd`, `p0001.uqd` и `p0002.uqd`. Их точные копии
подтверждены в существующих локальных релизах. Сохранение `slot1.urs`,
`game.urq` и системные APP URQ не были целями удаления. Для запуска Jim
потребуется вернуть три части из поставки. Форматирования не было.

Свидетельства подготовки: `HIL-PREFLIGHT-r3.json`, `HIL-CHESS-current-r1/`,
`HIL-CHESS-current-r2/`, `HIL-VMSTORE-DIAG-direct-r1.json`,
`vmstore-app-memory/run-{before,after}-free-space.log`,
`JIM-ASSETS-REINSTALLABLE-PROOF.json`. Все 27 проверок лабораторного
контроллера проходят, включая ожидание USB, сроки Flash, закрытие портов,
реальный формат каталожного списка и отсутствие обхода старой ФС.

По прямому указанию пользователя прежнее состояние в этой разработке
не анализируется, не резервируется и не восстанавливается. Контроллер
проверяет UID, CRC, точные целевые файлы и результат измерения. Он не
возвращает прежние прошивку, APP, кеш, калькулятор или часы; успешный
прогон заканчивается на проверенной обычной NEXT.
