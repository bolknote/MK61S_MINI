Финальные аппаратные замеры strcmp / strncmp на Classic приняты координатором и независимо закрыты. Испытана окончательная mixed-сборка F1C6EDF4: public strcmp — 20 байт; исходный public strncmp — 42 байта; runtime19 указывает прямо на него, диагностического переключателя нет. Выполнены ровно 54 запуска APP, 2592 группы и 18 144 сырых измерения при включённых IRQ. Исходная прошивка 3AB3DD45 восстановлена; все 524 288 байт совпали с двумя свежими резервными копиями. Файлы, данные калькулятора, ход UNSET-часов и закрытие USB-сеанса независимо приняты.

Для native strcmp все 288 медиан быстрее исходного 24-байтного тела. Выигрыш сохранился для SRAM/SRAM (−8,23%), SRAM/Flash (−7,58%) и Flash/Flash (−8,07%). У выбранного SDK-пути нет случаев с регрессией больше 5%; при длинном решающем префиксе ≥64 байт он примерно на 0,34% медленнее старого SDK. Для общего пути предлагается локальный 20-байтный strcmp, в том числе в shared APP; мост через runtime не выбирать.

Standalone newlib strcmp остаётся полезным ориентиром для длинного общего префикса. Его общее среднее — 174,617 цикла (−9,90% против старого SDK), но короткие случаи медленнее на 26,29%, 143 из 288 медиан медленнее более чем на 5%, худшая — в 2,57 раза. Тело занимает 734 байта. Поэтому результат не означает, что 20-байтный путь быстрейший при любом распределении строк: его предлагаем для общего короткого SDK-пути; newlib может быть полезен специализированному APP с длинными строками.

strncmp сохраняется базовым: 42 байта в прошивке/runtime и newlib 120 байт в автономном контрольном APP. Предыдущая полная матрица выявила существенные короткие регрессии DSP-вариантов. В финальном 96-случайном контроле native strncmp занимает в среднем 172,105 цикла, runtime19 — 193,988, standalone newlib — 194,154. Реальный runtime-переход стоит +12,72% против прямого вызова на этой контрольной матрице; для коротких случаев +17,22%, для длинных +0,20%. Это ограниченный контроль исходного тела, не повторный выбор по всем 516 случаям. У standalone SDK при варианте0 своего strncmp по-прежнему нет: контрольный APP подключает newlib явно через -lc.

Все числа — геометрическое среднее по медианам семи полных серий по 64 вызова; стоимость реальных переходов включена. Пустой вызов, dispatch или service не вычитались. Данные охватывают SRAM/SRAM, SRAM/Flash и Flash/Flash, четыре аппаратных сочетания выравнивания; полная HOST-проверка включает все 16 сочетаний. Это синтетический микроэксперимент без обещания холодного кеша или выигрыша в произвольном реальном приложении.

M0+ подготовлен и проверен на HOST; аппаратного победителя M0+ пока нет. Во время измерений основной checkout и принятый strlen-worktree не менялись. После измерений выбранный M4 source default подготовлен к слиянию; факта установки нового shipping image эти результаты не заявляют. Устройство возвращено на исходную прошивку, дальнейших действий с устройствами для этого выбора M4 не требуется.
