# strchr: M4 и M0+

Подготовка от `7a01beb4827c05bb2ba34fc0576f85f929b6160f`, без изменений
production-функций и ABI. Аппаратных замеров пока нет; победитель не выбран.
Основной checkout с чужими правками и принятый worktree `strlen` не менялись.

| Вариант | M4, байт | M0+, байт | Чтение |
|---|---:|---:|---|
| Текущий native M4 | 24 | — | По одному байту |
| Текущий standalone SDK | 24 | 18 | По одному байту |
| `byte1` | 18 | 18 | По одному байту |
| `byte4` | 58 | 58 | Четыре последовательных байтовых шага |
| `word1` | 84 | 84 | Выровненное слово, арифметические маски |
| `word2` | 112 | 112 | Два последовательных проверяемых слова |
| `dsp1` | 88 | — | Слово, `UQSUB8`, `RBIT`/`CLZ` |
| `dsp2` | 108 | — | Два последовательных DSP-шага |
| Newlib из ARM GCC 14.2.1 этой сборки | 206 | 196 | Контроль библиотеки |

Размеры включают литералы внутри символа; внешнее выравнивание, изменение
компоновки и дополнительные зависимости в них не входят. Размер функции
не доказывает её скорость. Для M0+ newlib здесь — контроль текущего
инструментария; actual native baseline нужно заново связать с фактически
установленной прошивкой PicoCalc. `ports/picocalc/memory.c` сейчас не
предоставляет `strchr`/`__wrap_strchr`.

Все варианты ищут первое вхождение `(unsigned char)c`, включая завершающий
NUL. При NUL до искомого символа возвращают NULL. Word/DSP предназначены
для обычной little-endian SRAM/Flash: до входного указателя не читают,
могут прочитать до трёх лишних байтов в слове с первым совпадением или NUL.
Каждое слово проверяется перед чтением следующего. `word2`/`dsp2` не
разрешают чтение восьмёрки целиком. Это не интерфейс работы с MMIO.

Runtime сохраняет 26 слотов, `strchr` — слот **18**. Shared APP использует
настоящую SDK-привязку и production `runtime.S`; standalone APP сохраняет
локальную функцию. Никакой исследовательский селектор в production не
добавлен: `ST_VARIANT=1..6` существует только в `candidates.S` и адаптере
сборки тестовых APP. Вариант 0 APP — исходный SDK, вариант 7 — явно
подключённый newlib. На M0+ допустимы варианты 1–4.

Локальные проверки:

- **620 640 вызовов** настоящего ARM-кода, Flash/SRAM и slot18 на M4/M0+.
  Все 256 байтов, усечение больших/отрицательных `int`, NUL, первое/повторное
  совпадение, длины до 1023, все четыре выравнивания, разные защитные края.
  Запрещены чтения перед указателем, после решающего байта/слова и любые
  записи во вход. Проверены AAPCS, SP, PRIMASK и CONTROL. 18 намеренно
  неверных ARM load/store подтвердили, что защитные hooks ловят нарушения.
- **16 настоящих упакованных APP**, три адреса загрузки, production header,
  ZX0/BCJ, CRC и релокации, SDK INIT/RUN и повторный запуск из кеша.
  **77 760** проверок результатов с SRAM и внешней Flash; все локальные
  кандидаты APP побайтово совпадают с квалифицированными ARM-телами.
- В те же APP включён `bench.c`: 87 успешных запусков, **4263 вызова поиска**
  с синтетическим ARM-таймером, семь сырых интервалов за запуск.
  Проверено отрицание неверного оракула, остановившегося таймера,
  отсутствующего слота 18 и неверной runtime-функции: 108 отрицательных
  проверок. Синтетические 17 ticks — свойство теста проводки, не скорость MCU.
- Всего 48 успешных инициализаций, 135 обычных запусков; **31 581** успешный
  переход в выбранное тело через runtime18 (включая синтетические серии).
  Максимальный тестовый APP — 1096 байт файла / 1760 байт загруженной RAM.
  Это бюджет этого теста, не проверка всех системных APP.
- `bench_self_test.c` с ASan/UBSan: точное число вызовов, временная ошибка
  внутри серии, остановка на первой ошибке, переполнение uint32 таймера,
  нулевой/слишком большой интервал и недопустимые входы.

Unicorn 2.1.4 проверяет ARMv6-M через модель Cortex-M0 и ISA M4. Он не
моделирует задержки Flash, кеши, частоту или IRQ реальных устройств. Из API
заглушены только query/capabilities; startup, bind, trampolines и функции
поиска исполняются как ARM. Ни один скрипт подготовки не открывает порты,
не ищет USB и не прошивает устройство.

`prepare.py` выпускает 1152 детерминированных случая (576 на каждый банк),
семь сырых длительностей полного цикла на маршрут без вычитания пустого
вызова. Каждая timed-функция вызывается косвенно, все возвращаемые указатели
сравниваются с независимым ожидаемым адресом. Вход должен содержать NUL
в заданном `text_bytes`, даже при более раннем совпадении.

`APP-CHECK.c` после INIT принимает через `request`, `request_tick` и
`request_mode` параметры того же измерительного ядра. Поставщик аппаратного
сценария привязывает фактические адреса SRAM/Flash и квалифицированный
32-битный таймер, затем вызывает штатный RUN и сохраняет `samples`.
Таймер не создаётся внутри APP. При `request_mode=0` выполняется только
проверка корректности; `external_text` требуется связать с обычной Flash.

Перед железом нужны актуальные installed identity/body/clock/power,
квалифицированный внешний сценарий возврата состояния и конкретное окно
координатора. Существующие операторы устройств сохраняют владение helpers
и leases. Старые пакеты и снимки других кампаний не являются текущей базой.
Результат следует выбирать отдельно для резидентной Flash/SRAM и APP,
сохраняя короткие регрессии и все сырые группы. У F401 Classic после
интеграции `strlen` минимальный резерв Flash уже достигнут; его контракт
нельзя ослаблять ради большего кандидата. Полные сборки и бюджеты будут
проверены после аппаратного выбора, до включения новой функции.

Воспроизведение из корня checkout, с ARM GCC 14.2.1 в `ST_TC` и Python с
Unicorn 2.1.4. Выходные каталоги должны быть новыми:

```sh
python3 -B tests/strchr_arm_self_test.py --toolchain-bin "$ST_TC" --output-dir /tmp/strchr-core
python3 -B tests/strchr_app_self_test.py --toolchain-bin "$ST_TC" --core-dir /tmp/strchr-core --output-dir /tmp/strchr-apps
python3 -B research/strchr-2026-10-28/prepare.py --toolchain-bin "$ST_TC" --output-dir /tmp/strchr-plan
```

Подробные результаты, SHA тел и происхождение сборки сохраняются в
`RESULTS-HOST.json` и `evidence/`. Исторические абсолютные пути показывают
место исходной проверки; повторение не требует наличия этих каталогов.
