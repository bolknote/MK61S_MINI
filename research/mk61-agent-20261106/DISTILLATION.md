# Flourish teacher continuation, 2026-11-06

The user authorized continuation with a large teacher and a fresh Russian Q4
evaluation. This round is under `.build/mk61-agent-20261106/distill-v1/`, with
remote execution in the existing isolated experiment directory. The separate
TinyTalk task and its Qwen service are not reconfigured or interrupted.

The existing local `Qwen/Qwen3.8-Flash-Next-FP8` API generated descriptions for
88 expression templates from the training structural partition. Four styles
cover direct instructions, games, practical situations and textbook algorithms.
After format filtering, 2,124 candidates remained. A second, target-blind pass
parsed their meaning back to an expression: 1,817 matched, 307 did not. Object
and array JSON ASTs are normalized without changing their operation. A checker
using the same teacher is a filter, not independent human verification.

The production microcode core checked all seven numerical examples of each of
21,804 augmented tasks. The initial SFT snapshot contains 56,648 rows: natural
programs, language-to-formula examples, real-emulator repairs/traces and 10,000
replay examples. A Q4 rollout on 640 TRAIN tasks supplies this model's own failed
attempts; none of the new test tasks supplies gradients or error examples.

Two arms start from the SAME previously validation-selected `language-plan/best`
checkpoint. `structured` emits a compact algebraic plan followed by bytecode;
`direct` emits bytecode directly. Both also learn a separately prompted
language-to-formula task. The formula evaluator is a diagnostic and never
substitutes a compiler for model-generated bytecode in the main benchmark.

Initial continuation: 6000 updates per arm, effective batch 32, microbatch 16,
learning rate 8e-5, QAT from update 1001, 512-token context, prompt limit 352 to
match generation. A spot check then exposed teacher statements with unlabelled
requests to write back to input registers. The running dataset is preserved;
the controller will exclude such statements for a further 4000 updates per arm,
learning rate 5e-5, QAT throughout, before post-training test evaluation. This
correction is made using TRAIN examples only.

While the initial workers continue, `teacher_broad.py` expands 32 training
algorithms with 12 styles, including ordinary conversational requests. These
descriptions also pass blind reverse parsing and real-emulator reference checks.
The cleaned continuation waits for this data and mixes it with the first corpus;
the new fresh test remains unopened for all checkpoint selection.

The second collection retained 1,855 descriptions after blind parsing and
1,839 after excluding unlabelled named-register writes. The first collection
retained 1,606 descriptions after the same exclusion. The combined cleaned
corpus has 3,445 distinct normalized descriptions. Additional real-emulator
checks cover 7,356 broad-language tasks, with no rejected numerical references.
The cleaned SFT file has 75,436 rows, including 833 distinct repair prompts from
actual student errors. Its SHA256 is
`612c372481d7944e8da086ea2873a440989e0528419b1b406b8c8ade5678231e`.

The initial 6000-update runs selected structured update 2000 (18/32 natural,
20/20 formal development) and direct update 4000 (19/32, 20/20). Direct formula
parsing on validation solved 11/32 despite syntactically valid formulas in all
32 cases. Removing the fixed few-shot example solved 18/32 versus 19/32 with
it, so the main evaluation retains its original prompting mode.

The initial frozen check consists of 32 separately authored natural validation
statements and 64 separately authored fresh statements. Before ANY new gradient
step, numerical probes were revised to include signed values for abs/neg and
feasible positive count inputs elsewhere. Both freezes and the revision remain
on disk. All 18 abs tasks in the two revised files have numerical cases that
distinguish abs from an identity operation. Elementary algorithm families may
occur in training: the fresh set measures wording/semantic transfer, not wholly
unseen algorithm discovery. It does not test complete historical games.

Checkpoint selection: Q4 natural validation accuracy, with a >=95% pass guard
on 20 formal development tasks. The fresh 64-statement audit does not enter
checkpoint or arm selection. The declared working target is >=80% on fresh
Russian conditions and >=95% on the existing 98-task formal regression suite.
Intermediate loss or a small improvement is not the quality target.

Independent generations are batched, while `agent_run`, its three-turn/160-token
budget, microcode execution and hidden-test grading remain unchanged. The
global calculator core is locked across threads. On the previous Q4 checkpoint,
all 12 basic tasks have exactly matching replies, histories and outcomes against
sequential execution (`distill-v1/batching-check.json`).

The packed weight format remains MKQ4v1, group 32 with FP16 scales. Host
activations and KV cache are FP32. Native PicoCalc inference, device memory and
speed are not implemented or measured by this round.
