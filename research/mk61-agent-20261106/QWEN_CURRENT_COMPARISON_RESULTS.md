# Qwen без дообучения: сравнение на замороженном BJ-тесте

Дата: 2026-11-08. Модель сервиса: `Qwen/Qwen3.8-Flash-Next-FP8`.
Обновлений весов: **0**. Прогон завершён; отдельный сервер остановлен,
обе B200 после остановки показывают 0 MiB и 0% загрузки.

## Условия

Тот же `spec-intent-recovery-v1/closed-clean.jsonl`: 958 условий,
из них 798 обычных русских и 160 структурированных. В циклах — та же
выборка 256 условий, каждое с правильным и повреждённым кодом (512 эпизодов),
тот же эмулятор, мутации и лимит 12 действий. Обе проверки используют одинаковые
начальные запросы. Никаких решений из теста в справочник не добавляли.

Qwen получил справочник компактной SPEC и машинных команд; ответ — JSON action/body,
WRITE содержит компактную SPEC. Это проверка исходной модели с инструкцией,
а не равенство вычислительных бюджетов: Qwen FP8, контекст 8192, до 1024 выходных
токенов на вызов, thinking выключен; специализированная 3M — Q4, контекст 1024.
Два простых предварительных теста протокола прошли проверку настоящим эмулятором.

## Сравнение с дообученной 3M

Для 3M использованы исправленные результаты независимого бюджета декодирования,
без повторного обучения и без изменения теста.

| Метрика | 3M LoRA Q4 | 3M full Q4 | Qwen, своя SPEC |
|---|---:|---:|---:|
| Верная SPEC на обычных русских условиях /798 | 629 | 659 | 119 |
| Успешное завершение /512 | 383 | 396 | 43 |
| Успешно исправлены неверные программы /256 | 181 | 189 | 15 |
| Испорчены правильные программы /256 | 10 | 9 | 1 |
| Принятые ложные DONE /512 | 27 | 22 | 3 |
| Все попытки ложного DONE | 295 | 261 | 23 |

Qwen исчерпал лимит действий в 466/512 эпизодов; приняты всего 46 DONE,
из них 3 ложные. Поэтому маленькое абсолютное число ложных DONE и порчи кода
нельзя трактовать как преимущество в надёжности при сопоставимой полезности.
Правильное завершение изначально верного кода: 28/256.
Защитный откат использован в 460 эпизодах: сохранность финального кода также
зависит от harness, а не только от решений модели.

На всех 958 условиях верная SPEC — 143; доступная для разбора SPEC — 511;
ошибки кодека — 447. На 798 обычных русских условиях ошибки кодека — 380.
Пример: «Посчитай, пожалуйста, синус 0.515. Запиши полученный результат в R0»
получил `00 28 0C`, то есть sin(RC), вместо ссылки на константу `10 0C`.
Среди ошибок — лишние байты, незавершённые деревья, путаница машинного HEX и SPEC.

## Эталонная SPEC только у проверяющего

Золотая формула скрыта от Qwen. При DONE проверяющий использует её вместо
гипотезы модели и может вернуть численный контрпример. Это привилегированная
диагностика; она не переносится в реальный продукт без источника эталона.

| Метрика | Своя SPEC | Эталон у проверяющего |
|---|---:|---:|
| Успешное завершение /512 | 43 | 105 |
| Исправления /256 | 15 | 22 |
| Порча верного кода /256 | 1 | 0 |
| Принятые ложные DONE | 3 | 0 |
| Все попытки ложного DONE | 23 | 18 |
| Исчерпан лимит /512 | 466 | 407 |

Нулевые принятые ложные DONE обеспечены эталонной проверкой: модель всё ещё
делала ложные заявления. Главный вывод — готовый Qwen в этом компактном
протоколе существенно уступает специализированной 3M. Это не измерение
общих математических способностей Qwen. Следующее отдельное исследование,
если потребуется, — обычная формула/AST на выходе Qwen с детерминированным
переводом в SPEC; в текущий зафиксированный прогон это изменение не вносилось.
