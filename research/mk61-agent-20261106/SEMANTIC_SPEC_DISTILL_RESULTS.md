# 3M Q4: компактная спецификация против HEX

Обе ветки дообучены от одного и того же Q4-состояния AQ full (шаг 2500). Меняется смысл байтов в WRITE: HEX — программа МК-61 с прежними макросами; SPEC — дерево выражения и один необязательный адрес записи результата. Дерево компилируется детерминированно. Во время экзамена DeepSeek не вызывалась.

На закрытом наборе SPEC лучше в одношаговом переводе: 175/294 против 154/294 у дообученного HEX (исходный HEX: 28/294). Общая парная разность +7.1 п.п.; интервал по задачам +1.0 … +13.6 п.п. В интерактивном отладочном протоколе HEX заметно сильнее: 112/256 правильных завершений против 27/256. По сравнению с исходным HEX само дообучение улучшило завершение с 32/256 до 112/256, снизив ложные DONE со 140 до 28 при почти одинаковом числе DONE (172 и 174). Результат поддерживает дальнейшую работу над SPEC как переводчиком, но не замену им действующего отладочного агента.

Это сравнение двух дообученных систем с одним исходным состоянием, а не оценка двух случайно инициализированных архитектур. Исходная сеть уже знала формат HEX; SPEC для неё новый язык вывода. Дерево не является свободным текстовым рассуждением и пока описывает только прямолинейную арифметику и запись результата, без циклов и ветвлений.

В каждом плече выполнено 3000 обновлений, batch 32, Q4 на каждом прямом проходе, вычисления и активации FP32. Обновлялись свежие адаптеры rank16 и шесть строк действий, всего 318,208 коэффициентов. После слияния модель в обоих случаях имеет 3 022 080 параметров. Русские входные строки словаря и все тензоры вне адаптеров сохранены. Выборки, число шагов, функция потерь и начальные коэффициенты совпадают; штрафа DONE, DPO и нового нейросетевого критика нет.

DeepSeek создавала русские перефразировки случайных деревьев и независимо восстанавливала по ним формулу. Обратная проверка не видела исходного AST. Совпадение проверено численно, программы эталонов — ROM. Метки WRITE/RUN/DONE/UNSURE получены через настоящие Session и эмулятор. Разные математические смыслы одного русского выражения и коррелированные ошибки учителя полностью исключить этим нельзя.

Удалены совпадения с учётом коммутативности +/* и несущественного углового режима, а также сигнатуры открытого пилота. Это не исчерпывающая проверка всех алгебраических тождеств. Новые сочетания удержаны из текущего обучения; они не объявляются отсутствовавшими во всей истории предыдущих этапов. Учебных состояний 26,298; одинаково допустимых в обоих форматах — все, исключённых по длине: 0. Контроль и закрытый тест различаются также удержанными парами операций.

Чекпойнты выбирались только на development, по минимуму качества known/novel, затем общему числу правильных программ и качеству завершения. После фиксации двух чекпойнтов закрытый тест открыт один раз для обеих веток и неизменённой исходной модели. На закрытом наборе веса и пороги не подбирались.

В основной проверке запрашивается одна гипотеза WRITE; выбор действия принудительно фиксирован. Успех означает, что полученный код корректно исполняет исходное условие на отдельных аудиторских входах, включая сохранение неназванной памяти. Для SPEC дополнительно отдельно проверяются разбор дерева и его математический смысл. У HEX подразумеваемая формула восстанавливается частичным символьным декодером, поэтому её отсутствие не отменяет правильное исполнение кода.

Интервалы отражают только разброс задач при одном общем seed обучения; разные seed не проверялись. Численные совпадения — конечные проверки с допуском 2e-6, не доказательство равенства произвольных программ.

На 120 задачах, правильно решённых обеими ветками, средний ответ HEX — 15.1 токена, SPEC — 13.9. Общее среднее в таблице включает и неверные гипотезы. Оба нативных пакета имеют размер 2 160 856 байтов; сокращение вывода не освободило память весов.

Пошаговый тест использует одинаковые 128 условий (по 64 из known/novel), правильный и ошибочный старт на каждое условие, реальные публичные факты, бюджет 12 действий. Raw принимает собственный DONE сети. Self дополнительно проверяет код против формальной гипотезы, сделанной отдельно до показа текущей программы. Эта гипотеза может неверно понимать запрос; её нельзя выдавать за независимо подтверждённую спецификацию.

Текущая программа показывается обеим веткам в HEX. SPEC должна читать HEX и выдавать дерево; однородный семантический вход для неё здесь не проверялся. Это ограничение интерпретации отладочного теста. В одношаговой проверке текущей программы на входе нет.

Дополнительно raw DONE на правильном по аудиту коде, но без успешной актуальной публичной проверки: HEX — 34, SPEC — 33. Они не включены в успешные завершения. В учебных RUN-целях этого этапа использовался только случай 01; переход к 00 после повторной правки требует отдельного покрытия следующего курса. Ошибки DONE следует читать вместе с количеством принятых ответов и отказов.

Самосогласованность кода и собственной спецификации не доказывает понимание запроса. В компьютерном прототипе ax_completion.py такие случаи имеют статус «код проверен по неподтверждённой спецификации». Прикладной DONE требует независимо подтверждённой спецификации; во время этого исследования raw/self остаются диагностическими режимами.

Обе ветки используют прежний русский словарь и тот же алфавит HEX-токенов. Генератор в обоих случаях ограничен одинаковым синтаксисом пар HEX-цифр; специальная грамматика дерева не помогает SPEC выбирать допустимую операцию. Префикс SPEC: FF либо 00..0E задаёт отсутствие/адрес записи, затем дерево; 00..0E — входные регистры, 10 kk — индекс константы, 11 — pi, 20..31 — унарные операции, 40..44 — бинарные. Режим углов задаётся harness, как и у HEX. Ограничение программы — 105 ячеек стандартного МК-61.

CPU-переэкспорт Q4, побитовое сохранение словаря и сравнение выбранных потоков B200 с CPU и переносимым C++-движком сохраняются в native-verification.json. Это проверка компьютерного исполнения. Скорость и память физического PicoCalc здесь не измерялись; прошивка и основной профиль модели не заменялись.

Модели: `server-results/export/hex` и `server-results/export/spec`. Локальная проба: `.build/squeal-chat-20261105/venv/bin/python research/mk61-agent-20261106/ay_chat.py --model <папка export/hex или export/spec> --task "Вычисли квадрат R0" --angle DEG --inputs '{"R0":"3"}'`. Скрипт работает офлайн и показывает гипотезу, итоговый HEX и фактический результат; понимание условия помечено неподтверждённым.

Полные данные, политики, начальные SHA, контрольные кривые, выбранные чекпойнты и экзамены находятся в `.build/mk61-agent-20261106/semantic-spec-distill-v1/`.

Историческая пользовательская проба «синус 22°» проверена отдельно и не входит в новые 294 задачи. В этом корпусе у каждого выражения требовался хотя бы один входной регистр; чисто константных условий не было. Обе ветки эту пробу провалили: HEX выбрала sin(3), SPEC — sin(10^(10+R1)). Это существенное ограничение для обычного использования. Следующий корпус должен включать чистые константы, новые числа и выбор их индекса из таблицы, а также полные траектории RUN для обоих номеров случая. По этой пробе веса текущего эксперимента не исправлялись; следующему обучению потребуется новый закрытый тест.

Экспорт содержит wire-format.json с обязательной политикой таблицы констант. База одинакова у обеих веток и содержит 12 значений; дополнительные числа добавляются в порядке извлечения из условия. При использовании этих весов harness должен применять данную политику и подходящий декодер WRITE. Пакеты не подменяли текущую прошивку или основной профиль модели.
