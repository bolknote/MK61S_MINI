## Одна задача, разные таблицы констант

На одном и том же поднаборе числовых условий сравниваются четыре вида таблицы. В extras меняются только дополнительные позиции; в full — все позиции, включая базовые. Для этих двух вариантов набор значений полностью совпадает с default. В distractors дополнительно вставлены отвлекающие числа. Задачи, текущие программы и эталоны пересобраны с новыми индексами; реальный машинный код сохраняется побайтово. Эти варианты не считаются независимыми новыми задачами.

## Отладка и завершение

raw — модель сама выбирает действие. self — прежний механический фильтр сверяет код с собственной гипотезой модели; он не получает правильную спецификацию запроса. permuted_raw — отладка с полной перестановкой таблицы. Каждое условие даётся с правильным и ошибочным начальным кодом; успех из пустой программы этим тестом не измеряется. Для успеха нужны верный код на аудиторских входах, DONE и оба обязательных запуска текущей редакции.

| Режим / версия | Успех | DONE | Ложные DONE | Ошибочных среди DONE | Правильный код, непроверенный DONE | Исправлено плохих стартов |
|---|---:|---:|---:|---:|---:|---:|
| raw / parent | 157/256 | 256 | 99 | 38.7% | 0 | 47/128 |
| raw / spec | 219/256 | 255 | 36 | 14.1% | 0 | 103/128 |
| self / parent | 147/256 | 151 | 4 | 2.6% | 0 | 51/128 |
| self / spec | 207/256 | 226 | 19 | 8.4% | 0 | 101/128 |
| permuted_raw / parent | 20/64 | 61 | 41 | 67.2% | 0 | 3/32 |
| permuted_raw / spec | 44/64 | 62 | 18 | 29.0% | 0 | 19/32 |

Ложный DONE означает фактически неверный финальный код. Он не смешивается с верным кодом, для которого пропущены публичные запуски. Падение ошибок без сохранения числа правильных завершений не считается достаточным улучшением. Механическая проверка относительно ошибочного понимания условия по-прежнему может пропускать неверные решения.

Новое closed не содержит сигнатур train/development/closed двух предыдущих семантических раундов и нового train. Удаление сигнатур учитывает коммутативность +/* и несущественный угловой режим, но не все алгебраические тождества. Отдельные числа и целевые пары операций удержаны из текущего обучения; это не заявление об их отсутствии во всей истории основания модели.

DeepSeek-V4.1-Flash создавала русские формулировки и отдельно восстанавливала формулу без доступа к исходному AST. Латинские имена функций в вопросах отбрасывались автоматически. Учитель не задавал правильность DONE: её определяли компилятор и реальный ROM.

Учебных состояний 58315, допущено по длине 58234. Детали построения: `{"plausible_stopped_errors": 2844, "literal_binding_goals": 112, "matched_same_program_pairs": 776, "retired_actual_false_DONE": 39, "mined_states": 1892}`.

Первые600 обновлений уделяют больше места коротким заданиям на привязку числа к индексу. Далее каждый batch содержит12 строк перевода,8 исправления,4 RUN,4 DONE и4 UNSURE. Примеры перевода/исправления подаются парами с разными таблицами; перестановки пересоздаются при каждом выборе. Часть исправлений — реальные ошибки родителя, часть — пары с одним наблюдаемым кодом и разными условиями. Положительные DONE имеют верный код и необходимые запуски; UNSURE обучается в реально исчерпанном бюджете.

Размер и протокол сохранены: 3 022 080 параметров, rank16 адаптеры,318 208 обучаемых коэффициентов, контекст1024; Q4 на каждом прямом проходе, вычисления FP32. Нового критика, DPO или штрафа за DONE нет. Начальные адаптеры совпадают с прежним выбранным SPEC; перед SGD на B200 проверены точные исходные Q4 payload. Русский входной словарь и тензоры вне адаптеров проверены отдельно.

Правило выбора зафиксировано до SGD. Оно сохраняет обычную точность и число успешных отладок в пределах3п.п. от родителя, навигацию — в пределах одного эпизода, известные запросы синуса — без потерь. Преимущество отдаётся совместному улучшению: не больше ложных DONE и минимум+10п.п. по худшему виду таблицы. Далее минимизируются ложные DONE и учитываются худшая точность таблиц и число правильных завершений. Родитель включён как вариант шага0. Закрытый экзамен не менял это правило.

## Отдельный прототип harness: канонизация таблицы

Файлы bb_canonical.py и bb_session.py приводят доступные константы к стабильному порядку перед вызовом модели и переводят индексы ответа обратно. Значения не добавляются и не удаляются; текущий HEX перенумеровывается без изменения машинного кода. Код не получает эталонной спецификации задания. Это отдельная диагностическая проверка harness после выбора весов; она не включена в основной результат обучения выше.

| Та же числовая когорта, канонизация harness | Родитель | Продолжение |
|---|---:|---:|
| extras | 102/128 | 108/128 |
| full | 102/128 | 108/128 |

Подтверждено точное равенство 2131 входных запросов модели при воспроизведении 512 отладочных эпизодов с полностью переставленной таблицей и тем же исходным машинным кодом. Поэтому использовались уже полученные потоки токенов; каждое действие и конечный код повторно прогнаны настоящим ROM. Это не дополнительные независимые пробы нейросети. Поведение с новым порядком становится таким же, как с каноническим, включая оставшиеся ошибки и ложные DONE. Добавление новых отвлекающих значений меняет набор таблицы и этой эквивалентностью не покрывается.

Готовая обёртка для моделирования: bb_session.Session; локальные предложения с необязательной внешней таблицей: bb_chat.py --pool JSON. Эта обёртка убирает зависимость от перестановки таблицы, но не исправляет неверное понимание задания.
