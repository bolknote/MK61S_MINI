# Разнообразные циклы SPEC с сохранением прежнего перевода

Ни один новый чекпойнт не прошёл защитные критерии; выбранным остаётся прежний рабочий родитель. Результат дообучения не принят как улучшение.

Главный результат: в одинаковом компактном протоколе завершения упали 213→142 из 512, а принятые ложные DONE выросли 4→15. Прежний длинный профиль завершает 269/512. Улучшение направленного восстановления не перенеслось на самостоятельный цикл.

При правильной SPEC, заданной проверяющим, восстановление после отклонённого DONE улучшилось: исправления 8→51 из 64, доведение уже верного кода 45→64 из 64. Первоначальный перевод условий изменился лишь 188→192 из 256. Положительный результат относится к явно направленному инструментальному протоколу, а не к общей автономности.

Обучение завершено: 3000 обновлений всех 3 022 080 параметров от прежнего рабочего родителя, Q4 на каждом проходе. Выбран шаг 0; 0 означает возврат к прежнему рабочему профилю после непрохождения критериев сохранения.

Данные: 384 новых задач, 2048 прежних условий, 19120 проверенных состояний. Непрерывные случайные числовые входы; отдельные ошибки операций, аргументов и порядка; правильный код после PUBLIC_RUNS и ошибочный код после COUNTEREXAMPLE; пересмотр неверной SPEC без показа кода. Пятьдесят процентов каждого обучающего батча заняты прежним переводом и исправлениями.

Новый закрытый набор: 256 задач, 512 обычных эпизодов, 64 эпизода с подставленной неверной SPEC и 128 эпизодов восстановления после принудительного отклонённого DONE. Это разные диагностические режимы; их результаты не смешаны. Начальный принудительный DONE исключён из числа ложных заявлений модели.

Чекпойнт выбран до открытия закрытого теста по отдельным 96 новым задачам и 96 прежним условиям. Допустима потеря не более двух ранее верных переводов; исправления, завершение правильного кода и ложные DONE защищены относительно родителя. Дополнительно защищён прежний длинный рабочий профиль.

Режим восстановления после принудительного отказа начинает с правильной SPEC, заданной проверяющим. Он изолирует навык работы с отказом и не равен самостоятельному пониманию условия. В режиме неверной SPEC гипотеза также задаётся проверяющим. Длинный и компактный профили имеют общий предел 1024 токена; длинные входы не обрезаются, переполнение считается неудачей. Проверка DONE числовая и конечная: совпадение на её входах может не сохраниться на отдельном аудите даже относительно той же SPEC.

Итоговая порча считается после механического отката неподтверждённых изменений упряжью. Дополнительно выше показаны неверные кандидаты до отката. Сопоставление SPEC и числовой проверки конечно; произвольные циклы и ветвления МК-61 этим набором не охвачены.

Обучение использовало одну B200 рядом с пользовательским Qwen: лимит аллокатора 1536 МиБ, фактический пик зарезервированной PyTorch памяти 1330.0 МиБ. Эффективный батч 32 набран четырьмя микробатчами по 8. Между шагами и вызовами добавлены паузы; целевой duty fraction 0.5. Память CUDA-контекста находится вне этого лимита. Конфигурация и контейнер Qwen из эксперимента не менялись; влияние на задержку Qwen отдельно не измерялось.

Q4: подтверждено 28 совпадающих потоков B200/CPU/C++, повторная упаковка из сохранённых весов точна. Память и скорость физического PicoCalc не измерялись.

Попарная неопределённость посчитана по 10 000 bootstrap-выборок из 256 задач; два начальных состояния задачи остаются вместе. Это не проверка устойчивости к seed обучения.

Артефакты: `.build/mk61-agent-20261106/spec-diverse-recovery-v1`. Рабочий профиль устройства автоматически не заменён.
