# Отдельный адаптер перевода условия в SPEC

Статус: завершено. Выполнены1500 обновлений адаптера, оба development
контроля, закрытое сравнение в Q4 и сверка35 потоков B200/CPU/C++.
Рабочий профиль не заменён: новый адаптер не прошёл удержание прежних задач.
Результаты: [PHASE_SPEC_ADAPTER_RESULTS.md](PHASE_SPEC_ADAPTER_RESULTS.md).

Причина: в последнем закрытом опыте первый перевод был верен для 190/256
условий, включая 96/160 составных. Все принятые ложные DONE обеих веток
были связаны с неверной начальной и конечной SPEC. Увеличение окна сняло
переполнения, но увеличило ложные DONE и порчу кода. Совместное обучение
перевода и инструментальной политики в предыдущем курсе ухудшило полный цикл.

Изменение: адаптер Q/V и MLP ранга16 обучается на прежнем рабочем родителе
3M, с Q4 на каждом проходе. Обновляются 317440 коэффициентов LoRA.
Словарь, embedding-матрица, action/correctness-головы и другие исходные
матрицы заморожены. Исходный actor хранится отдельно и не получает градиентов.

Точное переключение: принудительный WRITE при первоначальном переводе
и повторном разборе условия обрабатывает translator. Все обычные решения
actor, включая обычные WRITE и их тела, используют прежние веса. Условие
повторного разбора остаётся прежним и не содержит текущий код. Формат
наблюдения HEX, контекст1024, KV FP32, 12 действий, RUN/gate/rollback прежние.
Заморозка функции actor не гарантирует прежнего поведения полного цикла:
новая SPEC меняет его вход, поэтому весь цикл оценивается отдельно.

Данные: 512 новых/снятых с роли теста учебных AST, в том числе128 пар
с перестановкой операций; по две естественные формулировки DeepSeek.
Обратная проверка текста не получает исходный AST. Для development и
closed предусмотрены два разных обратных запроса. Это проверки одной
большой моделью, не независимая человеческая разметка. Сохраняются2048
старых учебных переводов и128 отдельных ранее открытых задач удержания.

Новый development:128 целей, из них80 композиций из16 новых троек.
Новый closed:256 целей, из них160 композиций из32 новых троек.
Новые числа development/closed различаются. Отложенные тройки исключены
из обучения; они отсутствуют в известных прежних целях и наблюдавшихся
гипотезах. Все reference/bad программы и их различные результаты проверены
ROM; замена слов сохраняет точные машинные программы. Закрытые AST не
отбрасываются по неудачным ответам маленькой модели.

Курс:1500 обновлений, контроль500/1500, эффективный батч32 из четырёх
микробатчей8, lr8e-5 с разогревом и косинусным спадом. Половина батча —
прежний перевод, четверть — парные перестановки, четверть — новые задачи.
Четверть примеров использует реальный формат повторного разбора. Loss
только на токенах SPEC, без action loss и критика правильности.

Выбор до closed: прирост минимум4 верных композиций из80 development;
общий перевод и унарные/бинарные задачи не хуже; удержание старого общего
результата и потеря не более2 прежде верных переводов. В полном цикле:
не меньше завершений, исправлений и доведённых верных стартов; не больше
принятых ложных DONE, порчи, эпизодов с ложными заявлениями и ложных DONE
при внедрённой неверной SPEC. Исходный профиль — допустимый шаг0.
На новом closed проверяются baseline, selected и fixed1500; совпадающие
варианты переиспользуют один результат. Тест не выбирает другой чекпойнт.

Сервер: GPU1 рядом с Qwen, allocator≤1536МиБ, минимум8192МиБ свободно,
целевая доля активного времени0.5. Qwen не меняется. После завершения
проверяются экспорты Q4, потоки CPU/B200/C++, неизменность actor и остальных
замороженных параметров, отсутствие собственных GPU-контейнеров.

Артефакты: `.build/mk61-agent-20261106/spec-phase-adapter-v1`.
