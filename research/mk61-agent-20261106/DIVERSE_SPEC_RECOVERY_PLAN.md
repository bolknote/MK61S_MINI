# Разнообразные циклы SPEC: подготовка следующего обучения

Курс был зафиксирован до первого обновления весов. После восстановления SSH выполнены все **3000 обновлений**, закрытое сравнение и сверка Q4 на B200/CPU/C++ завершены. Ни один новый чекпойнт не прошёл все защитные критерии; выбранным остаётся прежний рабочий родитель. Qwen и другие удалённые сервисы из этого опыта не менялись. См. [итоговый отчёт](DIVERSE_SPEC_RECOVERY_RESULTS.md).

## Данные и проверки

- Родитель: прежняя рабочая полная Flourish 3M, а не результат узкого опыта на 32 формулах.
- 384 новые учебные задачи: 72 унарные, 48 бинарных, 216 композиций и 48 задач с константами. Все 18 унарных операций представлены.
- 2048 прежних условий для сохранения перевода в SPEC.
- 19 120 различных обучающих состояний. Включены ошибки операций, аргументов и порядка; DIAG и пересмотр SPEC; реальные переходы после DONE_REJECTED; WRITE, RUN 00/01, DONE и UNSURE.
- Числовые входы преимущественно непрерывные случайные, с отдельными граничными значениями. Неверный пример обязан различаться с целью и на проверках упряжи, и на отдельном аудите. Исправлен один пример, который проходил проверки упряжи и расходился только на аудите; такой пример нельзя размечать как отклонённый DONE.
- На каждом шаге половина примеров — прежние перевод и исправления, половина — новые задачи и циклы.
- Проверены цели, гипотезы и восстанавливаемая формула видимого кода: отложенные тройки операций не попали в учебные состояния. Противоречивых меток для одинаковых входов нет.
- Локальная проверка: конечные градиенты; три настоящие задачи, шесть обычных эпизодов и шесть эпизодов восстановления после отклонения, без переполнения контекста. Это проверка работоспособности эксперимента, не оценка качества новой модели.

## Обучение и выбор

План: 3000 полных обновлений, Q4 на каждом проходе, контекст 1024, запас ответа 160. Эффективный батч 32, четыре микробатча по 8. Проверки на шагах 1000, 2000 и 3000.

Отдельный development содержит 96 новых задач; ещё 96 прежних условий проверяют сохранение перевода. Выбор защищает завершение уже правильного кода, исправления и ложные DONE относительно родителя. Допустима потеря не более двух ранее правильных переводов. Дополнительно сравнивается прежний длинный рабочий профиль. Если ни один чекпойнт не проходит защитные критерии, выбранным остаётся родитель.

Новый закрытый тест заморожен до обучения: 256 задач, включая 160 новых композиций. В нём 512 самостоятельных эпизодов, 64 диагностических эпизода с заданной неверной SPEC и 128 эпизодов восстановления после принудительного отклонения DONE. Начальный принудительный DONE не засчитывается как заявление модели. Родитель, выбранный чекпойнт и последние веса сравниваются на тех же заданиях. Затем проверяется совпадение Q4 на B200, CPU и C++.

## Сосуществование с Qwen

Одна физическая GPU, индекс 1. Лимит аллокатора PyTorch — 1536 МиБ; это не включает память CUDA-контекста. Перед запуском нужен запас не менее 8192 МиБ. Между шагами и вызовами предусмотрены паузы с целевым duty fraction 0,5. При недостатке свободной памяти рабочий процесс ждёт. Остановка или перенастройка Qwen не предусмотрена.

При первом запуске после восстановления SSH использованы следующие команды. Повторный запуск защищён маркером `launch.json`:

```bash
python3 research/mk61-agent-20261106/bs_remote.py probe
python3 research/mk61-agent-20261106/bs_remote.py deploy
python3 research/mk61-agent-20261106/bs_remote.py start
python3 research/mk61-agent-20261106/bs_remote.py status
```

Артефакты подготовки: `.build/mk61-agent-20261106/spec-diverse-recovery-v1`. Файлы `frozen.json`, `prepared.json`, `leakage-checks.json`, `eval-smoke.json` содержат хеши, проверки и нулевой счётчик обновлений. Запуск не должен повторно создавать данные или менять прежние эксперименты. Рабочий профиль PicoCalc автоматически не заменяется.
