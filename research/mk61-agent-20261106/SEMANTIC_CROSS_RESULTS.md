# 3M Q4: совместное понимание цели, кода и результата

Выбран по новому контролю: **late-coupled, шаг 0, β=0.0**. Новый чекпойнт прошёл условия выпуска после экзамена: **False**. Экзамен не использован для выбора весов. Отдельное заранее записанное условие выпуска требует удержания всех трёх панелей и уменьшения суммарных ложных DONE.

Перед прогоном разобраны 62 ложных DONE предыдущего экзамена: 61 программа неверна уже на открытом случае, одна — только на скрытом. Публичные результаты сеть видит; эталонные значения на вход не передаются. Эти прежние эпизоды теперь учебные.

Предыдущая попытка исправляла только пять линейных векторов действий. Теперь адаптируются внутренние признаки: `late` — Q/V и три матрицы MLP последних двух блоков, `all` — те же матрицы всех десяти блоков. Оба профиля начинают с одного AJ lr10-terminal Q4, свежие LoRA rank16/alpha32 имеют нулевое влияние при старте. Инициализация общих адаптеров, последовательность учебных выборок и потери одинаковы.

Проверено 591 учебных квадратов, помещаются в обучение 591. Каждый содержит две цели и два кода: диагональные сочетания правильны, остальные ошибочны. При фиксированном коде фактические результаты совпадают для обеих целей; оба ошибочных сочетания проверены на различающий публичный случай. Следовательно, одной частотой DONE или видом кода выполнить все четыре метки нельзя.

Классификация корректности и выбор действия обучаются вместе с четырьмя сравнениями внутри квадрата: по двум фиксированным целям и двум фиксированным кодам. Дополнительно учатся полные проверенные исправления WRITE→RUN→DONE, новые обычные задачи и сохранение прежних ответов. Общего штрафа за любое DONE нет. Для KD удерживаются только те действия/токены исходного учителя, где его argmax согласен с проверенной учебной меткой.

Учебных исправляющих шагов 5700, обычных 1234, удерживающих 20000. Выполнено по 750 обновлений на двух B200, всего 1500. Контроль каждые 250. Большая LLM в этом прогоне не вызывалась: учитель составляет исправление по исходной программе, метки и исполнения проверяются ROM-эмулятором.

Входной словарь и формат HEX не изменены. Слияние адаптеров даёт прежние 3 022 080 параметров; Q4 действует в каждом прямом проходе. Runtime не имеет скрытых тестов/эталонного кода/ожидаемых значений и не запрещает raw-DONE по порогу.

На панели операций рост общей точности классификатора оплачен дополнительными ложноположительными: 16 → 25. Пропусков верного кода стало 47 → 21. Поэтому одной общей точности недостаточно: следующий опыт должен отдельно ограничивать ошибочное признание неверного кода правильным.

Здесь правильность предсказана знаком существующего margin при фиксированном пороге 0; это диагностическая метрика, она не блокирует DONE и не используется для выбора весов.

Успех означает правильную программу, все обязательные публичные исполнения и DONE. UNSURE при правильном коде успехом не считается.

На каждой контрольной панели требуется не меньше успехов и завершённых верных стартов, не больше ложных DONE, чем у исходной сети. Среди подходящих вариантов сравнивается (успех − 4×ложные DONE)/размер с весами 0.60/0.25/0.15. Исходная сеть включена как шаг 0. Профили research выбраны только по контрольной полезности среди обученных, могут нарушать удержание и не подменяют основной отбор.

Следующий опыт должен отделить понимание условия от проверки программы. Предлагаемый порядок (в этом прогоне ещё не реализован):

1. Отдельный тест «условие → требуемая операция/аргумент/режим/ограничения» и «код + факты → какой эффект получен». Считать ошибки двух этапов отдельно, проверять новые русские формулировки и сочетания операций.
2. Обучить короткий явный план цели в том же HEX: сначала получить программу-гипотезу из условия, затем сравнивать её смысл с текущим кодом и запусками. Во время работы план предсказывает сама сеть; доверенный эталон в runtime не подставляется. Учитель готовит разнообразные формулировки и объяснения, ROM проверяет метки. Отдельно измерять качество предсказания плана и полных исправлений.
3. Сравнить такой учебный протокол с текущим при одинаковом бюджете обновлений и прежних ограничениях выпуска. Сначала проверить один короткий пилот. Увеличивать объём обучения после подтверждения переноса; текущий опыт не доказывает ни предел 3M, ни достаточность дальнейшего повторения тех же примеров.
