# Kon-Tiki 3M после дообучения на лишних UNSURE

На прошлом тесте число отказов выросло с 16 до 33. Среди 17 новых отказов после пересмотра SPEC в 14 случаях гипотеза расходилась с условием. В трёх случаях SPEC была верной и требовался WRITE. На прежней валидации нашлись ещё четыре таких отказа — два с верным кодом и два с ошибочным. Все семь разобранных состояний ушли в учебный повтор с целями WRITE (5) и DONE (2). DeepSeek предложил правильное действие во всех пяти случаях с WRITE. Два предложения переписать уже верную программу были отброшены.

Размечено 340 состояний, проверку прошли 144 ответа DeepSeek-V4.1-Flash. В выборку вошли 1095 парных состояний в пяти группах и повтор старых уроков. Выполнено 1500 обновлений адаптера исполнителя от предыдущего Q4-снимка. Исходная загрузка адаптера воспроизвела прежний пакет побайтно по тензорам. Снимки 300, 850 и 1500 проверены на валидации. Ни один там одновременно не снизил отказы при правильной SPEC, не сохранил все исходные исправления и не удержал число принятых ложных DONE и порчи кода. Для закрытого сравнения зафиксирован снимок 300 по критерию безопасности и отдельно снимок 850 с минимумом лишних отказов. Снимок 1500 проверялся на валидации и наборе восстановления.

На новом закрытом тесте 188 русских задач и по два старта. В наборе 40 задач на степень, 48 новых экземпляров знакомых сочетаний и 100 других композиций. Формулировки и спецификации отделены от обучения. Семейства для новых сочетаний отложены, отдельные внутренние фрагменты деревьев встречаются в разных задачах. DeepSeek получал только учебные состояния. В сравнении все версии использовали один и тот же переводчик, короткий промпт на длинных состояниях после пересмотра SPEC, независимый разбор и условный повтор WRITE. Обновлённые веса применялись только к этому короткому вызову. Первые программы совпали (144/188).

Снимок 850 вернул шесть действий вместо отказа при правильной SPEC. Выиграл три новых исправления и потерял два старых. Четыре из десяти исчезнувших отказов соответствовали неверной SPEC. Все шесть новых принятых ложных DONE пришлись на четыре задачи вида «вычисли степень с основанием a и показателем 10». Независимый разбор не поддержал эту формулировку. Например, для числа 2.80773 модель подтвердила собственную SPEC 2.80773^2.80773 и записала в R2 примерно 18.149335 вместо 30447.6251. В двух эпизодах такой WRITE заменил уже правильную программу.

Снимок 850 сохранил 48/48 исправлений на наборе восстановления. Известную задачу со знаком степени он закрыл своим WRITE за 675 токенов вместе с промптом. В закрытом прогоне все WRITE целевого короткого шага уместились в 1024 с заголовком и концом команды. По два обрыва WRITE в каждом варианте остались на других длинных шагах цикла. Проверка выполнялась на B200 с эмулятором МК-61.

В ходе обучения исправлена ошибка в коде отдельного оценщика. Его обновление остановило выпуск итоговой квитанции после 1500-го шага. Снимки уже были сохранены. Их и остальные зафиксированные входы сверили по хешам, после чего запустили оценку сохранённых весов. Рабочий профиль не заменён.
