# Адаптер SPEC отдельно от управления инструментами

Фиксированный адаптер после1500 обновлений улучшил первый SPEC 175→205 из256, завершения 264→275 из512, снизил принятые ложные DONE 19→10 и итоговую порчу правильного кода 9→4 на новом закрытом наборе.

На development при этом утрачены9 ранее верных переводов, приобретены6, общий счёт удержания105→102/128; одна унарная задача также перестала решаться. Поэтому исследовательский выигрыш нового адаптера не стал основанием заменить рабочий профиль.

Новый адаптер не прошёл весь заранее заданный отбор; selected остаётся исходным переводчиком. Все требования к сохранению прежних навыков пока не выполнены.

Результат последнего шага показан как обязательная исследовательская проверка. Выбор по development не пересматривается после просмотра closed; selected остаётся заранее зафиксированным вариантом.

Обучение завершено:1500 обновлений317440 коэффициентов LoRA Q/V и MLP ранга16, Q4 на каждом проходе. Входные embeddings, словарь, action/correctness-головы и остальные исходные матрицы переводчика не менялись. Отдельный actor полностью сохранён побитно. Основной профиль устройства не заменён.

Переключение: новый translator используется только для принудительного WRITE при первоначальном переводе и повторном разборе условия. Все обычные решения инструментов и тела ответов (в том числе обычный WRITE) выдаёт прежний actor. Условия повторного разбора, численный gate, RUN, rollback, контекст1024 FP32 KV и12 действий прежние. Новая SPEC меняет наблюдения actor, поэтому неизменность его весов не гарантирует сохранения поведения всего цикла.

Данные: 512 учебных AST (включая 66 снятых с роли теста ошибок и 128 пар перестановок), 1013 русских учебных вопросов DeepSeek,2048 прежних переводов. Четверть примеров обучала повторному разбору без кода, половина — повтору старого перевода. Loss только по токенам SPEC; action loss и нейросетевой критик не обучались.

Новые development/closed AST и числа различаются; отложенные тройки исключены из обучения, включая прежние цели и наблюдавшиеся гипотезы. Все заранее выбранные закрытые AST сохранены после проверки формулировок. DeepSeek восстанавливал смысл текста без исходного AST; для оценки использованы два обратных запроса. Генератор и проверяющий — одна большая модель, не независимые человеческие аннотаторы. ROM проверяет код и числа, но не истинность русского понимания.

Статистика принятых ложных DONE: `{'baseline': {'accepted_false_DONE': 19, 'initial_SPEC_wrong': 19, 'final_SPEC_wrong': 19, 'own_SPEC_fails_independent_audit': 2, 'wrong_candidate_before_rollback_on_correct_start': 48}, 'selected': {'accepted_false_DONE': 19, 'initial_SPEC_wrong': 19, 'final_SPEC_wrong': 19, 'own_SPEC_fails_independent_audit': 2, 'wrong_candidate_before_rollback_on_correct_start': 48}, 'final': {'accepted_false_DONE': 10, 'initial_SPEC_wrong': 10, 'final_SPEC_wrong': 10, 'own_SPEC_fails_independent_audit': 0, 'wrong_candidate_before_rollback_on_correct_start': 50}}`. Проверка gate относится к заявленной SPEC; ошибочная интерпретация может согласоваться с кодом. Конечные числовые тесты не являются доказательством на всех входах. Область этого опыта — прямолинейные числовые выражения и запись результата в память, не произвольные игры с ветвлениями и циклами.

Проверены 35 совпадающих потоков B200/CPU/C++ с реальным переключением профилей. Первый Q4 payload совпал с родителем; перепаковка сохранённых master-весов точна. Меняться могли только50 матриц Q/V и MLP; входной словарь, embedding/action-строки и остальные Q4-матрицы сохранены. Нативный bridge использует один буфер весов 2160856 байт, один KV и workspace. Переводчик и actor сохраняются отдельными пакетами; это дополнительное хранение профиля, а не одновременная загрузка двух моделей в этот буфер.

Физический PicoCalc не измерялся, сборка приложения не заменялась. Python/GPU-оценка держит модели одновременно для удобства эксперимента; утверждение об одном буфере относится к проверенному C++ bridge.

Обучение на одной B200 рядом с Qwen: allocator≤1536МиБ, минимум8192МиБ свободно, целевая доля активного времени0.5. Пик reserved PyTorch 880.0МиБ, CUDA-контекст и библиотеки в него не входят. Итоговый /health Qwen200; его контейнер и параметры не менялись, задержки отдельно не измерялись. Собственные GPU-контейнеры завершены.
