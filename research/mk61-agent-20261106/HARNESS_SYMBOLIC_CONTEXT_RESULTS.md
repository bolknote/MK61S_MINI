# Контекст и символьное наблюдение без обучения

Контекст 1536 с FP16 KV поднял завершения 280→302 из 512 и исправления 119→131 из 256. Но принятые ложные DONE выросли 15→28, итоговая порча правильного кода — 6→14. Увеличение окна без изменения политики не принято как улучшение рабочего агента.

Формула программы и MATCH/MISMATCH в испытанном текстовом формате также не дали улучшения без обучения: при окне 1536 на открытой диагностике завершения снизились 75→62 из 128 относительно HEX с тем же окном. Эта ветка не прошла в новый закрытый тест.

Ни один изменённый протокол не прошёл все защитные условия. Выбранным остаётся baseline; context1536 проверен как исследовательский кандидат.

Опыт завершён. Веса прежнего рабочего родителя 3M неизменны, Q4 во всех режимах, обновлений оптимизатора — ноль. Рабочий профиль устройства автоматически не заменён.

Диагностика принятых ложных DONE:

- baseline: всего 15; начальная SPEC неверна у 15, конечная — у 15; несоответствие даже своей SPEC на отдельном аудите — 0. Ошибки генерации: `{'context_overflow': 138, 'incomplete': 35}`.
- context1536: всего 28; начальная SPEC неверна у 28, конечная — у 28; несоответствие даже своей SPEC на отдельном аудите — 0. Ошибки генерации: `{}`.

Интервалы: 10 000 попарных bootstrap-выборок по задачам, оба начальных состояния остаются вместе. Это один замороженный набор; 160 составных задач используют шесть новых троек операций. Интервал по задачам не описывает полностью разброс между новыми семействами формул; повторяемость на других распределениях не установлена.

Формула выводится из текущего кода, а MATCH/MISMATCH/UNKNOWN — из проверки по текущей заявленной SPEC. Проверяющий не видит эталонную русскую интерпретацию. MATCH означает только совпадение на 16 проверочных входах. Отдельный аудит использует 32 других входа и эталон цели. Ошибочная SPEC может согласоваться с ошибочным кодом. Поэтому принятие ложного DONE относительно условия остаётся возможным. Символьный декодер дополнительно проверен на всех 640 начальных программах обоих наборов: 48 числовых входов на программу, расхождений с ROM нет. Это проверка наблюдения, не результат решения задач моделью.

Не изменялись численный шлюз DONE, автозапуск недостающих RUN, бюджет 12 действий и откат незавершённых правок. Итоговая порча считается после этого отката; неверные кандидаты показаны отдельно. Символьная ветка заменяет HEX только для поддержанного прямолинейного кода. Произвольные циклы и ветвления этим тестом не охвачены.

Новая текстовая запись не оказалась короче: в 128 сопоставленных начальных состояниях открытого набора (при одной и той же верной SPEC, без генераций) формула, статус и пояснение добавляют в среднем 62 токена, диапазон +34…+94. Поэтому symbolic1024 измеряет эффект конкретной новой записи вместе с её расходом контекста; сравнение combined1536 с context1536 помогает оценить её отдельно при большем окне. Этот опыт без обучения не доказывает, что сеть не сможет освоить более компактное символьное наблюдение после адаптации.

Проверено 10008 преобразований в IEEE FP16, 22 предварительных потока CPU/C++ (включая вход 1447 токенов) и 27 потоков закрытого опыта B200/CPU/C++. Повторная упаковка Q4 из сохранённых весов точна; входной словарь, веса и исходный родитель сохранены. Код продукта не изменён.

На B200 использовался один процесс с лимитом allocator 1536 МиБ и целевой долей активного времени 0,5. Пик reserved PyTorch: 80.0 МиБ; CUDA-контекст и библиотеки в этот показатель не входят. При свободной памяти менее 8192 МиБ процесс ждёт. Контейнер и настройки Qwen не менялись; итоговая проверка /health вернула 200. Влияние на задержки Qwen отдельно не измерялось.
