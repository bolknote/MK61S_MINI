# strlen M4: интеграция измеренных реализаций

Интеграция на базе `ad261f72c7e177af53d4df71939ab1d037ad2b98` переносит
принятый M4 `strlen` из коммита `6e814dd7bb8b12c8700bbb9ad3817a20ceb8800e`.
Аппаратные кампании 24 октября не повторялись. Финальная проверка исходного
DSP32 на Classic уже принята: final Root CLOSED SHA-256
`d9ad6427ae8fbe5ee4f380d736a26c35fd9b352e2ad9708bb2e6db640f998875`.

`RESULTS-M4.json` сохранён как исторический результат первоначального выбора:
его прежний статус ожидания финального HIL и прежние размеры относятся к тому
этапу. Ниже зафиксированы последующее принятие и интеграция 28 октября.

## Выбор с учётом бюджета

| Путь | Тело | Размещение |
|---|---:|---|
| Native F411 и LCD/OLED mini F401 | DSP32, 132 байта | Flash |
| Native графические F401xC, включая Classic V2/V3 | DSP8, 76 байт | Flash |
| Автономный SDK APP на M4 | DSP32, 132 байта | SRAM |
| Shared APP | прежний переход 12 байт | runtime slot 20 → native |
| M0+ | прежняя реализация | аппаратный выбор ещё не выполнен |

На актуальной базе DSP32 увеличивал F401 Classic V3 с 257980 до 258104 байт:
4040 свободных байт при обязательных 4096. Уже измеренный DSP8 экономит ровно
56 байт и проходит контракт. Compact выбирается только в native F401xC с
графическим профилем; mini LCD/OLED и SDK сохраняют более быстрый DSP32.
`code/strlen_m4.inc` меняет только число повторов 1/4. Нового алгоритма нет.

В исходной физической матрице Classic F411/96 MHz (фаза B, shared-flash)
геометрический выигрыш DSP32 против native baseline — 2.66208275×, DSP8 —
2.51569235×. DSP8 — самый быстрый кандидат размером не больше 76 байт:
DSP1 64 B — 2.23223289×, word2 76 B — 1.55831583×; DSP4 100 B —
2.55841807×, но в текущий резерв Classic F401 не помещается.
Эти числа получены на F411, физическая скорость F401 отдельно не проверялась.
Короткие строки имеют известные регрессии; универсальный выигрыш не заявляется.

Оба тела совпадают с измеренными побайтно, включая literal pool, при
выравнивании входа функции 16 байт:

- DSP32: `b86ba7f6a064105b6ea7bd4ceccb452676168453d52109472da5c0d958f59362`;
- DSP8: `0484a7f7fbd7fc9237abb81a5bd2e3ea2f9f72afc3472b896f1d5f65894c1620`.

Контракт — обычные строки SRAM/Flash. Нет чтений до входного указателя;
разрешена последняя выровненная восьмёрка с NUL, до семи байт после него.
Следующая восьмёрка читается только после проверки предыдущей. Входные данные,
AAPCS-регистры и SP сохраняются. ABI не менялся: 26 runtime-слотов, strlen=20.

## Проверка интеграции

| Release case | Образ, байт | Свободно | Минимум |
|---|---:|---:|---:|
| f411-stop-classic-v3-uc1609 | 375308 | 148980 | 131072 |
| f401-product-classic-v3 | 258048 | 4096 | 4096 |
| f401-product-classic-v2 | 258000 | 4144 | 4096 |
| f401-product-a00 | 221820 | 40324 | 8192 |
| f401-product-ws0010 | 229856 | 32288 | 8192 |
| f401-product-mini-v2-a00 | 221852 | 40292 | 8192 |

Лимиты Flash/RAM/стека и release-contract не ослаблялись. У Classic V3 F401
нет запаса сверх обязательных 4096 байт. Максимальный статический кадр:
F401 1304/2048, F411 1928/5120. Собраны 5 System APP для F411 и 11 для F401;
максимальное загруженное приложение — USBDISK, 20460/20480 байт.

Пройдены существующий ASan/UBSan HOST-набор строк/аллокатора, 10080 вызовов
ARM с контролем NUL/выравнивания/границ/регистров (три production-тела),
27000 вызовов ISO-строк в финальных native F411/F401 ELF. Четыре упакованных
SDK APP собраны для M4/M0+, standalone/shared. M0+ SDK strlen остался
побайтно тем же 16-байтным телом. Native PicoCalc не менялся.

Production-декодер проверил упаковку и перемещение M4 APP по трём адресам.
Реальные ARM startup, binding, strlen и runtime-переходы выполнили 2448
вызовов на SRAM/Flash-входах, включая 1632 вызова slot 20 (F411 и F401).
Нулевой slot 20 отклоняется при инициализации; проверен повторный запуск
кешированного APP. Только discovery/capabilities API моделировались.
Эмуляция подтверждает корректность и маршруты, не аппаратное время.

Локальные исходные журналы, отрицательные бюджетные проверки, команды и
хеши находятся в `.build/strlen-main-integration-20261028-v1/` основного
checkout. Новых аппаратных действий, установки прошивки и публикации нет.

Повторная проверка native: `tests/strlen_arm_self_test.py` принимает маленькие
production ELF с `--elf` и новым `--output`; `tests/native_strings_arm_self_test.py`
принимает полный `resident.elf`. Штатные release-сборки выполняются через
`tools/.mk61-gcc/build-standalone.py --release-case <case> --build-path <new>`.
