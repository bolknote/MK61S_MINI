Практическая верхняя граница времени `pow` для всех `binary64` остаётся
недоказанной. Здесь проверены альтернативы точному последовательному
сравнению коэффициентов. Прототип использует точные рациональные числа
и допускает отказ перед слишком большим промежуточным произведением.

Для положительного основания `x`, модуля показателя `p/q` и середины
округления `m` требуется определить знак `a^p-b^q`. Здесь `a=x` для
положительного показателя, `a=1/x` для отрицательного, `b=m`. Если оба
основания меньше единицы, их можно инвертировать, меняя знак ответа.
Основания по разные стороны единицы сравниваются сразу.

В [compare.py](compare.py) реализовано сокращение показателей по Евклиду.
После возможного обмена сторон записываем `p=t*q+r`. Тогда
`a^p/b^q=(a^t/b)^q*a^r`. При `a^t/b>=1` знак известен. Иначе, при
ненулевом `r`, задача заменяется сравнением `(b/a^t)^q` с `a^r` с
противоположным знаком. Новый меньший показатель равен `r<q`, поэтому
число делений ограничено. Для ничьи применяется чётность кодировки
нижнего соседа.

Оба запуска прошли 12 672 сравнения всех комбинаций восьми выбранных
рациональных оснований, `1<=p<=33` и `q` из `{1,2,4,8,16,32}`. Отдельный
набор содержит по две границы ответа MPFR для 404 пар `binary64`.
Каждый полученный ответ сравнивается с полными целыми степенями Python.
Ограничение касается предсказанной ширины отдельной степени числителя
или знаменателя. Деление рациональных чисел также может занимать память.

| Предел отдельной степени, бит | Точных сравнений с серединой | Отказов перед степенью |
| --- | ---: | ---: |
| 1 048 576 | 808 | 0 |
| 8 192 | 286 | 522 |

В первом запуске максимальная материализованная степень заняла 718 462
бита. На допустимом входе `x=0000000000000001`, `y=3BF6000000000001`
при сравнении с серединой непосредственно ниже единицы первый частный
показателей равен `13415813871788762645`. Нечётный коэффициент уже этой
степени содержит не менее `711038135204804420186` бит. Отделение
показателя двойки сохраняет эту оценку. Прототип останавливается до
выделения такой памяти. На входе `x=000FFFFFFFFFFFFF`,
`y=BBFFFFFFFFFFFFFF` аналогичная нижняя граница равна
`488838717953303172097` бит.

Компактный вариант хранит промежуточные основания как пары показателей
исходных `a` и `b`. Он выполняет 16 и 5 делений соответственно на этих
примерах. По завершении остаток имеет показатели `(p,-q)` исходного
сравнения. Тождество проверяется в каждом малом примере и в сохранённых
свидетелях. Компактное хранение ограничивает размер записи выражения,
а определение знака оставшегося выражения требует отдельного алгоритма.

Проверена также попытка определить знак по небольшому модулю. Для
`x=3FEFFFFFFFFFFFFF`, `y=C01FF80000000000` и середины после
`3FF0000000000003` точная разность выровненных коэффициентов занимает
60 957 бит. Модуль `1000000007*1000000009` занимает 60 бит. В классе
остатка есть и положительное, и отрицательное целое внутри той же
границы модуля разности. Эти представители приведены в JSON. Поэтому
данных такого остатка и границы недостаточно для выбора знака. Это
проверка конкретного способа реконструкции по модулю.

Алгоритм Этессами, Стюарта и Яннакакиса даёт полиномиальное сравнение
при фиксированном числе множителей. В доказательстве предложения 3.7
он вычисляет логарифмическую форму с точностью, определённой оценкой
Бейкера — Вюстхольца. Применение этого результата снова требует
сертификата достаточной точности для всего диапазона.
[Статья, раздел 3](https://arxiv.org/html/1304.5429v3#S3)

В подходе CORE Library сравнение алгебраических выражений использует
повышение точности и оценку разделения корней. Корректность завершения
этого процесса сама по себе не устанавливает нужный предел времени
на RP2040.
[CORE Library Tutorial, стр. 20](https://cs.nyu.edu/~exact/doc/tutorial99.pdf)

Три примера прямого компаратора отдельно проверены через публичную
ARM-точку входа образа `5CD0685C/511BE730` с заводским BootROM. Все
ответы совпали с MPFR 4.2.2 и были получены до входа в
`mk61_m0_pow_rescue`. Проверка характеризует ресурсы прямого компаратора.
[Публичные ARM-вызовы](public.json)

## Сертификаты для блоков оснований

Для 26 непересекающихся блоков, содержащих **1 030 792 675 328** кодировок
положительного основания, доказано, что при `q=2^116` существующая
1024-битная ступень всегда определяет округление. Блоки включают обычные
и субнормальные числа. При `q=2^116` единственная середина, к которой
результат может подойти на логарифмическое расстояние `2^-900`, равна
`m=1-2^-54`. Сертификат исключает и это сближение. Для других `q<=2^116`
он гарантирует такое же разделение с этой конкретной серединой.
[Предыдущие ограничения области](../../doc/measurements/m0-pow-residual-domain-20261117.md)

Пусть `x=A*2^(e-b)`, где `b=52` для обычных чисел и `b=e+1074` в
субнормальных бинадах. В блоке с центром `A0` и полуразмером `B` пишем
`I=A-A0`, `t=I/B`, `L(t)=abs(ln(x))` и `C=-2^116*ln(m)`. Из условия
`abs(y*ln(x)-ln(m))<=2^-900` следуют противоположные знаки `y` и `ln(x)`.
Кроме того, целое `n=2^116*abs(y)` удовлетворяет

```
abs(n-C/L(t)) < 2^-792.
```

В каждом блоке выбирается целый сдвиг `n0`, чтобы `abs(C/L(0)-n0)<2`.
Для поиска используются целочисленные полиномы `P(I,J)`, где `J=n-n0`.
Если доказано `abs(P(I,J))<1` во всей полосе вокруг `C/L(t)-n0`, то
у любого кандидата с целыми `I,J` обязательно `P(I,J)=0`. Проверка
четырёх пар остатков по модулю 2 показывает, что у сохранённых полиномов
нет общего целого нуля. Поэтому каждый успешный блок исключает все
числители сразу. Форма алгоритма основана на методе поиска целых точек
вблизи аналитической кривой. Для этой задачи используются ряды Тейлора и
проверка остатков. [Brisebarre и Hanrot, раздел 4](https://arxiv.org/html/2606.04858v2#S4)

Программа строит полиномы методом LLL через Python-FLINT. Для проверки
достаточно стандартной библиотеки Python. Она заново строит направленные
интервалы коэффициентов целыми числами и проверяет малость каждого
полинома, остаток ряда и отсутствие общих остатков. Для остатка ряда
используется окружность `abs(t)=2^(split-1)`, где
`abs(B*t/A0)<=1/4` и `abs(ln(1+B*t/A0))<=1/3`. На этой окружности
`abs(L(t))>510` для аналитического продолжения со знаком бинады и
`abs(C/L(t)-n0)<2^44`. Для смещения кандидата от кривой отдельно
ограничивается производная по `J`. Такой способ проверки принимает
любой подходящий сертификат независимо от способа его поиска.

Доказанная граница `2^-900` больше логарифмической ширины штатного
1024-битного интервала. Округление на концах этого интервала совпадает
для всех входов доказанной области. При `q=2^116` аргумент экспоненты
меньше `2^-53`, поэтому индекс редукции равен нулю. Границы на число
полноразмерных произведений в арифметических циклах составляют 384
на первой ступени и 766 на второй. Нативный тест существующего кода
проверил по 1 233 вызова обеих точностей. Ещё 234 прямых вызова
1024-битной ступени на краях и в центрах сохранённых блоков совпали
с направленным MPFR 4.2.2. Оба результата по сторонам середины
встретились в проверке. Модифицированные полиномы с выходом за норму,
общим нулём по модулю и дублированным блоком были отклонены.
[Сертификат штатного интервала](../../dev/tools/certify_m0_pow_interval.py)

В 14 обычных блоках при `split=16` один запуск LLL проверял `2^36`
оснований примерно за 5 секунд. Даже один слой `q=2^116` имеет до
37 355 520 таких блоков в 570 обычных бинадах. Меньшая решётка с
`split=18`, степенью 9, `work_bits=100` и `delta=0.88` дала сертификаты
для 22 из 24 пробных блоков. Медиана для успешного блока вместе с
проверкой составила 0,196 с при `2^34` основаниях на блок. Проверены
индексы блоков 1, 65536, 131072 и 196608 в каждой из бинад
`-1022,-950,-739,738,880,1023`. Экстраполяция этого темпа на весь слой
даёт порядок года работы одного ядра без учёта отказов генератора.
Граница времени `pow` для всего binary64 остаётся недоказанной.

При фиксированных `x` и середине среди активных показателей может
быть не больше одного кандидата. Шаг показателей
не меньше `2^-116`, а `abs(ln(x))>2^-53` для `x!=1`, поэтому значения
`y*ln(x)` различаются больше чем на `2^-169`. Условие отказа
8192-битной ступени допускает расстояние меньше `2^-8126`.
Это сводит дальнейшую проверку к блокам оснований и середин с поиском
целочисленного показателя внутри блока.
