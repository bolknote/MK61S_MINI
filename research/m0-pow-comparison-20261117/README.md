Практическая верхняя граница времени `pow` для всех `binary64` остаётся
недоказанной. Здесь проверены альтернативы точному последовательному
сравнению коэффициентов. Прототип использует точные рациональные числа
и допускает отказ перед слишком большим промежуточным произведением.

Для положительного основания `x`, модуля показателя `p/q` и середины
округления `m` требуется определить знак `a^p-b^q`. Здесь `a=x` для
положительного показателя, `a=1/x` для отрицательного, `b=m`. Если оба
основания меньше единицы, их можно инвертировать, меняя знак ответа.
Основания по разные стороны единицы сравниваются сразу.

В [compare.py](compare.py) реализовано сокращение показателей по Евклиду.
После возможного обмена сторон записываем `p=t*q+r`. Тогда
`a^p/b^q=(a^t/b)^q*a^r`. При `a^t/b>=1` знак известен. Иначе, при
ненулевом `r`, задача заменяется сравнением `(b/a^t)^q` с `a^r` с
противоположным знаком. Новый меньший показатель равен `r<q`, поэтому
число делений ограничено. Для ничьи применяется чётность кодировки
нижнего соседа.

Оба запуска прошли 12 672 сравнения всех комбинаций восьми выбранных
рациональных оснований, `1<=p<=33` и `q` из `{1,2,4,8,16,32}`. Отдельный
набор содержит по две границы ответа MPFR для 404 пар `binary64`.
Каждый полученный ответ сравнивается с полными целыми степенями Python.
Ограничение касается предсказанной ширины отдельной степени числителя
или знаменателя. Деление рациональных чисел также может занимать память.

| Предел отдельной степени, бит | Точных сравнений с серединой | Отказов перед степенью |
| --- | ---: | ---: |
| 1 048 576 | 808 | 0 |
| 8 192 | 286 | 522 |

В первом запуске максимальная материализованная степень заняла 718 462
бита. На допустимом входе `x=0000000000000001`, `y=3BF6000000000001`
при сравнении с серединой непосредственно ниже единицы первый частный
показателей равен `13415813871788762645`. Нечётный коэффициент уже этой
степени содержит не менее `711038135204804420186` бит. Отделение
показателя двойки сохраняет эту оценку. Прототип останавливается до
выделения такой памяти. На входе `x=000FFFFFFFFFFFFF`,
`y=BBFFFFFFFFFFFFFF` аналогичная нижняя граница равна
`488838717953303172097` бит.

Компактный вариант хранит промежуточные основания как пары показателей
исходных `a` и `b`. Он выполняет 16 и 5 делений соответственно на этих
примерах. По завершении остаток имеет показатели `(p,-q)` исходного
сравнения. Тождество проверяется в каждом малом примере и в сохранённых
свидетелях. Компактное хранение ограничивает размер записи выражения,
а определение знака оставшегося выражения требует отдельного алгоритма.

Проверена также попытка определить знак по небольшому модулю. Для
`x=3FEFFFFFFFFFFFFF`, `y=C01FF80000000000` и середины после
`3FF0000000000003` точная разность выровненных коэффициентов занимает
60 957 бит. Модуль `1000000007*1000000009` занимает 60 бит. В классе
остатка есть и положительное, и отрицательное целое внутри той же
границы модуля разности. Эти представители приведены в JSON. Поэтому
данных такого остатка и границы недостаточно для выбора знака. Это
проверка конкретного способа реконструкции по модулю.

Алгоритм Этессами, Стюарта и Яннакакиса даёт полиномиальное сравнение
при фиксированном числе множителей. В доказательстве предложения 3.7
он вычисляет логарифмическую форму с точностью, определённой оценкой
Бейкера — Вюстхольца. Применение этого результата снова требует
сертификата достаточной точности для всего диапазона.
[Статья, раздел 3](https://arxiv.org/html/1304.5429v3#S3)

В подходе CORE Library сравнение алгебраических выражений использует
повышение точности и оценку разделения корней. Корректность завершения
этого процесса сама по себе не устанавливает нужный предел времени
на RP2040.
[CORE Library Tutorial, стр. 20](https://cs.nyu.edu/~exact/doc/tutorial99.pdf)

Три примера прямого компаратора отдельно проверены через публичную
ARM-точку входа образа `5CD0685C/511BE730` с заводским BootROM. Все
ответы совпали с MPFR 4.2.2 и были получены до входа в
`mk61_m0_pow_rescue`. Проверка характеризует ресурсы прямого компаратора.
[Публичные ARM-вызовы](public.json)

Для воспроизведения из корня репозитория с установленным MPFR используются
следующие команды. Поля `prototype_sha256` и `reference_sha256` связывают
результаты с кодом прототипа и независимого оракула.

```sh
python3 -B research/m0-pow-comparison-20261117/compare.py --output /tmp/m0-pow-euclid.json
python3 -B research/m0-pow-comparison-20261117/compare.py --cap 8192 --output /tmp/m0-pow-euclid-8192.json
```

[Полный проверочный запуск](exact.json), [запуск с пределом 8 192 бита](limited.json).
В обоих результатах `practical_all_input_bound_established=false`.
