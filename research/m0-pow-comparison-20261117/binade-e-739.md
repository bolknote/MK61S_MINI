# Проверка бинады e = −739 для pow

Область доказательства состоит из всех положительных binary64 в
`[2^-739,2^-738)` и всех binary64-показателей со знаменателем
`q=2^116` после сокращения `abs(y)=p/q`. Для этого слоя возможна
только одна середина на логарифмическом расстоянии `2^-900` от
точного результата, `m=1-2^-54`. Исключение этой середины доказывает,
что штатный 1024-битный интервал определяет округление на всей
покрытой области. Предпосылки о ширине интервала и подсчёт работы
берутся из существующего рационального сертификата.
[Сертификат 1024-битного интервала](../../dev/tools/certify_m0_pow_interval.py)

Независимая проверка покрыла все **4 503 599 627 370 496** оснований
этой бинады. Для 69 699 блоков проверены полиномы и непрерывность
покрытия, для аналитического хвоста пересчитана граница. На первой
интервальной ступени нужно не более 384 полноразмерных умножений,
на второй — не более 766. Итог содержит хеши журнала, архива и
исходников, к которым применяется доказательство.
[Итог проверки](midpoint-binade-e-739.json)

## Разбиение области

Положим `L=abs(ln(x))`, `C=-q*ln(m)`. В этой бинаде `L` убывает
с ростом `x`. Поскольку `p<=2^53-1`, если рациональные границы дают
`(2^53-1)*L_upper+q*2^-900<C_lower` при некотором `x0`, условие
сохраняется для всей части с `x>=x0`. Двоичный поиск с направленным
вычислением логарифмов дал `x0` с кодировкой `11c44109edb2079d`.
Так доказано разделение для 3 306 188 822 149 219 оснований,
или 73,412% бинады. Оставшиеся 1 197 410 805 221 277 оснований
накрываются 69 699 блоками шириной `2^34`. Последний блок немного
заходит за `x0`. Общий счёт покрытых оснований учитывает пересечение
только один раз.

В каждом блоке кандидат на неразрешённое округление даёт целую
точку в узкой полосе вокруг `C/L`. Прежний генератор искал
полиномы по обычным степеням двух целочисленных координат. Новый
генератор использует произведения `binom(I,i)*binom(J,j)`.
Такие полиномы принимают целые значения и на отрицательных целых
координатах. Локальная норма базиса меньше, поэтому меньшая решётка
даёт достаточно полиномов для исключения целых точек.
[Newton polynomials, приложение D.5](https://arxiv.org/html/2606.04858v2#A4.SS5)

Проверяющая программа раскрывает биномиальные полиномы после
умножения на `d!`, где `d` — суммарная степень. Она заново
вычисляет целочисленные интервалы коэффициентов и проверяет,
что абсолютная величина каждого исходного полинома строго меньше
единицы по всей полосе. Если целая точка существует, каждый из
полиномов в ней обязан равняться нулю. Остатки `binom(n,k)` по
модулю 2 периодичны по `n` с любым периодом `2^s>k`, что следует
из `(1+z)^(2^s)=1+z^(2^s)` над полем из двух элементов.
Проверка полного набора остатков исключает общий ноль. Проверяющая
программа использует только целые и рациональные числа.

## Скорость и проверки реализации

На 14 одинаковых блоках медианное процессорное время генерации
и проверки сократилось с 271 до 82 мс. Основной вариант берёт
четыре подблока и решётку ранга 28 вместо одной решётки ранга
55 или 66. Прямой перенос целочисленного базиса на соседний блок
в замере 12 соседних блоков занял больше времени, чем пересчёт.
Сохранены первые 2 048 блоков, полученные прежним способом.
Генерация остальных 67 651 блока заняла 24 минуты с 10 рабочими
процессами.

В собранном ARM-образе `5CD0685C/511BE730` с заводским BootROM
проверено 27 разных пар у концов бинады, внутри неё и по обе
стороны аналитической границы. Все 32 вызова 1024-битной ступени
и все 32 вызова публичной функции совпали с MPFR 4.2.2.
Проверка журнала отдельно отклонила дубликат и неполное покрытие
и восстановила незавершённую последнюю строку.

## Воспроизведение

Генератор использует Python-FLINT 0.9.0, независимая проверка
работает со стандартной библиотекой Python 3.11 или новее.
Журнал разбит на группы по 64 блока. Повтор `generate` продолжает
расчёт недостающих записей. `verify` проверяет сами полиномы,
полное покрытие и контрольную сумму журнала.

```sh
root=research/m0-pow-comparison-20261117
python3 -B "$root/midpoint_binade.py" geometry
python3 -B "$root/midpoint_binade.py" generate \
  --checkpoint /tmp/pow-e-739-q116 --workers 10
python3 -B -S "$root/midpoint_binade.py" verify \
  --checkpoint /tmp/pow-e-739-q116 --workers 10 \
  --report /tmp/pow-e-739-q116.json
```

Для небольшого прогона можно задать `--stop 64` обеим командам.
Если установлен Python-FLINT, `midpoint_binade_flint_verify.py verify`
принимает те же аргументы и использует точное умножение целочисленных
полиномов из FLINT. Проверка норм и остатков при этом та же.
Первые 32 768 блоков отдельно перепроверены средствами стандартной
библиотеки. Для остальных использовалось точное умножение из FLINT.

Сверьте SHA-256 сохранённого архива с отчётом, затем распакуйте
архив и передайте путь к каталогу `baseline` в `--checkpoint`.
В этом запуске архив сохранён локально
в `.build/m0-pow-binade-20261117/pow-e-739-q116-checkpoints.tar.zst`.

```sh
root=research/m0-pow-comparison-20261117
archive=.build/m0-pow-binade-20261117/pow-e-739-q116-checkpoints.tar.zst
shasum -a 256 "$archive"
replay=$(mktemp -d)
zstd -dc "$archive" | tar -xf - -C "$replay"
python3 -B -S "$root/midpoint_binade.py" verify \
  --checkpoint "$replay/baseline" --workers 10 \
  --report "$replay/verified.json"
```

Покрытие остальных бинад или знаменателей требует отдельного
доказательства. Универсальная практическая граница времени `pow`
для binary64 остаётся открытой.
