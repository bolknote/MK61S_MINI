# Граница точности pow для малых двоичных показателей

Пусть `2^-64 <= abs(y) < 2^-54`, а значащая часть `y` после
удаления конечных нулевых битов занимает не более 20 бит. Для каждого
из **10 485 760** таких показателей, включая оба знака, и любого
положительного конечного основания binary64 результат определяется
не позднее штатной 256-битной ступени CORE-MATH. При `x=1` ответ
равен единице. Субнормальные основания входят в доказанную область.
[Машиночитаемый отчёт](small-exponents.json)

## Проверка всех оснований

Для `x!=1` проверяем модуль `y*ln(x)-ln(m)`, где `m` —
граница округления или само представимое число. Штатный тест
256-битной ступени проверяет обе разновидности границ. Так как
`abs(ln(x))<745`, потенциально близкие границы имеют вид
`m=1+j*2^-54` при `j<0` или `m=1+j*2^-53` при `j>0`.
Чётные `j` соответствуют представимым числам, нечётные — серединам.
Границы для `j` вычисляются рационально один раз на бинаду `y`.
Для `m=1` имеем `abs(ln(x))>2^-53` и, следовательно,
`abs(y*ln(x))>2^-117`.

Для каждой пары `(abs(y),m)` вычисляем направленный интервал для
`t=abs(log2(m)/y)`. Если `t=n+f`, `0<f<1`, нормализованные
прообразы границы для двух знаков равны `u=2^f` и `2/u`.
Нормализованная мантисса любого положительного binary64 лежит на
сетке `Z/2^52`. Для субнормальных оснований используется подмножество
этой же сетки. Если основание в другой бинаде, монотонность логарифма
даёт расстояние не меньше расстояния до ближайшего конца бинады
прообраза. Оба конца тоже лежат на сетке.

Логарифмы рассчитываются с направленной 256-битной арифметикой.
Для `2^f` используются 144-битные целые интервалы, две таблицы и
ряд Тейлора на остатке меньше `2^-24`. Проверка ограничивает
ошибки таблиц, вычисления ряда и целочисленных делений. Расстояние
каждого интервала до сетки превышает `2^-104`. На `[1,2]`
производная `ln` не меньше `1/2`. Вместе с `abs(y)>=2^-64`
это даёт логарифмическое расстояние больше `2^-169`. По
проверенному минимуму оно строго больше **`2^-151`**.

Проверены 1 170 210 816 пар «модуль показателя — граница» и
2 340 421 632 нормализованных прообраза. Указанная для CORE-MATH
относительная ошибка 256-битного приближения меньше `2^-240`.
После учёта её и битовой полосы отказ этой ступени требует
логарифмического расстояния меньше `2^-237`. Принудительно
вызванный 512-битный интервал также разделяет границу. Для него
получено не более 392 полноразмерных умножений в рядах.
[Доказательство исходной погрешности CORE-MATH](https://inria.hal.science/hal-04159652),
[сертификат 512-битного интервала](../../dev/tools/certify_m0_pow_interval.py)

## Округление к единице при 53-битных показателях

Для каждой из десяти бинад показателя берём максимальный `abs(y)`
среди всех binary64 в бинаде. Для двух знаков `y*ln(x)` отдельно
находим крайние основания, где направленная верхняя граница
`abs(y*ln(x))` отстоит от первой середины больше чем на `2^-117`.
Монотонность `abs(ln(x))` по обе стороны от единицы охватывает все
промежуточные основания. Ответ равен единице. У `x!=1` есть тот
же запас до `m=1` благодаря нижней границе на `abs(y*ln(x))`.
В отчёте сохранены границы в двоичных кодировках. Они покрывают
**19,413%** пар «положительное конечное основание — показатель»
в десяти указанных бинадах, включая все разряды показателя.

## Тесты округления

Когда тест отбрасывает младшие разряды приближения, расстояния
до левой и правой границ отличаются на единицу в укороченной
сетке. При исходной погрешности меньше 62 433 единиц 256-битной
мантиссы отбрасываются первые и последние 61 значения укороченного
остатка. Прежнее сложение с переполнением пропускало 59 значений
непосредственно перед правой границей. В 128-битном тесте сдвиг
правой границы учтён и для обычного, и для субнормального результата.
При подходе к середине между нулём и минимальным субнормальным
числом снизу 128-битная ступень передаёт неоднозначный результат
в 256-битную.

Тест скомпилировал предикаты из производственного исходника и
проверил 794 граничных состояния. Прежний предикат принимал, в
частности, 256-битное приближение на одну единицу ниже середины.
В двух синтетических ARM-тестах старый код принимал подставленное
приближение. Исправленный код перешёл к следующей ступени и вернул
ответ MPFR.
[Регрессионная проверка](../../tests/m0_pow_round_guard_host_self_test.py),
[исходный тест CORE-MATH](https://raw.githubusercontent.com/indigobio/core-math-binary64/d6a504a43319e9bedbdaeb1724955ffa2bbd7a7c/src/pow/pow.c)

В образе Pico H `2a2c28bf/56f961cd` с заводским BootROM все
80 395 вызовов публичного `pow` совпали с MPFR 4.2.2. Отдельно
проверены 40 крайних оснований из аналитических диапазонов и
38 их внешних соседей. Все крайние основания дали единицу, все
38 внешних соседей округлились в другую сторону. Ещё 116 пар
проверены через публичную функцию и напрямую через CORE-MATH.
В обоих случаях результаты совпали с MPFR и обходились без
`mk61_m0_pow_rescue`. Среди 20 ближайших к границе пар
инструментированная ARM-сборка зафиксировала один естественный
переход на 256 бит. При принудительном входе в `mk61_m0_pow_rescue`
эти 20 пар завершились на 512 битах. Вычисление 20 000 прообразов
независимо проверено интервалами Arb при 320 битах.

```sh
python3 -B tests/m0_pow_round_guard_host_self_test.py
python3 -B -S research/m0-pow-comparison-20261117/small_exponents.py \
  --workers 12 --report /tmp/pow-small-exponents.json
python3 -B -S research/m0-pow-comparison-20261117/round_one_ranges.py \
  --report /tmp/pow-round-one-ranges.json
```

Практическая верхняя граница времени для всех binary64 остаётся
открытой. Доказательство выше покрывает указанную сетку показателей
и не зависит от числа проверенных ARM-вызовов.
