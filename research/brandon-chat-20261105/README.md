# Brandon 10.7M: проверка 5 ноября 2026

Кандидат: [xaskasdf/brandon-tiny-10m-instruct](https://huggingface.co/xaskasdf/brandon-tiny-10m-instruct),
веса `ca6329de991a1cfc17b2a7a1aaae2cc38c08577a`.
Исходники автора: [brandon-tiny](https://github.com/xaskasdf/brandon-tiny),
ревизия `cd56eb1093b4b1da986cefc11c0ad79c9d358099`.
Файлы скачаны в `.build/brandon-chat-20261105`, отдельно от прошивки.

## Размер и память

Файл safetensors содержит 30 019 416 значений из-за повторной записи общих
параметров. Проверено точное равенство всех 216 копий тензоров слоёв и
копии выходного embedding. Загруженная модель имеет **10 706 776 уникальных
параметров**: 24 прохода по слоям, 12 уникальных блоков; выходные веса общие
со входным embedding. Кэши KV у всех 24 проходов отдельные.

Расчёт с Q4 (32 значения + FP16 scale, с дополнением строк до блока),
полным FP16 KV и проектом компактного SentencePiece BPE токенизатора:

| Часть | Байты |
|---|---:|
| Веса Q4 и малые параметры FP32 | 6 077 792 |
| Токенизатор, включая таблицу Unicode-нормализации и индекс | 385 963 |
| KV: 192 текстовых токена + 4 register tokens | 1 204 224 |
| Резерв рабочих буферов | 262 144 |
| Всего | **7 930 123** |
| Остаток из 8 388 608 байт PSRAM | **458 485** |

Итого около **7,56 МиБ**, свободно около 448 КиБ. Контекст включает вопрос,
всю историю и ответ. При контексте 256 запас только 65 269 байт сверх
заложенного резерва; для первого порта разумнее 192. Группы Q4 по 64 значения
дали бы ещё экономию, но эта численная схема здесь не испытывалась.

Это проект бюджета: нативный токенизатор и ядро PicoCalc не реализованы,
реальные рабочие буферы, SRAM и скорость не измерены. Прошивка не менялась.
Полный расчёт и контрольные суммы: `memory-budget.json`; воспроизведение:

```sh
.build/squeal-chat-20261105/venv/bin/python research/brandon-chat-20261105/memory_budget.py
```

## Качество

Проведены два запуска одной и той же небольшой серии из семи реплик:
исходный FP32 и имитация Q4 с восстановлением весов в FP32 для вычислений.
В обоих используется формат ChatML из примера автора, температура 0,7,
top-p 0,9, top-k 40, repetition penalty 1,2, запрет повторов триграмм,
seed 42, контекст 256, предел ответа 80 токенов. Общие веса квантуются
один раз. Квантованный файл для устройства не экспортировался; KV остаётся
FP32 в компьютерном эксперименте. FP16 KV в бюджете отдельно требует проверки.

Модель начинает отвечать по теме, но затем уходит в выдумки. Не ответила
верно на «What is two plus two?» и не вспомнила Boris в следующем ходе.
Все семь ответов обоих запусков дошли до ограничения длины. Это отдельные
пробы, а не стандартизованный benchmark; основания считать модель лучше
TinyTalk для разговора пока нет. Размер 10+ млн сам по себе улучшения не дал.

Сырые ответы и настройки: `smoke-sampled.json` и `smoke-q4.json`.
Интерактивный запуск в текущей подготовленной среде:

```sh
bash research/brandon-chat-20261105/chat.sh
bash research/brandon-chat-20261105/chat.sh --q4
```

Используются проверенные исходники автора с контролем SHA-256 и загрузка
весов через safetensors. Метод загрузки pickle из авторского кода не вызывается.
Зависимости этой изолированной среды перечислены в `requirements-lock.txt`.
