# Предложение интеграции `pow` R64

Это не применённый к production патч на `main` **65d698caabfef4c09cf925b329e139c7d9a2f1c6**. Он переносит только доказанный быстрый результат для отрицательного основания непосредственно перед степенью двойки и целого отрицательного показателя `−n`, `1≤n≤64`, когда результат нормальный.

Изменяемый вариант: существующий собственный RP2040 M0 EABI, `MK61_USE_M0_EABI=1` и `MK61_M0_RP2040_EABI=1`. Путь вызова: `compact_math::pow` → `mk61_m0_pow_fast` → `pow_negative_integer`. Выбор provider и существующий `MK61_PICOCALC_M0_EABI` не переключаются. Другие функции, SDK, APP API, CMake и linker script не изменяются этим предложением.

`main-guard-only.patch` меняет ровно три пути:

- `code/native_eabi_m0_pow_fast.inc`: RP2040-only проверка и точный результат после уже имеющейся проверки конечности и целого показателя;
- `tests/native_eabi_m0_arm_self_test.py`: 28 существующих регрессионных пар через публичный `pow` и имеющуюся проверку R4–R11/SP;
- `tests/fixtures/m0_pow_nearpower_r64.json`: закреплённые gold из прежней матрицы, SHA источника сохранён.

Полный частный R63/R64 runtime требует 49 отличающихся native/вспомогательных файлов, перечисленных в `proposal.json`, дополнительных translation units и отдельной проверки размещения. Они не входят в этот узкий патч. Контекст `qualified-R63-to-R64.patch` отсутствует в текущем main: проверка применения к неизменённой базе ожидаемо не прошла. Прямое копирование полного `pow_fast.inc` потянуло бы этот частный baseline и множество изменений других функций.

Узкий порт использует уже имеющиеся `m`, `ym`, `e`, `odd`, `U`, `D`, `bits/real`. Из R63 не нужны новые общие арифметические helpers: извлечение старшего слова показателя записано локально вместо R63-only `yh`. Новый предикат насыщения R63 и обход его проверок из R64 здесь не нужны — в main этого пути нет. Формула, границы нормального результата и точный знак совпадают с сохранённым сертификатом R64.

Статически проверено: патч применим к точным байтам свежего main, результат в отдельном `/private/tmp` совпал с заявленными SHA, Python-тест разбирается AST. Это **не** бинарно идентичный квалифицированной R64 образ. Его точность и производительность после интеграции ещё не измерены; старые численные и аппаратные результаты на этот порт не переносятся.

После Root review необходимы отдельные строгие проверки:

1. Cortex-M0+ compile/link с `-Os -ffp-contract=off -fno-lto`, без fast-math и libgcc dependency; сначала базовый main и перспективный порт одним инструментарием.
2. Существующий `tests/run_native_eabi_m0_tests.sh` и `tests/native_eabi_m0_arm_self_test.py --rp2040` с точным ROM, затем прежние 9701 пары нормального семейства, boundary/decline записи и исходный корпус 324446 состояний. Gold и стоимость каждого корректного Qfplib сохраняются; ни одного нового отстающего состояния.
3. READY/DIRTY/PENDING SIO, публичный ABI R4–R11/SP, произвольный NZCV, границы записей и стека, прежние отрицательные guard-контроли. 28 новых строк регрессии не заменяют эти проверки.
4. M4 и обычный M0: выключенная специализация должна сохранить байты объектов, символы и смысловые релокации относительно той же базы. Затем полный строгий PicoCalc build, ROM/runtime/ELF/stack/scratch/footer checks и `tests/run_ci_strict.sh`; физическое окно остаётся закрытым до нового отдельного допуска.
5. Вся строгая release matrix и обязательный F401 reserve **≥4096 байт**. Root сообщил для текущего main **2256 байт**; это существующий закрывающий gate. Не ослаблять предел, не удалять M61 и не выдавать прежнюю базу за текущий main. Последняя полная принятая база: `e2ac532a6f0b12d6ed967699457b2abbb92f3014`; сравнение с ней допустимо только как диагностика.

Перед фактической интеграцией заново зафиксировать актуальный main и повторить проверки применения и источников. В этой задаче ARM/MPFR/SDK/HIL не запускались, production source/index/refs и чужая M61 работа не изменены. Checkpoint измеренной частной R64: `985d7a95ede112fa31e5606bb610ac8db3f21a37`. Универсальное корректное округление, завершимость общего `pow`, FMA, стек и прочие отставания остаются отдельной незавершённой работой.
