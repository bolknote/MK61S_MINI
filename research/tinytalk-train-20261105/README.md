## Что получилось

Q4-файлы реально созданы и проверены обратной загрузкой. Каждая модель занимает
**4 706 696 байт (около 4,49 МиБ)**: 4 692 680 байт весов и 14 016 байт заголовка.
Исходный safetensors занимает 33 124 616 байт. Токенизатор и рабочая память в
размер файла весов не входят.

На двух B200 параллельно проведены два заранее выбранных опыта по 500 шагов:
обычное полное дообучение (SFT) и полное дообучение с имитацией Q4 (QAT).
Результаты на отложенных вопросах:

| Вариант | Факты из переписки, из 184 | Сложение, из 49 | NLL ответов учителя, ниже лучше |
|---|---:|---:|---:|
| Исходная FP32 | 0 | 0 | 6,025 |
| Исходная Q4 | 1 | 0 | 6,069 |
| SFT, FP32 | 114 | 3 | 5,124 |
| SFT, Q4 | 101 | 1 | 5,284 |
| QAT, FP32 | 99 | 2 | 5,186 |
| QAT, Q4 | 104 | 0 | 5,211 |

Это улучшение узкого навыка извлекать факты из диалога. В проверочных
формулировках и значениях внутри каждой категории есть отличия от обучения.
В 184 вопросах повторяются варианты для 46 значений; это не 184 независимых
навыка. Арифметический набор содержит вопросы для отложенных пар слагаемых,
не встречавшихся ни в одном порядке при обучении.

**Оснований считать дообученную модель лучшим универсальным собеседником нет.**
Обычный разговор местами стал хуже, арифметика практически не обобщается.
Разница 104 против 101 слишком мала, чтобы объявлять QAT победителем вообще.
Варианты сохранены как экспериментальные; исходная TinyTalk остаётся исходной
точкой сравнения. Уменьшение NLL не заменяет проверку смысловой правильности.

Примеры QAT после Q4:

- После сообщения «My name is Boris» на вопрос «What is my name?» отвечает
  «Your name is Boris.»
- На «What is two plus two?» отвечает «Two two.»
- На «What do you like to do?» выдаёт бессвязную фразу про проживание в колодце.

## Как запустить сохранённые Q4-файлы

В подготовленной локальной среде, из корня проекта:

```sh
bash research/tinytalk-train-20261105/chat-q4.sh
bash research/tinytalk-train-20261105/chat-qat-q4.sh
```

Первый запускает исходную TinyTalk после Q4, второй — экспериментальную QAT.
Команды `/new` и `/quit`; по умолчанию greedy, можно передать `--temperature 0.7`.
Хост загружает упакованные веса и вычисляет в FP32. **Это не нативный runtime
PicoCalc и не измерение его скорости или расхода памяти.**

Артефакты относительно корня проекта:

- `.build/tinytalk-train-20261105/quantized-original/model.ttq4` — исходная Q4;
- `.build/tinytalk-train-20261105/server-results/sft/model.ttq4` — SFT → Q4;
- `.build/tinytalk-train-20261105/server-results/qat/model.ttq4` — QAT → Q4;
- `.build/tinytalk-train-20261105/server-results/{sft,qat}/best` — полные веса;
- `sft-evaluation.json`, `qat-evaluation.json` рядом с этим README — сырые
  ответы, параметры декодирования и оценки всех сравниваемых вариантов;
- `verification.json` — локальная проверка скачанных файлов и сравнение CPU/B200.

## Формат файла

`TTQ4v1` — простой экспериментальный контейнер, описанный в `quantize.py`.
Это не GGUF. Матрицы разбиты по строкам на группы из 32 значений: FP16 scale
и 16 байт кодов, соответствующих значениям от −8 до 7. Векторы остаются FP32,
общий embedding/output хранится один раз. Заголовок содержит config, имена,
размеры, смещения тензоров и контрольную сумму исходника. Обратная загрузка
проверена на точное совпадение с имитацией квантования.

Для условного порта при контексте 256: Q4-файл 4 706 696 байт, FP16 KV
1 048 576 байт, ранее спроектированный компактный токенизатор 921 923 байта,
резерв 262 144 байта. Итого 6 939 339 байт (6,62 МиБ) из 8 388 608 байт PSRAM.
Нативный токенизатор, реальные буферы, использование SRAM и скорость пока
не проверены. В компьютерных проверках KV остаётся FP32.

## Данные и протокол

Подготовлено 896 коротких вопросно-ответных примеров через уже работающую
локальную `Qwen/Qwen3.8-Flash-Next-FP8`; 850 осталось после удаления дублей.
Темы заранее разделены между обучением, validation и test. Фильтр проверяет
структуру и длину, весь синтетический корпус вручную не проверялся.

Добавлены контролируемые задачи на имена, клички собак, города, любимую еду
и сложение чисел 0–20. Итог: 2 933 обучающих примера, 345 validation,
357 test. При выборе очередного обучающего примера доли категорий составляют
50% ответов учителя, 30% контекста, 20% арифметики. Обучение с возвращением.

Общие настройки обоих опытов: seed 5927, контекст до 256, minibatch 16,
AdamW, learning rate до `5e-5`, warmup и cosine decay, gradient clipping 1,0.
Обновлялись все параметры. Вычисления CUDA BF16, параметры и optimizer FP32.
Loss только на последнем ответе бота и EOS; вопросы и предыдущие ходы маскированы.
Оптимизированная проекция словаря проверена против штатного GPT-Neo: ошибка loss 0.

QAT использует straight-through estimator: forward с имитацией того же Q4,
backward на полные параметры. Общие embedding/output остаются одним Parameter.
Проверено, что временное снятие QAT для сохранения не меняет Parameter-объекты,
на которые ссылается optimizer. Checkpoint сохраняется в обычном safetensors.

Выбор checkpoint — по среднему NLL трёх категорий validation с ограничением
ухудшения NLL ответов учителя не более 0,15 относительно начального состояния.
Выбраны шаг 200 для SFT и шаг 300 для QAT; оба выбраны до открытия серверного
test. Test не участвовал в градиентах или выборе шага. До сервера локально
выполнялась техническая проверка кода на четырёх задачах и двух шагах CPU;
она не использовалась для подбора режима обучения.

Контекст считается верным при наличии нужного значения без значения отвлекающего
факта, без присвоения этого факта боту, без повторов триграмм и с завершением EOS.
Арифметика требует одного правильного числа и EOS. Ответы учителя оцениваются
только NLL, автоматической оценки их смысловой правильности здесь нет.
Дополнительно сохранены шесть свободных разговорных проб, не включённых в эти
числовые метрики.
