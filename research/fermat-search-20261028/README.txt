Поиск близких равенств Ферма на компьютере
=======================================

По умолчанию перебираются 100 <= a <= b < c <= 999 и 3 <= n <= 999.
Ищется минимум абсолютного отклонения:

    delta = (a^n + b^n)^(1/n) - c.

По умолчанию числа a, b И c трёхзначные. В таблице знак delta показывает, с какой
стороны от целого находится корень. Точное равенство не предполагается.
Проверяются степени включительно до 999. Эквивалентные перестановки a,b
не повторяются. Общий делитель выводится в CSV, но не служит фильтром.

Запуск
------

На этом Mac уже собран нативный arm64-исполняемый файл:

    .build/fermat-search-20261028/fermat-search

Дважды откройте run.command в этой папке. Он запустит поиск на четырёх
потоках и сохранит results-100-999-p3-999.csv рядом с исходниками.

Или из корня репозитория:

    .build/fermat-search-20261028/fermat-search --threads 4 --output results.csv

Параметры:

    --min 100 --max 999           диапазон для всех трёх чисел
    --min-power 3 --max-power 999 диапазон степеней включительно
    --threads 4                  количество рабочих потоков
    --top 20                     количество лучших результатов
    --output results.csv         файл с результатами
    --allow-trivial              разрешить c=b
    --probe 809 814 142 816       отдельно вычислить отклонение одного примера
    --self-test                  проверки арифметики и полноты малого перебора
    --help                       справка

Ctrl-C останавливает поиск и сохраняет найденные результаты с отметкой
PARTIAL. Нормальное завершение помечается COMPLETE. Уже существующий файл,
указанный в --output, заменяется при сохранении результатов.

Для четырёхзначного поиска откройте run-4digits.command или выполните:

    .build/fermat-search-20261028/fermat-search --min 1000 --max 9999 --threads 4 --output results-4digits.csv

Ограничение 2 <= min <= max <= 9999 относится к поиску. Режим --probe
принимает и более крупные основания. Степени в обоих режимах: 3..999.
Предварительно записанные ответы, калькулятор и libm не используются.

Почему по умолчанию c>b
----------------------

При большой степени и a значительно меньше b корень очень близок к b:
delta примерно b*(a/b)^n/n. Это даёт сколь угодно эффектные, но тривиальные
приближения за счёт исчезающе малого второго слагаемого. В статье такие
случаи тоже исключались. Здесь исключение строгое: c должно быть больше
обоих оснований. Для изучения такого эффекта есть --allow-trivial; тогда
все лучшие места займут именно эти примеры. Не смешивайте таблицы двух
режимов при сравнении рекордов.

Как сокращён перебор без потери ближайших кандидатов
--------------------------------------------------

1. GMP хранит a^n, b^n и c^n как точные целые числа (до ~4000 цифр).
2. При фиксированных b,c,n сумма a^n+b^n строго возрастает по a.
   Поэтому лучший a находится с одной из двух сторон от решения
   a^n=c^n-b^n. Двоичный поиск по таблице точных степеней выбирает оба
   соседних целых a в разрешённом диапазоне. Остальные a не могут дать
   меньшую ошибку для этих b,c,n.
3. Если c^n > 2*b^n, все разрешённые корни меньше c. Достаточно проверить
   a=b; все следующие c для этого b дадут ещё большую ошибку.
4. В рейтинг включаются ошибки менее epsilon=1/1024. Для всего заданного
   диапазона точное необходимое условие такой ошибки:

       |a^n+b^n-c^n| < 2*n*c^(n-1)/1024.

   Фильтр сравнивает большие ЦЕЛЫЕ числа с округлённой вверх границей,
   поэтому не зависит от точности double и не отбрасывает результат
   с ошибкой меньше epsilon.

   Обоснование: по теореме о среднем при |root-c|<epsilon разность
   степеней меньше n*epsilon*(c+epsilon)^(n-1). При n<=999,c>=2
   m*epsilon/c<1/2 для m=n-1. Следовательно,
   (1+epsilon/c)^m <= 1/(1-m*epsilon/c) < 2.
   Для корня ниже c оценка даже сильнее.

Этот фиксированный порог — ограничение выдачи, а не обещание находить
лучший результат, если во всём пользовательском диапазоне ошибки больше
1/1024. Для полного стандартного диапазона найдено значительно больше
20 подходящих троек, поэтому ограничение не влияет на первые 20 мест.

Точность результата
------------------

Для прошедших целочисленный фильтр кандидатов MPFR считает:

    delta = c * expm1(log1p((a^n+b^n-c^n)/c^n)/n).

Разность целых степеней вычисляется ДО перехода к MPFR. Эта форма
сохраняет очень малые отклонения, которые при прямом вычитании двух
почти равных чисел превратились бы в ноль. Начальная точность — 256 бит;
на каждом шаге вычисляются нижняя и верхняя границы направленным
округлением. CSV содержит наружу округлённые десятичные границы ошибки.
Для неоднозначного сравнения кандидатов точность удваивается, максимум
до 4096 бит; неразрешённое сравнение останавливает поиск с ошибкой.
Одинаковые суммы при одинаковых n,c имеют один результат и сортируются
по входным данным. Каждый поток хранит свой top-N, затем они объединяются.

Проверки
--------

--self-test проверяет три примера из статьи, точную разность степеней -1
для 135^3+138^3 и 172^3, отклонение порядка 10^-999, а также сравнивает
сокращённый поиск с полным перебором всех a,b,c на малом диапазоне.
Независимый малый перебор использует mpfr_rootn_ui и прямое вычитание,
без формулы log1p/expm1 и без целочисленного фильтра.
Дополнительный поиск в четырёхзначном диапазоне проверяет включение
примера 3987^12 + 4365^12 около 4472^12.

Полный стандартный запуск завершён: все 997 степеней, 2 465 695 целей
(b,c), 4 033 586 соседних троек, 14 067 троек с ошибкой менее 1/1024.
Лучший результат: a=809, b=814, c=816, n=142,
delta около -3.1717584803430509927175670383636049930066e-8.

Четырёхзначный запуск тоже завершён для всего диапазона
1000 <= a <= b < c <= 9999, 3 <= n <= 999. Дополнительного ограничения
на разность b-a нет. Проверены все 997 степеней, 205 188 679 целей
(b,c), 400 829 557 соседних троек. Время на этом Mac: около 39 секунд.
Результаты: results-1000-9999-p3-999.csv.
Минимум: a=6107, b=8919, c=9066, n=6,
delta = +1.2330774040798588118532346126760818021215e-9.
Точная целая разность 6107^6+8919^6-9066^6 равна 453127232314.
Отклонение корня примерно в 5.72494 раза меньше, чем у 3987/4365/12.
Все 20 строк независимо проверены прямым вычислением корня в Python
Decimal с точностью 200 десятичных цифр; детали и контрольные суммы
исходника/программы: independent-verification-4digits.json.

Сборка
------

    bash research/fermat-search-20261028/build.sh

Нужны clang++, GMP и MPFR. На этом Mac библиотеки уже установлены в
/opt/homebrew. Для другого расположения задайте FERMAT_LIBRARY_PREFIX.
Библиотеки GMP/MPFR включены статически: готовый файл использует только
системные libc++ и libSystem. Пересборка требует исходных библиотек.
Это отдельное исследование для компьютера; прошивка МК-61s не менялась.
