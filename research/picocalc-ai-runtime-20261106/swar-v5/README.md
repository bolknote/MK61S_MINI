# SWAR Q4 × INT8 для RP2040

Отдельный кандидат поверх проверенного prefetch-образа C047D816/F7035006. Образ **04FD5AED/EBF92364** испытан на RP2040 7 ноября 2026 года. Обычный интерфейс по умолчанию использует LUT_FLOAT32; INT8 и SWAR выбираются диагностической конфигурацией.

## Аппаратный результат

125 МГц, Flourish-3M Q4, полный словарь 8192, два ядра, DMA и двойной буфер, замороженный экран. Каждый замер: 2 токена prefill и 2 decode. Числа ниже — время decode на токен, без загрузки модели.

| Активации / матмул | Укладка Q4 | с/токен |
|---|---|---:|
| LUT_FLOAT32 | bitplanes | 8.333151 |
| INT8 | bitplanes | 2.797990 |
| SWAR_INT8 | bitplanes, преобразование группы | 3.117453 |
| SWAR_INT8 | nibbles | 2.561812 |
| INT8 | nibbles | 2.548193 |

**Сам SWAR выигрыша не дал:** при одинаковых нибблах он на 0.53% медленнее обычного INT8. Один короткий проход не позволяет уверенно отделить такую разницу от разброса. Ускорение примерно в 3.27 раза относительно LUT_FLOAT32 связано с INT8-активациями и укладкой весов. Для дальнейшего измерения частоты выбран обычный INT8 с нибблами.

Четыре integer-варианта дали одинаковые токены и контрольные суммы всех строк линейных слоёв. Нибблы получены без повторного квантования. Это подтверждает эквивалентность SWAR обычному INT8; качество INT8 относительно FP32-активаций здесь не оценивалось.

Последующая [отдельная проверка качества на 84 задачах](../../../doc/measurements/picocalc-ai-int8-quality-20261107.md) выявила потерю одного решения у INT8 относительно LUT_FLOAT32. SWAR + INT8 совпал с обычным INT8 во всех 84 итоговых ответах. Условие смены основного режима не выполнено, LUT сохранён.

Полные данные и ограничения: [аппаратный отчёт](../../../doc/measurements/picocalc-ai-swar-20261107.md). Исходные результаты: `.build/mk61ai/swar-v5/hil/`. У D численный тест успешен, но итоговый receipt остался HOLD из-за скрытого файла macOS при удалении каталога; последующее освобождение носителя зафиксировано отдельно. E сначала остановился на безопасном извлечении носителя, затем отдельный E-RESUME выполнил численный тест без повторной загрузки модели.

## Что готово

- `code/mk61_ai_swar.hpp`: две пары коэффициент/активация на один MULS; 16 MULS на 32 MAC. Все промежуточные произведения/суммы — uint32, отрицательные младшие активации сохраняют заём между полями. Сброс каждые 8 произведений гарантирует границы переноса и signed16-суммы.
- `Arithmetic::SWAR_INT8`: подготовка упакованных активаций один раз на вход линейного слоя, общие данные двух ядер, FP16 весовые scale и INT8 activation scale применяются на группу 32. Экран/пауза/DMA используют существующий путь.
- Диагностический `AIPERF2` принимает `arithmetic=4`. Обычный UI по умолчанию использует `arithmetic=3`. Для сравнения обычного INT8 и SWAR нужны одинаковые cores/prefetch/kernel/частота.
- Ниббловый Q4 — прямой путь. Исходные bitplanes поддержаны с преобразованием группы в SRAM. `repack_q4.py` один раз переводит весь MKA в нибблы без изменения квантованных значений, scales, токенизатора и размера файла. CRC пересчитываются.

## Проверено

16777216 комбинаций двух signed INT8 активаций и двух Q4 коэффициентов; 200084 группы по 32 с граничными переносами и невыровненными входными байтами. ASan/UBSan.

Полная Flourish-3M: 12 побитных сравнений всех логитов, KV на 16 позициях, оба формата Q4, FLASH/SRAM, два ядра и DMA. Результат совпадает с обычным INT8-путём. Качество относительно нынешних FP32-активаций нужно оценивать отдельно.

ARMv6-M сборка проходит: static SRAM 119304 B, heap 110072 B при минимуме 108544 B. Добавлено 896 B горячего кода SRAM. В dot32 нет вызовов вспомогательного умножения, 64-битного MUL и float-операций. Число инструкций MULS само по себе не предсказало ускорение полного forward.

## Воспроизведение

Патч подготовлен относительно исходников prefetch-v4. Из корня репозитория:

```sh
git apply research/picocalc-ai-runtime-20261106/swar-v5/candidate.patch
MK61_TEST_SANITIZERS=1 bash tests/run_mk61_ai_swar_tests.sh /path/to/MODEL.MKA
```

Копии всех изменённых файлов находятся в `source/`; исходный файл модели читается без изменений. Собранный кандидат: `.build/mk61ai/swar-v5/firmware/`. Никаких аппаратных обращений SWAR-тесты не выполняют.
