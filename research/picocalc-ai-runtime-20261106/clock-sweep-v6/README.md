# Диагностический sweep частоты AI на RP2040

Эксперимент поверх SWAR-v5. Образ **33180483 / A012D2BF**, 1 538 304 байта, static SRAM 119 364 байта, heap 110 012 при минимуме 108 544. Основной UI по умолчанию остаётся LUT_FLOAT32. Здесь выбирается INT8 с ниббловым Q4, потому что аппаратное сравнение не показало выигрыша SWAR.

Аппаратная серия завершена: **250, 260, 270 МГц прошли; на 280 МГц HardFault, более высокие частоты не запускались**. На 270 МГц после прогрева — 1.114016 с/токен, примерно в 2.25 раза быстрее 125 МГц. Это последняя прошедшая ступень данного короткого теста, не доказанный предел кристалла. Исходные результаты находятся в `.build/mk61ai/clock-sweep-v6/hil/`; общий receipt сохранён HOLD. [Итоговый отчёт](../../../doc/measurements/picocalc-ai-clock-sweep-20261107.md).

После сбоя выполнено только чтение crash. Native после автоматической перезагрузки: 33180483/A012D2BF, CRC valid, SYS 125 МГц, SERVICE CLOSED, RUNTIME NONE, CRASH AVAILABLE. Дамп не очищен. CDC закрыт, процессов-держателей нет, workers завершены/reaped. Исходный HOLD не переименован в PASS. Старое состояние не восстанавливалось.

## Что меняет диагностический образ

Ступени 125, 250, 260, 270, 280, 288, 292, 300 МГц. Точных 290 МГц нет среди допустимых целочисленных планов SDK при XOSC 12 МГц и VCO 750–1600 МГц; 288/292 исследуют этот участок с двух сторон. План не выходит за стандартные пределы PLL. Частоты выше штатной всё равно являются разгоном.

Flash работает с делителем 6. PERI/USB остаются 48 МГц. PSRAM PIO имеет делитель, ограничивающий его частоту 100 МГц. При переходе завершены jobs обоих ядер и DMA; USB отключается, deinit/reset удерживают его через перестройку PLL, затем USB инициализируется заново. После перехода I²C снова настроен на 10 кГц. Конкурирующий автоматический переход частоты звука в этом диагностическом профиле отключён; Audio DMA остаётся собранным. VSEL после загрузки не меняется: установленное значение соответствует 1,10 В, аналоговое напряжение не измеряется.

Оставляется retained trace стадии перехода. Host проверяет USB UID, BUILD/CRC и счётчик BOOTS после каждой из двух ожидаемых USB-переинициализаций. Неожиданный reboot или crash останавливает цепочку; он не считается штатным reconnect.

## Протокол одной ступени

1. SHA-256 полного MKA сверяется на устройстве. Модель уже записана в доказанно собственный каталог предыдущего теста; MSC не включается.
2. Контроль на 125 МГц, с теми же INT8, DMA, двумя ядрами и полным словарём 8192. Два prefill и два decode.
3. Переход на целевую частоту, такой же холодный проход.
4. 120 секунд проверяемых матмулов на двух ядрах и чтения/записи в собственном выделении 64 КиБ PSRAM. Экран удерживается, сервис и клавиатура работают.
5. Такой же горячий проход; все токены и хеши линейных слоёв сравниваются с контролем.
6. Host отправляет Esc во время отдельного forward. Требуются статус CANCELLED, неизменная позиция KV и подтверждение получения клавиши.
7. Возврат на 125 МГц внутри протокола, запись результата, закрытие собственного APP и CDC, завершение/reap worker. Следующая частота начинается только после PASS.

Встроенный ADC-датчик даёт приблизительную температуру при предположении 3,3 В; порог остановки 80 °C. Проверяются I²C, freeze/thaw, service gap, память, участие core 1, DMA, фактическая частота и неизменный VSEL. Это короткая проверка, а не доказательство суточной стабильности либо работы при другой температуре/питании. Длинный контекст модели здесь не измеряется.

## Воспроизведение исходников

`candidate.patch` применяется поверх `swar-v5/candidate.patch`; `source/` содержит 12 изменённых или новых файлов, `source-files.json` — их SHA-256. Диагностический флаг сборщика: `--ai-overclock-diagnostic`; совместно с `--audio-dma`. Нельзя одновременно включать конкурирующий профиль cosmic clock.

ARM-сборка, native ASan/UBSan с настоящей моделью, переносимый тест планов PLL/порядка USB/отказов и пять тестов host-контроллера прошли. Конкретные логи и манифест: `.build/mk61ai/clock-sweep-v6/`.

Контроллеры и расписание находятся в `.build/mk61ai/clock-sweep-v6/hil/`: `clock_controller.py`, `PLAN.json`, отдельный JSON каждой фазы, `run_sweep.py`. Они привязываются к exact SHA исходников, образа, MKA, APP и предыдущего доказательства владения каталогом. Разрешение — прямой запрос пользователя на этот sweep; техническое одобрение ROOT не заявляется. Старое состояние, прошивка, настройки и RTC не сохраняются и не восстанавливаются. После первой ошибки более высокие ступени не запускаются.

Пределы PLL: [официальный pico-sdk pll.h](https://github.com/raspberrypi/pico-sdk/blob/master/src/rp2_common/hardware_pll/include/hardware/pll.h). Расчёт температуры: [официальный пример Raspberry Pi](https://github.com/raspberrypi/pico-examples/blob/master/adc/onboard_temperature/onboard_temperature.c).
