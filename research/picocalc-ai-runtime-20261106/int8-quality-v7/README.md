# Качество INT8 и SWAR на модели для PicoCalc

Итог: **FAIL_NONREGRESSION_GATE**, основной режим LUT_FLOAT32 сохранён. На 20 прежних задачах 6 решений у LUT и 5 у INT8; на 64 новых — по 4. SWAR + INT8 функционально совпал с обычным INT8 во всех 84 строках. Конкретная потеря — деление R0/R1. [Подробный отчёт](../../../doc/measurements/picocalc-ai-int8-quality-20261107.md).

Это native HOST-проверка; аппаратных обращений и обучения нет. Чекпойнт и код те же, что в предыдущей серии скоростных замеров. Все новые эталонные программы прошли эмулятор: 384/384 примеров. Семейства выражений могут встречаться в обучении; заявляется новизна формулировок, а не алгоритмов.

`manifest.json` фиксирует источники, веса, исходные наборы и критерии. `swar-extension-manifest.json` фиксирует добавление SWAR по вопросу пользователя после исходной проверки. `paired-report.json` содержит основной вывод, `swar-report.json` — равенство SWAR/INT8, `memory-analysis.json` — расчёт 6144 байт LUT SRAM и внешнего KV 5120 байт/токен. Удаление LUT и расширение контекста не выполнялись, поскольку условие качества не прошло.

В каталогах отдельных прогонов — JSONL итоговых ответов и метрик, отчёты и progress. Включены исходники evaluator с явным oracle-режимом, который используется только для проверки известных эталонных программ. Нормальные прогоны используют настоящий inference. Автоматические попытки исправления внутри штатного агента разрешены одинаково для всех режимов; повторов эксперимента с выбором лучшего результата нет.

Скрипты `prepare.py`, `run.py`, `check_layout_and_memory.py`, `check_swar.py` воспроизводят процесс в рабочем `.build/mk61ai/int8-quality-v7/` с замороженным runtime `.build/mk61ai/swar-v5/source`. Выходные каталоги создаются один раз; для повторного эксперимента нужен отдельный каталог с новым манифестом. Исходные результаты не перезаписываются. Не запускайте эти скрипты из research-каталога как установщик: они сохранены как точные исходники уже выполненного эксперимента с зафиксированными путями.
