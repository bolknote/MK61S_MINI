# Пиксельные экраны USB / UF2 PicoCalc

Родная сетка 320×320: чёрный фон, светлый рисунок, охристые детали и
зелёные акценты. Никакого изменения размера кадров или
изображений при выводе. Крупные заголовки нарисованы пикселями отдельно;
обычные строки используют нативные Ark Pixel 14/16 с жирным штрихом
и дополнительным межбуквенным пробелом.
Язык заголовков, инструкций и клавиш выбирается настройкой EN/RU.

`dev/tools/generate_picocalc_utility_art.py` хранит исходный рисунок как
целочисленные примитивы и пиксельный алфавит заголовков. Он воспроизводимо
создаёт `ports/picocalc/utility_art.hpp` и `manifest.json` здесь.
Три иллюстрации занимают 790 байт ZX0 вместо 13520. Общий атлас штриховых
глифов не дублирует одни буквы во всех заголовках: весь комплект вместе
с брендом и восемью EN/RU-заголовками — 1058 байт вместо 22080. Отдельная
маска картриджа занимает ещё 720 байт во Flash и позволяет окрашивать его
при движении без дополнительной памяти кадра. Хеши реальных пикселей
заголовков проверяются после сборки из общего атласа.

```sh
python3 dev/tools/generate_picocalc_utility_art.py
python3 dev/tools/generate_picocalc_utility_art.py --check
python3 tests/picocalc_utility_scene_self_test.py
```

Основной рисунок распаковывается прямо в существующие строки кадрового
буфера LCD. Заголовки строятся из общей таблицы нативных штрихов; на время
этой операции таблица занимает 288 байт стека. Подвижный картридж
использует 720 байт стека;
состояние анимации занимает не более 32 байт. Дополнительный полный кадр,
таймер, IRQ, PSRAM-буфер или чтение графики с microSD не нужны.

USB: пакет появляется только после изменения реальных счётчиков MSC-чтения
или записи. Направление соответствует операции: карта→ПК при чтении,
ПК→карта при записи. Пакеты затухают через 700 мс без обмена. В простое
компьютер моргает один раз за 4 секунды; это не индикатор дисковой активности.
После безопасного извлечения на ПК появляется неподвижная галочка.
Enter/Esc до извлечения сохраняют прежнюю защиту владения картой.

Ключ отрисовки включает только текущую фазу: неподвижная сцена не
перерисовывается. Во время активного многосекторного SCSI READ обновления
LCD пропускаются; изменившиеся участки уходят через существующие окна DMA.

UF2: Esc на подтверждении отменяет операцию. После Enter короткая
неблокирующая анимация вставляет картридж за 960 мс. Затем программа
дожидается передачи последней инструкции на LCD и входит в ROM. В ROM
анимация уже не исполняется; экран остаётся неподвижным и предлагает
скопировать `.uf2` на `RPI-RP2`. Процент записи не имитируется.
USB/клавиатура продолжают опрашиваться во время перехода; новые обычные
клавиши и команды отбрасываются, диагностический C5 остаётся доступен.
При недоступном экране вход в ROM всё равно выполняется через 2400 мс,
поэтому аварийный `!`/DFU не зависит от успешной инициализации панели.

Проверки исполняют настоящий ZX0-декодер под ASan/UBSan, сверяют SHA256
всех распакованных ресурсов, границы кадрового буфера, таймер через wrap,
реальные Ui/Services/Screen/FatFs и обе локализации. Растры можно получить
через `--utility-native` хостового self-test с переменной
`MK61_LAYOUT_PREVIEW_PREFIX`. Сборки Classic не используют этот адаптер.
