# Mixed-cache VM с заимствованием workspace — 2026-10-15

Экспериментальная реализация на базе `18361c3a4190b626878bac484d530c98a176aa92`.
`MK61_LANGUAGE_VM_CACHE_MIXED=0` по умолчанию; включение — отдельным флагом
сборки. Игровые исходники, алгоритм шахмат и лимиты ресурсов не менялись.
Это следующий этап после [модели кеша](vm-cache-study-20261015.md), а не
обновление исторических результатов той модели.
Численные данные и SHA артефактов: [vm-mixed-cache-20261015.json](vm-mixed-cache-20261015.json).

## Устройство

В тех же 24 576 байтах кеша остаются 688 байт каталога и 23 888 байт payload,
16 слотов. Холодные незакреплённые образы можно хранить сжатыми; для исполнения
нужен обычный полный raw-образ. Сжатые байты никогда не выдаются VM.
Политика density использует исходный размер, а не размер сжатого представления.

На lookup, до создания `ExecutionState`, временно заимствуются существующие
4176 байт prefix workspace. Хвост 4016 байт с BASIC/FOCAL-значениями защищён
разделением workspace. При попадании тот же lease становится памятью состояния
VM; при промахе lease освобождается до VMSTORE/компилятора. Холодный reserve
не получает внешнего staging: prefix тогда принадлежит компилятору.

LZSS имеет словарь 256 байт, окно 256 байт и совпадения длиной 3..18 байт.
Источник, выход и словарь живут одновременно в непересекающихся span.
Кодирование — один проход с ограниченным выходом, без предварительного sizing.
Отказ не портит исходный raw-образ. Pinned-образы не перемещаются, не сжимаются
и не вытесняются. Если безопасно распаковать нельзя, остаётся обычный промах.

Размер каталога не вырос: логический размер уже есть в сертификате,
а константное поле magic только в состоянии PACKED хранит CRC полного raw-образа.
После распаковки проверяется CRC, затем восстанавливается magic сертификата.
Счётчики pack/thaw занимают прежнее резервное слово и насыщаются на 65535.
Заимствованный указатель нигде не сохраняется после синхронного lookup.

Цена включённого прототипа в сопоставимых math-0 сборках: **+2248 байт Flash,

обычный A/B/A её не включает.

## Локальные проверки

- ASan/UBSan: раскладка ровно 24 КБ, CRC полного образа, повреждённый literal,
  ограниченный несжимаемый выход, неверные/пересекающиеся loans, canary хвоста.
- Pins, поколения, stale/revision, слоты, фрагментация, OOM и 3000 случайных операций.
- BASIC/FOCAL с дробями, циклами и встроенными ресурсами: многократные pack/thaw
  и побайтно одинаковые значения/массивы/вывод, обе арифметики.
- Реальный resident flow: смешанный рабочий набор под давлением, INPUT/ESC,
  активный USB с canary, оба math × USB 0/1; файловый кеш с теми же комбинациями.
- Старые raw LRU/density, DWT в пяти детальных конфигурациях и полный восьмирядный
  HIL-oracle. Сохранённая qualification заново проверяется по порядку, размерам,
  счётчикам и FNV; другая трасса не принимается только по полю PASS.

На реальных owned-образах chess исполняется настоящий C++ cache/codec,
не Python-модель. Каждое попадание побайтно сверяется с исходным полным образом.
За подтверждённое тёплое окно 11 303 запусков:

| Вариант | Попадания | Промахи | Pack / thaw | Fallback |
| --- | ---: | ---: | ---: | ---: |
| Raw density | 11 245 | 58 | 0 / 0 | 0 |
| Mixed, тёплый prefix | 11 291 | 12 | 207 / 198 | 0 |

Это проверка корректности и счётчиков, **не время Cortex-M4**. Холодный replay
не моделирует публикацию VMC в NOR и изменения ревизии ФС. Неудачные попытки
сжатия и копирования тоже стоят времени; полезность решает аппаратный замер.

## Аппаратное сравнение и восстановление

Classic `AEB505B6E0067623`, F411 96 МГц; USB Screen включён.
Baseline → mixed → baseline, по два поиска на прошивку. Во всех стадиях один
побайтно одинаковый комплект LANGVM/LANGIN/BASIC/FOCAL/VMSTORE; игра сверена
с репозиторием. Книга выключена, уровень 2, глубина 8.

| Стадия | Первый после reset, с | Повторный поиск, с | ZX0 за повторный поиск |
| --- | ---: | ---: | ---: |
| A: raw density | 53,600 | 44,450 | 174 |
| B: mixed | 39,891 | 39,032 | 36 |
| A: обратный контроль | 45,181 | 44,456 | 174 |

Сравнение **повторных** поисков: медиана двух контролей 44,452702 с против
39,032234 с. Экономия **5,420467 с / 12,194% времени**, скорость ×1,1389.
Два контроля разошлись только на 6,15 мс. Это один A/B/A с одним повторным
поиском в каждой стадии, а не статистический доверительный интервал.

Первый поиск A записал недостающий файловый кеш (367 записей, 11 стираний),
следующие стадии получили уже прогретый NOR. Поэтому первый столбец нельзя
выдавать за сопоставимое холодное ускорение. В повторных поисках всех стадий
записей/стираний NOR — 0.

Все шесть поисков: `e2e3`, 420 узлов, восемь рядов, одинаковые полные кадры
доски после исключения только документированной области значка диска.
SHA доски: `ef261082a0230600d21d7c4ae116e7cfc226f0fb9ce43a22fbbc26bcbe580460`.
Проверено CRC 1877 кадров USB; `KBD overflow=0`, самовольных WFI/STOP нет,
MPU layout=ok/crash none. Накопительные pack/thaw между двумя `prof stop`
выросли на 207/198; это не отдельные оконные счётчики и включает UI-пролог.
Аппаратные 174→36 относятся к ZX0; прямые 58→12 промахов отдельно подтверждает
вышеприведённый побайтный C++ replay, не обычный аппаратный profiler.

После игры оставалось 10 608 байт стека в обоих контролях и 10 560 в mixed:
**наблюдаемый пик +48 байт**, резерв/guard не менялись. Это не нулевой расход
временного стека и не доказательство максимума для всех программ.
Максимальный native frame 1928 и статическая RAM при этом не изменились.

HIL завершился exit 0/PASS. Точно восстановлена исходная `E52F87BE`,
360 256 байт, SHA256
`88055774bbda4b98b1708667472b5e020133f0a131840ef6ef3d14ac00a5c530`;
firmware CRC valid. Все SHA 44 файлов/4 каталогов, регистры/стек/программа,
рабочий каталог и выключенные будильники совпали. Удалены только десять VMC,
созданных тестом; прежние VMC и заменённые APP возвращены. Повторных чтений
для восстановления не понадобилось. CDC закрыт, Mini не затрагивался,
Classic явно передан следующему агенту.

## Вывод и границы

Заимствование рабочего prefix работает и даёт реальный выигрыш без новой
статической RAM и расширения 24-КБ кеша. Цена включённого варианта — 2248 байт
Flash и измеренные дополнительные 48 байт стека на этом сценарии.
До двукратного ускорения далеко: на VM-вычисления эта оптимизация не нацелена.

По умолчанию флаг остаётся выключенным. Хостовые INPUT/ESC/USB-регрессии и
шахматный HIL не заменяют аппаратную проверку худшей задержки опроса на
других больших BASIC/FOCAL-программах. Следующая профильная цель — повторные
pack/thaw, неудачные encode и перемещения; аппаратных детальных времён кодека
этот обычный A/B/A не измеряет.

Основные воспроизводимые локальные проверки:

```sh
bash tests/run_language_vm_mixed_cache_tests.sh
MK61_VM_CACHE_MIXED_TEST=1 MK61_TEST_SANITIZERS=1 bash tests/run_language_vm_file_cache_tests.sh
MK61_TEST_SANITIZERS=1 bash tests/run_language_vm_image_cache_tests.sh
bash tests/run_vm_cache_storage_tests.sh
```

переопределения. Точные BIN/ELF, compile commands, подписанные образы, immutable
recovery, общие пять APP и HIL-driver сохранены в каталоге артефактов ниже.
