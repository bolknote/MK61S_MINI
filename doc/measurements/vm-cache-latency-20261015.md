# Задержки mixed-cache VM — 2026-10-15

Это исторический незавершённый этап wire8. Продолжение на wire9, исправление
драйвера PONG и завершённый A/B/A описаны в
[квалификации mixed cache](vm-cache-rollout-20261015.md).
Текущая совместная квалификация графики и итоговая политика кеша — в
[отчёте общей main](vm-cache-joint-20261015.md); числа wire8 остаются историческими.

## Решение

**На этом этапе штатное включение не квалифицировано.** `MK61_LANGUAGE_VM_CACHE_MIXED`
остаётся `0`. Первый измерительный A/B/A прервался на `PONG timeout >1s`
при прогреве mixed. Отдельный повтор mixed прошёл два тёплых прохода и
INPUT/ESC обоих языков, но причина первого отказа не установлена;
обратный контроль A не выполнен. Не выдаём одиночный PASS за зелёный A/B/A.

Дополнительно обнаружены большие паузы **уже у обычного кеша**. Mixed заметно
уменьшает их на прогретом наборе, но не устраняет холодные паузы около 0,9 с.
Условия проверки или ресурсные пределы ради включения не ослаблялись.

База: `b0c7528a2f567c41e3af8d59ba6ddcc88cf636d5`, wire v8, SDK ABI 6.
Это не продолжение численных результатов wire v7 из
[первого mixed-cache A/B/A](vm-mixed-cache-20261015.md).
Числа и SHA: [JSON](vm-cache-latency-20261015.json).

## Методика

Classic `AEB505B6E0067623`, F411 96 МГц, активный USB Screen.
Обе прошивки используют один побайтно одинаковый комплект пяти System APP:
LANGVM/LANGIN/BASIC/FOCAL/VMSTORE. Предел hot LANGVM **15360** не изменён;
квалифицированный APP занимает 15356 байт SRAM. Игра и её файлы не менялись.

Восемь BASIC-программ: исходники 1749..3366 байт при лимите 3584,
образы 1904..3633 байт. Восемь FOCAL: 868..1435 при лимите 1536,
образы 935..1516. В каждой — циклы и арифметика, встроенный строковый ресурс.
Языки чередуются; прогрев — 32 вызова, каждый тёплый проход — 128.
Размеры образов и число аппаратных обращений совпали с настоящим C++ replay.

M61 вызывает короткий вложенный ROUND, не превышая штатные 1536 байт текста.
PROF по-прежнему запрещён в сценариях: измерение запускает/останавливает хост,
границы отмечают два VER. FOCAL штатно ждёт клавишу после EXIT; хост отправляет
OK только по ожидаемой метке LATF00..07 на полном CRC-проверенном кадре.
Для точного распознавания сценарий временно выбирает уже установленный
Turochamp.FMK; scoped font session штатно восстанавливается при выходе.

Измерительные флаги: `MK61_DWT_SERVICE_GAPS=1`, `MK61_DWT_RUNTIME_DETAIL=1`.
GAP — **интервал между началами вызовов**, а не длительность тела функции.
Раздельно измеряются вызов scan, фактическое чтение матрицы, повторное чтение
каждой из пяти строк и service USB. Это реальный код опроса физических GPIO,
но не измерение от физического фронта нажатия до события с debounce.

Параллельно хост посылает один PING с индивидуальным nonce, следующий через
20 мс после ответа. Проверяются COBS, CRC пакетов и всех кадров, nonce PONG.
Порог отказа **1 с** сохранён. RTT включает планирование хоста и не заменяет
аппаратный GAP; короткий p50 не доказывает короткую худшую задержку.
DWT-разность 32-битная: интервалы больше полного оборота (около 44,7 с)
так не квалифицируются; секундный транспортный отказ прерывает такой тест.

## Полученные измерения

Raw ниже — завершённая стадия attempt-3; mixed — отдельный attempt-4.
У них одинаковые образы прошивок, APP и исходники, но это **не завершённый
контролируемый A/B/A** и не доверительный интервал ускорения.

| Вариант / фаза | Время, с | Hits / misses | Худший интервал строки, мс | Худший USB GAP, мс | Худший PONG RTT, мс |
| --- | ---: | ---: | ---: | ---: | ---: |
| Raw, прогрев | 22,578 | 0 / 32 | 907,383 | 817,988 | 814,378 |
| Raw, тёплый 1 | 90,452 | 0 / 128 | 915,583 | 817,776 | 817,092 |
| Raw, тёплый 2 | 90,412 | 0 / 128 | 908,589 | 817,830 | 816,381 |
| Mixed, повтор прогрева | 17,306 | 10 / 22 | 910,998 | 821,376 | 817,730 |
| Mixed, тёплый 1 | 25,667 | 128 / 0 | 158,961 | 116,368 | 95,546 |
| Mixed, тёплый 2 | 25,644 | 128 / 0 | 158,876 | 115,522 | 94,850 |

В тёплом mixed — 128 успешных pack и 128 thaw на проход, 8 сжатых слотов,
23296/23888 байт payload. Каталог с payload остаётся ровно 24576 байт.
Максимумы: lookup со всем thaw **5,282 мс**, pack **2,407 мс**,
thaw со вложенным pack **5,233 мс**. Эти вложенные времена нельзя складывать.
Сами эти максимумы не объясняют прежний секундный отказ: отказный профиль
в attempt-3 не был снят до сброса, поэтому его причину не приписываем кодеку.

У завершённых фаз `KBD overflow=0`, USB Screen оставался подключённым,
записей и стираний NOR во время профиля — 0. В трёх фазах raw проверено
748 полных кадров, у mixed — 660; дополнительные интерактивные кадры также
прошли проверку CRC. Профиль содержит крупные затраты компиляторов и замен
APP, но точная причинная атрибуция каждой длинной паузы ещё не выполнена.
«Тёплый» здесь означает повтор RAM-рабочего набора, не гарантию попадания
файлового кеша: raw продолжает промахиваться, а записи VMC не наблюдались.

Синтетический набор не является шахматами: эти 90,43/25,65 с нельзя выдавать
за ускорение chess или за время обычной прошивки без диагностических точек.

## INPUT и ESC

Используются большие дополнительные программы и обычные modal API.
INPUT ждёт видимую метку LAT INPUT, получает виртуальные 1/OK.
Перед ESC тест ждёт RUN ESCB/ESCF **внутри уже исполняемого длинного цикла**.
Проверены возврат в терминал, сохранение USB-сессии и отсутствие overflow.

| Случай | Raw, мс до терминала | Mixed, мс до терминала |
| --- | ---: | ---: |
| BASIC INPUT | 297,96 | 298,08 |
| BASIC ESC | 122,05 | 121,41 |
| FOCAL INPUT | 371,64 | 370,90 |
| FOCAL ESC | 420,51 | 420,72 |

Это **не** физическая задержка клавиши: helper удерживает/отпускает каждую
клавишу с общими 120 мс host pacing, плюс учитывается холодная finish APP
и штатное подтверждение FOCAL. Максимальные интервалы USB у этих холодных
aux-запусков достигают 877,584 мс в mixed против 874,580 мс у raw.
Численные значения переменных аппаратно не считывались; точные значения и
вывод этих образов проверены отдельно в host VM с обеими арифметиками.

## Локальные проверки и ресурсы

ASan/UBSan: mixed-cache/codec, raw cache LRU/density, pins/CRC/OOM,
значения/массивы/ресурсы, BASIC/FOCAL обе арифметики, USB 0/1,
файловый кеш с INPUT/ESC и рабочие модели/replay — PASS.
Новые GAP-тесты проверяют wrap, первый sample, reset/stop, насыщение,
пять физических строк и отсутствие вычисления аргументов выключенных probes.
Старые DWT-конфигурации, клавиатурный handoff и USB protocol/virtual keys/surface
также PASS. Offline HIL-тесты проверяют nonce/CRC, отрицательные GAP-таблицы,
порядок экранных подтверждений и строгий отказ позднего PONG.

Дополнительно подготовлены почти несжимаемые строковые ресурсы с исходниками
BASIC 3552/3584 и FOCAL 1504/1536. Точный host VM обеих арифметик и C++ cache
replay PASS: mixed по-прежнему имеет 128 промахов и 72 pack на тёплый проход,
fallback 0. **На устройстве этот корпус не запускался**: квалификацию не
продолжали считать зелёной после транспортного отказа.

| Обычная сборка, probes выключены | Flash, байт | Static RAM, байт | Максимальный native frame |
| --- | ---: | ---: | ---: |
| Raw math 0, D6873FBC | 360564 | 26880 | 1928 |
| Mixed math 0, 66D24A08 | 362796 | 26880 | 1928 |
| Mixed math 1, 86CD0279 | 353136 | 26880 | 1928 |

Цена mixed на сопоставимой math-0 базе: **2232 Flash, 0 static RAM**.
Эти обычные кандидаты собраны и проверены по CRC, foreground frames 80/608,
APP RAM и отсутствию libgcc/libm/libc/libstdc++/libnosys; аппаратный тест выше
использовал диагностические варианты. Сами probes в обычном raw стоят
**0 Flash/0 RAM**: весь BIN побайтно совпал с квалифицированным main b0c7528a2,
SHA256 `f26b78be2d008e41c5c6ce07e4531d9eff5d8d91bf2d4044720e2ece54cfb457`.

Обе диагностические сборки имеют одинаковые 28824 байта static RAM.
После сценариев watermark оставил raw 9480, mixed 9400 байт — наблюдаемый
дополнительный пик 80 байт, не нулевой временный стек и не доказанный worst-case.
Резерв 16384, guard, Flash headroom, глобальные RAM, APP/foreground/native-frame
лимиты, размеры исходников и квоты ФС **не изменялись**.
Свежая F401-матрица на этом этапе не запускалась; default не включён.

## Восстановление и артефакты

Все четыре попытки завершили точное восстановление. Последняя — exit 0,
`single-candidate diagnostic/PASS`, restored/files_preserved/calculator_preserved/
serial_closed=true, read_retries=[]. Вернулась исходная **122A5FF9**, 360564 байта,
SHA256 `059bff2d4d2aba948ba75ba382f52c4c7593439156be6ec045d674002f7db1da`;
CRC valid, crash none, MPU layout ok. Все SHA 44 файлов / 4 каталогов,
reg/stk/dump/pwd и выключенные будильники сохранены. Удалены только созданные
тестовые файлы /VMLAT; заменённые System APP и прежние VMC возвращены.
Mini не затрагивался. Classic явно передан другим агентам, этот этап больше
не открывает CDC.

Основные артефакты под `.build/vm-cache-latency-20261015.pJhBtT` основного checkout:

- `hardware/attempt-3/report.json` и baseline/prime, warm-0, warm-1, INPUTB/ESCB/INPUTF/ESCF;
- `hardware/attempt-4/report.json` и те же candidate-фазы;
- `hardware-3.log`, `hardware-4.log`, immutable images и полные исходные snapshots;
- `corpus-v4/manifest.json`, sources/images; `corpus-resource-v2` — host-only;
- `diag-raw`, `diag-mixed`, `ordinary-off`, `ordinary-mixed`, `ordinary-mixed-math1`;
- `mixed-host.log`, `file-cache-mixed-host.log`, `raw-image-cache-host.log`,
  `cache-storage-host.log`, `dwt-integrated.log`, keyboard/USB host logs.

Первая попытка была отклонена штатным PUT_TOO_LARGE из-за ошибочного длинного
M61-файла; лимит не поднимали, сценарий разбит на вложенный ROUND. Вторая
контролируемо остановлена до измерений для исправления протокола FOCAL finish.
Это ошибки подготовки теста, отдельно от транспортного отказа третьей попытки.
В новых версиях драйвера добавлены отказные screen/prof dumps и host-poll-gap
диагностика для следующего воспроизведения; **их данные нельзя приписывать
уже выполненному attempt-3**. Старый stdout-label attempt-4 «A/B/A PASS» неверен:
JSON правильно содержит single-candidate; вывод драйвера исправлен.

Следующий шаг перед rollout: воспроизвести секундный отказ с парными GAP,
host-pump-gap и отказным DWT-профилем; затем пройти полный A/B/A, включая
почти несжимаемый корпус. Для сокращения общих холодных пауз потребуется
разделить подготовку/загрузку/компиляцию на безопасные участки обслуживания.
Вызывать общий idle из кодека без проверки lease/reentrancy нельзя: у него
в этот момент живы заимствованные prefix, словарь и выходной буфер.
