# BASIC и FOCAL: индекс и байткод во Flash — 2026-10-17

Ветка `feature/flash-language-vm`, исходная база `c693f2859`.
Штатный запуск обоих языков больше не ограничен массивом на 192/80 строк
и RAM-образом байткода на 6144 байта. Исходник, внешний индекс, образ LBV2/14
и временная карта границ инструкций находятся в C9. Переходы, вызовы, циклы,
DATA и продолжения INPUT используют 32-битные адреса. Request ABI — 13.

## Память и надёжность

Writer и resident-кеш используют по одной странице 1024 байта в существующем
WORKSPACE. Writer повторно используется для внешней сортировки и вывода кода;
метаданные resident-кеша меньше 256 байт. Смена владельца WORKSPACE
инвалидирует страницу. Редактор сохраняет полный прежний префикс, когда VM
не читает байткод. Полного образа программы или индекса в RAM нет.

Индекс сортируется внешним слиянием; карта образа занимает 8 байт на строку.
Проверка CRC и границ завершается до атомарной публикации Manifest. Рабочая
банка и Owner позволяют пережить незавершённую запись и удалить опознанные
производные кеши при нехватке места. Сторонние файлы и исходники не удаляются.
Content stamp исходника переживает записи рабочих страниц и GC; ключ кеша
учитывает исходник, компилятор, VM, INPUT и резидент.

Предел исходника **65534 байта M8** остаётся ограничением файлового/source ABI.
Диапазоны меток языка и глубины стеков языка прежние. Предел нативного APP
остаётся **20480 байт**. Полный RAM image cache выключен на штатном пути;
legacy LBV1/13 API оставлен для reference-тестов и коротких INPUT-выражений.

F401 получает системный стек 10 вместо 6 КиБ; linker и MPU согласованы.
В освобождённой RAM больше нет прежнего полного образа байткода. F411 сохраняет
16 КиБ. В аппаратном диагностическом варианте Classic F411 со статическими
буферами, CORE и стеком 10 КиБ BASIC выполнил 605 строк в прямом/обратном порядке:
24,482/0,632 и 79,052/0,608 с; минимальный остаток — **2112 байт**. Вариант 8 КиБ
оставлял только 176 байт, поэтому не принят. Это проверка бюджета на Classic,
а не испытание физического F401. Единственная доступная плата — Classic V3.

## Внешние библиотеки

Языковые APP собираются без `-lc`, `-lm`, `-lgcc` и используют резидентный runtime.
Для NUL-проверок страниц SDK содержит собственный memchr. На ARM проверены
352 случая memchr и 1232 случая strcmp: границы чтения, выравнивания, unsigned,
нулевая длина и сохранение ABI. Старый `--local-float-math` для языковых APP
явно отвергается. Проверка карты линковки включена в сборку APP и комплекта:
нет членов архивов libgcc/libm/libstdc++/libc/libnosys. В резиденте binary64
реализован собственным compact_math; историческое имя backend LIBM не означает
внешнюю библиотеку.

Эксперимент с прежним опциональным профилем local float прекращён и удалён;
в поставляемых артефактах его нет.

## Автоматические проверки

- ASan/UBSan: 200 КиБ логического файла, случайные чтения/patches через 64 КиБ,
  3000 строк в обратном порядке, ограниченная RAM, ошибки I/O.
- Оба настоящих компилятора: 5002 строки, BASIC 43926 → 75072 байта,
  FOCAL 59475 → 75070 байт; переход за 64 КиБ и исполнение результата.
- VM: CALL/DO/FOR/IF, параметры, DATA, INPUT со сменой APP, длинный текст,
  потерянные страницы, повреждённые адреса. Проверены INTEGER_SPAN/SHORT,
  BLOCK_COMPARE и скалярный fallback для дробей.
- Регрессия 13-байтного IF: все три ветви при коротких и длинных образах,
  включая компактный текст из редактора. Исправлена неполная загрузка операндов
  на точной границе буфера.
- Настоящий C9 и NOR fault injection: 200 КБ, перезапуск, обрывы записи,
  физическое заполнение, ключи кеша, вытеснение производных и брошенного
  черновика FFFF. Компилятор и VM проверены вместе с C9 на обоих языках.
- Настоящие ARM compiler/VM/INPUT APP: образы больше 64 КиБ, три адреса APP,
  отравление предыдущего APP, INPUT/resume, три исхода FOCAL IF.
- Регрессии языков, арифметики, SIMD-подсказок, графики, source/editor,
  overlay/resident handoff, RAM/MPU и размеров APP проходят.

Команды основной проверки:

bash tests/run_language_flash_tests.sh
bash tests/run_program_store_tests.sh --language-flash
python3 tests/run_language_flash_arm_tests.py --resident-elf RESIDENT.elf --system-dir System

## Совмещение с main 5f2050282

Оптимизация source window из main сохранена. Компиляторы отдают Reader
только выровненный промежуток после flash::Program и до resident-страницы;
frontend, Writer, исходник, страница и удерживаемые значения не пересекаются.
Размер окна вычисляется через sizeof(Program) для каждой целевой ABI.
Перед первым чтением фиксируется content stamp. C9-тесты используют то же
размещение и проверяют защитные байты.

Общий тест PicoCalc обнаружил чтение длинного ON GOTO/GOSUB из короткого
буфера операндов. Теперь VM читает выбранную двухбайтную метку из образа.
Регрессии проверяют 1, 5, 6 и 9 различных целей, все допустимые индексы и
пропуск при нуле/выходе за список, в LBV1 и LBV2 больше 64 КиБ.
Выделенный noinline-декодер сохраняет RAM-предел APP: LANGVM — 20460 байт
при прежнем потолке 20480. Внешние библиотеки не добавлены.

Объединённые комплекты: Classic F411 **29AF5B48**, BIN 327252 байта;
F401 **14A3B8E7**, BIN 230300 байт. BASIC/FOCAL/LANGVM/LANGIN/SRCEDIT
занимают соответственно 20060/17528/20460/19196/18180 байт RAM.
Оба комплекта прошли ограничения размера, проверку стека и карты линковки
без внешних runtime-архивов. ASan/UBSan, полный набор языковых/SIMD-тестов,
source/editor, C9 fault injection и общий PicoCalc/Turochamp проходят.
Аппаратные измерения выше относятся к комплекту 3E8F4D7B; объединение
проверено автоматическими тестами, повторной прошивки при слиянии нет.

На итоговом ARM-комплекте оба frontend скомпилировали образы по 66225 байт:
BASIC — 4406 строк, FOCAL — 4407. Для каждого проверены три адреса загрузки
VM, выгрузка/отравление APP, INPUT/resume, а также длинные ON GOTO/GOSUB
в BASIC и три ветви IF в FOCAL. Фактическое source window — 1488 байт.
