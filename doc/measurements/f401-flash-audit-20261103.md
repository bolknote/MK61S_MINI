# F401 Flash audit, 2026-11-03

The overflowing main at `bac3dc945` was compared with the existing F401 work
through `97212d3af` / combined candidate `7d6eb0d17`. The optimization branch
has not been merged into main by this audit. Native measurements use GNU Arm
GCC 14.2.1-1.1, `f401-product-classic-v2`, unchanged release flags/budgets,
one source path and `SOURCE_DATE_EPOCH=1793448000`. The full load extent
includes constants, alignment, initialized RAM and the firmware footer.
The pinned date avoids small string-pool variations between ordinary builds.

The last change mainly restores RAM capacity: the 512-byte inode cache keeps
its capacity but yields its APP lease when needed. It saves 496 global RAM
bytes. While an APP remains loaded, metadata reads can bypass this cache;
the earlier qualification records the resulting NOR traffic cost.

## Hardware libraries

The native ELF contains the owned ADC/SPI/RTC/PWM/EXTI/USB device adapters,
not the removed generic Arduino adapters. The narrow-driver ELF gate passes.
USB CDC and MSC implementations remain necessary for the terminal and disk.
Merely seeing a library in the linker input list does not establish that its
unused implementations occupy Flash; allocation and retained symbols matter.

The Arduino path did retain the legacy UC1609 graphics base: `drawPixel`,
`fillRect`, `write` and its vtable survive despite MK61Display owning rendering.
The compact panel client was selected only for the native runtime. Selecting
it also for the supported direct STM32 SPI transport saves **984 bytes** in
the matched main stock-linker control: overflow drops from 3,868 to 2,884 bytes.
This alone does not repair main's Flash overflow. The working-tree change
enables that selection and extends the stock-linker test with the existing
narrow-driver/panel ELF gate for both MCUs.

## Data representation

ROM instructions already occupy three bytes each. AND_AMK tables already
omit the original seven padding bytes per row. Whole-row deduplication would
increase their storage: 368 unique nine-byte rows plus indexes need 3,696
bytes versus the existing 3,456.

The existing branch nevertheless packs AND_AMK further: conditional values
60/62/64/66 map reversibly onto codes 60..63. Each table becomes 897 rather
than 1,152 bytes, including the guard for the last bounded read. All logical
values and body identities are compile-time checked. Decoder overhead is
included in the 684-byte image saving above. It adds work when tables are
read from Flash; the previous ARM instruction-count qualification reports
up to about 11% additional instructions in a Flash-fallback microtick probe.
This is not a hardware timing measurement or an end-to-end slowdown estimate.

The sparse 560-byte segment strike becomes 128 bytes of precomputed scaled
spans on F401, preserving the original pixels and removing runtime scaling.
The proportional font bitmap and glyph metadata are already packed. Generic
compression ratios for them are not net firmware savings: random access,
decoder size and RAM needed for expansion must be accounted for.

## Review of the recent M61 additions

The new key handling needs paired DOWN/UP delivery, queue reservations and
state across nested scripts; the selected byte representation preserves them.
WAIT deadline restoration and timer state cannot simply be discarded.
Long Cx already existed: its recent changes concern access while a handler
pauses the calculator and cleanup of the newly introduced timer state.

An isolated experiment sharing unsigned table reads between the core and
M61, together with removal of the redundant 24-bit result fit check, saved
only 16 bytes. Shared decimal formatting/frame writes saved 120 bytes in
another experiment. A F401 cold prefetch dispatcher with inline rejection
of other ROM microaddresses saved 832 bytes on main. These experiments are
retained separately; their gains are not additive to the selected branch,
and their changes are not applied to production by this audit.

## Combined local verification

| Configuration | Image bytes | Free Flash | Required free Flash | Effective APP pool / required |
| --- | ---: | ---: | ---: | ---: |
| Native Classic V2 | 257,980 | 4,164 | 4,096 | 20,576 / 20,480 |

| Stock Arduino F401, with panel cleanup | 259,768 | 2,376 | 1,024 | Stock-linker control |
| Stock Arduino F411, with panel cleanup | 375,196 | 149,092 | 0 | Stock-linker control |

The stock control intentionally includes WBMP, CHIP8 and extended fonts;
its feature set differs from the native release cases. Its sizes must not
be used as a native/Arduino runtime-only overhead comparison.

Fresh local checks pass for M61 (ten runtime modes and three keyboard
layouts), UI rendering (legacy/F401, physical/USB/lifetime variants), Runner
(native/F401-like/mini, timers, LOOKUP, tables, input and asynchronous
campaigns), and both UC1609 transport fixtures, with ASan/UBSan. Both stock
Arduino builds and their narrow-driver/panel ELF checks pass. Native V2/V3
Flash, global-RAM, stack-frame and effective APP pool gates pass unchanged.

The earlier combined CI at `e2150a38c` passed strict HOST and Arduino checks
but failed the APP pool gate at 20,064 < 20,480 bytes. The later inode-cache
fix resolves that gate locally. Full native-nine/System-package CI was not
rerun here on the final combined candidate; local results are not a claim
of final CI or release qualification. No device was accessed, and no commit,
merge or push was performed by this audit.
