# F401: открытая совместимость после Runner/M61

Статус на 2026-10-31: **OPEN / FAIL по Flash**. Завершение этого этапа
выбрано для Classic F411 512 КБ и PicoCalc. Поддержка F401 требует отдельного
исправления размера и повторной проверки; успешной она здесь не объявляется.
Профиль F401, функции, флаги и ресурсные ограничения сохранены.

Перенесённый Runner2: исходный коммит
`0e97e2ac20ce3613ac7bc590c3daa5c6a3a11ecf` → `main`
`13611466d917a4093f5fffc85aeef88afc22dcc8`. Его полное дерево совпало с
проверенным объединённым кандидатом
`e753b6deed6a83bbb980e4fdeac655886e738804`: исходная `main`
`27b5e7e52a8f06d784850e43952640ad7bbe9a87` плюс ровно 48 изменений Runner2.
Экспериментальные изменения для уменьшения размера в этот перенос не входят.

## Незакрытый бюджет F401

Сопоставление выполнено штатным native GCC builder, GNU Arm GCC 14.2.1,
фиксированным case `f401-product-classic-v3` и прежними настройками.
Вместимость внутренней Flash — 262144 Б; обязательный свободный резерв —
4096 Б. Допустимый образ должен занимать не более 258048 Б.

| Проверяемое состояние | Образ / расчётный размер | Свободно до конца Flash | Дефицит до обязательного резерва | Результат |
| --- | ---: | ---: | ---: | --- |
| Исходный код Classic, соответствующий `eaaff37349149f86ebe7c25275a09da3f6ae906d`, до двух переносов Runner | 261328 Б | 816 Б | 3280 Б | Линк выполнен, Flash gate FAIL |
| Объединённый Runner1 + Runner2, кандидат `54fee9cbf32d4d8240fd610e811dd7bd9ed07210` | 263152 Б по extent неудачного линка | Переполнение 1008 Б | 5104 Б | Link FAIL |

Таким образом, дефицит существовал до этих переносов; их сопоставимый
добавочный размер составляет 1824 Б. Для неудачного combined link размер
263152 Б — расчёт по переполнению, а не размер готового пригодного ELF/BIN.
Отдельный лучший незакоммиченный эксперимент владельца сэкономил 192 Б.
Он не включён в `main` и проблему обязательного резерва не решает.

У исходного состояния анализ отдельных кадров стека прошёл: максимум
1304 Б при лимите 2048 Б. Проверка RAM в этой последовательности сборки
не была достигнута после отказа Flash gate. У combined F401 линк упал до
проверок стека и RAM; их успешность для этого кандидата не подтверждена.

**Публикация F401 блокируется действующим resource gate.** До отдельного
исправления и успешной проверки F401 нельзя публиковать как совместимую
готовую сборку. Резерв Flash, лимиты RAM/стека, функции и профиль ради
публикации не ослабляются. Возможность загрузки образа в более ёмкую F411
не является проверкой F401.

## Проверенные кандидаты для выбранных устройств

На точном объединённом source `e753b6deed6a83bbb980e4fdeac655886e738804`
выполнены свежие полные сборки и линк без обновления SDK или компилятора:

| Штатный target | Flash-образ | Свободная Flash | RAM | Стек / размещение |
| --- | ---: | ---: | --- | --- |
| `f411-classic-v3` | 381028 Б | 143260 Б | 21752 Б глобальных данных | Максимальный кадр 1928 / 5120 Б |
| `f411-classic-v3-usb-screen` | 385676 Б | 138612 Б | 22024 Б глобальных данных | Максимальный кадр 1928 / 5120 Б |
| `picocalc-pico-h`, собственный M0 runtime, QPI, без профилирования | 1537056 Б | 551904 Б до журнала настроек | 126512 / 229376 Б статической main RAM | Резерв core0 32768 Б; штатные linker bounds PASS |

Оба F411 case прошли прежний резерв Flash 16384 Б, лимит глобальных данных
104857 Б и проверку кадров стека без неограниченных кадров. Обычный
`f411-classic-v3` отключает USB Screen по контракту; отдельный USB Screen
case включает его и выносит Setup в APP. В обоих BASIC/FOCAL остаются APP.
ABI — Cortex-M4 hard-float. Для полученных сырых F411 ELF/BIN подтверждено
побайтное соответствие; перед установкой нужен штатный sealing.

PicoCalc собран с Cortex-M0+ soft-float, существующим Pico SDK 2.2.0
`a1438dff1d38bd9c65dbd693f0e5db4b9ae91779` и TinyUSB
`86ad6e56c1700e85f1c5678607a762cfe3aa2f47`. Проверка собственного ARMv6-M
runtime без членов архива libgcc прошла. Также прошли sealing, соответствие
sealed ELF/BIN и восстановление BIN из UF2. Журнал настроек размером 8192 Б
сохранён. Нефатальные предупреждения линкера о declaration/redeclaration
FLASH и `.note.GNU-stack` из toolchain `crtn.o` сохранены в журнале сборки.

Это **build/link PASS выбранных кандидатов, а не новая release/HIL-приёмка**.
Системные APP-пары в этом контрольном прогоне не пересобирались. Нового HIL
объединённой прошивки нет; прежние FAIL, HOLD и незавершённые проверки
сохраняют свои статусы.

## Отдельная задача F401

1. Найти и проверить уменьшение resident-кода, сохранив функции и контракты
   M61: клавиатуру, таймеры, кадры, callbacks, LOOKUP и кампании Runner.
   Вынос M61 в APP требует отдельного архитектурного решения и не считается
   готовым исправлением размера.
2. Собрать итоговый F401 source штатным fixed case и пройти линк, резерв
   Flash 4096 Б, прежние проверки RAM/стека и остальные поддерживаемые
   конфигурации F401. Успех F411 или HOST не заменяет эти проверки.
3. Сверить исходники, флаги и точные ELF/BIN/APP перед отдельной аппаратной
   приёмкой и публикацией F401.

Повторный контроль начинается с существующего builder и установленного
компилятора, без изменения case:

```sh
python3 tools/.mk61-gcc/build-standalone.py \
  --release-case f401-product-classic-v3 \
  --toolchain /path/to/arm-none-eabi-gcc-14.2.1 \
  --build-path .build/f401-runner-compatibility --jobs 4
```

Настройки и бюджеты определяет [release contract](../../tools/release-contract.json).
Исходные журналы, source guard и точные размеры/SHA артефактов сохранены
в пакете интеграции `main-ready-integration-20261031-001`: контрольные отчёты
`F401-COMPATIBILITY-CHECKPOINT-20261031-001.json`,
`F411-PICO-FULL-BUILD-CHECKPOINT-001.json` и
`RUNNER2-MAIN-TREE-VERIFIED.json`. Частные копии Flash в документ не включены.
