# RP2040 exp table in Flash and SRAM, 2026-11-17

One diagnostic image on a Pico H at 125 MHz ran the same `compact_math::exp`
entry point against two copies of its center coefficients. The entry was
`0x10176e99` and the original table at `0x10191280` contained 1,470 rows,
11,760 bytes. The timing APP copied those bytes to its own SRAM, checked
the copy, and switched the pointer outside the timed calls. The pointer
returned to Flash before each service call and before unloading the APP.
The production snapshot was `93cd91991770c91376401d2e12876b7639f2d43a`.
[Diagnostic patch](../../research/m0-math-probes-20261117/exp-flash-sram.patch)

SRAM cut both wide-group times by 0.50–0.61 µs and the XIP misses by
about 79%. Both times were still above the 5.4–5.5 µs target on this
diagnostic build. The absolute difference between Flash and SRAM medians
was at most 0.041 µs for the 13 previously slow individual cases.
A single input repeatedly hits the same coefficient row. A wider input
set exercises the cost of fetching many different rows.
[Per-group measurements](m0-exp-sram-20261117.csv)

Each group ran twelve rounds with alternating order after the same
one-second warm-up. Each timing subtracts the matching empty-call batch.
The quoted time is the median of six means across opposite orders.
The XIP figures subtract the matching counter control. XIP counters cover
both cores. Earlier firmware called with an immediate Flash base address
and had different code placement. The absolute times from that firmware
serve as context for the target. The paired Flash/SRAM delta is from this
single build. [Previous Flash placement test](m0-exp-layout-20261116.md),
[RP2040 datasheet](https://datasheets.raspberrypi.com/rp2040/rp2040-datasheet.pdf)

All 2,088 results in the 22 groups matched the independently recomputed
MPFR 4.2.2 values. ARM emulation with factory BootROM v3 agreed for both
locations and saw the same coefficient offsets across 729 distinct rows.
The APP protocol retained Flash across all service calls and on return,
and rejected incorrect entry addresses and an incorrect initial pointer
in the ARM fixture.

The handoff confirmed build `9E5007FE / E45F1DAC` with a byte-for-byte Flash
readback. The diagnostic build `95B740D6 / E24ADF49`, 1,805,072 bytes, was
written once and also read back in full. The session took 145 seconds.
`/MK61S-M0-TIMING-SRAM` was removed and the calculator's registers, stack,
history and current directory matched their pre-test values. The retained
image was left at CALCULATOR / CLOSED / NONE, `BOOTS=1`, `CRASH=NONE`, with
the Flash pointer restored and all five CDC sessions and the lock released.
The sealed campaign and raw receipts are in
`.build/m0-math-probes-20261116/exp/`.
