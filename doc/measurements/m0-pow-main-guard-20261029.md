# RP2040: проверенный быстрый путь `pow` для отрицательных целых степеней

База подготовки — tracked `main` `7a01beb4827c05bb2ba34fc0576f85f929b6160f`.
Три изменяемых пути побайтно совпали с базой уже проверенного порта. Применён
ровно patch `88f206c9bd5591328124065f4635dd2d6d1f9a77f87e98e60ddb4ae6e3d74baf`.
Итоговые три файла побайтно совпадают с квалифицированным HOST-кандидатом;
математический include также совпадает с source, использованным SDK-сборкой.

При отрицательном основании непосредственно перед степенью двойки и показателе
`−n`, `1≤n≤64`, нормальный результат получается из сохранённого точного
сертификата. Классификация целого показателя использует два 32-битных слова.
Обе специализации ограничены `MK61_M0_RP2040_EABI`; прежний путь остальных
платформ сохранён. Provider/default, API, linker script, SDK и прочие функции
не меняются; частный runtime из 49 путей не импортирован.

## Сохранённые проверки

разных потоков: normal9701 — 29103, boundary/ABI — 4854, old324446 — 324446,
decline — 49410. Вместе с 28 fixture и 18 guard-вызовами выполнено 407859 ARM-вызовов.
Ошибок кандидата и новых проигрышей корректному Qfplib нет. Относительно базы
58820 оценок быстрее, 348550 равны, **443 медленнее, максимум+4 инструкции**.
Все 443 ухудшения и 534297 неверных записей эталонов сохранены. В классификации
этого корпуса 193572 оценки всё ещё медленнее корректного Qfplib; 25007 не имеют
измерения эталона и 98326 — корректного эталона. Это оценки, не число уникальных пар.

Две полные строгие Pico SDK-сборки: **GNU text +56 байт**, статическая RAM +0,
новых таблиц нет. Длина обеих Flash-карт 1537008 байт благодаря прежнему размещению.
Пять отключённых контролей обычного M0/M4 сохранили байты, символы и смысловые
релокации. Новая полная сборка M4 этим утверждением не подменяется.

На Pico H RP2040 B2, ROM v3, 125 МГц выполнены те же 56 состояний каждой версии:
**4600 публичных вызовов**, из них 1120 наших математических — все верны.

## Возврат устройства и область результата

В каждом цикле две полные копии Flash до RAM и одна после RAM совпали:
SHA256 `a05379163123d8f634ad1c81e82daf1d48afd5ea500139201f3503b96ee8f126`.
Резидент остался исходным D6FABB43/EFBF5584. Математические образы исполнялись
только из RAM; новая production-прошивка не устанавливалась. Данные, настройки,
UI, будильники и ход часов проверены относительно единственного исходного
RTC1-снимка e768dd8… с прежним допуском ±3 с; final epoch 22, physical keys 0.

Базовый exact-receipt HOLD сохранён: после единственного `date` отдельный getter
показал следующую секунду. Повторной установки не было. Возврат базы принят
независимым readonly-снимком; прежний frozen final operator базы не запускался
и не объявляется PASS. Кандидатный F3 принимает exact echo/prompt и calendar +0/+1
при неизменной полном времени выполнения ≤1 с; полный возврат часов и final verify прошли.

Текст scope внутри 28-векторной fixture сохранён как историческая provenance
исходного предложения. Актуальные утверждения задаёт этот отчёт и новые receipts.
Универсальное корректное округление всей библиотеки, завершимость общего `pow`,
граница стека, FMA, оставшиеся отставания и полная production/release-приёмка
остаются открытыми. Перенос в main сам по себе не означает установку на устройство.

## Переносимое доказательство

Артефакт `m0-main-guard-evidence-20261029.tar.gz`, 15294331 байт,
SHA256 `73978815c4c77c68bb74037ad1684a22fd4bd8570149bce0091c59859969b82f`.
В нём все 407813 исходных численных записей, оба физических прогона с raw wire,
Root receipts, исходники до/после и сохранённые clock/HOLD/latch records.
После распаковки: `python3 -I -B m0-main-guard-evidence/verify.py`.
Проверка отдельной копии вне репозитория прошла; новых ARM/MPFR/SDK/device-вызовов
нет. Читатель пересчитывает сохранённые JSON records и проверяет хэши wire;
независимый CRC/nonce/order/ABI/SIO аудит подтверждён сохранёнными Root receipts.
Flash/ELF бинарники не включены, их размеры/хэши и приёмка сохранены.
