# Runner: проверка на PicoCalc через USB Screen

28 октября 2026 года. Проверялась игра из `programs/games/Runner` на
физическом ClockworkPi PicoCalc с Pico H / RP2040 125 МГц, скорость MAXIMUM.
Виртуальный экран — настоящий framebuffer 320×320, полученный по USB.

Использована временная прошивка из коммита `65d698caa` с `bind key`:
build `C19CE800`, CRC32 `A67BC1C7`. Незавершённые изменения рабочей копии
в неё не включались. Полный набор программных тестов PicoCalc прошёл.

## Игровая проверка

Тест `tests/hil_runner_picocalc.py` выполнил 18 проверок за 176 секунд.
Отправлялись обычные события экранной клавиатуры; координаты, регистры
и байты программы во время игры не подменялись.

Проверены короткие и повторные нажатия, удержание и остановка после
отпускания, ходьба, обе пары лестниц, три этажа, прожиг, падение,
восстановление пола, перезапуск, памятка и возврат из неё. ESC завершил
сценарий и очистил калькулятор. Кадры принимались с устройства, отдельно
проверялись четыре слова опубликованного сегментного ряда.

Для Mini физический скан OK — 29, а логический код M61 — `13` hex.
Начальная ошибка тестового контроллера со сканом 0 (Cx) исправлена;
повторная полная проверка с правильным OK прошла.

## Скорость

Удержание вправо на протяжении пяти секунд дало только две клетки.
После падения таймер оставшихся 17 кадров прожига дошёл до нуля за
67,7 секунды наблюдения. Текущий темп не подходит для аркадной игры.
`wait 120` добавляет паузу к времени вычисления, а не задаёт период кадра.

Отдельный профиль за 8,087 секунды показал:

| Точка | Вызовы | Суммарное время | Среднее |
| --- | ---: | ---: | ---: |
| Эмулятор МК‑61 | 185 | 6,802 с | 36,767 мс |
| USB | 458 | 1,026 с | 2,239 мс |
| Отрисовка | 24 | 0,200 с | 8,339 мс |
| M61 | 458 | 0,080 с | 0,174 мс |
| Передача LCD | 14 | 0,033 с | 2,351 мс |

Метрики включают вложенные вызовы. Главная затрата здесь — исполнение
калькуляторных команд. Следующий шаг — сокращать вычисления и обращения
к таблицам за один кадр. Эти результаты не являются замером STM32.
Длительности отдельных игровых проверок включают чтение регистров и
ожидание точки полного кадра, поэтому не служат точной оценкой задержки ввода.

## Возврат устройства

До временной установки сохранены вся Flash 2 МиБ, настройки, программа,
регистры, стек и рабочий каталог. После теста восстановлена исходная
прошивка `D6FABB43` / CRC32 `EFBF5584`; вся Flash прочитана обратно и
совпала с резервной копией побайтово. Исходная последовательность настроек — 331.
