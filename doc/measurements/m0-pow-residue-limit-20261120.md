# Предел сравнения `pow` по остатку для малых показателей

Пусть $y=\pm p/q$, где $p$ нечётно, $q=2^k$, $k\ge11$ и
$0<|y|\le2^{-11}$. Для сравнения после 16 384-битной логарифмической
ступени известен зазор
$\left|y\ln(|x|)-\ln m\right|<2^{-16300}$.
Из него следует $|\ln m|<745\,2^{-11}+2^{-16300}<\ln2$.
Поэтому середина $m=b2^f$ лежит в $(1/2,2)$, $b>2^{53}$
нечётно и $f$ равно $-54$ или $-53$. Для основания $|x|=a2^e$
имеем нечётное $a<2^{53}$ и $|e|\le1074$.

При выравнивании положительных степеней одинаковые масштабы
потребовали бы $pe=qf$. Сокращённость $p/q$ даёт $q\mid e$.
При $k\ge11$ это означает $e=0$ и затем $f=0$, что несовместимо
со значением $f$. Следовательно, у двух выровненных целых разная
чётность. Их общий делитель $G$ нечётен, делит $a^p$, и
сокращённая степень середины превышает $2^{53(q-p)}$.
Операнды близки с точностью до множителя два, поэтому меньший
из них превышает $2^{53(q-p)-1}$. При отрицательном показателе
сравнивается нечётное произведение с положительной степенью
двойки. Общий делитель равен единице, а меньший операнд
превышает $2^{53q-1}$.

Разность после сокращений нечётна. Для метода с одними
остатками и известным логарифмическим зазором даже точная
оценка радиуса $(\exp(2^{k-16300})-1)\min(A/G,B/G)$
превышает $2^{53(q-p)+k-16301}$. При $q\ge4096$ внутри такого
радиуса у каждого класса остатка по прежним модулям остаются
нечётные представители обоих знаков. Стандартная формула
$N+k+2-16300$ для достаточной ширины модуля даёт нижние оценки
92 204 бита при $q=2048$ и 200 696 бит при $q=4096$, даже с
полным сокращением общих множителей.

Это ограничение доказательства знака по остатку и ширине.
Условие о малом зазоре здесь используется как предположение.
[Проверка целых границ](../../dev/tools/certify_m0_pow_residue_limit.py),
[предыдущий компаратор на 147 455 битах](m0-pow-coprime-residue-20261120.md).

## Обращённая проверка слоя с сеткой $2^{-115}$

Для $2^{-63}\le |y|<2^{-62}$ известное ограничение оставляет
две возможные середины $m$ около единицы. Пусть $p=2^{115}|y|$,
$C=2^{115}|\ln m|$ и $\sigma$ есть знак $\ln|x|$. Направленные
логарифмы концов блока задают интервал для $p$. В нём пишем
$p=p_c+Ht$, $|t|\le1$. Вещественная мантисса, удовлетворяющая
равенству на середине, имеет вид

$$
A_*(t)=D\,2^{-e}\exp\left(\frac{\sigma C}{p_c+Ht}\right),
$$

где $D$ задаёт сетку мантисс данной бинады. Если
логарифмический зазор меньше $2^{-16300}$, то истинная целая
мантисса отстоит от $A_*$ меньше чем на $2^{117-16300}$.
В проверке используются две целые координаты $p-p_c$ и
$A-A_0$, где $A_0$ — целый центр. Для остатка Коши учитывается
полюс при $t=-p_c/H$ и геометрическая сумма ряда обратного
знаменателя. Коэффициенты экспоненты пересчитываются целыми
направленными интервалами. Допустимая погрешность проверяется
у каждого биномиального полинома по его производным.
[Исходник](../../research/m0-pow-comparison-20261117/midpoint_band_inverse.py),
[исходный план слоя](m0-pow-rotated-band-20261119.md).

Обращённая схема закрыла блок из $2^{44}$ оснований при
$e=-600$ для середины $1-2^{-54}$. Поиск со степенью 18 занял
33,670 с на сервере. Отдельная проверка целыми числами Python
приняла сертификат за 11,042 с. Более широкие блоки остались
открытыми в испытанных конфигурациях. При переносе между
соседними блоками на 32 последовательных блоках шириной
$2^{38}$ ни один из уже построенных полиномов не удалось
повторно использовать. Предварительный перенос всей решётки
увеличил время с 12,794 до 22,269 с, поэтому для сплошного прогона
использовался прямой поиск с `flatter`.
[Обращённый сертификат](../../research/m0-pow-comparison-20261117/q115-inverse-block-w44.json).

## Четыре полные бинады основания

На Xeon 6740P прямой поиск с `flatter` закрыл четыре целые
бинады основания для обоих знаков $y$ при $2^{-63}\le|y|<2^{-62}$.
Независимый `verify-bundle` пересчитал разбиение, проверил обе
необходимые середины и принял все 3 819 листьев в 3 584 корневых
блоках. Охват составляет 15 762 598 695 796 736 положительных
кодировок основания. Генерация заняла 236,950 с при 104 процессах,
проверка на 40 процессах — 25,450 с. Время CPU на генерацию
составило около 17 182 с. При том же среднем темпе весь план
из 1 339 778 корней потребовал бы около 13 часов генерации на 140
процессах, с отдельным временем на проверку. Это проекция
четырёх бинад, стоимость разбиения остальных областей измерена
только на пробных блоках.
