# RP2040 `pow` — меньше пересчёта в точном сравнении

После промаха кеша произведение продолжает вычисление с ближайшего
сохранённого переноса перед запрошенным разрядом. Перенос сохраняется
после извлечения разряда и равен входному переносу следующей колонки.
Соседние узлы цепочки степеней используют разные ячейки кеша. Если оба
множителя сохранены целиком, разряд вычисляется тем же 64-битным
накопителем, что и при материализации.

В конечном произведении для отрицательного показателя виртуальный
множитель читается через кольцевой буфер в свободном конце одного из
существующих массивов. Буфер используется, когда второй множитель
сохранён целиком и помещается окно той же ширины. При проходе от младшей
колонки к старшей конец диагонали сдвигается не больше чем на один
разряд, а её ширину ограничивает число разрядов сохранённого множителя.
Массивы по 1 728 16-битных разрядов вмещают коэффициент из 512
множителей шириной 54 бита. Сравнение использует фиксированный стек.

## Принудительные сравнения

Для `x = 3FEFFFFFFFFFFFFF` выбираются обе границы округления вокруг
ответа MPFR. В таблице указан счётчик вызовов функции контроля
прогресса. Один вызов соответствует 1 024 учитываемым шагам, плюс один
начальный вызов на сравнение. Старая реализация из `4b9dc244` не
завершала эти случаи в пределах 200 000 вызовов на хосте.

| Показатель | Вызовов на каждую границу |
| --- | ---: |
| `1023` | 1 908 |
| `−1024` | 1 901 |
| `−1023` | 1 954 |
| `1023/128` | 1 939 |
| `−1023/128` | 3 403 |

Действительный ответ проверен по целым степеням Python. В регрессионной
проверке те же пары должны завершиться до 4 096 вызовов. Дополнительная
пара с `−1/1024` проверяет виртуальную степень середины между
соседними результатами. Остальные 1 494 проверки
охватывают обычное сравнение и вложенный пересчёт при искусственно
уменьшенных массивах.

## Сборка Pico H

ELF `EA016910/14801092`, собранный GCC 14.2.1, дал правильную сторону
в 14 прямых ARM-вызовах с factory BootROM и моделированием обращения к
физическому watchdog. Все десять трудных случаев на старом ELF
достигли лимита 4 096 вызовов контроля. Пиковый расход стека на входе
в функцию контроля нового компаратора составил 20 040 байт при прямом
вызове `side`. Размеры фреймов по `-fstack-usage` составили 11 888 байт
для `compare` и 7 208 байт для `recompute`. Секция точной ветки
занимает 8 000 из выделенных 12 288 байт. Сборка использует 119 896
байт статической RAM и занимает 1 805 072 байта во Flash.

В публичных ARM-точках входа 413 600 вызовов `pow`, `exp`, `sin`,
`cos` и `atan` совпали побитно с направленным оракулом MPFR 4.2.2.

Счётчик характеризует работу принудительной ветки. Для произвольного
binary64 всё ещё нет практической верхней границы задержки. Абсолютное
время новой ветки на PicoCalc требует отдельного замера.

## Последовательный проход с двумя окнами

Виртуальная степень с сохранёнными множителями теперь отдаёт разряды
по порядку с собственным переносом. Если после квадрата идёт умножение
на основание, для него может использоваться второе кольцевое окно.
Оба окна размещаются в свободных концах исходных массивов. Внутреннее
окно заканчивается на произведении двух полностью сохранённых
множителей. Для более глубоких выражений доступен прежний точный
пересчёт разрядов с контрольными точками.

Сохранённая диагональ суммируется одним проходом, кольцевая — максимум
двумя. Для квадрата сумма внедиагональных членов удваивается перед
добавлением центрального члена. Диагональ учитывается в счётчике
целиком перед вычислением. Между вызовами обслуживания watchdog при
этом выполняется не более `1024 + 1728 - 1` учитываемых шагов.
Средние точки, переносы и округление к чётному вычисляются точно.

### Граница работы точного сравнения

Пусть `abs(y) = p/q` в сокращённом виде. Следующие диапазоны гарантируют
последовательный проход для любой допустимой середины округления.

| Знак `y` | `p` не больше | `q` не больше |
| --- | ---: | ---: |
| Плюс | 1 024 | 1 024 |
| Минус | 1 024 | 256 |
| Минус | 512 | 512 |
| Минус | 256 | 1 024 |

Нечётные коэффициенты основания и середины имеют не более 53 и 54 бит.
Степени до 512 помещаются в массив на `L = 1728` разрядов. Для
основания хватает `ceil(53*512/16)+1 <= L` разрядов с учётом отдельного
округления длины каждого множителя. Для степени середины показатель
равен степени двойки, поэтому последний квадрат требует не более
`2*ceil(54*256/16) = L` разрядов. До показателя 1 024 возможен ещё
один виртуальный квадрат и, для основания, умножение на исходный
коэффициент шириной до четырёх разрядов. При отрицательном показателе
и одном виртуальном множителе показатель сохранённого множителя
ограничен 256 в указанных диапазонах. Его окно помещается в свободную
половину того же массива. Если нужно ещё и четырёхразрядное внутреннее
окно, предыдущая сохранённая степень основания имеет показатель до
512 и оставляет не менее 32 свободных разрядов.

Сумма членов диагоналей и числа записанных разрядов для квадрата
ограничена `S(n) = n*(n+1)/2 + 2*n`, для произведения —
`P(n,m) = n*m + n + m`. Длина входа каждого следующего квадрата в битах
как минимум удваивается. То же верно для длин перед умножениями на
основание, поскольку между ними есть квадрат. Для построения степени
в одном массиве это даёт верхние границы
`sum(S(ceil((L/2)/2^j))) = 502007` и
`sum(P(ceil(L/2^j), 4)) = 17351` по `j` от 0 до 13. Меньше двух бит
имеет только коэффициент 1, для которого произведения пропускаются.
Виртуальный конец каждой степени добавляет не более
`S(L) + P(2*L, 4) = 1514596` шагов. Последнее произведение для
отрицательного показателя добавляет не более `P(2*L+4, L) = 5984068`.
Если грубые границы длин пересекаются, выравнивание сдвигает
коэффициент не дальше битовой длины другой стороны. Поэтому внешний
проход добавляет не более `4*L+10` шагов. Всего получается не более
**10 058 898 учитываемых шагов на одно сравнение** для этих диапазонов.

### Проверка на ARM

Показаны принудительные вызовы точного сравнения при `x = 1 − 2⁻⁵³`
и нижней из двух смежных границ ответа MPFR. Связанные образы
`F5A9F08C/F5CD13BB` и `5CD0685C/511BE730` выполнялись в эмуляторе с
заводским BootROM. Столбцы содержат инструкции Thumb.

| `y` | Прежний образ | Новый образ |
| --- | ---: | ---: |
| `511` | 23 657 926 | 12 319 933 |
| `1023` | 97 800 633 | 41 047 280 |
| `−1023` | 104 317 027 | 43 022 100 |
| `−1023/128` | 162 978 179 | 73 289 486 |

Для `−1023/128` прежний образ сделал 3 389 входов в общий пересчёт и
записал 20 048 байт стека. Новый прошёл без общего пересчёта с пиком
12 744 байта. В 15 прямых вызовах все стороны совпали с MPFR.
Ещё 40 395 публичных `pow` и 40 196 `exp` совпали с MPFR 4.2.2.
Отдельный прогон общего пересчёта с `y = −2049/16` был ограничен
1 024 вызовами watchdog. За это время он вошёл в пересчёт 75 раз и
записал до 20 048 байт стека. Тестовое APP в эмуляторе выдало пять
ожидаемых ответов.

### Замер на PicoCalc при 125 МГц

`POWEXACT` выполнил по одному вызову на вход в образе `5CD0685C/511BE730`
из коммита `aba99640`. Все пять результатов совпали с MPFR 4.2.2.
Для двух точных сравнений основание равно `1 − 2⁻⁵³`. Время всей
цепочки включает принудительный проход ступеней до 8 192 бит.

удалён, устройство оставлено с `5CD0685C/511BE730` в калькуляторе с
