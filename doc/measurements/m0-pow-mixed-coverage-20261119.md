# Проверка охвата остатка на 88 415 бит для `pow`

Общее доказательство остаётся открытым. Контрпример не найден. Для
округления к ближайшему с ничьими к чётному проверяется остаточная
область `0 < abs(y*ln(abs(x))-ln(m)) < 2^-16300` и `N+k > 104713`.
Здесь `m` — точная середина округления, `2^k` — знаменатель
сокращённого `abs(y)`, а `N` — верхняя граница двоичного логарифма
меньшего целого операнда компаратора. Точные ничьи уже разрешает
степенная ступень. Верхняя граница времени для всех `binary64`
зависит от результата этой проверки.
[Доказательство точных ничьих](m0-pow-power-bounds-20261117.md),
[арифметика остатка](m0-pow-mixed-residue-20261119.md).

## Проверка ширины и полный набор корней

Режим `--mixed-residue` программы проверки использует отдельную
версию сертификата и проверяет отпечаток исходника прототипа. Полная
проверка в этом режиме должна выдать `PASS_MIXED_RESIDUE`. Результат
означал бы, что цепочка может завершаться с этим прототипом после
отказа штатного остатка. Прототип пока не подключён к прошивке.

Для фиксированного `abs(y)=p/2^k` можно проверить ширину по двоичным
масштабам. Пусть `x=a*2^u`, `m=b*2^v` с нечётными `a,b`. При
положительном показателе из обеих степеней выносится общий масштаб
`min(p*u, 2^k*v)`. Из верхних границ логарифмов степеней вычисляется
верхняя граница логарифма меньшего выровненного операнда. При
отрицательном показателе целый порог равен `2^(-p*u-2^k*v)`, если
сумма масштабов отрицательна. При неотрицательной сумме знак известен
сразу. Для интервала кодировок проверка берёт нижнюю границу масштаба
у первого значения и верхнюю границу логарифма у последнего.

Грубая граница `N <= max(53*p,54*2^k)` для `y>0` или
`N <= 53*p+54*2^k` для `y<0` даёт охват всех оснований для 11 855
положительных и 10 811 отрицательных показателей. В подсчёте для
`k>0` берутся только нечётные `p`. У 49 152-битной ступени такое же
условие принимает 7 404 положительных и 6 364 отрицательных показателя.

Локальное продолжение серверной контрольной точки посетило ещё
1 400 000 областей за 33,32 с. Независимая проверка пересчитала
677 265 принятых листьев, из них 297 762 добавились в этом проходе.
В текущем разбиении осталось 1 817 728 открытых листьев и четыре
ссылки на отдельно проверявшийся слой `q116`. Новые листья приняли
прежние правила исключения. Проверка вернула `INCOMPLETE`.
SHA-256 сжатой контрольной точки
`536c995b6e9be6815c3434c695139aee2fbbc797306d7d8661c3eaaee9fa35fb`.
[Проверяющая программа](../../dev/tools/verify_m0_pow_binary64.py),
[правила полного покрытия](m0-pow-binary64-proof-20261119.md).

## Поиск контрпримера в корпусе CORE-MATH

Направленный MPFR 4.2.2 проверил 1 003 177 пар закреплённого файла
`pow.wc`, включая 999 847 пар после грубых условий входа и 2 314 866
сравнений с серединами. `pow` с округлением вниз и вверх ограничил
положение результата. В проверку вошла середина каждого оставшегося
интервала между соседними кодировками и по одной внешней середине.
Более далёкие середины отделены ещё одним шагом сетки, логарифмическая
длина которого больше `2^-54`.

В 10 722 сравнениях интервал MPFR пересекал полосу `[-2^-16300,2^-16300]`.
Проверка целых размеров покрыла все эти сравнения ещё в точной
степенной ступени. Максимальная грубая оценка ширины была 874 бита.
У всех отделённых сравнений зазор больше `2^-172`. При
`x=0f1234687b59d4f7`, `y=3c3101a6c819d38d` и нижнем соседе
`3feffffffffffffb` он меньше `2^-171`. Дополнительная проверка целыми
направленными интервалами на 224 битах подтвердила оба неравенства. Опубликованный
корпус охватывает выбранные семейства трудных входов.

## Два полных среза для показателей рядом с единицей

Для `y=1+2^-52` и `y=1-2^-53` доказано `abs(y*ln(x)-ln(m)) > 2^-184`
для всех положительных конечных `binary64` оснований и всех середин.
В каждом срезе покрыты все 2 047 непустых поля показателя, включая
субнормальные числа, всего 9 218 868 437 227 405 311 оснований.

Пусть `y=1+δ`, `x=a*2^e`, где `2^e` — шаг сетки оснований в данном
поле показателя. Если логарифмический зазор не превышает `2^-184`, из
`abs(ln(x))<745` следует `1/2 < m/x < 2`. Любая такая середина в
своём или соседнем поле имеет шаг, кратный `2^(e-2)`. Это также
верно около нуля и порога переполнения. Поэтому `d=4*(m-x)/2^e`
есть ненулевое целое. По теореме о среднем для экспоненты

```text
D(a) = 4*a*expm1(δ*ln(a*2^e))
abs(D(a)-d) < 2^56 * abs(y*ln(x)-ln(m)) <= 2^-128.
```

Производная `D` равна `4*((1+δ)*x^δ-1)`. Знак определяется знаком
`δ*(ln(x)+ln(1+δ)/δ)`, а выражение в скобках строго возрастает.
Проверка направленными интервалами делит поле в точке смены знака,
если такая точка есть. На каждом монотонном участке для всех целых
`d` в диапазоне она либо исключает корень за концом, либо проверяет
две соседние целые мантиссы, между которыми лежит корень. Во всех
проверках расстояние больше `2^-128`. Обычный `double` подсказывает
начальную мантиссу, решение принимают только направленные сравнения.

MPFR 4.2.2 проверил 2 904 442 целевых смещения выше единицы и
1 452 218 ниже. Списки выполненных заданий проверены на полное
покрытие без повторов. SHA-256 упорядоченного журнала
`d39bb2c222cd3d5ecceff51fdae7be4c7cd21f8455c6850e3d579f1bd953f2f6`.
[Исходник сертификата](../../research/m0-pow-comparison-20261117/certify_adjacent_one.c).

## Воспроизведение

```sh
tool=dev/tools/verify_m0_pow_binary64.py
src=research/m0-pow-comparison-20261117
python3 -B -S "$tool" search "$run_dir/frontier.jsonl.gz" \
    --continue-from "$prior_frontier" --mixed-residue --reuse-q116 --workers 8 --nodes 1400000 --seconds 75
python3 -B -S "$tool" verify "$run_dir/frontier.jsonl.gz" --mixed-residue
python3 -B -S tests/m0_pow_binary64_proof_self_test.py
cc -O3 -std=c11 -Wall -Wextra -Werror "$src/search_wide_residue.c" \
    $(pkg-config --cflags --libs mpfr gmp) -o "$run_dir/search_wide_residue"
cc -O3 -std=c11 -Wall -Wextra -Werror "$src/certify_adjacent_one.c" \
    $(pkg-config --cflags --libs mpfr gmp) -lm -o "$run_dir/certify_adjacent_one"
```

Для корпуса используется файл `pow.wc` из ревизии
`bc80b31cd1ea1f8051f92b2669f58f8ff1892239` с SHA-256
`deb40211a63a53023c0f5cd9dd47b51a8e3706b18e6811fb8875f8b98aa40863`.
Перевод каждой пары в две 16-разрядные шестнадцатеричные кодировки
делается по тому же правилу, что в `qualify_m0_pow_worst.py`.
[Закреплённый файл](https://gitlab.inria.fr/api/v4/projects/core-math%2Fcore-math/repository/files/src%2Fbinary64%2Fpow%2Fpow.wc/raw?ref=bc80b31cd1ea1f8051f92b2669f58f8ff1892239).

```sh

python3 -B -S - <<'PY' | xargs -n 3 -P 8 "$run_dir/certify_adjacent_one"
```
