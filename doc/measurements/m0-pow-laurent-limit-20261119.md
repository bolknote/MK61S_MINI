# Предел автоматического подбора параметров Лорана для `pow`

Для прямого применения [теорем 1 и 2 Лорана, стр. 326–327](https://www.impan.pl/shop/en/publication/transaction/download/product/82485)
не существует параметров, которые дали бы нужную текущему RP2040
зазору оценку на всей области binary64. Ниже исключаются все
параметры этих двух формул и все невырожденные целочисленные
замены двух рациональных оснований их степенными произведениями.
Доказательство не исключает другие методы, дополнительные независимые
основания или гибридные проверки, которые обходятся без теоремы
на нужных входах.

Получаемую из этих формул границу для логарифмического зазора
нельзя поднять до **`2^-103063`** в рассматриваемом случае.
Существующая логарифмическая ступень требует **`2^-16300`**.
Это предел формул, а не оценка фактической наихудшей точности.

## Какой случай исключает подбор

Положим `U=ln(x)`, `V=ln(m)`, где `m` — середина округления,
`y=p/q∈[1,2)` в несократимом виде и
`Delta=abs(y*U-V)`. Требуются `U>700` и взаимно простые
нечётные коэффициенты `x,m`, логарифм каждого из которых больше 36.
Точная проверка восстанавливает настоящий соседний порог для
`x=7fd0000000000001`, `y=3ff0040201008043`. Две строгие
логарифмические оценки помещают `x^y` между соседними серединами,
а округлённый ответ имеет код `7fe00000000007f5`.
Для самого примера зазор находится между `2^-57` и `2^-56`;
этот вход не требует большой точности и не является контрпримером
к правильному округлению. Направленная проверка MPFR 4.2.2
независимо вернула ту же кодировку.

Пусть новые логарифмы `u_i=r_i*U+s_i*V` получены целой
матрицей с `d=abs(det)>0`. Основания можно обратить, чтобы
логарифмы стали положительными. Пусть `M=max(abs(r_i),abs(s_i))`,
а `H_i` — рациональная логарифмическая высота нового основания.
Взаимная простота нечётных частей не позволяет им сократиться,
поэтому `H_i >= 36*max(abs(r_i),abs(s_i))`. В частности,
обе высоты не меньше 36, одна не меньше `36*M`.

Обозначим `t=ln(rho)>0`, `W=a_1*a_2/t`. В обеих теоремах
`a_i >= (rho-1)*abs(u_i)+2*H_i`. Смешанные слагаемые
произведения и равенство `abs(s_2*u_1 - s_1*u_2)=d*U` дают
`W > 2*36*700 = 50400`, так как `rho-1 >= t`.
Также `max(abs(u_i)) >= U/(2*M)`. Отсюда:

- При `t <= sqrt(M)` произведение высот даёт
  `W >= 4*36^2*sqrt(M) >= 210*ln(M)`.
  Последнее следует из `ln(M) <= 2*sqrt(M)`.
- При `t > sqrt(M)` используем `rho-1 >= t^5/120` и
  больший из двух логарифмов. Тогда `W >= 36*700*t^4/(120*M)`,
  что больше `210*M`, а значит и `210*ln(M)`.

Код делит замкнутый интервал `mu∈[1/3,1]` на 256 частей.
На каждой строится рациональная нижняя граница `mu/sigma^4`
через монотонность `sigma=(1+2*mu-mu^2)/2`.
Все части дают больше `4/5`. Это включение интервалов,
не оценка только в точках сетки. Далее `c=(16/9)*(4/5)=64/45`.

## Теорема 1

Пусть `N=K*L`. Условия мощностей множеств требуют
`R1*S1>=L` и `R2*S2>=(K-1)*L+1`. Из `R=R1+R2-1`
и `S=S1+S2-1` следует `R*S>=R1*S1+R2*S2-1>=N`,
так что `g>=1/6`. Множество целых `r*b2+s*b1`
лежит между нулём и `(R-1)*b2+(S-1)*b1`. Этот верхний
конец не меньше `(K-1)*L`.

Факториальный множитель в знаменателе для `b` — взвешенное
геометрическое среднее чисел `j=1,...,K-1` с весами `K-j`.
Среднее арифметическое равно `(K+1)/3`, откуда
`b >= 3*(K-1)*L/(2*(K+1))`. При `L>=2` имеем `b>=1`.
При `L=1` положительный член условия (2) неположителен.
Для `K>=5` также `b>=1`, а при `K∈{2,3,4}` имеем
`b>=1/2` и `(K-1)*ln(2)<2*ln(K)`. Значит, `L=1`
не удовлетворяет (2). Величина `epsilon(N)` положительна:
`ln(N!) >= N*ln(N)-N+1` и в её числителе есть слагаемое `e^N`.

Условие (2), AM–GM и `g>=1/6` теперь дают
`N*(sigma-1/L)*t > (L/3)*sqrt(N*a_1*a_2)`. В частности,
`sigma*L>1`. После возведения в квадрат:

```text
mu*N*t > mu*L^2*W / (9*(sigma-1/L)^2) >= (16/9)*(mu/sigma^4)*W > c*W.
```

Предпоследнее неравенство следует из `z^2>=4*(z-1)` при
`z=sigma*L>1`. Оно не требует сетки для `rho,K,L,R,S`.

Для перевода результата теоремы с `Lambda'` на `Delta`
левая часть формулы имеет вид `A*Delta*exp(A*Delta)`. После
замены баз целые коэффициенты формы получаются умножением
`(p,-q)` на присоединённую матрицу. Их общий делитель `j`
делит `d`, поскольку `p,q` взаимно просты. После сокращения
каждый коэффициент не больше `(p+q)*M/j < 3*q*M/j` по модулю.
Коэффициент перехода от `Delta` к новой форме равен `d*q/j`;
с `L>=2` это даёт `A>=1/(3*M)`. Дополнительное умножение
обоих коэффициентов на общее целое не меняет этот переход
для `Lambda'`. Здесь рассматриваются приложения с двумя
ненулевыми слагаемыми противоположного знака.

Поэтому граница для `Delta`, которую можно извлечь из
`abs(Lambda')>exp(-mu*N*t)`, не больше
`3*M*exp(-mu*N*t)`. Её показатель потери строго больше
`c*W-ln(3*M) > (c-1/210)*50400-2 = 71438` натов.

## Теорема 2

Здесь `lambda=sigma*t`, `omega>=4`, `theta>=1`.
Первый положительный член потери уже не меньше
`(16/9)*(mu/sigma^4)*W > c*W`: в константе `C`
корень не меньше `omega/3`, а `(h+t)^2>=t^2).
Логарифмическая поправка тоже положительна, так как
`C' >= 8/(3*lambda^3)` и подлогарифмический множитель
не меньше `8*W/3>1`. Деление результата на `d*q/j>=1`
при возврате к `Delta` ослабляет границу. Значит, общий
предел 71438 натов применим и здесь.

Без замены оснований обе величины `abs(u_i)>700`.
Тогда `W >= 700^2*(rho+1)^2/t >= 8*700^2`, где
`rho>=1+t` и `(t+2)^2/t>=8`. Это даёт ещё более слабую
максимальную гарантию этих формул для прямого представления.

## Воспроизведение и решение по запуску

```sh
python3 -B -S dev/tools/certify_m0_pow_laurent_limit.py
python3 -B -S tests/m0_pow_laurent_limit_self_test.py
```

Скрипт проверяет точные числовые неравенства доказательства,
сплошное покрытие параметра `mu`, свидетеля округления и
порог существующей ступени. Он не меняет прошивку и не выдаёт
полного доказательства времени `pow`. Длительный CPU/GPU-перебор
параметров этих формул не имеет смысла: указанное ограничение
доказано для всего семейства. Для нового вычислительного поиска
нужна другая проверяемая оценка или другой алгоритм сравнения.
