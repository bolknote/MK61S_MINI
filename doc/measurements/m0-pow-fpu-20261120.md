# Проверка аппаратной схемы x87 для `pow`

У x87 нет отдельной инструкции `pow`. Библиотека получает
`t=y*log2(x)` через `FYL2X` или через `FYL2XP1` около единицы.
Затем выделяет целое `n=round(t)`, вычисляет `2^(t-n)-1`
через `F2XM1`, прибавляет единицу и масштабирует через
`FSCALE` на `2^n`. Intel 8087 использовал CORDIC с табличными
константами, широкими сдвигами и суммированием. Позднее Intel
перешёл на полиномиальные приближения.
[Архитектура 8087, Р. Наве](https://ethw-images.s3.us-east-va.perf.cloud.ovh.us/ieee/8/8b/Nave_implenent_transcendental_algos_1983.pdf),
[описание Intel](https://www.intel.com/content/www/us/en/developer/articles/technical/the-difference-between-x87-instructions-and-mathematical-functions.html),
[схема glibc для i386](https://codebrowser.dev/glibc/glibc/sysdeps/i386/fpu/e_pow.S.html#202).

У Cortex‑M0+ нет аппаратного FPU. BootROM RP2040 хранит
программные примитивы с плавающей точкой. Быстрая ветка проекта
уже вычисляет логарифм и экспоненту с редукцией аргумента и
проверяет округление по оценке погрешности.
[Arm Cortex-M](https://developer.arm.com/Additional%20Resources/Compare%20IP%20for%20Cortex-A%20premium%20CPUs),
[RP2040, раздел 2.8.3.2](https://datasheets.raspberrypi.com/rp2040/rp2040-datasheet.pdf?hkey=EF798316E3902B6ED9A73243A3159BB0),
[быстрая ветка CORE-MATH](../../third_party/core_math/pow/pow.c#L1716).

## Контрпример для переноса схемы как полной реализации

Тестовый код исполнил аппаратные инструкции на Intel Xeon 6740P.
Режим x87 использовал округление к ближайшему с ничьими к чётному
и 64 значащих бита. Направленный MPFR 4.2.2 на 256 битах
определил ответ binary64 для каждой из 86 238 выбранных пар
корпуса. В выборке конечное положительное основание, нецелый
конечный показатель и нормальный результат.

| Вычисление | Расхождения с правильным округлением |
| --- | ---: |
| x87 с отдельным умножением логарифма на `y` | 10 669 |
| x87 с вычислением `y*log2(x)` одной инструкцией | 10 753 |
| Точная степень с округлением сначала до 64, затем до 53 значащих битов | 9 748 |

Один вход дал одинаковое расхождение во всех трёх проверках.

```text
x                       0x1.1d06cac4007f7p-1
y                       0x1.2999bb0510100p-4
ответ x87               0x1.eaaae1482004ep-1
верный результат RNE    0x1.eaaae1482004fp-1
```

Для середины `m=17263827892830365/2^54` направленные целые
интервалы независимо дают `2^-116 < y*ln(x)-ln(m) < 2^-115`.
Следовательно, точная степень чуть выше середины. Расстояние
до неё меньше `2^-114` по оценке `exp(t)-1<2*t` при
`0<t<1/2`. Середина точно представима в формате с 64 значащими
битами, половина его шага здесь равна `2^-65`.
Первое округление попадает ровно в середину, второе выбирает
чётного нижнего соседа. Поэтому даже идеально округлённый
промежуточный результат x87 не даёт общей гарантии для binary64.
[Рациональная проверка свидетеля](../../tests/m0_pow_binary64_proof_self_test.py).

Выборка намеренно состоит из трудных аргументов и не показывает
долю расхождений на обычных вызовах. Для использования быстрой
аппроксимации остаётся проверка положения относительно середины.
Для универсальной практической границы RP2040 по-прежнему нужен
сертификат остаточной области или ограниченный по времени точный
компаратор. [Остаточная область](m0-pow-mixed-coverage-20261119.md).

## Воспроизведение на x86

```sh
src=research/m0-pow-comparison-20261117/check_x87_pow.c
cc -O3 -std=c11 -Wall -Wextra -Werror "$src" \
  $(pkg-config --cflags --libs mpfr gmp) -lm -o /tmp/check-x87-pow
/tmp/check-x87-pow < /path/to/pow.wc
python3 -B -S tests/m0_pow_binary64_proof_self_test.py
```

SHA-256 входного `pow.wc`
`deb40211a63a53023c0f5cd9dd47b51a8e3706b18e6811fb8875f8b98aa40863`.
