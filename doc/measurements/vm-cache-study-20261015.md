# Профиль chess и модель смешанного кеша VM — 2026-10-15

База: `72d704cf20630300553f547ae0cda2639de14ac1`, после оптимизации OPEN/подготовки VM.
Это исследование, **не внедрение сжатия и не аппаратно измеренное ускорение**.
Численные данные: [vm-cache-study-20261015.json](vm-cache-study-20261015.json).

## Что проверено на Classic

Два одинаковых поиска, книга выключена, уровень 2, предел глубины 8:
оба `e2e3`, 420 узлов, все восемь рядов доски, одинаковый SHA кадра,
705 кадров USB Screen прошли CRC. Диагностические времена: 56,731 с холодный,
47,498 с повторный. Сравнивать их с обычными 44,427 с из предыдущего A/B
как замер ускорения/регрессии нельзя: включены подробные DWT scopes и хеширование порядка.

Повторный поиск: **11 303 обращения, 11 245 попаданий, 58 промахов**.
42 промаха приходятся на `board` и `search` — по 21 на каждый.
174 ZX0-декодирования: 58 LANGVM, 58 VMSTORE и 58 в категории исходника.
Записей/стираний NOR в повторном измеряемом поиске нет.

| Участок | Время диагностического поиска | Как читать |
| --- | ---: | --- |
| Исполнение LANGVM | 21,347 с | self, без вложенных услуг |

Строки таблицы **нельзя складывать**: есть вложенность.
Кеширование не устраняет основную вычислительную работу VM; само по себе
оно не обещает двукратного ускорения всего хода.

В диагностический режим добавлена подпись порядка source inode:
FNV-1a64 по двум байтам inode, `count=11303`, `fnv64=2258983549102710787`.
Host-трасса совпала по порядку, размерам и числу запусков каждого модуля.
Полный цикл host имеет ещё два вызова вне замера — init и menu.
Replay штатного C++ density даёт 60 промахов за полный тёплый цикл;
за измеряемое окно — **58, с совпадением промахов по каждому модулю**.
Холодный replay не моделирует публикацию файлового кеша/инвалидации ревизии ФС;
его нельзя выдавать за прогноз холодного поиска на устройстве.

## Модель, действительно ограниченная памятью

Кеш остаётся 24 576 байт: 688 метаданных, 23 888 payload, 16 слотов.
В полном UI-цикле используются 17 модулей: 32 256 байт с выравниванием;
даже сумма всех LZSS-образов без выравнивания — 26 425 байт.
Просто «сжать всё и держать навсегда» здесь не получится.

Учтены выравнивание, отдельные непрерывные span, временные source/output,
256-байтный словарь, запрет перемещения/сжатия/вытеснения pinned-образов,
фрагментация, полная компактизация только без pins, 16 слотов и fallback.
Отдельный стресс-тест проверяет закреплённые указатели; сама игровая трасса
имеет последовательные вызовы с освобождением образа между ними.

| Вариант модели, тёплое окно | Промахи | Сжатия / распаковки | Переносы компактизации |
| --- | ---: | ---: | ---: |
| Штатный raw density | 58 | 0 / 0 | отдельная исходная политика |
| Всё временное только внутри payload | 127 | 182 / 81 | 2,085 МБ |
| Рабочий prefix доступен только на тёплом lookup | 12 | 207 / 198 | 4,367 МБ |
| Prefix якобы свободен всегда — непригодный оптимистичный контроль | 9 | 266 / 259 | 4,969 МБ |

Рабочий prefix — существующие 4176 байт workspace, не новая RAM.
Во время холодного reserve он занят компилятором/VMSTORE: там модель
даёт **ноль** внешнего staging. На тёплом lookup можно исследовать
временное заимствование до подготовки ExecutionState; реальная интеграция
обязана доказать lifetime. Пик заимствования модели — 4032 байта.

Проверен также вариант с +32 байтами метаданных **внутри тех же 24 КБ**:
126 промахов без staging и те же 12 на тёплом prefix, 208/199 операций.
Нулевая прибавка метаданных — гипотеза переиспользования полей каталога,
не уже доказанный layout прошивки.

Наивный cache-only packing следует отклонить: промахов стало больше.
Вариант тёплого заимствования — кандидат для прототипа, не штатная настройка.

## Цена кодека

Экспериментальный LZSS выполнен в Cortex-M4 ISA через Unicorn с реальным
`memcpy` проекта. Для всех 17 образов проверены roundtrip, CRC упакованных
байтов против host C++, границы записей, неизменность источника,
сохранение SP и callee-saved регистров.

Для варианта 12 промахов: 30 675 346 ARM-инструкций успешных encode/decode
за ход; с отдельным полным проходом определения размера — 56 239 605.
Ещё 4 871 966 байт копирования/компактизации и неудачные попытки кодирования
в эти числа не входят. Это **инструкции, не такты и не секунды Cortex**.
Точный сжатый размер известен модели offline; в реальном коде нужен
ограниченный выход либо явно оплаченный sizing pass.

Freestanding-проба занимает 936 байт ROM, включая общий memcpy;
mutable static — 0, внешний словарь — 256 байт, измеренный стек
encode/decode — 116/64 байта. Это не обещание такого же Flash/stack delta
при встраивании в resident: интеграцию надо отдельно собрать и проверить.

## Память, восстановление и воспроизведение

При выключенной детальной диагностике прошивка **побайтно совпадает** с
предыдущей: `56B3329F`, 360 072 байта, static 28 072,
SHA256 `e5d56c43e12ffbbc0049cf4d5a8750de3782cff0da29339622134bde37dbee03`.
Изменения обычных Flash/RAM/стека — 0. Лимиты не ослаблены.
Диагностический `612CFA6C`: 362 908 байт, static 29 664, максимальный native
frame 1928; штатные foreground-stack, APP RAM и native-library gates PASS.

Первый финальный fsget отвергнут по разрыву DATA-offset, поэтому исходный
драйвер честно сохранил FAIL. Отдельное завершение recovery прошло exit 0:
точная исходная `D80CE1D1`, CRC valid/crash none, все SHA 44 файлов/4 каталогов,
регистры, стек, программа, каталог и выключенные будильники сохранены.
Возвращены два временно заменённых APP и удалены десять созданных тестом VMC;
повторные чтения recovery не потребовались. CDC закрыт, Classic освобождён,
Mini не затрагивался. Первичный FAIL не переписан задним числом в PASS.

отрицательные тесты подписи, комбинации DWT и экранный HIL oracle PASS.

## Следующий этап

1. Только экспериментальный, по умолчанию выключенный mixed-cache прототип
   с заимствованием prefix на тёплом lookup, без новой арены и изменения 24 КБ.
2. Сохранить generation/pin/revision/validated-image гарантии; ограниченный
   выход кодека, безопасный отказ при нехватке места. Не отдавать VM packed bytes.
3. Сократить повторные сжатия и ненужные компактизации; отдельно измерить
   неудачные попытки, sizing, копирование и полную подготовку VM.
4. Обе арифметики, BASIC/FOCAL, INPUT/ESC, активный USB, инвалидации ФС,
   F401/F411, Flash/RAM/stack gates без ослаблений; затем аппаратный A/B/A.
5. Включать штатно только по реальному времени полного хода и проверкам
   поведения. Для цели ×2 отдельно атаковать горячее исполнение VM —
   профиль оставляет там 21,347 с self даже после всех обсуждаемых промахов.
