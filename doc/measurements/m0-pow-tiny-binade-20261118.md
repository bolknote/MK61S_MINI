# `pow` для `2^-64 <= abs(y) < 2^-63`

Для положительного конечного основания `x` результат в этой бинаде
показателя округляется к `1` или к предыдущему binary64
`3fefffffffffffff`. Единственная возможная граница округления
`m = 1 - 2^-54`. Это следует из `abs(ln(x)) < 745`, включая
субнормальные основания. Направление `y*ln(x) >= 0` всегда даёт `1`.

Сертификат ограждает `-ln(m)` целыми интервалами на сетке из 256 бит.
При `n = abs(y)*2^116` нужно сравнить `n*abs(ln(x))` с
`C = -2^116*ln(m)`. Проверка минимального субнормального и
максимального конечного оснований даёт пороги для двух знаков.
Ниже них **3 684 959 993 743 332** знаковых показателя дают `1`
при любом положительном конечном основании. Ещё один диапазон
оснований даёт `1` для всех показателей этой бинады и обоих знаков.
Границы диапазона имеют кодировки `11c44109edb2079d` и
`6e19476504ba8727` включительно.

Для остальных входов положим `K = ceil(C/ln(2)) = 6653256548922161431`.
Из двоичного показателя основания получаем `j <= abs(log2(x)) <= j+1`.
При `n*j >= K` результатом служит число перед единицей. При
`n*(j+1) < K` результат равен единице. Для степени двойки
логарифм по основанию два целый, поэтому сравнение точное.
Для каждого `n` обе границы могут не решить округление только при
`j = floor((K-1)/n)`. В убывающем направлении этот `j` соответствует
одной бинаде основания. За счёт этого **более 99,97%** пар в области
разрешаются до вычисления логарифма.

В оставшейся бинаде основания повторно используется `pow_refined_log`
с абсолютным ограждением Q94. Для субнормального `x = M*2^-1074`
модуль логарифма вычисляется как `1075*ln(2)-ln(2*M)`. Число `2*M`
точно представимо как нормальное binary64. Произведение с `n` и сдвиг
на 53 дают `abs(y*ln(x))` в Q157. Целая часть `-ln(m)` в Q157
равна `2^103 + 2^48`. Защитная граница сравнения учитывает
погрешность Q94, усечение произведения и дробную часть `-ln(m)`.

Для перехода в общую ветку истинный логарифм результата должен лежать
ближе `1284*2^-157` к логарифму середины. При фиксированном `y`
разница между логарифмами результатов для соседних оснований больше
`2^-118`. Поэтому на каждый знаковый показатель остаётся не более
одного основания, для которого возможен защитный переход. Точная
ничья исключена по порядку двойки. У сокращённого показателя
знаменатель не меньше `2^64`, а порядок двойки основания по модулю
не больше 1074. При ничьей знаменатель делил бы этот порядок, хотя у
середины порядок двойки равен `-54`. Остаётся доказать достаточное
разделение для близких входов. Общая ветка сохраняет правильное
округление, и практическая граница времени для всех binary64 открыта.

## Проверка Pico H

В ELF `BE550AE2/DA00E4AE` все 12 695 публичных вызовов из целевого
набора совпали с направленными результатами MPFR 4.2.2. Два
дополнительных вызова с искусственно приближённым логарифмом прошли
через общую ветку и также вернули результаты MPFR. Регрессия прошла
80 395 вызовов `pow` и 80 196 вызовов `exp`. Эмулятор исполнял
заводскую BootROM RP2040 и проверял сохранение регистров и стека.
`Scratch Y` занимает 4 096 байт.

В связанном ELF проверены размеры участков и отсутствие циклов
на пути для положительного конечного основания. При решении
целочисленными границами верхняя оценка **2 878** инструкций от
`compact_math::pow`. Сюда входят 2 791 полуслово диспетчеризации
и сравнения, до 44 на `clz64` и до 43 на 64-битное умножение.
Для ответа через Q94 добавляются до 2 412 полуслов функции логарифма,
82 инструкции двух вспомогательных умножений и 23 инструкции сдвига
с переходником. Итого **5 395** инструкций на любой вызов в этой
области, который завершится до общей ветки. При подсчёте полуслов
учтены целые функции и переходники, включая альтернативные ветви.
Эти оценки относятся к инструкциям ELF. Время этой сборки
на PicoCalc не измерялось.
