# Общедоменная проверка последней ступени `pow` на RP2040

Проверка ищет доказательство того, что штатная цепочка `pow` не
вызывает потоковый компаратор ни для одной пары binary64 при
округлении к ближайшему с ничьими к чётному. Это достаточное
арифметическое условие для границы без медленного потока, но
не расчёт времени в тактах и не доказательство компилятора.
На 19 ноября полное доказательство **не получено**.

## Условие приёмки

Корни задаёт сам проверяющий код. Для каждого знака `y` они покрывают
все положительные конечные `abs(x)`, кроме 1, все
`2^-64 <= abs(y) < 2^63` и все положительные границы округления
от середины между нулём и минимумом до порога переполнения. Спецслучаи,
область за пределами `y` и знак результата для допустимых отрицательных
оснований сводятся штатными правилами перед точным сравнением.
Отпечаток связывает проверку с проверенными исходниками цепочки.

Каждая запись `split` делит унаследованную полузамкнутую область
по одной границе кодировок. Проверка требует обе половины, все четыре
корня и отсутствие лишних записей. Для листьев проверяется одно из
условий:

- `gap`, `y-grid`: направленные целые интервалы исключают
  `abs(y*ln(abs(x))-ln(m)) < 2^-16300` напрямую или проекцией
  на точную сетку binary64 для `abs(y)`, в том числе через бинады.
- `affine`: в одной бинаде каждого аргумента показатель на сетке
  задаётся целым числителем `p`. Для кандидата `D*p-A*I-B*J`
  было бы целым. Проверка заново ограждает значение в центре,
  обе частные производные и вертикальный сдвиг; полученный
  интервал не содержит целого.
- `scale-grid` заново проверяет всю пару диапазонов нормализованных
  мантисс для всех показателей и двоичных масштабов. Это правило
  применяется к листьям внутри одной бинады основания и одной
  бинады середины.
- `entire` применяет один полиномиальный сертификат ко всему
  прямоугольнику основания и середин. Для показателей проверяется
  включение двоичной сетки листа в сетку сертификата.
  [Доказательство и результаты](m0-pow-entire-surface-20261119.md).
- `powers`, `residue`: проверяются размеры степеней или остатка,
  достаточные для завершения в существующей ограниченной ступени.
- `origin`: пересчитывается рациональный сертификат определителя
  Лорана для заявленной окрестности единицы.
- `q116`: отдельный слой `2^-64 <= abs(y) < 2^-63`. Если все
  остальные ветви закрыты, проверка этого листа требует исходные
  журналы, пересчитывает полиномы и прямые проверки, затем проверяет
  аналитически исключённый центральный диапазон. Сам отчёт с числом
  блоков не даёт права закрыть даже этот лист.

`PASS_NO_STREAM` выдаётся только после проверки всех листьев. При
`open` результат `INCOMPLETE` (код 2): это пропуск в доказательстве,
а не найденный неправильный результат `pow`. Ошибка формата или
ложное исключение дают код 1. Поиск может сохранять открытые листья
и продолжать с них; принятые поиском листья не являются результатом
проверки, пока команда `verify` их заново не проверит.

## Запуск

```sh
tool=dev/tools/verify_m0_pow_binary64.py
python3 -B "$tool" search "$run_dir/frontier.jsonl" \
  --workers 24 --nodes 5500000 --seconds 150 --reuse-q116
python3 -B "$tool" verify "$run_dir/frontier.jsonl"
python3 -B "$tool" search "$run_dir/continued.jsonl" \
  --continue-from "$run_dir/frontier.jsonl" --workers 24 --reuse-q116
python3 -B tests/m0_pow_binary64_proof_self_test.py
```

Для полного независимого прогона с листьями `q116` передаются
`--q116-layer` (дерево сжатых журналов) и `--q116-edge` (журналы
отдельной бинады −739). `--flint-products` включает точное
умножение FLINT в сжатом журнале. Для частичного сертификата
дорогая перепроверка этого слоя откладывается.

## Проверка без перебора показателей и двоичных масштабов

Представим $|x|=2^e X$, $m=2^f M$ с $1\le X,M<2$.
Здесь $X=A/2^{52}$ и $M=B/2^{53}$, включая субнормальные
основания, середину между нулём и минимальным субнормальным
числом и порог переполнения. Возьмём общий знаменатель
$Q=2^{116}$ для всей активной области показателей. Тогда
$y=P/Q$ с целым $|P|<2^{179}$, и

$$
\frac{Q\,(y\ln |x|-\ln m)}{\ln 2}
= P\log_2 X-Q\log_2 M+Pe-Qf.
$$

Поэтому при опасном зазоре $P\log_2 X-Q\log_2 M$ должно лежать
вблизи целого. Проверяющий код позволяет любые целые $P$ в
указанном интервале и любые целые $e,f$. Пусть $U,V$ — целые
нижние оценки для $2^h\log_2 X$ и $2^h\log_2 M$ с ошибкой до
двух единиц. Условие перехода к потоку требует, чтобы целое
$PU-QV$ отстояло от кратного $2^h$ не больше чем на
$W=2\,(2^{179}-1)+2Q+1$. Последняя единица ограждает
$2^hQ\,2^{-16300}/\ln 2$.

Для данного $A$ алгоритм Евклида подбирает один раз малые целые
$s,t$ с $s\equiv tU\pmod{2^h}$. Тогда остаток $tQV$ должен
отстоять от кратного $2^h$ не дальше $|s|(2^{179}-1)+|t|W$.
Если эта проверка оставляет кандидатов, две евклидовы суммы
целых частей точно считают число $P$, попавших в полосу.
Может остаться точное равенство $a^P=b^Q$ для нечётных частей
$a,b$ мантисс. Оно обнаруживается целыми степенями и корнями.
После восстановления масштабов его зазор равен нулю или имеет
модуль хотя бы $\ln(2)/Q>2^{-117}$. Точную ничью разрешает
существующая степенная ступень.
[Проверяющий код](../../research/m0-pow-comparison-20261117/midpoint_scale_grid.py),
[классификация ничьих](m0-pow-power-bounds-20261117.md).

При $h=512$ полный проход прямоугольника из $2^{14}\times2^{14}$
мантисс принял все **268 435 456** пар за 27,676 с на десяти
процессах. Это доказательство зазора для всего прямоугольника
при обоих знаках и всех допустимых `y`, а также при всех
допустимых двоичных масштабах. Прямой проход остальной
нормализованной сетки требует порядка $2^{105}$ проверок
пар. При измеренном темпе даже идеальное масштабирование на
140 процессов даёт порядок $10^{16}$ лет. Для полного охвата
нужен способ исключать большие множества обеих мантисс за раз.

```sh
python3 -B -S research/m0-pow-comparison-20261117/midpoint_scale_grid.py \
  0x19000000000000 0x19000000004000 0x2a000000000000 0x2a000000004000 --workers 10
```

## Наблюдения

Ранее на сервере отдельно перепроверены 156 610 112 блоков слоя
`q116`, без пропусков. Контрольная сумма манифеста блоков:
`ce3fcd4056eef826bc18e799ecf5122244c18934571ce2da27743f2babab503e`.
Этот результат не относится к остальным значениям `y`.

Два начальных локальных прохода с интервальным отсечением посетили
1 780 000 областей. Независимая проверка пересчитала 405 201
закрытый лист; на границе поиска остались 969 594 открытых листа
и 4 ссылки на один отложенный слой `q116`. Рост числа открытых
областей не даёт оценки времени завершения.

На 32 пробных блоках `128×128` около `x=3.125`, `m=5.25`,
`1<=y<2` аффинное исключение приняло 26 блоков. Это
проверка нового правила, не закрытие соответствующей бинады.
Перенос той же схемы разбиения на GPU не устраняет размер оставшейся
двумерной области. См. прежний [пилот полиномиальных сертификатов](m0-pow-remaining-20261118.md#переменная-середина-округления).

Запуск с четырёх корней на 24 серверных CPU-воркерах посетил
1 772 262 области за 156,58 секунды, включая запись контрольной
точки. Локальная перепроверка этой точки приняла 379 503 листа
и вернула `INCOMPLETE`: 1 013 252 открытых листа, отдельно четыре
отложенных ссылки на `q116`. На этой глубине до аффинных отсечений
поиск не дошёл. Контрольная точка допускает продолжение, но скорость
перебора не даёт практического срока для полного доказательства.

SHA-256 сжатой серверной контрольной точки:
`b51b8a5a4246b8f0d96c602f442090883c9e50b1152dda2dde399b7b162d4962`.
GPU в этом прогоне не использовался.
