# Кандидат точного компаратора `pow`: несколько остатков

Поиск сравнил пять схем с одинаковым бюджетом рабочих массивов.
Лучшая по охвату схема вычисляет остатки последовательно по
`B=2^w`, `B-1` и `B+1`. При 18 432 байтах рабочих массивов
она восстанавливает знак разности с гарантией на **88 415 битах**
вместо **49 152 бит**. Быстрая штатная ветка может остаться на
месте, расширение имеет смысл после её отказа. Прошивка не менялась.

| Модули | Биты остатка | Допустимое `N+k` при штатном зазоре | Верхняя граница разрядных произведений кандидата |
| --- | ---: | ---: | ---: |
| `B` | 49 152 | 65 450 | 9 814 860 |
| `B, B-1` | 73 727 | 90 025 | 21 146 970 |
| `B, B+1` | 73 696 | 89 994 | 21 132 621 |
| `B-1, B+1` | 73 695 | 89 993 | 26 565 838 |
| `B, B-1, B+1` | 88 415 | 104 713 | 26 764 039 |

Граница в последнем столбце считает только произведения 16×16,
не такты и не время полного вызова. Первый ряд относится к общей
экспериментальной реализации, не к отдельно оптимизированной
штатной [ветке остатка](m0-pow-residue-20261118.md).

## Доказательство знака и ограничения

Пусть `D=A-C` — разность целых степеней после приведения к
общему масштабу, `q=2^k`, а `min(A,C) <= 2^N`. Из уже
доказанного ограничения логарифмической ступени
`abs(y*ln(x)-ln(m)) < 2^-g` следует
`abs(ln(A/C)) < 2^(k-g)`. При `g>=k+2` отсюда
`abs(D) < 2^(N+1+k-g)`. Требуемая ширина:

```text
W = N+2+k-g
```

При `W<=1` разность нулевая. Во всех остальных случаях достаточно
совокупного модуля `P>=2^W`: целое из `(-P/2,P/2)`
восстанавливается однозначно. Нулевая разность выбирает чётного
соседа, а для отрицательного показателя знак сравнения произведения
обращается. Ни одного утверждения о знаке по слишком малому модулю
код не делает.

Для тройки `P=B*(B-1)*(B+1)`. Модули попарно взаимно просты:
в частности, общий делитель `B-1` и `B+1` делит 2 и нечётен.
Пусть `r0,r-,r+` — соответствующие остатки. Каноническое
представление разности имеет вид `r0+B*(a+(B-1)*t)`, где

```text
a = (r- - r0) mod (B-1)
b = (r0 - r+) mod (B+1)
t = (a-b)/2   mod (B+1)
```

Деление по нечётному модулю выполняется добавлением `B+1`
к нечётному представителю и сдвигом. Сравнивать с `P/2` можно
лексикографически: сначала `t` с `B/2`, затем `a` с `B/2-1`,
затем `r0` с `B/2`. Произведение шириной `3w` в памяти
не строится. Для пар формула сводится к двум координатам; у пары
нечётных модулей равенство целой нижней половине положительно.

Степени считают по одному модулю за раз тремя рабочими окнами.
Два уже вычисленных остатка сохраняются в двух дополнительных
окнах. Для `B+1` нужно по одному дополнительному 16-битному
слову в каждом окне для значения `B` (оно равно −1 по модулю).
При тройке помещается 1 842 слова на основной остаток:
`w=29 472`, `floor(log2(P))=3*w-1=88 415`.
Длинное произведение получается по столбцам; его старшие слова
сразу прибавляются или вычитаются из младших, так как `B≡±1`.
Ни одного окна двойной ширины не выделяется.

Если модуль принят, из логарифмического условия вытекает
`max(A,C)<2^(N+1)`. Неотрицательные масштабы, а в обратном случае
произведение, дают ту же верхнюю границу для каждой степени
отдельно. Перед `j` оставшимися квадратами логарифм текущей
неприведённой степени меньше `(N+1)/2^j` по основанию 2.
Остаток не больше исходного целого; особое значение `B` в кольце
`B+1` обрабатывается отрицанием. При принятых ширинах
получается не более 16 квадратов на нетривиальную степень;
короткое умножение на основание требует не больше четырёх слов.
Для `B` считаются только диагонали ниже `w`, для `B±1` —
все. Точная формула для треугольных сумм и максимально безопасный
размер переноса пересчитаны в
[числовом сертификате](../../dev/tools/certify_m0_pow_mixed_residue.py).

Автоматический выбор перебирает пять написанных схем для
вычисленной `W`, отбрасывает не помещающиеся, выбирает
наименьшую верхнюю границу разрядных произведений, при равенстве —
меньшую память. Это модель работы, а не оптимизатор времени ARM.

## Результаты проверок

- 41 506 исчерпывающих восстановлений знака при малом основании
  проверили формулы и оба края знакового интервала.
- Скомпилированный C++ прошёл 9 072 кольцевые операции и 4 308
  реконструкций знака с 16-битным словом. 640 границ `pow`,
  четыре точные ничьи и 11 принудительных пограничных случаев
  сверены с полными целыми степенями или направленным MPFR 4.2.2.
- На ARMv6-M закрыты в том числе запрошенные ширины 49 153,
  73 727 и 88 415. Обе реализации отказались при 88 416.
  Наблюдавшаяся нижняя запись относительно входного SP — 19 608
  байт для принятого вызова кандидата с включённой проверкой
  ABI. Это измеренный максимум на выбранных входах.
- На общем контрольном входе ширины 16 000 автоматическая
  ветка кандидата выполнила 5 057 311 инструкций, штатная —
  4 562 560. Для этого диапазона порт не показал преимущества.
- На первом принудительном входе за пределом штатной ветки
  (49 153 бита) выбранная тройка сделала 2 440 704 разрядных
  произведения и 70 248 866 инструкций ARM. На входе шириной
  88 415 бит выполнено 7 882 536 разрядных произведений; счётчик
  инструкций там не включался.

Принудительные входы используют ослабленный, отдельно доказанный
порог `g`, чтобы целочисленная ступень действительно получила
заданную ширину. Они не доказывают, что реальная цепочка пропускает
эти пары через штатный порог `g=16300`. Замеров на PicoCalc не было.
[Сырые данные хоста](m0-pow-mixed-residue-host-20261119.json),
[результаты ARM](m0-pow-mixed-residue-arm-20261119.json).

**Остаток задачи:** исключить отказ логарифмической ступени при
`N+k>104713` либо найти ещё один точный алгоритм для этого случая.
Для полного диапазона binary64 из ограничений на показатели
получается лишь грубое `N<2^127`. Ни охват, ни практическая
граница времени для всей области этим экспериментом не доказаны.
