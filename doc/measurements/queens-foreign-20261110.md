# Ускорение 8-QUEEN с сохранением алгоритма, 2026-11-10

Программа: [8 Queens optimized.m61](../../programs/examples/8%20Queens%20optimized.m61).
За основу взят предоставленный пользователем `8-QUEEN.m61`: из двух чужих
вариантов он быстрее и в прежнем аппаратном замере, и в ROM-проверке.
По указанию пользователя сохраняется именно его алгоритм.

Это алгоритм с флагом RB. Он отличается от буквального Pascal qbench,
поэтому результату `s = 876` здесь соответствие не заявляется. RB остался
флагом, его сбросы, увеличения и проверки сохранены, как в исходнике.

## Оптимизации

| Приём | Адреса | В чём выигрыш |
| --- | --- | --- |
| Указатель просмотра перенесён из RD в R0; `КИП0` совмещает уменьшение указателя и чтение ферзя | 21, 29 | Вместо отдельного уменьшения, записи указателя и косвенного чтения используются возможности штатной команды |
| Условие окончания просмотра проверяется как `1 − y ≥ 0`, то есть `y ≤ 1` | 22–26 | Один условный переход вместо отдельных проверок нуля и отрицательного `y − 1`; смысл и число проверок цикла сохранены |
| Результат `1 − y` повторно используется в диагональной проверке через стек | 22–24, 27–37 | Не нужно повторно читать y и заново вычислять расстояние между строками |

В начале итерации `y_old` ещё не уменьшен, поэтому вычисленное
`g = 1 − y_old` равно `−y_new`. После `КИП0` диагональная проверка
использует `x + g − abs(t) = x − y_new − abs(t)`. Исходник проверял на
ноль выражение `abs(t) − (x − y_new)`; знак выражения не влияет на
проверку равенства нулю. Разность координат `t` и порядок двух проверок
сохранены.

Все циклы остались циклами. Разворачивания, нулевого ограничителя,
отложенных записей массива, симметрий и новых отсечений нет. Каждое
изменение координаты сразу записывается в тот же элемент R1–R8.
Начальная очистка массива также сохранена: первые 21 байт кода идентичны.

Команды 62–65 восстанавливают исходное размещение служебных выходных
значений: вычисленный указатель копируется обратно в RD, R0 обнуляется.
Эти четыре команды входят в измерение. После `С/П` совпадают все 15
регистров памяти R0–RE, X и IP:

```text
R0 = 0
R1…R8 = 8, 4, 1, 3, 6, 2, 7, 5
R9 = RA = RE = 0
RB = 1
RC = 8
RD = 1
X = 0
IP = 67
```

## Проверка сохранения алгоритма

Оригинальный и оптимизированный машинные коды выполнены одним и тем же
независимым скалярным декодером ROM в стандартной памяти 105 шагов.
Наблюдатель только читает состояние и всегда возвращает управление ядру.
Обе трассы также сравнены с независимой моделью исходного алгоритма
на Python, включая продолжение просмотра после конфликта и поведение RB.

Полностью совпала последовательность из **5568 событий**:

| Событие | Количество |
| --- | ---: |
| Запись координаты ферзя, включая нулевые значения при откате | 540 |
| Изменение флага RB | 719 |
| Начальная установка указателя просмотра | 299 |
| Проверка условия цикла просмотра | 1735 |
| Проверка пары ферзей | 1436 |
| Проверка условия цикла отката | 476 |
| Проверка условия повтора по RB | 299 |
| Проверка условия окончания всего поиска | 64 |

Из присваиваний координат 484 имеют ненулевое значение — одинаково в обеих
версиях. Сравниваются сами события в исходном порядке, а не только их
количества и конечная расстановка. Первоначальный выбор новой точки
отправки не следует путать с сохранением алгоритма Pascal: эталоном этой
проверки является именно `8-QUEEN.m61`.

SHA-256 полной трассы:
`cc4846f9d6f81175be0a329a4e262da9f15abfcdd667c4283391c9fa5488b603`.

## Скорость

Считается полное исполнение до остановки, включая очистку массива,
операции с RB и восстановление выходных служебных регистров.
Шаг — вызов `core_61::step()`, **не миллисекунда**.

| Программа | Исполнено команд | Шагов ROM-ядра |
| --- | ---: | ---: |
| Оптимизированная 8-QUEEN | 26336 | **18968** |
| Исходная `8-QUEEN.m61` | 30288 | 22582 |
| `8-queen_anv (1).m61` | 38954 | 27537 |

По числу шагов ядра выигрыш составляет **16,00%** относительно выбранного
исходника и **31,12%** относительно Анварова. Аппаратный замер этой версии
в ms не выполнялся; пользователь согласовал проверку ROM.

## Воспроизведение


конечных регистров, X и IP и меньшего числа шагов ядра, чем у обеих
предоставленных исходных программ. Исходные байты включены в тест без
изменений; удалённые файлы из Downloads не требуются.
