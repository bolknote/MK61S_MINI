# Постраничная VM: повторная проверка Classic — 2026-10-18

Работа и доступ к Classic согласованы с задачей «Фокал». Её исправление
`c19c5f317` уже в `main` через `fe36d17c4`; дублирующих изменений прошивки
в этой сессии нет. Катастрофическое замедление первого поиска устранено,
результат повторяется. Возврат к историческим 25 с **не подтверждён**.

## Причина регрессии

Каждый RUN выгружал уже загруженный LANGVM, хотя байткод был готов.
В отдельной диагностике «Фокал» 536 RUN привели к 536 загрузкам APP:
34,933 с за 40 с наблюдения ушли в загрузку, включая вложенную распаковку.
Исправление сохраняет горячий исполнитель при передаче постраничного образа.
Холодная компиляция, смена APP, pin/busy и проверки media revision сохранены.

Дополнительно уже включены окно инструкций 128 байт, ограниченный кеш страниц
и дескрипторов образов. Полный исходник/байткод не требуется размещать в RAM.
Подробности исправления и отрицательные эксперименты с окнами 256 байт —
в [предыдущем отчёте](chess-flash-page-cache-20261017.md).

## Что именно измерено

Classic V3 UC1609, STM32F411CE, 96 МГц, NOR EF3013 512 КиБ,
PublicID `AEB505B6E0067623`. Resident — проверенный установленный **3AB3DD45**,
SHA-256 `0acbf033ecf553eed89f33220c5ba04c052394f98577090efbc4b90932c2e635`.
Пять языковых APP собраны из чистого git archive
**4f3fa7173b7b4861adc91d7dc6c5f63abbb9eb53**; от прежнего установленного
набора отличается только LANGVM. Чужие незакоммиченные изменения исключены.

Нативная прошивка этой базы собрана (**65DAB54B**) и прошла gates,
но **не установлена**: используется режим без записи firmware из-за известного
зависания перечисления DFU в macOS. Это проверка новых APP на фиксированном
исправленном resident, а не замер всей свежей нативной прошивки.
Появившийся во время замеров `d8b23c262` в измеренную базу не входит.

Те же 29 файлов Turochamp, книга выключена, уровень 2, глубина 8.
Отсчёт от OK при выборе чёрных до полной доски после хода. Загрузка файлов
и меню не включены. Обычные пять поисков выполнены без профилировщика.

## Отдельный профиль прогретого поиска

Шестой поиск с базовым DWT завершился за **60,034 с**, с тем же ходом,
420 узлами и SHA доски. Он не входит в обычную статистику.

| Точка | Вызовов | Время, с |
| --- | ---: | ---: |
| idle.main, включительно | 227013 | 5,492 |
| usb.service, вложен в idle.main | 227014 | 2,143 |
| flash.read | 4572 | 0,424 |
| zx0.decode | 0 | 0 |
| flash.write / verify / erase | 0 | 0 |

Вложенные времена не складываются. Физическое чтение NOR и повторная
распаковка не объясняют оставшиеся ~59 с. Базовый профиль не разделяет
M61/OPEN, подготовку VM, исполнение и CPU-затраты на попадания RAM-кеша;
приписывать весь остаток одному из этих путей пока нельзя.

На полностью прогретом интервале повторного запуска: 206523 обращения
к кешу, 206168 попаданий, 355 промахов, 0 инвалидирований — **99,83% попаданий**.
Этот интервал между снимками счётчиков включает меню и повторное открытие,
а не только отсчитываемый поиск.

Проверен дополнительный локальный кандидат: wide-байткод сейчас вызывает
полный `instruction_end()` даже для фиксированных инструкций. Отдельный
тест воспроизвёл лишние декодирования. Быстрый выбор ширины прошёл языковые
тесты, но не gate APP: +52 байта сверх 20480; вариант с упакованными
ширинами — +60, вынесенный общий helper — +52. **На плату эти варианты
не ставились, production-код не изменён, выигрыш скорости не измерен.**

Следующий обоснованный шаг — раздельный профиль M61/OPEN/подготовки и
скалярного wide-пути VM. Затем один компактный кандидат и парный A/B/A;
увеличивать кеш или сокращать опрос USB/клавиатуры по этим данным оснований нет.

## Лимиты, проверки и восстановление

- Потолок APP — прежние **20480 байт**; LANGVM **20468**, LANGIN **19180**.
- Прежний бюджет кеша Classic — **32768 байт вместе с метаданными**,
  payload 29696. Лимиты не менялись.
- Чистая нативная сборка: Flash 370272/524288, запас 154016; максимальный
  resident frame 1928 при лимите 3072; APP RAM effective 34880. Gates прошли,
  членов libgcc/libm/libstdc++/libc/libnosys в линковке нет.
- На устройстве минимальный остаток стека **8208 байт**, MPU layout=ok,
  CRASH none; CRC USB-кадров проверены.
- ASan/UBSan: BASIC/FOCAL, обе арифметики, reference/shipping VM,
  образы >64 КиБ, INPUT со сменой APP, длинные операнды, ошибки I/O — PASS.
- Настоящий C9: инвалидирование, reboot, torn writes, границы страниц,
  replay горячих страниц 7540 → 11 физических чтений — PASS.
- APP flow: 20 горячих передач сохраняют APP, холодное вытеснение и отказ
  при pin — PASS. Офлайн-проверки HIL guard/оракула/восстановления — PASS.

На выходе восстановлены все **24 исходных файла и 2 каталога**, прежние

Записей внутренней Flash — **0**, firmware CRC valid, CDC закрыт.
