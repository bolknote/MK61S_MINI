# RP2040 math follow-up, 2026-11-16

## Exact pow rounding

Commit `8cd7fe67` strips powers of two from the input significand before
building the integer power. For an exponent `y = p/q` in lowest terms and
an adjacent rounding boundary `M * 2^t`, the comparison then uses the odd
coefficient of the base and the odd midpoint coefficient `M`. For positive
`p` the two coefficient powers each have a separate 6,912-bit capacity.
For negative `p` their product must fit. Each multiplication checks its
capacity before any result is accepted.

For any positive finite binary64 base and any initial search hint, the exact
stage now covers 1,041 signed exponents. The sufficient bounds are
`max(53*p, 54*q) <= 6912` for positive `p` and
`53*|p| + 54*q <= 6912` for negative `p`. The former domain contained 912
signed exponents. Narrower coefficients extend the domain further, including
`1.5^4096` and subnormal boundaries with denominators of 512 and 4,096.
The runtime stores no new table or global state.

The [integer range certificate](../../dev/tools/certify_m0_pow_exact_small.py)
checks the scale limits, the coefficient capacity, and the midpoint search.
The [host test](../../tests/m0_pow_exact_small_host_self_test.py) checks 5,089
pairs and 21,496 calls with search hints against directed MPFR 4.2.2, with
zero mismatches. It covers every exponent in the arbitrary-base bound and
additional input-dependent cases. The [ARM test](../../tests/m0_pow_exact_small_arm_self_test.py)
also checks the exact midpoint search, saved registers, stack and SIO divider
state. Its 207 calls used up to 2,892 bytes of callee stack. A separate
test-only build forced the public CORE-MATH fallback through the 1,024-bit
stage and exact comparison on 35 cases. All passed and the largest observed
stack depth was 5,936 bytes.

The linked Pico H math was checked against MPFR on 813,199 `pow`, `exp`,
`sin` and `cos` cases. The final image differs from the ELF's tested Flash
contents only at the stored build ID and integrity CRC. On the final
`4D133820` image, a further public `pow` audit matched MPFR on 261 archived
hard cases and 24,501 exponent values generated near binary64 rounding
boundaries. The audit observed no calls to the final rescue function.
The generic Cortex-M0 and Cortex-M4 control objects matched byte for byte.

The general `pow` decision remains open when both the 1,024-bit enclosure
and the exact comparison cannot decide. The final trap
remains in [the rescue function](../../code/native_eabi_m0_cr.cpp#L95).
The known precision bound for two independent logarithms is too large for
the Pico H memory and watchdog budgets. The public CORE-MATH worst-case
search covers a subset of the exponent domain. See the
[November 14 analysis](m0-math-followup-20261114.md#host-results) and the
[CORE-MATH worst-case scope](https://core-math.gitlabpages.inria.fr/worst.html).

## Pico H at 125 MHz

The sealed PicoCalc image from `main` at `8cd7fe67` was built with Pico SDK
2.2.0 and ARM GCC 14.2.1. Its ID is `4D133820` and its Flash CRC is
`78AA379D`. The full 1,803,876-byte image matched the device readback.
The first boot status reported that the keyboard was still initializing.
The measurements started once it reported ready, on the same installed image.

The [27-group replay](m0-math-rom-20261116.csv) uses the November 14 inputs
and the factory RP2040 v3 ROM as the reference for `exp`, `sin` and `cos`.
Each group uses twelve calibrated batches with alternating call order, reduced
to six paired estimates. All six differences favor the project implementation
in every group. Both implementations matched MPFR for all 2,510 return values.

| Workload | Project, µs/call | ROM, µs/call | November 14 control, µs/call |
| --- | ---: | ---: | ---: |
| 13 former slow `exp` cases | 5.389–5.497 | 6.056–6.880 | 11.763–12.067 |
| Broad `exp`, 512 inputs in [−8, 8] | 5.995 | 6.448 | 5.469 |
| Broad `exp`, 512 inputs in [−700, 700] | 5.887 | 6.421 | 5.397 |
| Broad `cos`, 96 inputs | 12.299 | 12.945 | 13.320 |

The broad `exp` groups are still 9.6% and 9.1% slower than the project
control from November 14. The ROM comparison is paired within the same
session, while the project control comes from that earlier installation.

The separate tiny-exponent `pow` group ran the 196
[historical input pairs](../../research/m0-pow-boundary-20261023/exact-space/tiny-profile.json)
through both the public `compact_math::pow` and `mk61_m0_cr_pow` in the same
image. The order-balanced estimates were 2.335 and 1,253.702 µs/call
respectively. All 392 return values matched MPFR. The six paired differences
ranged from −1,253.809 to −1,250.564 µs/call. The raw v5 report has SHA-256
`31a871b34349725906f304cf94a31ec84652937ed474fc06c82bd397112cadef`.

The image remains installed. Both temporary SD directories were removed,
calculator state matched before and after each benchmark, and CDC was closed.
The first Flash readback is in `.build/m0-math-20261116/hardware-01/`. The
raw reports and the final session record are in
`.build/m0-math-20261116/hardware-02/`.
