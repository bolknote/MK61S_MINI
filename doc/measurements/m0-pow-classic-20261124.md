# Совместимость и скорость pow на RP2040

Эталон для публичного `pow` на PicoCalc — результат System API прошивки Classic STM32F411 `CDB065DC` в режиме `BINARY64`. Сравниваются все 64 бита, включая знак нуля и содержимое NaN. Например, для двоичного представления `1.2` и показателя `3` обе платы должны получить `3ffba5e353f7ced9`. Classic выполняет два отдельных умножения с округлением. Точно округлённая математическая степень в этом примере имеет младший байт `d8`.

## Выполнение

Точные показатели 0, ±1, 2, 3, 4 и положительный квадратный корень обрабатывает короткая входная функция ARMv6-M. Для обычной степени при `1/16 ≤ |x| < 16` и `2⁻¹² ≤ |y| < 32` ядро использует имеющиеся таблицы логарифма и экспоненты и расширяет интервал на ошибку вычислений Classic. Оно возвращает ответ, когда весь интервал округляется в одно число. В остальных случаях RP2040 выполняет общий с Classic код разложения логарифма и восстановления степени двойки. Восстановление имеет собственную короткую проверку. На неоднозначной границе оно выполняет те же 15 шагов полинома Q62, что и Classic. Субнормальный результат получает окончательный масштаб перед округлением. Публичный вызов обходится без 16 384-битного компаратора.

Рациональная проверка охватывает все старшие слова нормализованной мантиссы. Она ограничивает ошибку полинома логарифма на целых интервалах и учитывает округление промежуточных операций Classic. В обычной области ошибка логарифма с умножением составляет меньше `3·|y|` единиц Q64, а добавка от экспоненты меньше 20. Для отдельной проверки уже редуцированного аргумента достаточно 28 единиц Q64. Одна единица Q64 равна `2⁻⁶⁴`. [Проверка для Classic](../../dev/tools/certify_m0_pow_classic.py) · [Проверка табличных ядер](../../dev/tools/certify_m0_pow_fast.py)

## Проверка прошивок

ARM-эмулятор вызвал штатные сервисы PicoCalc и Classic на 135 483 парах. Получено ноль побитовых расхождений. В набор входят 32 768 произвольных двоичных пар, по 32 768 обычных степеней, входов около единицы и входов около пределов диапазона. Отдельно проверены 576 сочетаний особых значений, 2 440 десятичных пар, 440 библиотечных векторов, 28 случаев около степеней двойки и 927 пар около границ ветвления и округления. [Сравнительный тест](../../tests/m0_pow_classic_self_test.py)

На 24 входах аппаратной матрицы эмулятор насчитал 22 017 инструкций через публичный сервис PicoCalc и 60 399 через сервис Classic. У PicoCalc меньше инструкций на 18 из 24 входов. В двух вариантах, собранных для одной и той же ARMv6-M и исполняемых из SRAM, счётчики составили 21 518 у нового ядра и 123 234 у прямого переноса эталона. Новое ядро выполнило меньше инструкций на каждом из 24 входов. [Все пары и счётчики](m0-pow-classic-20261124.json)

| Вход | PicoCalc, инструкции сервиса | Classic, инструкции сервиса |

| `1.3 ^ 0.7` | 1 373 | 5 555 |
| `0.7 ^ 1.3` | 1 424 | 5 844 |
| `1.2 ^ 3` | 269 | 160 |

## Аппаратный прогон

На PicoCalc при 125 МГц новое ядро `pow` в SRAM заняло в среднем **10,183 мкс**. На Classic STM32F411 при 96 МГц публичный вызов `pow` из установленной прошивки `CDB065DC` занял **42,338 мкс**. Выигрыш PicoCalc составил **4,16 раза**. Прямой перенос эталона в ту же SRAM PicoCalc занял **57,836 мкс**, что даёт ускорение **5,68 раза** на одном процессоре. Новое ядро быстрее обеих реализаций на каждом из 24 входов. Все три результата для каждой пары совпали побитово.

| Вход | PicoCalc, мкс | Classic, мкс | Прямой перенос на PicoCalc, мкс |
|---|---:|---:|---:|
| `1.3 ^ 0.7` | 15,032 | 88,091 | 104,112 |
| `1.2 ^ 3` | 2,552 | 2,704 | 3,656 |
| `2 ^ −1074.5` | 16,968 | 64,903 | 105,416 |
| `(1 − 2⁻⁵³) ^ 2⁵²` | 55,272 | 70,716 | 92,360 |

Для каждой пары из медианы семи серий по 128 вызовов вычтена медиана контрольного цикла. Разность в тактах делится на `128 × 125` для PicoCalc и на `128 × 96` для Classic, что даёт время в микросекундах на вызов. Все 24 входа имеют одинаковый вес при расчёте среднего. 55,272 мкс — наибольшее измеренное время ядра PicoCalc в этой матрице. Верхняя граница времени для всех `binary64` потребовала бы отдельной оценки тактов. [Счётчики для каждой пары](m0-pow-classic-20261124.json)

На PicoCalc подтверждены UID и flash ID `E6657CD423721C35` по адресу USB `0x01130000`. Сторожевой таймер вернул штатную прошивку `305C81A5/250488DD`. После загрузки подтверждены валидный CRC и `SERVICE=CLOSED`. Время публичного вызова из Flash на PicoCalc потребует замера с установленной новой прошивкой.

На Classic `AEB505B6E0067623` исходная прошивка `076CC619` заменена на `CDB065DC`. До запуска все 407 100 записанных байт сверены чтением через DFU. Запущенная плата подтвердила UID и CRC `CDB065DC` до и после замера. Приложение проверило частоту DWT по системным миллисекундам, вызвало публичный System API из Flash и выдало 400 байт показаний. После чтения результата тестовые файлы удалены, на Classic оставлена `CDB065DC`. [Протокол PicoCalc с переводами строк LF](m0-pow-classic-20261124/pico-cdc.txt) · [Показания DWT Classic](m0-pow-classic-20261124/classic-dwt.bin)

Исходники пакета находятся в [каталоге аппаратного теста](../../tests/fixtures/pow_classic_bench). Для Pico используется CMake с Pico SDK 2.2.0 и типом образа `no_flash`. Для Classic тот же `bench.cpp` собирается через `tools/apps/portable/build_portable_app.py --target stm32 --name POWCLASS --shared-runtime`. Команда `prepare` сверяет матрицы в ELF обоих тестов, сегменты прошивки Classic с BIN и ответы четырёх ARM-путей. Подкоманды `pico` и `classic` выполняются в выделенном окне. Команда `check` сравнивает записи аппаратных счётчиков. [Подготовка и оценка](../../tests/m0_pow_classic_benchmark.py) · [Аппаратный запуск](../../tests/hil_pow_classic.py)

Для повторной проверки сохранённого замера из корня репозитория достаточно Python 3.

```sh
python3 tests/m0_pow_classic_benchmark.py check \
  --receipt doc/measurements/m0-pow-classic-20261124.json \
  --pico-log doc/measurements/m0-pow-classic-20261124/pico-cdc.txt \
  --classic-bin doc/measurements/m0-pow-classic-20261124/classic-dwt.bin
```
