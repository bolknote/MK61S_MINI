# F401 six-bit AND_AMK storage, 2026-10-31

F401 packs each nine-column AND_AMK body into seven Flash bytes. Values 0..59 retain their codes; conditional values 60/62/64/66 map reversibly to 60..63 and are expanded before L-latch selection. All 128 bodies retain distinct addresses. Each table is 897 bytes, including a guard byte for the last bounded read, instead of 1152. Compile-time roundtrips check all 3456 logical values; unrepresentable literals reject initialization.

Historical ROM rows, 16-byte RAM bodies, padding and logical 16-byte snapshot offsets remain unchanged. Reversing the enumerated private storage/access substitutions reproduces the entire prior core source, including Ms, BBS, context helpers and settings. F411/Pico tokens match in 20 core and two graphics cases; 54 F401xC/xE syntax cases and six invalid-ROM mutants pass their respective checks. No public ABI, feature, math backend, release flag or budget changes.

Runtime uses the existing bounded little-endian primitive; compile-time evaluation uses byte arithmetic. Columns 0..8 read two bytes at offsets 0..6; the final guard bounds the last read. RAM uses raw bytes. Resident Flash/SRAM body addresses are distinguished by bit 29 on ARM, or active stride on HOST. The separate F401-only LINE noinline attribute leaves the complete primitive body unchanged.

All nine native F401 cases default to HOT_TABLES 2 / PACKED 0 / MERGED 1 / PREDECODED 0; five product cases use native hot paths, four capability cases do not.
