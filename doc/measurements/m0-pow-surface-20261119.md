# Пилот для переменной середины `pow`, 19 ноября 2026

Крупное разбиение этим методом не подтверждено. Раздельные
четвёрки блоков при положительном и при отрицательном показателе
полностью перепроверены для ширины `2^20` по обеим осям.
Проверка охватывает **все** binary64-показатели в бинаде
`1 <= abs(y) < 2`, включая чётные и нечётные числители,
для основания и середины из проверенного блока. При большей
ширине проверенные настройки новых сертификатов не дали.
Общедоменный запуск и GPU не использовались.

## Что проверяется

В нормальных бинадах основания и середины их приращения имеют вид
`x=x0*(1+a*u)`, `m=m0*(1+b*v)`, где `u=I/H`, `v=J/H`,
а `I,J` целые в полуоткрытом блоке. Обозначим через
`F=2^52*abs(ln(m))/abs(ln(x))` точный прообраз середины на сетке
показателя. Корректность сертификата сводится к отсутствию целого
`p=2^52*abs(y)` в полосе
`abs(p-F) <= 2^52*2^-900/abs(ln(x))`. Знак, при котором
`y*ln(x)` и `ln(m)` противоположны, проверяется отдельно
через нижнюю границу логарифма основания.

Решётка ранга три подбирает целочисленную замену координат
`L = T*(I,J,p-p0)` с определителем ±1. Новый базис состоит
из произведений `binom(L_i,k_i)`. Это многочлены с целыми
значениями в целых точках, в том числе при отрицательных `L_i`.
Поиск коротких комбинаций использует LLL; одна настройка
оптимизирует только изменение многочлена, без постоянного члена.
Идея поиска целых точек около аналитического графика восходит к
[работе Стеле, Лефевра и Циммермана](https://research-management.mq.edu.au/ws/portalfiles/portal/16915442/mq-8829-Publisher%20version%20%28open%20access%29.pdf).

Отдельная программа не принимает результат LLL на доверии.
Она пересчитывает ряд на двоичной целочисленной сетке. Для
комплексного бидиска используется рациональная оценка остатка
после линейных членов частного логарифмов; оценка Коши ограничивает
хвост по суммарной степени. Вертикальный сдвиг `p-F` проверяется
отдельно. Полученный интервал либо не содержит целого, либо
содержит только ноль для набора многочленов. Во втором случае
проверяются все классы остатков трёх координат по степени двойки,
без предположения о чётности `p`. Общий нуль по модулю 2 запрещён.
Элементарная граница ширины штатного 1024-битного интервала
проверяется прежним точным расчётом.

## Результаты

Положительный контроль: `x ∈ [3,3.25)`, `m ∈ [5,5.5)`.
Отрицательный: то же основание и `m ∈ [5/32,3/16)`.
Случайные центры фиксированы `seed=2040`, поэтому наборы разных
ширин с одинаковым числом проб берутся около одних и тех же
точек. Время в таблице — медиана CPU на один блок в первом
прогоне, не время с учётом параллельности.

| Ширина | Степень | Вариант | Принято | CPU, с |
| ---: | ---: | --- | ---: | ---: |
| `2^20` | 6 | Без поворота, положительный | 4/4 | 3,06 |
| `2^20` | 6 | С поворотом, положительный | 4/4 | 3,53 |
| `2^20` | 6 | С поворотом, отрицательный | 4/4 | 3,38 |
| `2^20` | 5 | С поворотом | 0/4 | 0,64 |
| `2^21` | 7 | Свободный центр | 0/4 | 13,15 |
| `2^21` | 7 | `delta=0.99`; одна короткая строка без исключения | 0/4 | 17,38 |
| `2^22` | 6 | С поворотом | 0/4 | 3,28 |
| `2^22` | 8 | Свободный центр, `delta=0.97` | 0/2 | 73,62 |
| `2^23` | 7 | С поворотом | 0/4 | 12,99 |
| `2^24` | 7 | 128 рабочих бит | 0/4 | 11,94 |
| `2^24` | 7 | 192 рабочих бита | 0/2 | 34,87 |
| `2^28` | 8 | С поворотом | 0/4 | 54,21 |
| `2^32` | 8 | С поворотом | 0/4 | 77,41 |
| `2^37` | 8 | С поворотом, проверка порога масштаба | 0/1 | 102,10 |

Для принятых блоков проверка стоила **0,24–0,25 с CPU** с
целым умножителем FLINT или **11–13 с CPU** со стандартным Python
без FLINT. Один блок охватывает `2^40` пар «основание — середина»;
знаковое округление и тайминг прошивки этим пилотом не измерялись.

В положительном контрольном прямоугольнике по `2^49` значений
на ось. Равномерное разбиение требует `2^(98-2*w)` сертификатов
при ширине `2^w`, то есть **`2^58`** при проверенной ширине.
Даже условные (10^9) полностью проверенных блоков в секунду
дали бы **9,13 года на один прямоугольник**. При наблюдавшейся
цене 3,78 CPU-с на блок и идеальной загрузке 192 воркеров для
недели потребовалась бы ширина не меньше `2^37`. Это критерий
масштаба данного разбиения, не нижняя граница для других методов.
В самой пробе `2^37` из 102,10 CPU-с **97,97 с** ушли на
редукцию целой решётки, и доказательство не получено. Ускорение
проверки уже найденных сертификатов не устраняет этот лимит.

## Воспроизведение

```sh
tools_dir=research/m0-pow-comparison-20261117
python3 -B -S "$tools_dir/midpoint_surface_rotated.py" verify \
  "$tools_dir/midpoint-surface-rotated-positive.json.gz" --workers 4
python3 -B -S "$tools_dir/midpoint_surface_rotated.py" verify \
  "$tools_dir/midpoint-surface-rotated-negative.json.gz" --workers 4
python3 -B -S tests/m0_pow_surface_proof_self_test.py
```

Для повторного поиска нужно Python-FLINT 0.9.0. Команда `sample`
принимает `--width`, `--degree`, `--samples`, `--workers`,
`--plain`, `--free-center`, `--inverse`, `--flint-products` и
сохраняет отчёт в новый файл `--output`. Перепроверка, у которой
не хватает сертификатов для хотя бы одного блока, возвращает
`PILOT_INCOMPLETE` и код 2. Даже `PILOT_VERIFIED` относится
только к явно заданной выборке. Код прошивки не менялся.

SHA-256 сырых сертификатов двух полностью перепроверенных запусков:

- положительный: `2b10ac4e057e1d31a06f835f21a5861a453e7a8749af00d63b074d4cc446f78b`;
- отрицательный: `39ac17619efda21b31b653dfcece10cde988efe71120883508c3ce8720578cfb`.
