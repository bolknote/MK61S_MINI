# Mixed cache VM проверка PONG и задержек

Это исторический этап wire9. Актуальная совместная квалификация графики,
RAM/MPU и SIMD, а также итоговая политика mixed24 вне Classic и raw32
на Classic описаны в [отчёте общей main](vm-cache-joint-20261015.md).
Числа ниже относятся только к базе wire9, не к текущему продукту.

## Решение

Полный аппаратный A/B/A на Classic прошёл для двух наборов больших
BASIC/FOCAL-программ. Mixed включён по умолчанию для overlay VM с ненулевым
существующим RAM-кешем. Размер кеша остаётся **24576 байт**, F401 без кеша
сохраняет прежний путь. Переопределение `MK61_LANGUAGE_VM_CACHE_MIXED=0`
оставлено для контроля. Ресурсные ограничения не ослаблялись.

На повторяющемся наборе время диагностической серии относительно среднего контролей уменьшилось
с **90,365 до 24,721 с**. На плохо сжимаемом наборе без попаданий оно выросло
с **65,735 до 67,708 с**, на **3,00%**. Худший холодный интервал USB во всех
проверках вырос с **887,1 до 916,6 мс**, на **29,5 мс**. Это принятый компромисс,
а не утверждение об отсутствии замедлений. Секундный предел PONG соблюдён;
все INPUT/ESC, CRC и проверки памяти прошли.

База — `05638655da3dbd29bcc776dcc5f9e266b4932efd`, wire v9, APP ABI 6.
Это продолжение [предыдущей проверки задержек](vm-cache-latency-20261015.md),
а не перенос чисел wire v8. Подробные числа и SHA — в
[машиночитаемом отчёте](vm-cache-rollout-20261015.json).

Default изменён только в рабочем дереве этого этапа, без commit/merge.
После замеров в параллельной main появилась графика (`a6d45ecb0`, wire10,
request9). Её совместная сборка с новым default этим A/B/A не квалифицирована;
при интеграции нужно сохранить новые ширины, ABI и номера графических opcodes.

## Причина ложного таймаута PONG

В драйвере `end_measurement()` запрещал новые измеряемые запросы, но разрешал
служебный PING до получения последнего измеряемого PONG. Через 700 мс в RX
могли оказаться два PING. У firmware один слот отложенного управляющего
ответа: `readRx()` способен обработать оба запроса до `scheduleTx()`,
и второй PONG заменяет первый. Драйвер затем ждал ответ, уже вытесненный
его собственным служебным запросом.

Регрессия со старым драйвером воспроизводит этот отказ при обслуживании
запросов через 850 мс, то есть раньше секундного предела. Исправленный
драйвер принимает ответы за 200/700/850/990 мс и отклоняет настоящий ответ
после секунды. Теперь ровно один запрос ожидает ответа: служебный PONG
дожидаются перед первым измерением, измеряемый — перед возвратом к keepalive.
Nonce `0x0061` зарезервирован только для служебного запроса. Проверки CRC,
nonce и **порог 1 с не изменены**.

Отрицательный аппаратный контроль намеренно послал два PING одним OUT.
Пришёл только второй PONG `6100`, первый отсутствовал, хотя максимальный
интервал USB service был **1,022 мс**. Это отдельно отмеченный ожидаемый отказ,
не успешный тест задержки. В последующих обычных фазах все **7792** измеряемых
PING получили свои PONG. Профиль и трасса пакетов сохранены.

Первый исторический отказ wire v8 не имел отказной трассы пакетов, поэтому
его точную причину ретроспективно доказать нельзя. Теперь отдельно
воспроизведены гонка драйвера и вытеснение ответа реальной прошивкой.
Исправление обмена находится на хосте и не добавляет Flash/RAM устройству.

## Условия аппаратного сравнения

Classic `AEB505B6E0067623`, USB `2068336B4731`, F411 96 МГц,
classic-v3-uc1609, arithmetic 0, активный USB Screen. Raw, mixed и обратный
raw используют одни и те же пять APP и исходники. Диагностические флаги:
`MK61_DWT_SERVICE_GAPS=1`, `MK61_DWT_RUNTIME_DETAIL=1`; различие вариантов —
только `MK61_LANGUAGE_VM_CACHE_MIXED=0/1`.

В каждом корпусе чередуются 8 BASIC и 8 FOCAL. Прогрев — 32 вызова,
каждый из двух повторов — 128. Обычные исходники занимают BASIC 1749..3366,
FOCAL 868..1435 байт; плохо сжимаемые — 3552 и 1504 соответственно.
Штатные пределы BASIC 3584, FOCAL и M61 1536 не менялись. Строковые ресурсы
плохо сжимаемого набора состоят из детерминированных случайных символов.

Проверено 1728 модульных вызовов и ещё 24 интерактивных сценария.
INPUT получает 1/OK только после появления запроса; ESC посылается внутри
исполняемого длинного цикла, после RUN ESCB/ESCF. Подтверждение завершения
FOCAL привязано к ожидаемой метке полного CRC-проверенного кадра. Сценарии
временно используют установленный Turochamp.FMK через scoped font session;
игра и её алгоритм не менялись. В пакетных фазах проверены **3657** полных
кадров; интерактивные кадры также проходят тот же CRC-парсер.

GAP измеряет интервал между началами реальных вызовов: scan, выборка GPIO,
повторная выборка каждой из пяти строк и USB service. Это не измерение от
физического фронта клавиши до события debounce. Клавиши INPUT/ESC виртуальные;
время до терминала включает host pacing и загрузку/подтверждение finish APP.
Максимальный зафиксированный host-poll gap — 54,3 мс; PONG RTT не заменяет GAP.

Корпуса имеют независимый холодный старт: перед заменой owned-файлов второго
корпуса одинаково для A/B/A выполняется warm reset вне профиля. В предыдущем
прогоне загрузка fixture после VM/INPUT/ESC получила `PUT_BUSY`; fsput требует
свободной рабочей области и staging. Этот незавершённый прогон сохранён,
восстановление прошло, после исправления подготовки A/B/A повторён целиком.
Смена рабочего набора внутри каждого корпуса проверяется 16 модулями и
последующими INPUT/ESC-программами.

## Результаты двух повторов

Интервалы ниже — максимумы в двух тёплых проходах, не во всём запуске.

| Корпус и вариант | Время двух проходов, с | Hits / misses на проход | Строка клавиатуры, мс | USB service, мс | PONG, мс |
| --- | ---: | ---: | ---: | ---: | ---: |
| Обычный raw A | 90,430 / 90,360 | 0 / 128 | 927,8 | 830,2 | 829,7 |
| Обычный mixed B | 24,771 / 24,672 | 128 / 0 | 162,8 | 118,4 | 96,8 |
| Обычный raw A повторно | 90,350 / 90,320 | 0 / 128 | 928,8 | 830,3 | 829,0 |
| Ресурсы raw A | 65,704 / 65,705 | 0 / 128 | 611,9 | 518,5 | 514,3 |
| Ресурсы mixed B | 67,724 / 67,691 | 0 / 128 | 643,7 | 548,4 | 544,4 |
| Ресурсы raw A повторно | 65,769 / 65,764 | 0 / 128 | 612,7 | 518,7 | 519,1 |

Дрейф контролей: −0,066% у обычного и +0,095% у ресурсного набора.
Снижение времени обычного набора — **72,64%** относительно среднего контролей;
это синтетический профиль с приборами, **не ускорение chess и не время
обычной production-прошивки**.

У mixed на обычном проходе 128 pack и 128 thaw. На ресурсном — 760 попыток
pack при 128 промахах, без thaw; упаковка суммарно занимает около 1,84 с.
Максимальная отдельная попытка — 3,707 мс. Повторные безрезультатные попытки
объясняют заметную часть неблагоприятного случая и остаются целью оптимизации.

Холодные загрузки и дополнительные INPUT/ESC меняют картину максимумов:

| Все измеренные фазы варианта | Строка клавиатуры, мс | USB service, мс | PONG, мс |
| --- | ---: | ---: | ---: |
| Raw A | 928,1 | 886,7 | 886,9 |
| Mixed B | 924,1 | 916,6 | 894,3 |
| Raw A повторно | 928,8 | 887,1 | 864,7 |

Mixed уменьшает число длинных пауз на прогретом повторяющемся наборе,
но не устраняет холодные паузы около 0,9 с и может удлинить отдельную паузу
попытками упаковки. Во всех 42 окнах `KBD overflow=0`, cache dropped=0,
нет ошибок CRC/nonce, записи и стирания NOR по профилю — 0. Записи установки
fixture и восстановления находятся вне этих окон.

## Ресурсы и локальные проверки

| Обычная сборка без новых probes | Flash, байт | Static RAM, байт | Максимальный native frame |
| --- | ---: | ---: | ---: |
| Raw arithmetic 0 | 360564 | 26880 | 1928 |
| Mixed default arithmetic 0 | 362796 | 26880 | 1928 |
| Mixed default arithmetic 1 | 353136 | 26880 | 1928 |

Цена mixed на сопоставимой arithmetic-0 базе — **2232 Flash, 0 static RAM**.
Каталог и payload кеша вместе остаются 24576 байт: metadata 688, payload 23888.
Рабочий prefix заимствуется, отдельный словарь в RAM не добавляется.
Новые GAP probes по умолчанию выключены. Свежие сборки с неявным default
побайтно совпали с обычными сборками с явным `mixed=1` в обеих арифметиках.
Проверки CRC, APP RAM, runtime archives и foreground frames 80/608 прошли.

Диагностические сборки имеют 28824 байта static RAM в обоих вариантах.
Watermark после подготовки и всех фаз обычного корпуса: raw 9472/9464,
mixed 9376 байт остатка; ресурсного: raw 6608/6608, mixed 6520.
Наблюдаемый дополнительный пик стека — **88..96 байт**, не нулевой расход
и не доказанный worst case. Резерв 16384 байта, guard и frame-бюджеты сохранены.

Пять общих System APP соответствуют wire9. Hot LANGVM занимает 16628 байт
при уже принятом в базовом main бюджете 18432; этот этап бюджет не меняет
(см. [данные квалификации integer spans](vm-integer-spans-20261015.json)).
Loader APP ceiling 20480, ограничения исходников, квоты ФС и Flash headroom
не изменены. При этом NOR-счётчики выше относятся только к измеренным фазам,
а не к произвольным первым запускам файлового кеша.

ASan/UBSan: реальный mixed/raw cache и codec, pins/rollback/OOM/CRC,
файловый кеш/INPUT/ESC/USB 0/1 и обе арифметики — PASS. Оба корпуса прошли
72 точных host-исполнения в сумме, C++ cache replay проверил байты, canary
и сохранность значений. DWT gap tests покрывают first sample, wrap, reset,
stop, saturation и отсутствие вычислений у отключённых probes.
Клавиатура, USB protocol/virtual keys/surface и терминал — PASS.

Полный `tests/run_all_tests.sh`, включая теперь обязательный mixed-cache suite,
завершился **exit 0** в отдельном TMPDIR. Исправлены три устаревшие проверки
базовой main: точный список семи уже tracked tools, ожидание собственного
STM32 startup вместо SDK startup и актуальные catalog flavors integer spans.
Неизвестные tools и SDK startup по-прежнему запрещены; продуктовые сборщики
и ресурсные лимиты ради прохождения этих тестов не менялись.

Полная F401 release/capability матрица — **9/9 PASS**, с прежними бюджетами
Flash/RAM/стека и APP-гейтами. Матрица собрана с явным mixed=1, который
не создаёт кеш при image-cache=0. После включения default компилятор отдельно
проверил все девять реальных контекстов без override: image-cache=0,
mixed=0, file-cache=0. Profile-тесты также проверяют F411 с кешем,
без кеша и явный raw override. Cross-MCU WS0010 RAM comparison не запускался.
