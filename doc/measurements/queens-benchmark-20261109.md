# Архивный эксперимент qbench для МК-61

**Этот вариант не используется при текущем требовании сохранить структуру
циклов.** В нём есть разворачивание и нулевой ограничитель. После уточнения
пользователя эталоном выбран предоставленный `8-QUEEN.m61`;
[актуальная оптимизация с тем же алгоритмом](queens-foreign-20261110.md)
находится в [8 Queens optimized.m61](../../programs/examples/8%20Queens%20optimized.m61).

Программа: [8 Queens benchmark.m61](../../programs/examples/8%20Queens%20benchmark.m61).
Основа — исходный Pascal из [статьи «Benchmark 8 ферзей»](https://pmk.arbinada.com/category/00030.html),
также присланный пользователем. Тест ищет первое решение и выводит число
попыток `s`. В исходнике присутствуют `s := 0`, `inc(s)` и `writeln(s)`;
счётчик входит в сравниваемую работу.

## Обычные выходные значения

После загрузки M61 программа запускается сама. При ручном вводе:
В/0, С/П. После остановки:

```text
R1…R8 = 8, 4, 1, 3, 6, 2, 7, 5
RA = X = 876
R9 = 8
R0 = 1
IP = 98
```

Координаты представлены обычными целыми числами. Счётчик непосредственно
растёт в RA через `ИПA 1 + ПA`, начиная с нуля. Последний ферзь записывается
в R8 перед `С/П`, затем в X читается RA. Весь этот код, включая
инициализацию, подсчёт попыток и окончательную запись результата, входит
в измеренное исполнение. Внешнего пересчёта регистров не требуется.

## Что сохранено

Каждый новый ферзь начинает с горизонтали 8; при конфликте номер уменьшается
ровно на единицу. Предыдущие ферзи проверяются в исходном порядке: сначала
совпадение горизонталей, затем диагональ. Сохранены откат при нуле,
`inc(s)` при каждой попытке и остановка при `x = 8`.

На исполняющем ROM-ядре проверено совпадение всей последовательности событий
с независимым буквальным переводом Pascal:

| Событие | Количество |
| --- | ---: |
| Начало попытки: `s`, `x`, вся активная расстановка | 876 |
| Проверка пары: `x`, `y`, обе координаты | 2205 |
| Присваивание `a[x]`, включая нулевые значения при откате | 981 |

Сравниваются сами упорядоченные события, а не только количества и конечная
расстановка. Последующие события проверяют также исходы проверок и все
переходы между кандидатами. SHA-256 последовательности из 4062 событий:
`b039b084fb20272af6a8a616fd659de86cc9506cedfbbe269b56b722bf9c4bd7`.

## Машинные оптимизации

Использованы штатные команды МК-61, 98 ячеек из 105.

| Pascal | Представление в МК-61 |
| --- | --- |
| `x` | R9 |
| `y` | R0, указатель при обходе предыдущих ферзей |
| Текущий `a[x]` | RB; записывается в R[x] при переходе вперёд и перед остановкой |
| Предыдущие `a[i]` | Ri |
| `s` | RA |

`КИП0` уменьшает R0 и читает очередного предыдущего ферзя. Предыдущие
координаты находятся в диапазоне 1–8. Когда R0 становится нулём,
косвенное чтение самого R0 возвращает ноль, который завершает просмотр.
Сравнение с несуществующим ферзём при этом не выполняется. Перед
окончательной остановкой R0 устанавливается в 1, как конечное `y` в Pascal.

Текущий `a[x]` читается прямой командой `ИПB`. Запись в массив отложена до
перехода к следующему ферзю: проверки читают только предыдущие элементы,
поскольку после каждого конфликта начинается новая попытка с `y := x`.
Запись последнего элемента выполнена до остановки, поэтому R1–R8 содержат
полную расстановку.

Первые три итерации внутреннего цикла развёрнуты: в них расстояния между
вертикалями равны 1, 2 и 3. Обе исходные проверки выполняются, конец массива
проверяется перед каждой парой. Остальные итерации идут общим циклом.
Условные переходы расставлены так, что успешная проверка продолжается в
следующей итерации без дополнительного безусловного перехода.

Разворачивание и способ завершения цикла — оптимизации машинного кода;
дерево, порядок поиска и все проверки совпадают с Pascal. Эти приёмы следует
явно указывать при подаче программы, если регламент отдельно ограничивает
реализацию циклов. Статья с тестом не заменяет полный регламент конкурса.

## Сравнение скорости

Одинаковый чистый старт и первое решение, стандартная память 105 шагов.
Выполнение через ROM, без математического или языкового перехвата команд.
Шаг — вызов `core_61::step()`; это **не миллисекунда**.

| Программа | Исполнено команд | Шагов ROM-ядра |
| --- | ---: | ---: |
| Новый qbench, обычные координаты и прямой счётчик | 30921 | **22327** |
| `8-queen_anv (1).m61` | 38954 | 27537 |
| `8-QUEEN.m61` | 30288 | 22582 |

Снижение числа шагов — **18,92%** относительно Анварова и **1,13%**
относительно `8-QUEEN`. Конечная расстановка одинакова у всех трёх.
Сам `8-QUEEN` используется как контроль скорости; эталоном хода поиска
служит исходный Pascal.

По согласованию с пользователем достаточно проверки ROM. Аппаратного
замера новой версии по `runtime_ms` нет; прежние времена в ms нельзя
выдавать за замер этой программы.

## Воспроизведение

Этот раздел описывает проверку архивного варианта. Текущая команда ниже
уже проверяет новую оптимизацию `8-QUEEN.m61`, описанную в отдельном отчёте.

```sh
bash tests/run_queens_benchmark_tests.sh
```

При получении этих результатов тест собирал независимый скалярный декодер
ROM без ускоренных путей, сверял полную трассу с Pascal, проверял счётчик в RA и X, обычные
координаты в R1–R8 и преимущество над обоими неизменёнными наборами
исходных кодов. Наблюдатель только читает память и не вмешивается в
исполнение. Завершённые записи наблюдаются на следующей границе команды,
а проверяемая пара — после успешного теста окончания просмотра.

SHA-256 M61-файла:
`46e1999bd1aed3d4b8c0e37383b9fa75eb7c2fe19dbbfd4bc6670fcd192f0967`.

Версия от 9 ноября занимала 102 ячейки, хранила удвоенные координаты
и обратный счётчик, требовала 22362 шага ROM-ядра. Текущая версия
заменяет её в файле программы и в проверке.
