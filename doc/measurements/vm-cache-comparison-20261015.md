# Сравнение raw24, mixed24 и raw32 — 2026-10-15

База всех прошивок: `05638655da3dbd29bcc776dcc5f9e266b4932efd`, wire9,
Classic F411 96 MHz, LIBM, density и файловый кеш. Производственный код,
программа Turochamp и алгоритм поиска не менялись. Коммит стенда —
`35774b1a3` с уточнениями `250f73246` и `7ea3ebf0b`. Штатные настройки в этом эксперименте не переключаются.

## Условия

Во всех трёх прошивках один побайтно одинаковый комплект System APP.
Его девять APP также совпадают с квалифицированным комплектом из
[integer spans](vm-integer-spans-20261015.json); ARM APP generation16
проверка здесь повторно не запускалась. LANGVM занимает 16628 байт.
Изменяются только `MK61_LANGUAGE_VM_IMAGE_CACHE_BYTES` и
`MK61_LANGUAGE_VM_CACHE_MIXED`; значения проверены в compile commands.

Аппаратный план: raw24 → mixed24 → raw32 → обратный raw24, по одному
миграционному и двум повторным поискам на стадию. USB Screen включён,
книга выключена, level2/depth8. Перед каждой стадией восстанавливаются
исходные VMC; после всей серии — точная исходная прошивка, APP/VMC,
остальные файлы и reg/stk/dump/pwd. Отдельные INPUT/ESC/USB latency тесты
mixed выполняются соседней задачей и не подменяются замером шахмат.

## Локальная квалификация

| Вариант | Кеш с каталогом | Payload | Flash | Static RAM | Эффективный динамический пул |
| --- | ---: | ---: | ---: | ---: | ---: |
| raw24 | 24576 | 23888 | 360576 | 26880 | 46560 |
| mixed24 | 24576 | 23888 | 362804 | 26880 | 46560 |
| raw32 | 32768 | 32080 | 360576 | 26880 | 38368 |

Цена mixed — 2228 байт Flash; raw32 арендует ещё 8192 байта RAM после
инициализации кеша. Native max frame 1928/5120, foreground main/terminal
80/608. Прежние проверки native source/runtime/drivers и shared APP RAM
пройдены для всех трёх прошивок. У raw32 хватает памяти на полный APP
maximum20480, USBDISK, staging2560, MSC8264 и filesystem temporary824;
общие пределы APP/стека и защитная граница не менялись. Это расчёт проверяемого
пула, не измеренный пик живого heap.

ASan/UBSan: три реальных C++ кеша под давлением, byte-exact возврат,
canary значений и workspace, pinned/stale/revision. Полные существующие
resident/file-cache регрессии для raw24/raw32 и mixed24, обе арифметики,
USB0/1, INPUT/ESC, ошибки, обновления source/compiler и повреждения.
Исследовательские codec/storage/replay/trace qualification тесты PASS.

Свежий host UI-cycle содержит 11305 запусков, измеряемое окно11303 точно
совпадает по порядку, source CRC, размерам и счётчикам модулей с сохранённым
аппаратным профилем. Собраны реальные owned-образы wire9. C++ replay
исполняет настоящий cache/codec, сверяет каждый байт образов и защищает
хвост значений; время Cortex этим replay не измеряется.

| Тёплый replay | Промахи | Pack / thaw | Fallback |
| --- | ---: | ---: | ---: |
| raw24 | 58 | 0 / 0 | 0 |
| mixed24 | 12 | 201 / 194 | 0 |
| raw32 | 1 | 0 / 0 | 0 |

Все варианты имеют прежние 16 слотов. raw32 не объявляется вместилищем
всех модулей UI-цикла: остаётся один промах `history`; исходный пул всех
17 образов с выравниванием32256 превышает payload32080. Результат replay
не выдаётся за аппаратный процент ускорения.

## Аппаратные результаты

| Стадия | Первый повтор, с | Второй повтор, с | Медиана повторов, с | ZX0 в повторах |
| --- | ---: | ---: | ---: | --- |
| A: raw24 | 42,912 | 42,995 | 42,953 | 174 / 174 |
| B: mixed24 | 37,331 | 37,303 | 37,317 | 39 / 36 |
| C: raw32 | 35,981 | 34,964 | 35,473 | 27 / 3 |
| A: обратный raw24 | 42,898 | 42,993 | 42,945 | 174 / 174 |

Среднее двух контрольных медиан — **42,949 с**,
дрейф обратного контроля -0,019%.
Mixed24 сокращает время на **13,114%**;
raw32 — на **17,408%** относительно raw24
и на **4,941%** относительно mixed24.
На этой зафиксированной базе и этом поиске самый быстрый вариант — raw32.
Цена — дополнительные 8192 байта постоянно удерживаемого после инициализации
RAM-кеша; штатные настройки этим экспериментом не переключаются.

Первый повтор raw32 ещё догревает кеш: 27 распаковок против 3 во втором.
Медиана учитывает оба повтора, включая 35,981 с; 34,964 с не выдаётся за
медиану или гарантированное время каждого хода. C++ replay даёт установившийся
цикл, а не точную модель холодной публикации VMC и инвалидаций ФС.

Миграционные поиски сохранены в JSON, но исключены из процентов: число
NOR-записей в них различается, а физическая история размещения C9 не
восстанавливается снимком файлов. В обоих повторных поисках каждой стадии
записи и стирания NOR отсутствуют.

Все **12 поисков** дали e2-e3 и 420 узлов, все восемь рядов доски совпали
побайтно по SHA256. Проверено **3607 CRC-кадров**,
KBD overflow=0, MPU layout=ok/crash none. Остаток стека из 16384 байт:
9668 → 9620 → 9668 → 9668. Наблюдаемый общий пик mixed выше на 48 байт,
raw32 совпадает с raw24 на этом сценарии. Эти watermark включают первый
миграционный поиск и компиляцию; это не изолированная цена helper или
измеренный максимум heap.

Процесс завершился exit0/PASS. В точности восстановлены исходная
122A5FF9 (360564 байта, SHA256
`059bff2d4d2aba948ba75ba382f52c4c7593439156be6ec045d674002f7db1da`),
44 файла/4 каталога, оригинальные APP/VMC и reg/stk/dump/pwd. Удалены
только 10 созданных тестом VMC; read retries=0, alarms off, CRC valid,
crash none, CDC закрыт. Mini не использовалась. Classic явно передан
следующему согласованному чату до оформления этого отчёта.

[Численные данные и SHA](vm-cache-comparison-20261015.json).
Полные артефакты: `.build/vm-cache-three-way-20261015`, исходный HIL
`hardware/attempt-2/report.json`. Предварительная попытка1 остановилась
на sandbox EPERM до открытия USB; её локальный журнал сохранён отдельно.
Полная серия attempt2 прошла после разрешённого запуска с доступом к USB.

Отдельный временный снимок новой main `a6d45ecb0` с wire10/request9
также прошёл полный comparison suite и storage/trace tests. Это проверка
совместимости инструментов после интеграции графики; измеренные BIN/APP
остаются wire9 и не пересобирались под эту новую базу.
