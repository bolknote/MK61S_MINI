# Точное сравнение `pow` по остатку на RP2040

После 16 384-битной логарифмической ступени `pow` пытается
определить сторону середины округления по младшим битам разности.
Память ограничена тремя массивами по 3 072 16-битных слова.
Результат учитывает чётность при точной ничьей. Если обоснованный
размер остатка превышает 49 152 бита, цепочка переходит к
поточному сравнению. [Ограждение логарифмов](m0-pow-log-side-20261118.md)

## Восстановление знака

Пусть `abs(y)=p/q`, `q=2^k`, а `m` — точная середина между
соседними кодировками. При положительном `y` степени `x^p`
и `m^q` приводятся к общему двоичному масштабу, давая целые
`A,B`. При отрицательном `y` так же приводятся `x^p*m^q`
и единица, а полученный знак обращается.

Предыдущая ступень гарантирует
`abs(y*ln(x)-ln(m)) < 2^-16300`. Поэтому модуль
`ln(A/B)` меньше `2^(k-16300)`. При `abs(t)<=1/4`
выполняется `abs(exp(t)-1)<2*abs(t)`.
Если хотя бы один из целых операндов не превосходит `2^N`,
то `abs(A-B) < 2^(N+1+k-16300)`.

Если правая часть не больше единицы, разность равна нулю.
Иначе выбирается `w=N+2+k-16300`. Поскольку разность
строго внутри `(-2^(w-1),2^(w-1))`, её знак и ноль
однозначно определяются по остатку по модулю `2^w`.
Квадраты и произведения вычисляют только младшие разряды.
Для отрицательного показателя сравнение с `2^s` при
`N=s` сводится к знаку остатка произведения: `2^s`
кратно модулю.

## Доказанная граница работы

В принятом сравнении `N<=65450-k`. Каждый коэффициент
степени имеет не больше 65 451 бита, а при отрицательном
показателе сумма их длин не больше 65 452 бит. До квадрата,
за которым предстоит всего `j` квадратов с учётом текущего,
длина операнда ограничена делением конечной ширины на `2^j`.
Коэффициент 1 возвращается сразу, для остальных нужно не более
15 квадратов на степень. Сертификат отдельно суммирует пары
слов квадрата, произведения на короткий коэффициент и
заключительное произведение при отрицательном показателе.

| Знак `y` | Максимум произведений 16×16 в новой ступени |
| --- | ---: |
| Плюс | 5 614 932 |
| Минус | 5 602 202 |

Эта оценка охватывает разрядные произведения. Сравнение также
выполняет переносы, копирование, вычитание и обслуживание watchdog.
Ширину хранящегося остатка и границы циклов проверяет
[рациональный сертификат](../../dev/tools/certify_m0_pow_residue.py).

Для произвольного основания достаточно
`max(53*p,54*q)+k <= 65450` при положительном показателе
или `53*p+54*q+k <= 65450` при отрицательном. Первая
формула, например, закрывает `p<=1234` при `q<=1024`.
Для отрицательного показателя безопасные максимумы `p` равны
1 233 при `q=1`, 1 104 при `q=128` и 713 при `q=512`.
Короткие нечётные коэффициенты и фактические двоичные масштабы
могут допускать более высокие показатели.

Практическая граница для всех пар binary64 остаётся открытой.
Вход с логарифмическим зазором меньше `2^-16300`
и остатком шире 49 152 бит по-прежнему может перейти к
точному потоковому сравнению.

## Проверки

Нативная проверка полными целыми степенями подтвердила 4 024
принятых сравнения, включая четыре точные ничьи. Ещё три
проверки подтвердили отказ при ширине на бит больше предела.
Тесты на связанном ELF `77D87243/EAD063B8` проверили вход в логарифмическую
ступень, ничью, разрешённую по остатку, и передачу управления
после принудительного отказа новой ступени. Регрессия с
заводской BootROM прошла 80 395 вызовов `pow` и 80 196
вызовов `exp` по направленному MPFR 4.2.2.

Для `x=7edf123456789abf`, `y=-527/512` и середины после
`0000002e95bafb6d` коэффициенты степеней имеют 27 909 и 19 734
бита. Первый виртуален, а окно второго не помещается в свободный
конец ни одного из массивов потоковой ветки. Прямой вызов этой
ветки на хосте сделал 843 852 вызова контроля прогресса,
что соответствует от 864 103 424 до 864 104 447 учитываемых
шагов. В ARM-эмуляторе прямая ветка остатка для той же границы
сделала 70 245 135 инструкций. Оба компаратора указали сторону,
подтверждённую MPFR.
Хост подтвердил зазор меньше `2^-35` точным неравенством
`abs(A-B)/min(A,B) < q*2^-35`; этого хватило для модуля
шириной 47 618 бит. Замер характеризует отдельное сравнение.

## Замер на PicoCalc при 125 МГц

Временное `POWRES.APP` выполняло компараторы из SRAM на
установленном образе `F1B747A6/CF0B0F3B`. Для трёх строк
с модулем 49 152 бита порядок был A–B–B–A, по одному вызову
на фазу. A — потоковое сравнение, B — вычисление по остатку.
На четвёртом входе APP сделало два вызова B. Для каждого
входа переданный в B зазор отдельно проверен полными целыми
степенями. Все стороны совпали с MPFR.

| `y` | Поток, мс в среднем | Остаток, мс в среднем |
| ---: | ---: | ---: |
| `1025` | 443,310 | 560,622 |
| `−1087/128` | 670,662 | 779,225 |
| `−469/512` | 807,319 | 1 012,243 |
| `−527/512` | — | 941,940 |

На первых трёх входах потоковый алгоритм закончил быстрее.
На четвёртом замерен компаратор по остатку для случая с
повторным вычислением виртуального произведения в потоке.
Тестовое приложение проверено по двум адресам в ARM-эмуляторе
с наблюдавшимся пиком записанного стека 19 312 байт.
APP и входы считаны обратно, временный каталог удалён,
CDC освобождён. Установленный образ и данные калькулятора
сверены после замера, сбросов watchdog и записей настроек
не было.
