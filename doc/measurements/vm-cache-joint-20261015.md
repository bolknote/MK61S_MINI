# Mixed cache VM и графика на общей main

Полный аппаратный raw24 → mixed24 → raw24 на общей main с графикой,
RAM/MPU и SIMD завершён успешно. Проверены два набора больших BASIC/FOCAL,
INPUT/ESC и холодные/тёплые графические страницы с активным USB Screen.
Ресурсные лимиты не менялись. Данные всех 54 окон и SHA сохранены в
[JSON отчёте](vm-cache-joint-20261015.json).

## Штатная политика кеша

Mixed включён по умолчанию для overlay VM с ненулевым кешем вне Classic.
Mini и 40th F411 сохраняют свои 24576 байт. Classic V2/V3 F411 сохраняют
отдельно выбранный [raw32](classic-raw32-20261015.md), а F401 и профили без
кеша — прежний путь. Явные mixed=0/1 остаются доступны для контроля.

Аппаратное сравнение здесь намеренно использует **24576 байт в обоих
вариантах**, не 32 КБ. Значение подтверждено actual compiler context и символом
ELF после переноса raw32 default. Поэтому выигрыш не получен добавлением RAM.
Это квалификация синтетического рабочего набора, не новый замер chess.

Это цена холодного пути, а не отсутствие ухудшений. Во всех обычных окнах

## Нагрузки и графика

Classic AEB505B6E0067623, F411 96 МГц, classic-v3-uc1609, arithmetic 0.
Оба варианта используют одни и те же пять System APP и байты исходников;
wire10, Request ABI 9, APP ABI 6. В каждом корпусе чередуются 8 BASIC и
8 FOCAL: прогрев 32 вызова, затем 2×128. Всего 1728 модульных вызовов,
24 интерактивных случая и 12 запусков двухстраничного Graphics.tbi.

Исходники обычного набора: BASIC 1749..3366, FOCAL 868..1435 байт;
ресурсного: 3552 и 1504. Штатные пределы 3584/1536/1536 сохранены.
Ресурсный набор содержит детерминированные плохо сжимаемые строки PRINT.
Перед установкой второго корпуса одинаково для A/B/A выполняется warm reset
вне измерений: fsput требует свободной transfer/stage workspace.
Смена рабочего набора внутри измерений проверяется чередованием 16 модулей,
затем большими INPUT/ESC-программами.

Все **24 выбранных полных кадра** холодной/тёплой графики совпали по байтам
между корпусами и A/B/A. SHA256 страницы примитивов:
`13401718041d86b7f4064060955657a3b0566fe8de5cb635bcbdaf74ab305bc3`;
графика:
`07ae52e42c88adfbc581e3658cacfaa73209f345be4312a3b13e2d85a9b18383`.
В batch и graphics CRC-проверено 3799 полных кадров;
интерактивные кадры проходят тот же обязательный CRC-парсер.

## Исправления измерительного драйвера

Исправлен [воспроизведённый single-slot конфликт PONG](vm-cache-rollout-20261015.md):
служебный keepalive больше не может вытеснить последний измеряемый ответ.
Одновременно ожидается не более одного PONG; nonce 0x0061 зарезервирован
только для служебного запроса. Отрицательный аппаратный контроль снова
воспроизвёл вытеснение первого ответа двумя PING одним OUT, хотя USB GAP был
1,022 мс. Это ожидаемый отказ
отдельного контроля, не успешная проверка задержки. Offline-регрессии
принимают ответ до 990 мс и отклоняют настоящий ответ после секунды.

Первый совместный прогон остановился на сравнении двух фаз анимации дискеты:
различались только пиксели x190..191, y10..11. Прошивка штатно накладывает
индикатор поверх bitmap. Теперь драйвер ждёт восстановления полного BOX
после исчезновения индикатора и сравнивает **все 1536 байт**, без маскирования.
Обе фазы наложения покрыты offline-тестом. После исправления полный A/B/A
повторён с начала; первый прогон не используется как завершённый контроль.

| Raw arithmetic 0 | 346816 | 23424 | 1960 |

Цена matched mixed arithmetic-0 — **2232 Flash и 0 static RAM**.
Default-сборки обеих арифметик побайтно совпали с явным mixed=1.
Новые GAP probes по умолчанию выключены вместе с их mutable storage.
Диагностические raw/mixed: 378656/380944 Flash, одинаковые globals 26904;
native frame max 1928, foreground frames 80/520 при лимитах 128/768.

Каталог и payload вместе — 24576 байт: metadata 688, payload 23888.
Рабочий prefix 4176 байт заимствуется из существующей workspace 8192;
persistent tail 4016 не трогается. Отдельный словарь не выделяется.

Watermark остатка стека после обычного корпуса raw A / mixed B / raw A:
9536/9456/9544 байта; после ресурсного — 6680/6592/6680.
Зафиксированный дополнительный пик mixed — **80..88 байт**, не нулевой
расход стека и не доказанный worst case. Резерв 16384, guard 256,
native-frame cap 5120, APP ceiling 20480, hot APP limits 19456/19968,
wire code/maps cap 6144 и owned-image cap 9728 не менялись.
Новые scoped allocations RAM/MPU из общей main учтены APP RAM gate:
5184 байта плюс placement slack 224, а не объявлены полностью свободной RAM.

## Проверки общей реализации

Оба корпуса прошли 72 точных host-исполнения в сумме на двух арифметиках;
настоящий C++ cache replay проверил raw24/mixed24/raw32, байты и canary.
ASan/UBSan mixed-cache и файлового кеша покрывают pins, rollback, OOM,
CRC, INPUT/ESC/USB и обе арифметики.

ARM-проверки прошли: полный flow LIBM и CORE, LANGVM/LANGIN overlay
с отравлением неактивных слотов, native/VM графика 80×16 и 192×64,
GRAPH, nested PRINT AT и INPUT eviction. Ресурсные, CRC, APP RAM,
runtime archive и foreground stack gates прошли.
Полная F401 release/capability матрица — 9/9 PASS; actual compiler contexts
повторно подтвердили cache=0/mixed=0/file-cache=0 на финальной конфигурации.
Cross-MCU WS0010 RAM comparison в эту квалификацию не входит.

Финальный полный `tests/run_all_tests.sh` на обновлённой main завершился
с **exit 0**, включая PowerShell-проверки. В suite обязательны новые
PONG/graphics/DWT регрессии, mixed-cache и sanitized mixed VMSTORE.
SHA256 полного лога приведён в JSON отчёте. Предыдущий запуск был остановлен
из-за запрета sandbox на запись в каталог тестовых сборок, затем повторён
целиком с нужным доступом; код и проверки ради этого не менялись.
