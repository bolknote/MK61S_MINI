# Шрифты интерфейса UC1609

Пропорциональные шрифты интерфейса доступны только на STM32F411 с большим
графическим экраном UC1609. Меню, проводник, настройки и обычный текст
Markdown получают естественную ширину букв. Индикатор МК-61 рисуется отдельным
фиксированным шрифтом и от этой настройки не зависит.

На F401, A00, A02 и WS0010 этот слой не компилируется: их интерфейс, расход
памяти и способ вывода остаются прежними.

## Что видно в меню

В `Настройки` → `Шрифты…` всегда есть:

- `5x8` — встроенный классический моноширинный растр одного размера;
- `Pixel` — встроенный Ark Pixel, размеры 12, 14 и 16;
- по одному пункту на каждый корректный файл `/Fonts/*.FMK`.

У внешнего пункта названием служит имя файла без `.FMK`: файл
`DejaVu-14.FMK` отображается как `DejaVu-14`. Размер берётся из заголовка
самого FMK, поэтому отдельного поля размера у такого пункта нет. Чтобы дать
одну гарнитуру в нескольких размерах, положите несколько самостоятельных
файлов, например `MyFont-12.FMK` и `MyFont-14.FMK`.

Файлы перечисляются по имени без учёта регистра. В оперативную память при
этом не загружается весь каталог: прошивка читает только 16-байтовый заголовок
каждого кандидата. Полный FMK занимает общую арену только после выбора.

## Установка

Готовые файлы находятся в [`programs/Fonts`](../programs/Fonts). Документация,
контрольные суммы и лицензия лежат отдельно, в
[`tools/.fmk-font/external-fonts`](../tools/.fmk-font/external-fonts/README.md),
и на диск прибора не копируются.

1. Включите USB-диск MK61S.
2. Создайте на диске каталог `/Fonts` и скопируйте в него только нужные
   `programs/Fonts/*.FMK`. Сам каталог репозитория целиком копировать не надо.
3. Корректно извлеките диск на компьютере и выключите USB-диск в меню прибора.
4. Откройте `Настройки` → `Шрифты…`.
5. На поле `Шрифт UI` нажимайте OK или ШГ+стрелку. Обычные стрелки двигаются
   между полями. Нижняя строка сразу показывает выбранный растр.
6. Нажмите ESC. Выбор сохраняется и восстанавливается после перезапуска.

В каталоге должны лежать сами файлы `*.FMK`, без дополнительных подкаталогов.
Файлы FONT в других папках по-прежнему можно просматривать или запускать как
обычные файлы, но в списке системных UI-шрифтов они не появляются.

Прошивка сохраняет не номер узла C5 и не позицию в отсортированном списке, а
стабильный 32-битный ключ имени. Поэтому добавление файлов, перестройка
каталога и перезапись выбранного файла не меняют выбор. Переименование или
удаление выбранного файла приводит к безопасному возврату на `Pixel` того же
размера. Совпадение ключей у двух разных имён трактуется как ошибка, а не как
разрешение выбрать случайный файл.

Старые корневые `UI12.FMK`, `UI14.FMK` и `UI16.FMK` читаются только как
миграционный резерв для уже сохранённой настройки прежней прошивки. Новые
шрифты надо устанавливать в `/Fonts`; корневые имена больше не предлагаются
как особое семейство.

## Готовые файлы

Репозиторий содержит два проверенных пропорциональных растра DejaVu Sans:

| Файл | Строк на 192×64 | Назначение |
| --- | ---: | --- |
| `DejaVu-12.FMK` | 5 | больше текста по ширине и высоте |
| `DejaVu-14.FMK` | 4 | более крупный основной интерфейс |

Оба включают 169 знаков: ASCII, русскую кириллицу с Ё/ё, четыре стрелки,
многоточие, градус и нужные математические символы. Пиксели получены заранее
на компьютере без сглаживания; FreeType и масштабирование на приборе не нужны.
Исходник, контрольные суммы и лицензия зафиксированы в host-only каталоге
`tools/.fmk-font/external-fonts`.

## Создание своего FMK

Обычный конвертер TTF/OTF/BDF/PCF/FON:

```bash
tools/build_fmk_font.sh font.ttf MyFont-14.FMK \
  --cell 12x14 --size 14 --line-gap 2 --proportional \
  --chars 'ascii,cyrillic,°×÷≤≥←→↑…π√' \
  --compression auto --max-file-size 8192
```

Имя выходного файла можно выбирать свободно в пределах C5. Для готового
BDF/PCF/FON следует выбирать существующий bitmap-strike без масштабирования и
проверять результат на физическом дисплее.

Для утверждённых пикселей есть отдельный упаковщик. Сначала
`font_preview.cpp` экспортирует JSON-атлас с baseline, bearings и advance,
затем упаковщик переносит его в FMK бит-в-бит:

```bash
python3 tools/build_fmk_from_ui_atlas.py approved-14.json \
  programs/Fonts/MyFont-14.FMK
python3 tools/build_fmk_from_ui_atlas.py approved-14.json \
  programs/Fonts/MyFont-14.FMK --check
```

Обычный предел конвертера по умолчанию — 1536 байт для совместимости с F401.
UI-шрифт F411 может занимать до 8192 байт — размер уже существующей общей
арены `BULK`, а не новая статическая память.

## Требования к файлу

Помимо полной проверки FMK1, структуры и CRC-16 прошивка требует:

- высоту 12, 14 или 16 пикселей;
- ширину глифа и горизонтальный шаг не более 16 пикселей;
- межстрочный интервал не более 4 пикселей;
- не менее трёх видимых строк на UC1609;
- обязательные глифы пробела и `?`;
- общий размер не более 8192 байт.

Рекомендуемый набор — `ascii,cyrillic`: русский и английский тогда можно
свободно смешивать в одной строке. Неизвестный Unicode-символ заменяется на
`?`. Формат поддерживает Unicode BMP (`U+0000..U+FFFF`). Лицензию исходного
шрифта следует распространять вместе с FMK, если этого требует автор.

Короткая проверка заголовка нужна лишь для безопасного и быстрого построения
списка. При применении файл заново целиком читается в bounded-арену и только
после проверки длины, CRC, диапазонов и всех глифов становится видимым
рендереру. Файл с правдоподобным заголовком, но повреждённым телом может быть
показан в списке, однако применён не будет; прежний шрифт останется активным.

## Где какой шрифт применяется

| Поверхность | Шрифт |
| --- | --- |
| Меню, настройки, проводник, диалоги | выбранный `5x8`, `Pixel` или `/Fonts/*.FMK` |
| Имена файлов, поиск и переименование | выбранный UI-шрифт; ширина и курсор считаются в пикселях |
| Обычный текст и заголовки Markdown | выбранный UI-шрифт |
| Блоки и фрагменты кода Markdown | встроенный моноширинный 5x8 |
| Индикатор калькулятора UC1609 (F401 и F411) | отдельный неизменяемый крупный шрифт |
| FOCAL, TinyBASIC, исходники и дампы | прежний моноширинный текстовый режим |

Длинные подписи обрезаются по пиксельной ширине с многоточием; UTF-8 при этом
не разрывается. Размер 12 обычно даёт пять строк, 14 — четыре, 16 — три.

## Память и USB

Активный внешний файл живёт в уже существующей 8-КиБ арене `BULK`: второго
буфера, нового framebuffer и динамического выделения памяти нет. Каталог
перебирается с постоянным малым стековым буфером и не создаёт RAM-список.

USB-диск использует ту же арену как секторный кэш. Перед включением USB ссылка
на FMK отзывается. После завершения сеанса прошивка снова находит файл по
сохранённому ключу имени, целиком читает и проверяет его; изменение внутреннего
ID файла безопасно. Если имя исчезло, высота поменялась или данные испорчены,
включается встроенный `Pixel`. Рендерер не обращается к памяти, которой уже
владеет USB.

Явный `Run` другого FMK применяет его к обычному моноширинному текстовому
экрану и отдаёт ему единственную арену; UI тогда переходит на `Pixel`. Обратный
выбор UI-файла аналогично вытесняет обычный внешний текстовый шрифт.

## Приёмка

1. Проверить `5x8`, все три размера `Pixel` и каждый файл `/Fonts/*.FMK`:
   название и образец должны меняться вместе.
2. Проверить русский, английский, смешанную строку, Ё/ё и длинное имя файла.
3. Перезапустить прибор: выбранное имя должно восстановиться.
4. Добавить файл с именем, которое сортируется раньше выбранного: выбор не
   должен перескочить.
5. Включить и выключить USB-диск: должен вернуться тот же шрифт без мусора.
6. Переименовать или испортить выбранный файл: прибор должен перейти на
   `Pixel` и продолжить работу.
7. Открыть Markdown: обычный текст использует выбранный FMK, код остаётся
   моноширинным; калькуляторные цифры, точка и минус не меняются.

Детали ABI приведены в [UI-FONTS.md](../sdk/portable/UI-FONTS.md), бинарный
формат — в [MK61s-mini-FMK.md](src/MK61s-mini-FMK.md).
