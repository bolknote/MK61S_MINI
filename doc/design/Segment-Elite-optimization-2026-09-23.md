# ELITE: второй этап оптимизации, 23.09.2026

Сравнение с предыдущей установленной версией: игра из `d5a90c7f`, прошивка
`7F650965`. Новая игра занимает **3100 байт вместо 3183**: экономия
83 байта (2,6%). От первоначальных 3336 байт сэкономлено 236 (7,1%).
Свободны 484 байта, распределённые по хвостам всех 32 занятых банков.
Шесть файлов загрузки, миры, алфавит, товары и боевые возможности сохранены.

## Применённые техники

1. **Удаление ненужных записей кадра.** `2F 53` уже сравнивает результат
   с видимым кадром внутри ядра. Повторное копирование четырёх слов из
   B29.R0…R3 в R4…R7 удалено; четыре поля страницы освобождены.
2. **Сокращение переходов после размещения.** Сборщик повторно пробует
   ближнюю форму для дальнего перехода, оказавшегося внутри банка. Попытка
   принимается только при уменьшении размера всей программы, включая
   переходы между частями модулей. Удаляется и безопасный переход на
   следующую команду: только после ST, перед LD и без самостоятельной
   метки на переходе. Так сохраняется состояние ввода чисел ПЗУ.
3. **Повторное использование значений.** Вычитание стоимости сделки
   организовано через Y без лишнего обмена. Дистанция и сила противника
   используются прямо из RD/RE, возвращённых обработчиком. Прибор числа
   дронов читает уже поддерживаемый рабочий кеш R6.
4. **Объединение чтений страниц.** Цена возвращает также запас рынка.
   Один обработчик HOLD при покупке возвращает количество выбранного
   товара и свободный трюм. Продажа обходится без подсчёта вместимости.
   Все проверки отказа по-прежнему предшествуют изменению игровых данных.
5. **Обратный счётчик.** Выпуск дрона использует 3 → 2 → 1 → 3 вместо
   деления номера хода и вычисления остатка по модулю 3. B27.R4 теперь
   хранит этот отсчёт; полное игровое время остаётся в B24.R3.
6. **Общее исправление `1F` в ядре.** Условия читают окончательный X
   после записи результата ПЗУ. Воспроизведён случай `0−19`, при котором
   старое ядро проверяло ещё положительный знак. Защитные NOP удалены
   из игры; сборка требует исправленной прошивки, проверена `544269E1`.
   Распознавания ELITE или подмены игровой арифметики в ядре нет.

Источником приёмов послужил справочник
`~/Projects/MK-61/docs/20-mkpro-optimization-reference.md`: сохранение
значений в стеке, сокращение обращений к регистрам, замена дорогой
арифметики при известном диапазоне, удаление ненужных записей и повторное
размещение переходов с проверкой семантики ПЗУ. Это применения в собственном
сборщике ELITE; компилятор MK-Pro при сборке игры не запускается.

Во время испытания исправлены две ошибки аппаратного стенда:

- Одного локального IP недостаточно для определения остановки: он мог
  совпасть в другом банке, пока перелёт ещё выполнялся и сохранял прежний
  кадр. `check_state` теперь проверяет все доступные регистры R0…RE,
  содержимое активного банка B0 и повторный снимок регистров после ожидания.
  У игры после завершения того перелёта все данные оказались правильными;
  полный маршрут повторён с исправленной проверкой.
- Пакет DETACH оставляет сеанс USB Screen ждать переподключения. Его
  OVERLAY-память мешает C6 получить индекс для изменения каталога, поэтому
  удаление временного загрузчика в конце давало `rm: storage error`.
  Стенд теперь удаляет загрузчик до включения USB Screen, сразу после
  загрузки программы в RAM. Возврат к заставке выполняется через обычный
  `autoexec.m61` с закрытием вступительной памятки.
