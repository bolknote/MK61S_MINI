# Аппаратный CRC-32 на STM32F401/F411

Статус: реализован и проверен эмуляцией регистра; аппаратный timing ещё не снят
Дата: 29.07.2026

## Решение

F401 и F411 имеют один CRC-блок AHB1 с фиксированным полиномом
`0x04C11DB7` и 32-битным входом. C5 и APP используют обычный отражённый
CRC-32 с полиномом `0xEDB88320`, начальным состоянием `0xFFFFFFFF` и финальным
XOR `0xFFFFFFFF`.

Форматы математически эквивалентны. Аппаратный backend:

1. собирает четыре последовательных байта в little-endian слово;
2. перед записью в `CRC->DR` выполняет `RBIT`;
3. после последнего полного слова выполняет `RBIT` результата;
4. хвост из 1–3 байт продолжает программным отражённым алгоритмом;
5. применяет прежний финальный XOR.

Физический формат C5, APP headers и уже записанные CRC от этого не меняются.

## Владение периферией

CRC-регистр хранит только одно состояние и не имеет программируемого `INIT` на
F401/F411. Поэтому аппаратные `mk61_crc32::Context` нельзя вкладывать или
чередовать.

Текущая реализация не содержит автоматического runtime fallback:

- один последовательный bulk-поток использует аппаратный `Context`;
- параллельный CRC блока и всего файла явно оставляет один поток программным;
- callback-потоки, которые сами могут читать C5 и считать CRC, используют
  чистые `extend()`/`finish()`;
- host tools, тесты и другие MCU выбирают программный backend при компиляции.

USB MSC выполняет операции C5 отложенно в основном цикле, поэтому CRC-регистр
не разделяется между main и USB interrupt.

## Проверки

Host-тест эмулирует именно STM32 MSB-first регистр, `RBIT` и 32-битные записи.
Проверяются:

- известный вектор `123456789` → `0xCBF43926`;
- размеры 0–80 и границы до 4095 байт;
- разбиение входа на порции 1, 2, 3, 4, 5, 7, 16, 63, 64, 255 и 512 байт;
- программный и STM32-emulated варианты APP;
- оба варианта полного C5 набора, включая GC и power cuts;
- ASan/UBSan.

Эмуляция использует один глобальный регистр. Случайно вложенные аппаратные
контексты портят его состояние и обнаруживаются интеграционными тестами.

## Размер

Сборки F401 с LTO + CORE math:

```text
до аппаратного CRC:
  mini-v3-a00 text = 190952
  mini-v2-a00 text = 191000

с аппаратным CRC:
  mini-v3-a00 text = 191440
  mini-v2-a00 text = 191496

контрольная FORCE_SOFTWARE после общего рефакторинга:
  mini-v3-a00 text = 191384
```

Непосредственная цена STM32-backend относительно той же новой реализации —
56 байт `.text`. Общая разница с предыдущим firmware включает общий потоковый
API и перевод C5-путей.

F411 `mini-v3-a00` также собирается: BIN вырос с 279636 до 280180 байт.

## Что ещё измерить

До окончательного вывода о скорости нужен DWT cycle benchmark на F401:

- непрерывные блоки 12, 64, 512, 1536 и 4095 байт;
- CRC resident image;
- чтение small и large ZX0 из C5;
- сравнение аппаратного и `MK61_CRC32_FORCE_SOFTWARE` вариантов.
