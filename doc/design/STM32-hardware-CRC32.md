# Аппаратный CRC-32 на STM32F401/F411

Статус: безопасный lease/fallback и реальная работа peripheral подтверждены;
изолированный timing-бенчмарк F401 остаётся отдельным измерением
Дата: 02.08.2026

## Решение

F401 и F411 имеют один CRC-блок AHB1 с фиксированным полиномом
`0x04C11DB7` и 32-битным входом. C5 и APP используют обычный отражённый
CRC-32 с полиномом `0xEDB88320`, начальным состоянием `0xFFFFFFFF` и финальным
XOR `0xFFFFFFFF`.

Форматы математически эквивалентны. Аппаратный backend:

1. собирает четыре последовательных байта в little-endian слово;
2. перед записью в `CRC->DR` выполняет `RBIT`;
3. после последнего полного слова выполняет `RBIT` результата;
4. хвост из 1–3 байт продолжает программным отражённым алгоритмом;
5. применяет прежний финальный XOR.

Физический формат C5, APP headers и уже записанные CRC от этого не меняются.

## Владение периферией

CRC-регистр хранит только одно состояние и не имеет программируемого `INIT` на
F401/F411. Поэтому первый живой `mk61_crc32::Context` арендует peripheral, а
любой вложенный, конкурентный или возникший из IRQ контекст автоматически
выбирает программный backend. Оба варианта дают побитно одинаковый результат и
имеют один API.

Флаг занятости меняется в короткой секции с PRIMASK. IRQ выключены только на
время проверки/изменения этого флага, но не на время чтения flash или расчёта
CRC. `finish()` освобождает аренду сразу, а деструктор освобождает её и при
раннем выходе. Копирование `Context` запрещено.

Это позволяет безопасно считать, например, CRC всего файла аппаратно, а CRC
вложенного блока программно, не разводя ручные правила по вызывающему коду.
RAM-swap FOCAL/TinyBASIC использует тот же `calculate()` и получает hardware
автоматически, когда блок свободен. Host tools и другие MCU по-прежнему
компилируют только программный backend.

## Проверки

Host-тест эмулирует именно STM32 MSB-first регистр, `RBIT` и 32-битные записи.
Проверяются:

- известный вектор `123456789` → `0xCBF43926`;
- размеры 0–80 и границы до 4095 байт;
- разбиение входа на порции 1, 2, 3, 4, 5, 7, 16, 63, 64, 255 и 512 байт;
- программный и STM32-emulated варианты APP;
- оба варианта полного C5 набора, включая GC и power cuts;
- внешний аппаратный и вложенный программный `Context` с продолжением обоих
  потоков после вложенности;
- освобождение hardware lease деструктором незавершённого контекста;
- статистика аппаратных аренд и software fallback;
- ASan/UBSan.

Эмуляция использует один глобальный регистр, поэтому тест действительно
воспроизводит ограничение STM32, а не подменяет каждый контекст отдельным
состоянием.

На реальном F411 последовательность `fsput`, снимков и восстановлений FOCAL и
TinyBASIC дала 11 аппаратных аренд, ноль software fallback и ноль ошибок
целостности swap. Отдельный `fsput` после `mem reset` дал `acquire=1,
fallback=0`. Это подтверждает не только наличие блока, но и совпадение CRC при
записи заголовка, данных, распаковке и повторной проверке результата.

## Размер

Сборки F401 с LTO + CORE math:

```text
до аппаратного CRC:
  mini-v3-a00 text = 190952
  mini-v2-a00 text = 191000

с аппаратным CRC:
  mini-v3-a00 text = 191440
  mini-v2-a00 text = 191496

контрольная FORCE_SOFTWARE после общего рефакторинга:
  mini-v3-a00 text = 191384
```

Непосредственная цена STM32-backend относительно той же новой реализации —
56 байт `.text`. Общая разница с предыдущим firmware включает общий потоковый
API и перевод C5-путей.

Историческая F411-сборка первого внедрения выросла с 279636 до 280180 байт.

Эти числа относятся к первому внедрению CRC и оставлены как история локальной
цены backend. В общей SRAM-архитектуре 02.08.2026 итоговый размер следует брать
из `Shared-SRAM-arena.md`, потому что одновременно изменились кеш таблиц, swap,
ZX0 workspace и диагностика.

Терминальная команда `mem` показывает `crc-hw supported`, текущий `busy`, число
`acquire` и `fallback`; `mem reset` обнуляет только статистику.
