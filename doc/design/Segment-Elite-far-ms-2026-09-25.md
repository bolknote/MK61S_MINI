# ELITE: обмен Ms с произвольным банком

25.09.2026. Исходная версия — `b46fe9ef`, 3092 занятых байта и файл
`elite.bin` размером 2009 байт. Пользователь согласовал одну новую команду:
`1F 56 nn`, дальний вариант обмена `56`.

## Команда

Три байта обменивают Ms с первыми 63 байтами выбранного банка. Номер банка
двоичный: `1F 56 18` означает B24. Банк исполнения остаётся прежним;
следующая команда находится за тремя байтами. Обмен текущего банка также
разрешён, следующий код берётся из уже изменённой памяти.

Поддерживаются полные банки 0…88. B89 содержит только адреса 9968…9999,
поэтому обмен 63 байт для него отклоняется. Общий пул остаётся прежним:
32 одновременно выделенных банка. Пустой банк исходно нулевой. Места для
целевого банка и продолжения исполнения резервируются до изменения данных;
нехватка слотов не оставляет частично выполненный обмен.

Операция исполняется на следующей границе выборки, используя существующий
такт префикса. Это позволяет продолжить с настоящей следующей команды,
не отдавая байт номера банка декодеру обычных команд ПЗУ. Отдельный NOP
или дополнительный шаг программы не нужен. Другие новые опкоды не добавлены.

## Переработка игры

Страница открывается как `1F 56 nn; 55`, закрывается как `55; 1F 56 nn`.
Внутри открытой страницы R0…R8 содержат её поля, а Ms — рабочую девятку
вызывающего кода. После закрытия восстановлены рабочие регистры и Ms.

Сборщик сохраняет определения операций в соответствующих исходных модулях,
но встраивает однократно используемые тела в места обращения. Убраны адреса
обработчиков в RF и промежуточные вызовы через банки данных. Инициализация
PILOT/HOLD, оплата, оружие и движение врага оставлены отдельными процедурами:
так итоговое размещение меньше. Чистая `sum_hold` используется и внутри
открытого HOLD, и с внешним открытием. Текстовые сообщения сохраняют
косвенный вызов по RF.

Из шести страниц удалены все CALL. READ/WRITE оставлены только в B24, B25
и B27: для частых одиночных обращений они компактнее двух прямых обменов.
В B26 и B28 редкие операции встроены; B29 обслуживается только через новый
обмен. Служебный код в банках данных уменьшился со 114 до 39 байт (−75),
но часть экономии расходуется на открытие/закрытие в других местах и
переходы между продолжениями. Итоговая экономия всей программы — 58 байт.

## Проверки

- Полный набор ELITE: 144 сценария, 2486 остановленных состояний. С исходной
  версией сравнены шесть страниц, кадры, X, режим игры, число смен кадра,
  удержание экрана при вводе и боевые кеши R5…R8. Различий нет.
- `tests/run_elite_tests.sh`: игровой набор и проверка загрузки BIN через
  настоящий M61-загрузчик; прежние ограничения скорости сохранены.
- `tests/run_mk_math_tests.sh`: Flash- и SRAM-таблицы. Проверены все 89
  допустимых банков, текущий банк, точные 63 байта, сохранность хвоста,
  R0…RF и пяти регистров стека, обратимость числовых страниц и сохранение
  контекста между шагами. Отдельно: пустой банк, двоичный операнд `1F`,
  ошибочные номера, полный пул и три положения команды на границе банка.
- Сырые байты, включая тетрады A…F, сравниваются в `AFTER_EXECUTE` самого
  обмена. Это существенно: Ms остаётся физической дорожкой ПЗУ; произвольные
  нечисловые комбинации могут влиять на дальнейший RUN и изменяться при
  последующей работе ПЗУ. Это наблюдалось и с обычной `56`; новый обмен не
  превращает Ms в отдельный массив RAM. Двойной обмен проверяется на
  числовых страницах, которые использует ELITE.
- Проверены детерминированная повторная компоновка и продолжение после
  `55 1F 56 52`: байт номера банка `52` не считается командой возврата.
- `tests/run_program_memory_policy_tests.sh` проходит; AUTO уже распознаёт
  префикс `1F`, отдельная эвристика для новой команды не нужна.
- F401: штатный `f401-product-classic-v3`, CORE math, ProductBuild; ELF text
  248572 байта, data 2016. Образ 250600 байт, CRC `2221DD0E`; проверки
  размера, стека и ресурсов проходят.
- F411: Classic V3, штатный Arduino Core, выборочная O3, строгие предупреждения;
  396924 байта Flash, 62580 байт глобальных данных. Сборка проходит.
