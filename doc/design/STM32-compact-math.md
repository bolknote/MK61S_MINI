# Binary64 для Cortex-M4: своё математическое ядро

Первый этап замены оставшихся библиотек — 11 функций `mk_math`: `sin`, `cos`,
`tan`, `asin`, `acos`, `atan`, `ln`, `log10`, `exp`, `sqrt`, `pow`.
В самостоятельной сборке `MK61_USE_COMPACT_LIBM=1` включён по умолчанию.
`MK61_USE_COMPACT_LIBM=0` оставляет контрольную GNU libm. Backend CORE, внешний
Arduino backend и ABI System/ordinary APP сохраняются. В окончательных ELF
Classic и mini нет стандартных функций libm; базовая арифметика `double`
пока остаётся в libgcc и относится к отдельному следующему этапу.

## Реализация и точность

Собственные `sin/cos/atan/exp` используют целочисленные Q62-полиномы. Четыре
точных умножения 32×32→64 образуют произведение 64×64→128; GCC выдаёт UMULL
на M4. Упаковка результата округляет к ближайшему чётному. Промежуточное
произведение и его округление встроены вместе: передача структуры из 128 бит
между функциями давала лишние копирования на стеке при некоторых решениях LTO.

65 значений atan(i/64), π/2 и коэффициенты вычисляет проектный генератор.
Факториальные коэффициенты округляются из точных рациональных чисел, остальные
значения согласуются при 400/450 десятичных знаках. Для полного диапазона углов
целочисленный Payne–Hanek использует 1600 бит 2/π, независимо согласованных при
600/650 знаках. Небольшие/средние углы используют сокращённое приведение fdlibm.
Таблица хранится в Flash; временное длинное произведение — на стеке.

`sqrt` получает начальное приближение аппаратной float-командой VSQRT на
нормализованном числе в [1,4). Затем целочисленные уточнения, UDIV и точный
106-битный остаток определяют окончательный **binary64** результат. Округление
входа до float используется только для начального приближения. Вход/выход не
переводятся в float; корень округляется правильно, включая subnormal и −0.

`ln`, `log10`, `asin`, `acos`, `pow` разделяют необходимые полиномы и ядра.
Эти выражения и малое/среднее приведение адаптированы из Sun fdlibm/OpenLibm,
[проверенная ревизия](https://github.com/JuliaMath/openlibm/tree/5fe399749f9276eaa0b8403e507470da05cbbb3f).
Разрешительное уведомление Sun сохранено в исходнике.

Контракт — 53 значащих бита IEEE binary64, весь диапазон конечных аргументов,
subnormal, знаки нуля/бесконечности и классификация NaN при nearest-even.
Публичный `mk_math` не предоставляет errno/fenv. Для трансцендентных функций
не обещается побитовая идентичность GNU libm или глобальное правильное
округление: тестовый предел — 4 ULP, для sqrt — 0 ULP. На большом host-корпусе
наблюдалось до 3 ULP у tan, 2 у pow и 1 у остальных; на независимых аппаратных
векторах обеих плат — максимум 1 ULP, sqrt совпал побитно.

[Qfplib-M3](https://github.com/mysterywolf/Qfplib-M3) предоставляет float, а
[Qfplib-M0-full](https://github.com/mysterywolf/Qfplib-M0-full) имеет double
с ограничениями диапазона/NaN/subnormal. Поэтому они не заменяют наш контракт
напрямую. В эксперименте замена длинных умножений M0 на инструкции M4 дала
выигрыш базовым операциям, но CORDIC сохранил большую часть стоимости
тригонометрии. В проект не включены их исходники или таблицы, равно как код
emFloat: Q62 и полное приведение реализованы самостоятельно.

## Размер и аппаратные результаты

Одинаковые полные конфигурации, GNU Arm 14.2.1, Cortex-M4, −Os/LTO.
Flash — весь подписанный образ; RAM — `.data + .bss + .noinit`.

| Плата | Flash до | Flash после | Экономия Flash | RAM до/после | CRC после |
|---|---:|---:|---:|---:|---|
| Classic V3 UC1609 | 367808 | 361760 | 6048 | 28608 | FAF4CD3F |
| mini V3 A00 | 339208 | 333160 | 6048 | 27224 | F8C56B67 |

На Classic публичный System API с одинаковыми входами 0,7/1,3, pow(1,3;0,7),
медиана девяти пакетов по 1024 вызова, мкс/вызов:

| Функция | GNU libm до | Своё ядро после |
|---|---:|---:|
| sin | 12,764 | 10,186 |
| cos | 16,742 | 10,457 |
| tan | 43,198 | 26,844 |
| asin | 58,741 | 48,319 |
| acos | 53,718 | 43,467 |
| atan | 33,509 | 22,591 |
| ln | 27,204 | 26,429 |
| log10 | 31,033 | 29,543 |
| exp | 30,515 | 28,323 |
| sqrt | 12,928 | 4,326 |
| pow | 97,508 | 90,574 |

На mini пройден тот же численный корпус. Шаг эмулятора: Classic
1711192→1712216 циклов (+0,06%), mini 1709641→1711025 (+0,08%). Чтение 64 КиБ,
по 60 отсчётов: Classic 24986→24987 мкс, mini 24773→24772. Читающие кеши
сохранены. ADC, 100 чтений 64 КиБ с одинаковой CRC и нулевыми ошибками SPI/DMA
прошли на обеих платах. После тестов сравнены исходные файлы, программа,
IP, регистры, стек и текущий каталог. Коррекция RTC и настройки не изменялись.

## Сравнение с опубликованными результатами SEGGER

[Основная таблица SEGGER](https://www.segger.com/products/development-tools/runtime-library/technology/floating-point-library/#explicit-function-performance)
содержит **binary32**, исполняемый из RAM NXP K66FN2M0 Cortex-M4. Значений для
соответствующих **double** там нет. В [Knowledge Base](https://kb.segger.com/SEGGER_Floating-Point_Library)
приведены точные hex-входы/результаты и другой, более ранний набор циклов.
Мы сохраняем обе версии и не смешиваем их. Случай sqrt ниже есть только в KB.

На реальной Classic (STM32F411, 96 МГц) измерены те же 51 входа: исходные float
битовые шаблоны точно расширяются в double. Три диагностических APP выполняют
GNU float, GNU double и наше double из SRAM вместе с арифметическими
помощниками, без resident imports. DWT CYCCNT: медиана девяти пакетов по 512
вызовов минус соответствующий identity-цикл. Вход/выход volatile, поэтому LTO
не выносит вычисление из пакета. Прерывания не запрещаются; между пакетами
обслуживаются USB/watchdog. Отдельно измеряется resident API из Flash с вычетом
пустого диспетчера. SRAM и Flash — отдельные сборки, не один перемещённый ELF.

| Вход | SEGGER float, опубликовано | GNU float, RAM | GNU double, RAM | Наш double, RAM | Наш double, Flash |
|---|---:|---:|---:|---:|---:|
| sin(1) | 139 | 190,1 | 3358,9 | 2040,2 | 1580,5 |
| sin(1e38) | 186 | 4096,3 | 15638,7 | 5585,1 | 4174,3 |
| cos(1) | 136 | 176,1 | 3072,8 | 1992,2 | 1589,3 |
| tan(1) | 258 | 268,2 | 7048,9 | 4317,4 | 3270,3 |
| exp(0,25123) | 81 | 159,1 | 3287,9 | 2285,3 | 1629,6 |
| ln(4177,25) | 140 | 177,1 | 4447,5 | 4302,4 | 2816,5 |
| sqrt(1e−4), KB | 68 | 47,0 | 1918,1 | 475,3 | 321,4 |

На этих 51 входах наше double отличается от GNU double максимум на 1 ULP;
после округления в float оба совпадают со всеми опубликованными эталонами.
GNU float отличается на 1 ULP в трёх случаях. SEGGER float — 24 значащих бита,
оба double — 53; таблица не устанавливает соотношение скорости нашего double
и emFloat double. Лицензированная библиотека emFloat локально не исполнялась.
Различаются также MCU, компилятор, детали памяти и измерения накладных расходов.

## Воспроизведение

```sh
MK61_MATH_SAMPLES=1000000 bash tests/run_compact_math_tests.sh
MK61_TEST_SANITIZERS=1 bash tests/run_compact_math_tests.sh
python3 tests/compact_math_arm_self_test.py \
  --resident-elf .build/native-classic/resident.elf \
  --resident-elf .build/native-mini/resident.elf --json .build/math-arm.json
```

Unicorn — зависимость только ARM-теста. Host-тесты не требуют mpmath: 1897
эталонов сохранены в TSV, генераторы нужны лишь для их воспроизведения.
ARM-тест исполняет реальный System API, проверяет ещё 54 случая IEEE, сохранность
R4–R11/D8–D15/SP и отсутствие записей вне стека у нашего ядра. На каждой плате
через обычный APP исполнены все 1897 эталонов. Пройдены 16 F411 и 9 F401 сборок;
F401 сохраняет CORE, размеры всех девяти образов остались прежними.

Численный HIL: собрать `tests/fixtures/compact_math_probe_app.c` как MATHCHK,
передать файл в `tests/hil_compact_math.py` с port/public-id/expected-build.
Тест размещает эталоны отдельными блоками ≤4096 байт и удаляет свои файлы.

Для DWT собрать `math_cycles_double.cpp` как SEGGD, `math_cycles_float.cpp` как
SEGGF и `math_cycles_gnu_double.cpp` как SEGGG инструментом build_portable_app.py
с `--include code`. Для GNU-вариантов передать `--library` путь `libm.a` из
`arm-none-eabi-gcc -mcpu=cortex-m4 -mthumb -mfpu=fpv4-sp-d16 -mfloat-abi=hard -print-file-name=libm.a`.
`tests/hil_math_cycles.py` принимает три APP, port/public-id/expected-build,
keyboard-layout и output-dir. Он проверяет состояние до/после, снимает сырые
показания и удаляет только свои зарезервированные файлы. Ни один HIL не
перепрошивает устройство автоматически.

Полный отчёт: [stm32-owned-math-20261014.json](../measurements/stm32-owned-math-20261014.json).
Отдельный [графический этап](STM32-owned-graphics.md) также завершён.
Остаются CMSIS startup, libgcc, libc_nano и USB.
