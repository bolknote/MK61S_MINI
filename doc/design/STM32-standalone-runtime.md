# Самостоятельный runtime STM32F401/F411

Работа выполняется тремя измеряемыми этапами при сохранении функций прошивки.

## 1. USB и вывод — выполнено

`mk61_io::Output` заменяет Arduino Print для терминала, MK61Display и UC1609.
Используются только текст/байты и 32-битные числа в существующих основаниях;
CRLF и ограниченный вывод сохраняются. USB Serial не имеет виртуальной таблицы,
Stream timeout state и неиспользуемых readBytes/readBytesUntil.

Собственный CDC поддерживает одну ACM-функцию, endpoints OUT1/IN2/CMD3,
только Full Speed. У RX/TX сохранены прежние ёмкости 192/128 байт. Буфер
управления уменьшен 512 → 8 байт; согласованный public handle — 36 байт.
SET_LINE_CODING принимает ровно 7 байт, короткий/неправильный OUT отклоняется.
IN на 64/128 байт завершается ZLP, затем освобождает очередь. Пустая RX-очередь
возобновляет OUT; заполненная оставляет endpoint невооружённым для NAK.
Reset/disconnect и начало TX/RX защищены сохранением/восстановлением PRIMASK.

CDC/MSC конфигурационные дескрипторы находятся в Flash; HS, other-speed и
qualifier исключены. Общий device protocol ST, BOT/SCSI и ранее написанный
контроллер OTG FS сохранены. Отчёт: `../measurements/stm32-owned-usb-20261014.json`.
Сборка использует проектные snapshot-файлы; установленный STM32 SDK не меняется.
Внешние MCU сохраняют прежний Arduino backend.

## 2. Запуск, время, питание и GCC — в работе

Самостоятельная таблица векторов/startup CMSIS, фиксированное HSE/PLL/APB,
SysTick и задержки, PVD/STOP/wake. Arduino Core и реализации HAL исключаются
из списка объектов; CMSIS, LL ST и нужный USB protocol остаются.
Нативная прошивка требует отдельной проверки запуска и глубокого сна.

## 3. RAM по времени жизни — далее

Проверить совмещение наших временных буферов с явным владением. Ёмкости кешей,
производительность NOR и доступность функций проверяются отдельно.
