# Ускорение массового USB-импорта на mini

Дата: 12.10.2026. База разработки: `0b01164c6`.
Ветка: `feature/usb-import-speed`.

`plan-fat12.md` удалён по указанию пользователя. Текущая работа касается
массового импорта и выхода из USB на mini A00.

## Реализация

Встроенный USB-диск на F411 с символьным экраном собирает до четырёх
маленьких TXT под одним каталогом вне корня. Внешний UTF-8 размер ограничен
64 байтами. Неизменённые файлы между изменениями не разрывают группу.
Группы поддерживают создание и замену; старые ссылки соседей сохраняются.
Большие файлы, другие типы, корень тома и перемещения используют обычный путь.

Перед первой физической записью проверяются ID, типы, родитель, имена,
коллизии внутри группы, M8, FAT-назначения, квота новых узлов и no-op.
Данные и неизменяемые F9CH mapping записываются в один заранее выбранный
сектор; transient pin запрещает его использовать для GC/метаданных.
Если ошибка чтения заставляет writer сменить сектор, группа не публикуется.
Один существующий W9 record публикует весь ограниченный набор inode.
Формат C9 и APP ABI не меняются.

Буфер группы находится на стеке APPLY; в BSS добавляется только указатель.
Указатель восстанавливается при каждом выходе из обхода, включая ошибку.
F401 и Classic сохраняют путь по одному файлу и прежние ROM/APP резервы.
`MK61_C9_BULK_IMPORT` позволяет явно выбирать fast path для исследования.
Обычная запись с уже заданным ID не повторяет поиск имени по всем siblings;
полная проверка конфликтов видимых имён остаётся.

## Проверки

Прямой batch suite: preflight, создание и смешанные create/replace,
512 Before/Prefix/Bits/Complete cut points, checkpoint, remount, повтор,
соседний guard payload и no-op без flash mutations.
Полный VFAT mutation/recovery corpus: 587 случаев. Strict Clang18 и
AppleClang ASan/UBSan CI, 16 F411 и 9 F401 release cases прошли.

Контрольный mini B1AA6D73: 320 native пустых + 320 macOS файлов,
1980 readbacks / 146456 bytes, 5 warm reset, delete/refill 107, cleanup.
Время выхода после создания: 36.358 с, после delete/refill: 24.598 с.

Первый batch-only кандидат 71C2CD5E прошёл такой же полный HIL;
выход 29.912 / 23.851 с. Смешанный кандидат D44BEB86 добавляет
групповые замены; его финальные аппаратные результаты приведены ниже.

Первая попытка D44BEB86 остановилась на отказе macOS loginwindow
размонтировать том. После проверенного force-unmount/eject все 655 файлов
совпали; remount и cleanup прошли. Время этой попытки не используется
для оценки ускорения. Окончательный непрерывный повтор прошёл оба eject без host dissent;
побайтовые проверки после обоих перезапусков завершились. Финальный cleanup
завершён. Полный прогон620.07с,1980 readbacks/146456bytes,5warmreset,
interrupted upload1,cleanup=true. CRC valid,VFAT0/staged0,CRASHnone,WDOGreset0;
в корне толькоSystem, устройство в CDC.

## Не принятые прототипы

Полная blank-sector проверка перед erase уменьшила операции на host-модели,
но почти не ускорила реальную flash, ранее заполненную старыми записями:
выход 35.556 / 23.682 с. Эта оптимизация не включена в итоговый код.
Консервативное сохранение live-sector bitmap между публикациями проверено
host/fault suites, но не прошло исходный Classic STOP ROM reserve и также
не включено. Ни RAM, ни ROM gates не ослаблены.

## Окончательные измерения D44BEB86

| Сценарий | B1AA6D73, с | D44BEB86, с | Сокращение |
| --- | ---: | ---: | ---: |
| Выход после создания 320 host файлов | 36.358 | 30.189 | 17.0% |
| Выход после 107 удалений/refill и rename | 24.598 | 21.446 | 12.8% |

Это end-to-end время от команды macOS eject до CDC на том же устройстве
и том же контрольном наборе. Оба окончательных eject штатные, без force и
без loginwindow dissent. Массовое создание на хосте существенно не
ускорилось: улучшение приходится на публикацию/выход. Большой изменённый
том всё ещё выходит за 21–30 с; мгновенный выход не заявляется.

Classic normal fallback:393148 bytes, static RAM40272. STOP WS/Classic:
free151448/131124 при прежнем reserve131072, RAM30144/40272. Все resource
лимиты и C9/APP ABI сохранены.
