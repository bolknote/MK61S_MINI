# Узкий UC1609 после математического этапа

Кадры Classic уже рисовал собственный MK61Display. В native UC1609 теперь
не наследует ERM19264_graphics: нет vtable, виртуальных write/drawPixel,
курсора, масштаба/поворота, активного framebuffer и программного SPI. Пины
и геометрия 192×64 — константы, в объекте остаются только контраст и режим
адресации (2 байта). Исходник generic graphics исключён из native CMake.
Проверки обрезки входных буферов, общая шина SPI и протокол панели сохранены.

Classic: Flash 361760→360656 (−1104), RAM 28608→28560 (−48), CRC BB67EF5C.
Mini A00: тот же побайтно образ F8C56B67, Flash 333160 / RAM 27224; эта библиотека
там не применялась. Для прочих MCU сохранён прежний интерфейс.

Host-тест исполняет реальный драйвер в старой и новой конфигурациях под
ASan/UBSan: полный кадр, страницы, обрезка источника, питание/сон и занятый SPI.
Четыре UI-конфигурации сравниваются с независимой пиксельной моделью. На обеих
платах до изменения и на Classic после него получено по 103 полных CRC-кадра
через обычный APP: все 1536 байт совпали с независимой формулой. Размер стека
проверен до reset: осталось 13028 байт при пороге 12288. Пройдены 16 F411 / 9 F401,
ARM-тесты математики, обыкновенных APP и запуска. ELF-гейт отклоняет старую
vtable даже при отсутствии прямых вызовов graphics; исходный ELF даёт
ожидаемый отрицательный результат.

Шаг эмулятора Classic: 1712216→1712200 циклов. Чтение 64 КиБ по 60 отсчётам:
24987→25008 мкс (+0,084%).100 чтений по 64 КиБ прошли с одинаковой CRC и
нулевыми ошибками SPI/DMA. Исходные файлы и состояние калькулятора сверены.

Новый HIL также обнаружил проблему на исходной прошивке: после выхода из
графического APP и USB Screen удаление временного APP возвращает storage error
до перезапуска. Это отдельный сценарий для последнего этапа USB/cache.
В `tests/hil_graphics_narrow.py` обычный путь сохраняет этот регрессионный
сценарий; явный `--restart-after` позволяет измерять кадры на исходном образе.
Он допускает только пустую программу и нулевые регистры/стек/IP, проверяет
файлы и полное сохранённое логическое состояние после reset/очистки. Прошивку
тест не меняет. Отчёт:
[stm32-owned-graphics-20261014.json](../measurements/stm32-owned-graphics-20261014.json).
