# Бинарная загрузка программ МК-61

24.09.2026. В терминале и M61 работает `load <адрес> <путь.bin>`.
ELITE переведена на один бинарный образ; прошивка `7C3ABA81` и комплект
игры установлены и проверены на Classic V3 / UC1609.

## Команда и формат

```text
reinit
load 0000 elite.bin
run
```

Адрес — ровно четыре десятичные цифры. Байты распаковываются подряд по
абсолютным адресам, автоматически переходя через границы банков по 112
байт. Поэтому один образ ELITE заполняет все 32 банка, включая нулевые
промежутки. Сама команда не очищает память и не запускает программу;
несколько `load` могут загрузить независимые диапазоны.

Файл содержит:

| Смещение | Данные |
| --- | --- |
| 0…3 | CRC32/ISO-HDLC распакованных байтов, u32 little-endian |
| 4…EOF | Один прямой поток ZX0 v2 с маркером конца |

Полей размера нет. Декодер обнаруживает конец по ZX0, затем проверяет EOF
и CRC фактически записанной памяти. Адресный предел и наличие свободных
банков проверяются по мере записи. В AUTO включается расширенная память;
принудительный режим 105 шагов сохраняет свой предел. Загрузка во время
RUN и из trap-обработчика запрещена.

В терминале путь отсчитывается от текущего каталога, в M61 — от каталога
выполняемого файла. Поддержаны абсолютные пути, пробелы и кавычки. Старые
`load <номер>` и `load <путь.m61>` сохранены, включая `load 2026 demo.m61`.
Для остальных двусмысленных числовых имён можно заключить полный путь
в кавычки.

При ошибке распаковки M61 останавливается; запуск и прямая правка команды
блокируются до `reinit` или открытия нового корневого M61. Частичная
запись не откатывается. Ошибка открытия файла до распаковки не блокирует
старую программу.

`ztart`, `zin` и Base91 удалены из прошивки и упаковщика.
Старые загрузчики с этими командами требуют пересборки.

## Хранилище и память

Добавлен тип C6 `MK61_BINARY = 11`, magic `M3`, расширение `.bin`, предел
4096 байт. Числа прежних типов не менялись, форматирование C6 не требуется.
USB MSC и CDC `fsput`/`fsget` передают файл побайтно. Дополнительного
M8/UTF-8 преобразования и прозрачного сжатия C6 нет.

Большие BIN используют существующий потоковый механизм C6. Он подключён
как в резидентный USB-диск F411, так и в отдельный `USBDISK.APP` F401;
таблицы типов публичного C API и portable SDK обновлены.

Входной буфер загрузчика — 128 байт. Словарём ZX0 служит уже записанная
программная память; полной копии образа в RAM нет. Аппаратная CRC
захватывается после окончания чтения файла, чтобы не пересекаться с CRC
самого C6. Локальный frame `program_load::load` на F411 равен 280 байтам
по `-fstack-usage`; у прежней `data` он был 272 байта. Это размер одной
функции, не всей цепочки вызовов.

У C6 BIN длиннее 1600 байт хранится в больших блоках с 4-КиБ erase-секторами.
Поэтому уменьшение длины файлов ниже не означает такой же процент
освобождённых физических секторов NOR: он зависит от размещения записей.

Упаковка на ПК:

```sh
python3 tools/program_pack.py raw-image.bin program.bin
python3 tools/elite/build.py --check
```

Python-обёртка автоматически собирает и вызывает оптимальный C++ ZX0.
Допустимы 1…3584 исходных байта. Генерация детерминирована.

## Размер и загрузка ELITE

| Показатель | До | После |
| --- | ---: | ---: |
| Файлы с образом | 2 M61 | 1 BIN |
| Суммарная длина этих файлов | 2558 | 2017 байт |
| Полный распакованный образ | 3584 | 3584 байта |
| Занятые байты игрового кода/данных | 3100 | 3100 |
| Медиана команды открытия загрузчика, устройство | 103,883 | 43,946 мс |

Файлы уменьшились на 541 байт (21,1%). В аппаратном замере команда
завершалась примерно в 2,36 раза быстрее. Это пять измерений `open`
с очисткой и загрузкой, без памятки и запуска игры, включая задержку CDC.
Исходная прошивка устройства — `65CDC4E9`, новая — `7C3ABA81`; секунды
характеризуют комплекты до/после, а не изолированное время ZX0.
После каждого замера прочитаны и сравнены все 3584 байта.

Распакованные байты побайтно совпали с исходной сборкой:

- CRC32: `466D2C18`;
- SHA256: `6c34a2138a7099a5739d6d64ee405cf5abc84612c1c0303350c84da2d143a25d`.

Контрольные сборки одинаковыми инструментами и опциями до/после изменения:

| Сборка | Flash до → после | Постоянная RAM до → после |
| --- | ---: | ---: |
| F411, Classic V3, USB Screen | 349944 → 349568 (−376) | 65604 → 65572 (−32) |
| F401, Classic V3, внешний USBDISK, без USB Screen | 251612 → 251160 (−452) | 35372 → 35324 (−48) |

Flash здесь — отчёт Arduino CLI; запечатанный F411 BIN занимает 350092
байта. F401 также собран с проверкой CRC; его `USBDISK.APP` занимает
13186 байт. На физическом F401 эта редакция не испытывалась.

## Проверки

На ПК прошли:

- загрузчик с ASan/UBSan: все значения байта, случайные данные, все усечения,
  неверная CRC, лишний хвост, ошибки чтения/записи, 105/10000-байтовые пределы,
  несколько диапазонов без очистки и 2000 повреждённых потоков;
- M61: относительные пути корня и вложенного файла, остановка на строке
  ошибки, сброс блокировки новым корневым сценарием;
- C6 и virtual FAT: хранение и перезапуск, многокластерный BIN, все 4096
  байт и отказ при 4097, сохранение предыдущей записи при отказе;
- терминал, каталог команд, справка и portable APP/ABI;
- вся ELITE через настоящий M61-runner, бинарный загрузчик, ядро и ПЗУ:
  **2486 остановленных состояний**, включая торговлю, 256 миров и бои.

На устройстве `AEB505B6E0067623`:

- полный 3584-байтовый образ ELITE совпал с ПК;
- общий BIN с байтами 00…FF, переходом через банки и адресом 9999;
- несколько загрузок без очистки, относительные пути и вложенный M61;
- плохая CRC, обрыв, хвост, выход за адрес 9999 и исчерпание 32 слотов
  останавливают загрузку и блокируют запуск;
- обычный USB-диск: 4096-байтовый BIN с русским длинным именем импортирован,
  прочитан через C6, пережил reset и экспортирован обратно без изменений;
  два безопасных извлечения, `vlog code=0`;
- заставка и семь действий через USB Screen: новая игра, кредиты, покупка,
  трюм, выбор мира, расстояние, перелёт. Состояния и кадры совпали с ПК;
  ввод не менял индикатор, каждое действие публиковало один готовый кадр.

Финальная аппаратная CRC прошивки: `valid`, backend `hardware`;
`CRASH none`. Справка обновлена, `part00.m61` и `part01.m61` удалены,
временные тестовые файлы очищены. Игра оставлена на заставке.
