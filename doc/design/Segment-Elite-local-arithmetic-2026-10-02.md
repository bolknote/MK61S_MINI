## Четыре изменения

### Одно вычитание для манёвра

`enemy_tick` вычисляет манёвр минус 4 и сохраняет результат в COMBAT.R4.
Ноль обозначает манёвр 4; отрицательные значения — остальные три манёвра.
Две дальнейшие проверки половинного урона читают R4 и проверяют ноль,
не повторяя вычитание. До первого хода R4 остаётся нулевым резервным значением.
При инициализации встречи и запросах поведение сохранено.

Явный В↑ перед следующей двойкой сохранён. Следующая операция Lx читает
двойку, полученную сложением, поэтому перенос записи R4 не меняет её аргумент.
Это изменение внутреннего представления единственного поля; команды игрока
и модель движения, половинного урона и уклонения прежние.

### Готовая разность для нагрева лазера

После охлаждения успешная проверка оставляет в X значение `нагрев−70`.
При разрешённом выстреле прибавляется 98, получается `нагрев+28`.
Повторное чтение регистра и ввод 28 больше не нужны. Условие закрывает
числовой ввод, поэтому цифры 98 автоматически поднимают разность в стек.
При слишком горячем лазере выполняется прежний отказ без прибавления нагрева.

### Пробное сокращение через границу банка

Сборщик прежде рассматривал только дальние переходы, чья цель уже находилась
в банке вызывающего кода. Теперь пробуются все не закреплённые дальние
переходы: сокращение инструкции может позволить целому блоку цели переехать
в этот банк. Каждая попытка заново размещает программу и расширяет
невалидные короткие переходы. Принимается только строго меньшая стоимость
всех инструкций и переходов между частями модулей; иначе восстанавливаются
флаги переходов и ширина указателей.

В ELITE вызов `show_message` из `start` становится коротким, а процедура
перемещается из B26 в B00, начиная с позиции 100. Стартовые обработчики
сдвигаются на два байта, оставаясь в разрешённых позициях 01…99.
Регрессионный пример без кода игры показывает такое же перемещение:
цель 224 → 100, стоимость 220 → 218, без перехода продолжения.

### Дальняя граница схемы дистанции

У `draw_range → range_far` сохранена существующая дальняя форма `1F 5C`.
Добавление двух байтов условия убирает четырёхбайтовый переход продолжения
из хвоста B08. Все сто вариантов схемы дистанции проверяются прежним тестом.
Это локальная настройка размещения, а не изменение набора команд.

## Проверки

Сравнены 187 одинаковых сессий, 5765 остановленных состояний каждого
варианта. Проверялись кадры и число публикаций, удержание дисплея при вводе,
X, ошибки и остановка, все шесть страниц, символический режим игры и
боевые кеши. Переехавшие указатели режимов сверялись по соответствующим
меткам, включая точную отрицательную форму, которую нормализует ПЗУ.

Для COMBAT.R4 проверяется точное преобразование: нулевое поле до хода
сохраняется, ненулевой исходный манёвр становится меньше на четыре.
Только после этой проверки поле приводится к прежнему представлению для
сравнения остальных страниц. Других исключений для игровых данных нет.
Все девять вариантов дали те же результаты и кадры во всех состояниях.

Обычный набор дополнен 24 сценариями: исходный нагрев 0, 9, 10, 79, 80, 90
при каждом из четырёх манёвров. Независимое ожидание использует прежние
правила: сначала охлаждение на 10 с ограничением нулём; затем выстрел
только при нагреве меньше 70 и прибавление 28. Проверяются нагрев, корпус,
щит, время, деньги, HOLD, дистанция, урон, режим и кадр. Нулевое R4
до первого хода и новое представление после хода проверяются отдельно.
Эти сценарии добавляют 144 состояния; полный обычный набор содержит 5909.
Прежние проверки неизменности страниц при отказах и запросах не ослаблены.

`bash tests/run_elite_tests.sh` проверяет 5909 состояний, сборку BIN,
CRC32, размещение и детерминированную повторную сборку; отдельно выполняет
два опыта самомодификации через Ms. `git diff --check` проверяет патч.
Итоговый BIN побайтово совпадает с экспериментальным вариантом «все четыре».
На физический калькулятор эта редакция не заливалась.
