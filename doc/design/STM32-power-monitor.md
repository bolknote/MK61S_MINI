# Контроль питания STM32 PVD и запрет опасных записей

## Цель

Внешняя W25Q128JV допускает питание не ниже 2,7 В. При исчезновении USB
прошивка не пытается «успеть сохранить всё»: без измеренного hold-up time это
невозможно гарантировать. Вместо этого аппаратный PVD STM32 закрывает вход для
новых команд NOR program/erase и новых USB MSC writes до опасного участка
спада. Уже начатая операция не прерывается.

Решение одинаково собирается для STM32F401 и STM32F411. На остальных
платформах API остаётся безопасным no-op и разрешает записи.

## Порог и гистерезис

По умолчанию используется `PLS=6` (`MK61_PVD_LEVEL=6`). Общий для
STM32F401/F411 паспортный диапазон:

- падение: 2,85–2,99 В, типично 2,93 В;
- восстановление: 2,96–3,10 В, типично 3,03 В.

Это выше минимальных 2,7 В W25Q128JV, но ниже измеренных на mini V3 3,28 В.
`PLS=7` не выбран: верхняя граница восстановления 3,21 В оставляет слишком
малый запас относительно штатной линии 3,3 В. После восходящего фронта запись
остаётся закрытой ещё `MK61_PVD_RECOVERY_STABLE_MS=100` мс. Новый спад в это
окно начинает ожидание заново.

Выбор ступени является build-time параметром. `threshold_range()` компилирует
только выбранную строку, а не хранит таблицу всех уровней в дефицитной Flash
F401.

## Инициализация и IRQ

`power_monitor::initialize()` вызывается до инициализации C5 и USB. Он:

1. читает корректный `.noinit` breadcrumb предыдущего запуска;
2. включает PWR/PVD и EXTI16 на оба фронта;
3. сразу считывает фактический `PVDO`, чтобы старт при уже низком VDD был
   закрыт без ожидания IRQ;
4. ставит `PVD_IRQn` приоритет 1, выше SPI DMA с приоритетом 2.

ISR не печатает, не вызывает файловую систему, USB, NOR или allocator. Он
только считывает компаратор и время, меняет атомарное состояние и счётчики,
публикует 16-байтный breadcrumb. ELF gate ограничивает весь обработчик 128
байтами и проверяет отсутствие запрещённых вызовов.

Основной цикл дополнительно считывает `PVDO` в `poll()`. Это закрывает короткое
окно, когда EXTI уже pending, но IRQ был временно замаскирован критической
секцией. Повтор одного уровня не создаёт фиктивного события.

## Состояния

- `stable`: записи разрешены;
- `low`: PVD ниже порога, новые записи запрещены немедленно;
- `recovering`: напряжение поднялось, но ещё не прошло 100 мс устойчивости;
- `uninitialized`/`unsupported`: диагностические состояния платформы.

Переход `stable → low` закрывает gate. `low → recovering` запускает таймер.
Любой bounce возвращает `low`. Только непрерывные 100 мс высокого уровня
возвращают `stable`. Расчёт времени корректен при переполнении `millis()`.

## Два уровня защиты записи

Высокий уровень USB MSC отклоняет новый пакет, deferred write и sync, а
динамический `WRITE PROTECT` сообщает хосту текущее состояние. Это даёт
понятный отказ протокола и не запускает новую C5-транзакцию.

Нижний уровень `SpiNorFlash` является обязательной последней защитой:

- проверка перед `WREN` для каждой страницы или сектора;
- повторная проверка после захвата CS, непосредственно перед destructive
  opcode;
- отдельные счётчики отказов program/erase/MSC.

Повторная проверка нужна потому, что `writeEnable()` может ожидать окончания
предыдущей операции. Верхний gate без нижнего не является достаточным.

Эта схема не обещает завершить page program или sector erase, уже начавшийся
перед падением VDD. Сохранность обеспечивают существующие C5 staging/commit и
восстановление последней завершённой транзакции. Реальное окно от PVD до BOR
нужно измерять регулируемым источником и осциллографом; обычный USB power-cycle
доказывает отсутствие ложных срабатываний, но не worst case.

## Breadcrumb

В `.noinit.mk61_power_monitor` лежит 16 байт:

- magic и его инверсия;
- `millis()` последнего падающего фронта и его инверсия.

Последовательность записи делает разорванное обновление недействительным.
После reset валидная запись становится `previous_unstable`; при устойчивом
питании breadcrumb очищается. Это диагностическая улика, а не доказательство
причины reset: точная интерпретация учитывает также RCC reset flags.

## Диагностика

`df` и `prof` печатают строку вида:

```text
POWER PVD6 fall=2850-2990 rise=2960-3100 state=stable gate=1 wait=0 event=0/0 last=none@0 prev=0@0 reject=0/0/0 reset_flags=0x...
```

Поля `event` — число падений/восстановлений, `reject` — отклонённые
program/erase/MSC, `prev` — валидная улика предыдущей загрузки. Счётчики
насыщаются и не переполняются.

## Доказательства и ограничения

- pure policy test: фронты, bounce, recovery и wraparound;
- source gate: ISR не содержит высокоуровневых API, NOR и MSC имеют gate;
- ELF gate F401/F411: сильный vector, bounded handler, breadcrumb в `.noinit`;
- строгая release matrix и отдельный F401/UC1609 Flash/RAM budget;
- HIL: штатная линия 3,3 В не должна создавать событий, C5/USB остаются
  работоспособны после обычных power-cycle.

Не завершено без отдельного стенда: медленный ramp, порог конкретного
экземпляра, время PVD→BOR под erase/program и проверка осциллографом.
