# Новый FOCAL поверх общей VM

Реализация написана в отдельном worktree `compact-focal-next`, ветка
`feature/compact-focal-next`. Основой служат платформенный адаптер,
хранилище и редактор BASIC; прежний код FOCAL при реализации не читался.

## Архитектура

`focal_syntax.hpp` содержит компактные таблицы операторов/функций и общий
сканер для транслятора и клавиатуры. `focal_compiler.hpp` — два прохода по
тексту: расчёт адресов/размеров и эмиссия. Сохраняется только отсортированный
индекс строк, без дерева выражений, токенизированной копии или heap.
Выражения для ASK имеют отдельную специализацию без таблицы строк/ресурсов.

`focal.cpp` — адаптер экрана, файлов, меню и редактора. Compiler APP хранит
только текст и данные выбора/диагностики. Исполнение происходит после его
выгрузки через существующий protocol BASIC/VM. Литералы могут быть собственными
ресурсами образа или проверенными ссылками на неизменный исходный файл;
одинаковые тексты интернируются, M8 не преобразуется.

Редактор использует общий `text_editor` BASIC и специализированные hooks:
операторные клавиши в полях после номера/`;`, приоритет общей пунктуации K,
атомарная навигация/забой, калькуляторные макросы, защита текста комментариев.
`IF` вставляется прежней клавишей B; `BRANCH` не принимается.

## Расширение байткода

Добавлено **шесть** инструкций, в конце enum, без перенумерации прежних:

| Инструкция | Байты | Поведение |
| --- | --- | --- |
| `ARRAY_CELL` | 2 | Два индекса → физический индекс элемента именованного массива |
| `CALL_PARAMS` | 7 | Адрес, граница естественной подпрограммы, число параметров, признак результата |
| `LOAD_PARAMETER` | 1 | Номер ARG со стека → значение параметра текущего вызова |
| `RETURN_VALUE` | 1 | Вернуть значение, восстановив стек/циклы вызывающей стороны |
| `DROP` | 1 | Отбросить результат EXEC |
| `PRINT_PRECISION` | 3 | Ширина поля и число значащих цифр |

`MIN` понижается в NEG/MAX/NEG, `MOD` использует существующий MOD.
Цепочки операторов, ASK, CLS и FOR также используют существующие инструкции.
Существующие JUMP/BRANCH сохраняют активный вызов; FFFF в ветви означает
продолжение, выход за тело активного цикла снимает соответствующие циклы.
SOURCE_POS работает для обоих языков, UPDATE_LOCAL применяется и новым
транслятором. HALT/EXIT корректно завершает всю программу из подпрограммы.

Параметры остаются в существующем стеке Value, не в отдельном массиве аргументов.
CallFrame содержит только дополнительные байтовые base/arguments/mode:
параметры переживают вложенный вызов и замещение native APP. CALL требует
явного RETURN со значением; автоматический возврат допустим только для DO.

Массив использует пары key/value в отдельном пуле Value. Для 32 элементов
нужно 512 байт. Ключ точно представим в binary64: имя + два 15-битных индекса.
Массив BASIC не уменьшается и не очищается при запуске FOCAL.

Байткод: VERSION=5, REQUEST_VERSION=8. Continuation/ExecutionState вырос на
64 байта до 1584. Сохраняемые значения выросли с 3504 до 4016 байт; защищённый
compiler prefix теперь 4176 байт. Snapshot/flow версии обновлены.

## Проверка

Host-проверки с ASan/UBSan: язык, массивы и пределы, параметры, рекурсия,
цепочки, IF, формат, MK-61 references, мини/classic/40TH клавиатуры; общая VM,
owned/source resources, INPUT и BASIC; resident и split-overlay исполнители.

Реальные ARM APP исполнялись под Unicorn на трёх адресах с отравлением памяти
каждого выгруженного APP. Проверены CALL/ARG/RETURN, рекурсивная функция,
ASK в массив внутри функции при незавершённом выражении вызывающей стороны,
сохранение частичного PRINT, ввод выражения, формат вывода и общий APP flow.
Это проверка машинного кода, не измерение живого устройства или прошивка.

Измерения xPack ARM GCC 14.2.1, -Oz/LTO, ZX0+BCJ:

| APP | Файл | Загруженная память |
| --- | ---: | ---: |
| FOCAL compiler | 12245 | 16732 |
| BASIC compiler | 13253 | 18488 |
| LANGVM split | 9761 | 14476 |
| LANGIN | 11488 | 15136 |

Полный F401 Classic V3 CORE-комплект собран: sealed resident 256572 байта,
статические глобальные данные 36364 байта; LANGVM 9750/14452 байт и LANGIN
11466/15096 байт (файл/память). LIBM в этом F401-профиле превышает Flash на
10448 байт, поэтому CORE выбран по умолчанию для F401+FOCAL. F411 сохраняет
LIBM. Прочие цифры таблицы совпадают с полным комплектом. Compiler workspace ARM:
FOCAL 1708 байт, BASIC 3976 байт. Host adapter с данными: 2432 байта.

Полностью автономный FOCAL с собственным kernel не помещается в 20-KiB APP
арену. Поэтому portable builder всегда выпускает compiler FOCAL, а штатный
bundle выбирает общую VM. Native fallback оставлен только для host-проверок
и встроенной исследовательской сборки, не как поставляемый FOCAL.APP.

## Восстановление прежних контрактов, 09.10.2026

Сначала добавлен отдельный красный коммит тестов прежнего поведения: клавиши,
компактный исходник и editor-view, публичный CompileFocal/RunFocal, переходы из
DO, PRINT, макросы и атомарный забой, отказ записи/переименования, локализация
и Serial-трассировка. На mini/classic/40TH до исправлений было 43 падения,
с трассировкой — 45. После восстановления все проверки проходят; расширения
языка и BASIC остаются в отдельном регрессионном наборе.

В runtime хранится точный короткий текст файла, а развёрнутый редактор использует
временный хвост той же аренды. Compiler runtime остаётся прежнего размера;
editor lease укладывается в защищённый prefix 4176 байт и освобождается после
редактирования. Параметры CALL не теряются при внутренних переходах; процедуры
DO сохраняют прежнюю семантику распространения GOTO/IF.

Семантическое изменение байткода отмечено VERSION=6 (структуры request v8 не
меняются). Для отладочных APP добавлен append-only DEBUG_WRITE, capability
DEBUG_IO; сервис resident включается только с MK61_FOCAL_TRACE. Тот же флаг
передаётся compiler/VM при сборке bundle и входит в ключ каталога APP.

Итог восстановления: обычный FOCAL.APP 13604 байта, загрузка 18556 байт;
отладочный 13729/18716 байт. Все APP укладываются в прежнюю арену 20 KiB.
Полный обычный F401 resident: 256572 байта, отладочный: 256700 байт;
статические данные в обоих — 36364 байта. Проверки совместимости: 82 без
трассировки и 85 с ней, на каждой из трёх раскладок (501 проверка).
ASan/UBSan, общий BASIC/VM, кеш и compiler-flow проходят. Реальные ARM
пакеты проверены на трёх адресах, с замещением APP и проверкой журналов UART.
Текст редактора и слота, отказ записи/удаления и результат перехода проверяются
на реальной реализации; файловое устройство и Serial в host-проверках — fixtures.


## Перенос SIMD-сканера, 09.10.2026

Перенесён коммит `76b41485219b0e9b1a697ce46abac131e988d6cf`
из основной ветки. Общий `language_source_scan.hpp` подключён также к
новому `focal_next::Compiler::index_lines()`: ARM SIMD32 проверяет четыре
байта за раз с USUB8/SEL, точный хвост обрабатывается скалярно. На других
платформах сохраняется скалярный путь. Дополнительных постоянных буферов,
heap или требований к выравниванию нет.

Тесты перенесённого коммита нашли ошибку нового компилятора: SOURCE_POS
содержал смещение от начала файла вместо колонки физической строки.
Исправлено вычисление колонки; ошибку массива во второй строке проверяет
отдельный тест. LF, CR, CRLF и LFCR, пустые строки и EOF без разделителя
дают одинаковые инструкции, таблицы строк и ресурсы. Размер и CRC исходного
текста закономерно различаются. Байткод остаётся v6, request ABI — v8.

Проверены скалярный и эмулированный SIMD пути с ASan/UBSan: все соседние
пары байтов и позиции внутри слова, M8, точные границы буфера, расширенный
FOCAL с массивами, CALL/ARG, цепочками и форматом PRINT. Полный VM/BASIC/FOCAL
набор прошёл с `MK61_VM_DSP_SCAN_TEST=1`, включая 501 проверку совместимости
на MINI, CLASSIC и 40TH с трассировкой и без неё. Прошли проверки лимитов
APP и целостности транспорта HIL; физический HIL в этом worktree не запускался.

Реальные ARM APP прошли overlay и compiler FLOW_STEP тесты под Unicorn на
трёх адресах загрузки с отравлением выгруженного APP. Добавлены CR/LF/M8
случаи и смешанные переводы строк при CALL/ASK с сохранением состояния.
В дизассемблированном FOCAL присутствуют обе пары USUB8/SEL; общий helper
занимает 86 байт. На macOS запуск Unicorn требует выхода из sandbox:
внутри sandbox его init_cache_info завершается до исполнения ARM кода.

Измерения xPack ARM GCC 14.2.1, -Oz/LTO, ZX0+BCJ после переноса:

| APP | Файл | Загруженная память | Изменение файла / памяти |
| --- | ---: | ---: | ---: |
| FOCAL compiler | 13690 | 18652 | +86 / +96 |
| FOCAL compiler с трассировкой | 13815 | 18812 | +86 / +96 |
| BASIC compiler | 13335 | 18568 | +82 / +80 |
| LANGVM split | 9860 | 14588 | 0 / 0 |
| LANGIN | 11485 | 15128 | 0 / 0 |

Изменение FOCAL включает исправление SOURCE_POS. LANGVM и LANGIN побайтно
совпадают с пакетами до переноса. Compiler workspace по ARM-пробе остаётся
1708 байт для FOCAL и 3976 для BASIC. Ускорение компиляции нового FOCAL на
физическом устройстве отдельно не измерялось; исторические HIL-цифры
в `sdk/portable/VM-CACHE.md` относятся к прежнему компилятору.

Артефакты локальной проверки: `/tmp/focal-simd-next/`, отчёты
`overlay-arm-report.json` и `flow-arm-report.json`.
