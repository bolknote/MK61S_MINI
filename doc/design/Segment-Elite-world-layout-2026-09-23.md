## Формула мира

Прежнее вычисление для номера `i` от 0 до 255:

```text
((251*i + 12345) mod 65536)*256 + i
```

После раскрытия скобок это `(64257*i + 3160320) mod 16777216`.
Вместо общего деления с извлечением целой части выполняются:

```text
world = 64257*i - 13616896
if world < 0: world += 16777216
```

Промежуточный результат находится в диапазоне −13616896…2778639.
Все целые точно помещаются в восемь десятичных цифр. Нужна максимум одна
коррекция; она перестаёт требоваться начиная с номера 212. Это упрощение
зависит от ограничения номера мира и не применяется к генератору случайных
чисел при прыжке, где возможны многократные переполнения модуля.

Тест всех 256 миров по-прежнему вычисляет эталон старой формулой. Совпали
полные коды миров и двенадцать масок индикатора. Отдельно ограничено время
выбора каждого мира: не более 88 шагов ядра.

## Размещение и окончания вывода

Частые процедуры `number_frame`, `name_frame`, `battle_frame` и `gauge_frame`
перенесены из B19 в B08. Их адреса теперь трёхзначные, поэтому при каждом
вызове вводится на одну цифру меньше. Обслуживание станции занимает B19;
команды пользователя и поля страниц данных остаются прежними.

Варианты переноса форматтеров в B04, B07 и B08 дали одинаковое число шагов
и занятых байтов. B08 выбран по размеру сжатого загрузчика. Итоговые части
занимают 1349 + 1216 = **2565 байт** вместо 2568. Образ остаётся равным
3584 байтам; свободны 432 байта, распределённые между банками.

Окончание вывода `2F 53; В/О` состоит из трёх байтов. Дальний переход
к общей процедуре стоил четыре байта и отдельное исполнение перехода.
Шесть окончаний встроены в форматтеры, отдельная процедура `display` убрана.
Сначала по-прежнему полностью собирается кадр B29, затем одна `2F 53`
публикует его. Промежуточных кадров и мигания при вводе не появилось.

После сокращения форматтеров начало `draw_gauge` помещалось в последние
семь байтов их банка. Жадное размещение добавляло перемычку к остатку
процедуры — это замедляло часть просмотров на шаг. У меток сборщика появился
параметр `keep_block=True`: блок до следующей безусловной передачи управления
размещается целиком. Он применён к `draw_gauge`, которая теперь начинается
в B22. При точном заполнении банка возврат может занимать последний байт;
лишнее место под перемычку внутри такого блока не резервируется.

В сборщике длины оставшихся фрагментов вычисляются без повторного суммирования
всего хвоста для каждой инструкции. Это ускоряет поиск раскладок на компьютере,
не меняя команды игры. Построение загрузочного образа также допускает целиком
свободные банки и заполняет их нулями, сохраняя полный размер образа.

## Испытанные, но не принятые варианты

* Два поиска порядка модулей проверили 3984 и 2991 размещение. Профиль снят
  по 299736 границам команд на тех же 113 партиях. Оценки по размеру, частоте
  переходов и длине указателей использовались только для отбора: двенадцать
  финалистов первого поиска затем полностью исполнены через ПЗУ. Лучшие по
  статической оценке перестановки оказались медленнее версии с одной новой
  формулой. Произвольная перестановка порядка модулей в итог не внесена.
* Обмен денег R0 и счётчика ходов R3 позволял выбирать поля приборов по
  формуле `RA+2`, убрав специальный случай денег. Вместе с новой формулой
  мира это давало 3157 байт, но 204522 шага вместо 203292 у варианта без
  перестановки. Пробы с новым размещением также замедляли часть действий.
  В сравнении этого опыта номера полей переводились обратно в исходную
  схему; игровые значения и кадры совпали. Перестановка не принята.
* Автоматическое сохранение всех подходящих блоков целиком сокращало
  суммарное время сильнее, но добавляло шаги к отдельным боям и перелётам.
  Например, сочетание с перестановкой полей давало 3141 байт и 199806 шагов,
  при этом 133 действия замедлялись на 1…3 шага относительно исходной игры.
  Выбран вариант с явной отметкой только `draw_gauge`, без замедлений.

Совмещение адресного байта с командой и применение тёмных адресов в самой
игре на этом этапе не добавлялись.
