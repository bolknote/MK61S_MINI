# ELITE: стек, X1 и проверка префиксов — 23.09.2026

Исходная версия — `210b3d3d`: 3187 занятых байтов, 397 свободных,
199153 шага ядра на 105 партиях / 1608 остановленных состояниях.
Этот этап применяет приёмы из [разбора 18 игр](Segment-Elite-optimization-reading-list.md)
к существующим формулам и обработчикам ELITE.

## Принятые изменения

* **Стек вместо временного регистра.** В `price_market` множитель `16+e`
  остаётся под вычисляемым треугольным числом. Убраны сохранение и повторное
  чтение RD; точность целочисленной формулы сохранена. При пробитии щита
  отрицательный остаток уже находится в X — повторно читать R5 не требуется.
* **X1 вместо повторного ввода константы.** `Lx` возвращает верхнюю границу
  после сравнения: 60 для щита и 99999999 для награды. Тот же приём возвращает
  6 при выборе цели и 2 при расчёте перемещения. Это использование последнего
  операнда X1, а не скрытого регистра X2.
* **Конечный регистр результата.** Ветви оружия сразу формируют исходящий
  урон в RD; лазер уже получил нужное значение в этом регистре. Входящий
  урон читается непосредственно из RE. Промежуточные копии через RC удалены;
  возвращаемый корпус по-прежнему находится в RC.
* **Один ноль для нескольких записей.** После `Cx; П4` или `Cx; ПE` ноль
  повторно сохраняется в следующий регистр без второго `Cx`.

Игра занимает **3170 байт**, свободны **414 байт**. Размер образа остаётся
3584 байта, сжатых частей — 2568 байт (1349 + 1219): меньший исполняемый код
не обязательно уменьшает поток ZX0 после изменения адресов.

## Испытанный, но отложенный вариант

Для станции проверены последовательные вычитания при разборе команды и
общий указатель на чтение/запись с автоинкрементом R5. Начальное значение
`READ−1`, первый `1F A5` получает адрес READ; прибавление `WRITE−READ−1`
готовит второй `1F A5` к записи. Сохранение R5 при обмене страниц работает.

Вместе с остальными изменениями вариант занимает 3164 байта и проходит все
1608 сравнений состояния, но требует 197703 шага: на 47 больше выбранной
версии. После переразмещения кода 181 действие замедляется на один-два шага.
В текущую игру этот вариант не включён.

## Исправление общей команды `2F 0E`

Обработчик читал X при ранней выборке префикса, когда ПЗУ ещё завершало
запись предыдущего результата. Воспроизведены четыре случая без разделяющего
NOP: `√81` выводило 81 вместо 9; `int(9/2)` ошибочно считалось дробным;
`0−19` принималось за положительную маску 19; `9/2` принималось за маску 2.
Числовой режим также мог показывать промежуточное значение.

Публикация теперь выполняется после существующего ROM NOP префикса,
аналогично уже исправленным условиям `1F`. Следующая команда поступает
в ту же выборку; отдельная задержка или дополнительная команда не нужны.
Отложенное состояние занимает прежнее двухбайтовое поле контекста:
старший бит различает условие `1F` и вывод `2F`.

Добавлено 48 сочетаний: 12 арифметических выражений × два вида индикатора
× размещение внутри банка / на его границе. Эталон — выполнение с явным
ROM NOP. Сравниваются результат, отказ для недопустимых масок, курсор,
кадр, числовой индикатор и пять регистров стека. Дополнительно проверяется
продолжение после сохранения и восстановления контекста между шагами.
Новая проверка падает на старом ядре и проходит после исправления.

Дальние FL продолжают требовать положительный целый счётчик: отказ при нуле
документирован и не изменён. Регрессии `1F`, `55/56`, пакетного вывода и
форматирования `2F 53/6n/7n` проходят в обоих вариантах таблиц ядра.
