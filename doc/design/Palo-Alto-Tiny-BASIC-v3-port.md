# План переноса Palo Alto Tiny BASIC v3

Источник совместимости — листинг Li-Chen Wang от 26 апреля 1977 года. Цель —
сохранить поведение языка Palo Alto Tiny BASIC (PATB), встроить его в интерфейс
MK61s mini и не потерять уже существующие калькуляторные расширения.

Текущий выполненный этап переносит семантику PATB в существующий C++-движок.
Это ещё не буквальный перенос компактной организации 8080-листинга. Поэтому
функциональная совместимость достигнута, а цель радикального уменьшения кода —
нет; она выделена ниже отдельным незавершённым этапом.

## Принятые ограничения

| Ресурс | Было | Стало |
| --- | ---: | ---: |
| Текст программы | 1536 байт | 3584 байта |
| Строки | 96 | 192 |
| Вложенность `GOSUB` | 8 | 16 |
| Вложенность `FOR` | 8 | 16 |
| Глубина выражения | 64 | 96 |
| Переменные | 26 (`A`–`Z`) | 26 (`A`–`Z`) |

Размер 3584 байта выбран так, чтобы программа вместе с метаданными по-прежнему
помещалась в один 4-КиБ сектор данных C5. Массив и рабочие структуры используют
существующее 8-КиБ языковое рабочее пространство, а не новую постоянную область
RAM.

## Этапы

- [x] Отделить лимит TinyBASIC от лимита FOCAL и увеличить его во всех путях:
  хранилище, virtual FAT, terminal upload, редактор и portable ABI.
- [x] Поднять пределы строк, `GOSUB`, `FOR` и выражений; оставить `A`–`Z`.
- [x] Вернуть конструкции PATB: `@(expr)`, `SIZE`, `STEP`, знак `#`, несколько
  присваиваний в `LET`, управляющие символы `^X`, ширину `PRINT #n` и выражения
  во вводе.
- [x] Разрешить исторический `;` между командами, сохранив `:` и существующий
  `;` внутри `PRINT`/`INPUT`.
- [x] Вернуть продолжение после `GOSUB` и `FOR` в той же строке и историческое
  поведение поиска нужного цикла командой `NEXT`.
- [x] Сохранить расширения MK61s mini: вещественную арифметику, ссылки `.X` и
  `.R0`, тригонометрию, логарифмы, округление и экранный редактор.
- [x] Убрать большой локальный буфер редактора: максимальный статический кадр
  ARM-стека снижен с 4976 до 728 байт.
- [x] Объединить синтаксическую проверку и исполнение команд в один проход и
  заменить цепочки сравнений ключевых слов компактными таблицами.
- [x] Убрать дублирование без сокращения языка: прямой разбор слов из исходника,
  общий табличный разбор бинарных/префиксных операторов, упакованные таблицы,
  резидентные форматирование и чтение чисел, разбор ссылок MK61, штатная
  раскладка редактора и базовые `mem*`-подпрограммы.
- [ ] Заменить рекурсивный C++-парсер отдельным компактным ядром по структуре
  PATB: табличный диспетчер, единый указатель текста и общий стек кадров; после
  этого вернуть расширения MK61s mini поверх ядра и повторно измерить APP.
- [ ] Провести проверку на реальном устройстве: редактор, C5/USB, длительные
  циклы, прерывание `ESC` и восстановление языкового workspace.

## Direct-режим

Исторические `RUN`, `LIST` и `NEW` представлены действиями меню и редактора.
Отдельная текстовая direct-консоль не входит в этот перенос: добавление второго
пользовательского интерфейса не меняет семантику сохранённых программ, но
увеличивает `BASIC.APP`.

## Контроль размера

Исходный 8080-код PATB занимает адреса `F000`–`F7FF`, то есть 2048 байт ROM.
Это не прямой эквивалент файла `BASIC.APP`: APP также содержит интерфейс экрана,
редактор, хранилище, форматирование вещественных чисел и ABI-обвязку.

После добавления совместимости размер сначала вырос до 12 676 байт. Второй
этап убрал дублирование и повторяющиеся ветви без удаления возможностей:

| Артефакт | До переноса | После совместимости | Сейчас | К старой версии |
| --- | ---: | ---: | ---: | ---: |
| `BASIC.APP` (ZX0+BCJ) | 11 848 | 12 676 | 9779 | −2069 |
| Несжатый образ | 17 256 | 18 308 | 14 017 | −3239 |
| Полная память APP | 17 340 | 18 396 | 14 048 | −3292 |

То есть расширенный интерпретатор теперь меньше прежней реализации APP. Часть
кода стала общей для BASIC и FOCAL: резидентная прошивка выросла с 247 456 до
249 256 байт, но оба языковых APP вместе уменьшились с 25 831 до 22 444 байт.
Суммарно прошивка плюс два APP занимают на 1587 байт меньше; свободный запас
F401 после запечатывания составляет 12 888 байт. Это не маскировка размера
простым переносом всего интерпретатора в resident: общими стали только реально
повторявшиеся службы.

До 2-КиБ ROM оригинала весь экранный модуль всё ещё не приблизился. Дальнейшее
радикальное уменьшение потребует отдельного компактного ядра, а не удаления
функций или проверок.

Карта текущего несжатого образа показывает основные источники размера:

| Символ/группа | Байты кода |
| --- | ---: |
| Диспетчер и исполнение команд `tb_process_one` | 2844 |
| Первичные выражения и функции `parse_primary` | 1292 |
| Остальные уровни парсера выражений | 832 |
| Экранный редактор `EditTinyBasicSlot` | 1236 |
| Компиляция индекса строк и цикл исполнения | 996 |
| Вход модуля и ABI `mk61_module_entry` | 636 |

Только эти крупные символы дают 7836 байт несжатого кода, ещё до небольших
процедур ввода-вывода, хранения, форматирования, таблиц, строк и релокаций.
Тригонометрия не объясняет основной разрыв: его создаёт архитектура движка.
