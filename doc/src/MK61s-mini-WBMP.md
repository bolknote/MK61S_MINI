# Монохромные изображения WBMP

Версия документа: 26.07.2026

MK61s открывает стандартные файлы Wireless Bitmap (WBMP) Type 0 с расширением
`.wbmp`. Это однобитный несжатый формат: строки идут сверху вниз, старший бит
байта расположен слева, `1` означает белый пиксель, `0` - чёрный. Реализация
следует разделу 6 и приложению A спецификации WAP WAE от 24.05.1999:

<https://wapforum.org/what/technical/SPEC-WAESpec-19990524.pdf>

Собственного content magic и собственного варианта BMP у просмотрщика нет.
Тип файла в C5 называется `IMAGE1`, его публичная двухбайтовая сигнатура -
`I1`, но байты файла остаются обычным WBMP и открываются стандартными
программами.

## Подготовка изображения

ImageMagick создаёт совместимый WBMP штатной командой:

```bash
magick input.png -colorspace Gray -threshold 50% -monochrome WBMP:output.wbmp
```

Порог можно менять, например `-threshold 42%`. Для схем и пиксельной графики
полезно заранее привести картинку к целевому размеру без сглаживания:

```bash
magick input.png -filter point -resize '192x64>' \
  -colorspace Gray -threshold 50% -monochrome WBMP:output.wbmp
```

Файл копируется на USB-диск MK61s как обычный `output.wbmp`, в том числе в
произвольный каталог. Его можно открыть коротким `OK` в Проводнике либо из
терминала:

```text
open /Pictures/output.wbmp
```

Каноническое видимое расширение - `.wbmp`. В короткой FAT 8.3-записи оно
представлено как `.WBM`; этот псевдоним также принимается при чтении тома без
LFN.

Встроенных демонстрационных изображений в прошивке нет.

## Только графический экран

Просмотрщик работает только с графической поверхностью 192x64:

- физическим UC1609;
- активным виртуальным USB-экраном.

LCD1602 A00/A02 не является графическим экраном. Прежний вывод окна 80x14
через временной CGRAM-мультиплекс удалён: WBMP не уменьшает изображение, не
подменяет пиксели символами и не занимает CGRAM физического LCD.

На mini с A00/A02 файл можно хранить и видеть в Проводнике всегда, но открыть
его можно только во время активной сессии USB-экрана. Если сессия не запущена,
оболочка показывает `ГРАФИКА` / `НЕДОСТУПНА`.

Если виртуальный экран исчез во время просмотра, fullscreen немедленно
закрывается, физический LCD восстанавливается и показывает то же сообщение.
Если backend сменился на другой графический экран, просмотрщик заново
захватывает fullscreen и перерисовывает текущую область.

## Условная компиляция

Графический backend считается скомпилированным, если выбран UC1609 либо задан:

```text
-DMK61_ENABLE_USB_SCREEN=1
```

Отдельный просмотрщик без Markdown управляется флагом:

```text
-DMK61_ENABLE_WBMP_VIEWER=1
```

Если Markdown включён, он сам открывает `I1/.wbmp`, а отдельный WBMP-компонент
не собирается независимо от этого флага. При выключенном Markdown значение по
умолчанию равно наличию скомпилированного графического backend; явное `1` без
UC1609 и без USB-экрана является ошибкой конфигурации. Значение `0` при
выключенном Markdown исключает декодер и экранный модуль, но не тип `IMAGE1`:
записанные `.wbmp` остаются видимыми, копируемыми и удаляемыми.

На STM32F401 при `Markdown=0, WBMP=1` просмотрщик собирается как согласованный
`/System/WBMP.APP`. Он регистрирует сигнатуру `I1` в поле
`handled_type_magic` и получает файл общей командой `FILE_OPEN`. При
`Markdown=1` отдельного файла нет: графический `MARKDOWN.APP` принимает и
`T2`, и `I1`. На F411 те же варианты используют встроенную реализацию.

Общий механизм обработчиков и отличие type magic от первых байтов файла
описаны в
[`MK61s-mini-CHIP8.md`](MK61s-mini-CHIP8.md).

## Ограничения и проверка файла

Максимальный размер WBMP-файла - 1600 байт. Этого достаточно для полного кадра
192x64: 1536 байт пикселей и 4-5 байт заголовка. Изображение может быть шире
или выше экрана, если весь файл укладывается в квоту; тогда доступна
прокрутка.

Перед показом проверяются:

- TypeField `0`, отсутствие extension headers и нулевые reserved-биты
  FixedHeaderField;
- корректная big-endian multi-byte запись ширины и высоты;
- ненулевые размеры и отсутствие арифметического переполнения;
- точное соответствие длины файла вычисленному растру;
- нулевые неиспользованные биты в конце каждой неполной строки;
- CRC записи C5 при чтении из SPI NOR.

Повреждённый или не относящийся к Type 0 файл не выводится частично.

## Управление

`ESC` и `OK` закрывают просмотрщик. Стрелки влево/вправо сдвигают окно на
восемь пикселей. Сдвинутые стрелки влево/вправо перемещают его вверх/вниз на
64 пикселя. Координаты ограничиваются границами изображения, поэтому за
последней строкой или колонкой пустая область не прокручивается.

## Окно 192x64

Растр декодируется непосредственно в off-screen буфер 192x64 в нативном
page-major формате общего графического API. После успешной подготовки все
1536 байт передаются одним кадром без предварительной очистки экрана. При
прокрутке старый кадр остаётся видимым до полной готовности нового.

На время просмотра дисплей переходит в modal fullscreen-режим. Фоновые
обновления текстовой сетки и курсора продолжают обслуживать остальную систему,
но не могут перерисовать изображение. При выходе режим снимается и обычный
экран восстанавливается полной перерисовкой.

## Использование общей RAM

Файл один раз читается из C5 в `shared_scratch`; повторных чтений SPI NOR и
повторной проверки CRC в каждом кадре нет. Декодированный кадр размещается во
взаимоисключающем `language_workspace`, который также используется FOCAL,
TinyBASIC, CHIP-8 и USB-диском. Просмотрщик не может одновременно владеть этим
буфером с другим модальным runtime.

`shared_scratch` имеет 1600 байт ради максимального WBMP. Полный fullscreen
занимает 1536 байт независимо от UC1609 или USB-экрана. Отдельных буферов,
таблиц фаз и частоты LCD1602 больше нет.
