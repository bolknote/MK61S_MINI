# Расширения `1F` и `2F`

Это команды MK61s, а не реконструкция микропрограмм исходного МК-61. Они
исполняются в режиме памяти `112 шагов + RF` и в `auto`, если программа содержит
префикс как **команду**. В принудительном классическом режиме `105 шагов`
остаётся поведение ПЗУ МК-61. После обычной двухбайтовой команды перехода или
вызова (`51`, `53`, `57`…`5E`) байт `1F`/`2F` — её аргумент, а не префикс.
Исходное ПЗУ трактует такие аргументы как шаги 25 и 35 соответственно;
расширенный декодер обычного `ПП` сохраняет это правило.

## `1F`: абсолютная адресация

Программа разделена на банки по 112 байтов. Адрес `0000`…`9999` означает
`банк = адрес / 112`, `шаг = адрес % 112`; последний банк неполный. Банк 0 —
обычная память программы. Остальные банки выделяются по мере записи или
перехода. `55`/`56` продолжают работать с текущим банком.
На STM32F401 и STM32F411 одновременно могут быть заполнены 32 банка (включая
банк 0). Адресовать можно любой из 90 банков диапазона, но при исчерпании
свободных слотов запись или переход завершается ошибкой расширения. Очистка
программы освобождает все слоты.

| Последовательность | Действие |
| --- | --- |
| `1F 51 HH LL` | Безусловный переход |
| `1F 53 HH LL` | Вызов подпрограммы |
| `1F 57`…`5E HH LL` | Дальняя условная команда с условием указанного кода |
| `1F 7n/8n/9n/An/Cn/En` | Дальняя косвенная команда с регистром `Rn` |

`HH LL` — четыре десятичные цифры адреса в двух BCD-байтах: `1F 51 02 50`
переходит на адрес 0250. Косвенная команда берёт абсолютный адрес из
регистра. Для `R0`…`R3` и `R4`…`R6` сохраняется автоматическое
уменьшение/увеличение регистра. При ложном условии выполняется команда сразу
после всей последовательности `1F`.

Вызов сохраняет адрес **после** четырёх- или двухбайтовой команды. Обычные
`ПП`, косвенные и дальние вызовы используют общий расширенный стек глубиной
64; `В/О` возвращает и через границу банка. Некорректный адрес, неподдерживаемый
подкод или переполнение стека останавливает программу и устанавливает
внутренний флаг ошибки расширения. Для дальних `FL0`…`FL3` счётчик должен быть
положительным целым: при нуле расширение останавливает программу вместо
исторического десятичного переполнения регистра.

## `2F`: управление индикатором

Позиции `00`…`0B` — двенадцать знакомест слева направо: `00` — знак мантиссы,
`01`…`08` — цифры мантиссы, `09` — знак порядка, `0A`…`0B` — цифры порядка.

| Последовательность | Действие |
| --- | --- |
| `2F 00`…`0B` | Выбрать позицию |
| `2F 0D` | Очистить кадр и удерживать его пустым до `2F 52`, не меняя X |
| `2F 0E` | Вывести X; в сегментном виде записать маску и передвинуть курсор |
| `2F 25` | Передвинуть курсор без записи |
| `2F 50` | Отключить автоматическое обновление из X |
| `2F 52` | Вернуть автоматическое обновление |
| `2F 2A` | Переключиться на сегментный вид |
| `2F 30` | Вернуться к числовому виду |

В сегментном виде целое X от 0 до 255 — маска: биты 0…6 задают сегменты
A…G, бит 7 — точку. Все 12 позиций, включая знаковые 0 и 9, принимают
произвольную маску. Автоматическая публикация X меняет текущую позицию **без**
продвижения курсора; явный `2F 0E` продвигает его по кругу. X остаётся
арифметическим регистром, независимо от состояния экрана.

Произвольные сегменты рисуются на UC1609 с фиксированным калькуляторным
шрифтом. Символьный LCD1602 не может показывать независимую 12-позиционную
сегментную маску; на нём числовое удержание работает, но сегментный кадр не
визуализируется.

## Ввод из терминала

`hin` и `asm` принимают четырёхзначный абсолютный адрес в режимах `auto` и
`112 шагов + RF`; `hout <адрес> <число-байтов>` печатает произвольный
диапазон как команды `hin`. В `asm` отдельный байт можно написать двумя
hex-цифрами, даже если у него нет мнемоники. Одна строка записывает не более
112 байтов.

```text
hin 0000 1F510250
hin 0250 0750
hout 0248 8
```

Команды очистки программы и `reinit` очищают и добавленные банки, освобождая
все 32 слота для следующей программы.
Классический пошаговый редактор и `ins` не пересчитывают адреса внутри
многобайтового `1F`; для таких программ используйте `hin`/`asm` и проверяйте
байты через `hout`.
