# Исправления четырёх дефектов VM

База проверки: `43eea5d82875a61cc9a729c4ccc2332eb49d73c8`.
Измерения выполнены 6 ноября 2026 года с GCC ARM 14.2.1.
Аппаратные платы не использовались.

## Что исправлено

1. `integer_span` больше не выполняет FOCAL `JUMP` как простое изменение PC.
   Команда передаётся общему обработчику `focal_jump`, который возвращается
   из однострочного DO, разворачивает групповые DO и сохраняет границы CALL.
   BASIC сохраняет быстрый путь переходов. Проверены четыре сценария DO/CALL
   в обычном и постраничном исполнении, включая отдельные циклы PicoCalc.

2. INPUT больше не занимает верхние 32 слота стека исполняемой программы.
   Резидент владеет независимым `InputWorkspace`: 256 байт образа выражения
   и 32 временных Value. Он переживает выгрузку LANGIN/LANGVM и инициализируется
   только при вводе, без дополнительной очистки при каждом RUN.
   Сохранены MAX_STACK=96, MAX_CALLS=16, ExecutionState=1992 и рабочая область 8 КиБ.
   Проверены 15/16 вложенных GOSUB по четыре аргумента, INPUT переменной/массива,
   выражение глубиной 16, ошибка/повтор ввода и сохранение всех 96 слотов.

3. Сырые компиляторы BASIC/FOCAL записывают карту исходника отдельным проходом
   после записи кода. Временные длинные константы при свёртке больше не портят
   карту на окончательной границе кода. Проверены точная ёмкость с защитными
   байтами, столбцы исходника, исполнение и побайтное совпадение с paged-образом.
   Это добавляет проход только полному сырому компилятору; штатный paged-путь
   и двухпроходная компиляция выражений INPUT сохраняются.

4. Ключ целого образа linked PoC использует inode первого фрагмента контейнера,
   смещение модуля и эпоху носителя. Локальный отладочный source_id больше не
   подменяет идентичность файла. Зарезервированный диапазон chunk-ключей
   использует существующие поля ReadCache, без расширения RAM-кеша.
   Проверены разные контейнеры, разные невыравненные смещения, повторное тёплое
   заимствование и смена эпохи. В PoC экспорт использует объявленную в KernelExport
   таблицу Services, разделяя штатный kernel вместо второй специализации.

`REQUEST_VERSION=15`, обновлены private compiler/flow magic. Нужен согласованный
комплект прошивки и System APP. Формат LBV2 не менялся.

## Цена и лимиты

Одинаковые параметры сборки базы и исправления; бюджеты не изменялись.

| Сборка | Flash до | Flash после | Изменение | Статическая RAM после | Максимальный frame / лимит |
|---|---:|---:|---:|---:|---:|
| F411 Classic, BINARY64, USB Screen | 400244 | 400276 | +32 | 22024, без изменения | 1928 / 5120 |
| F401 product, CORE | 256964 | 256996 | +32 | 29364, без изменения | 1312 / 2048 |

Запас Flash после сборки: F411 — 124012 байт при минимуме 512;
F401 — 5148 байт при минимуме 4096.

Резидентный FlowContext вырос с 232 до 744 байт, CompilerContext — с 312 до 824.
Это 512 байт временного C-стека, а не статическая RAM или уменьшение кеша.
Максимальный frame запуска VM в сборке F411 — 1392 байта.

| APP | Загружаемый размер после, байт |
|---|---:|
| BASIC | 20364 |
| FOCAL | 17952 |
| LANGVM | 20172 |
| LANGIN | 19516 |

LANGVM: 20444 → 20172 байта (**−272**). Лишняя копия Services при INPUT
устранена: проверенное выражение не содержит INPUT и других команд управления.

Отдельно собирается linked PoC: LANGVM 20228, VMSTORE 14004;
F411 linked-резидент 404224 байта Flash, статическая RAM 22024.

## Проверки

ASan/UBSan, обе арифметики BINARY64/CORE:

- `bash tests/run_language_vm_review_tests.sh`: все четыре регрессии,
  host / STM32 APP / специализированный PicoCalc entry.
- `MK61_TEST_SANITIZERS=1 bash tests/run_language_vm_tests.sh`:
  VM, Value, скалярные/целочисленные блоки, переходы, INPUT, сброс состояния,
  BASIC/FOCAL, исходники и повторные вызовы.
- `bash tests/run_language_flash_tests.sh`: RAM/paged identity, ресурсы,
  образы >64 КиБ, INPUT/resume, чтение и заимствования страниц.
- Overlay, compiler-flow, mixed-cache, file-cache, linked-program,
  linked-loader, repeat и repeat-resident suites; полные проверки CORE
  `run_mk_math_tests.sh`. Все завершились успешно.

Реальные ARM APP в Unicorn с F411 BINARY64-резидентом:
`tests/run_language_flash_arm_tests.py` — BASIC 75224 байта / 5006 строк,
FOCAL 75229 байт / 5007 строк; три адреса загрузки, порча выгруженной APP,
постраничный и цельный режимы, INPUT/продолжение и неизменность стека.
Дополнительно выполнены 15/16 вложенных вызовов с 61/65 живыми слотами,
двумя INPUT массива и проверкой всех аргументов на трёх адресах.

Это проверки корректности и размеров, не новый замер скорости шахмат
или задержек клавиатуры/USB на физическом устройстве.
